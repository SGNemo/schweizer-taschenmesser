# Agent team – roster, delegation, sandbox start

For Claude Managed Agents sessions (one session = one task = `nemo-lead` + at most 4 child threads, one sandbox, one budget class). **Routing first:** [WORK-ROUTING.md](WORK-ROUTING.md) decides whether a task goes to a Claude Code chat (all building) or to the agents (bounded coordination and review); agents decline the rest. `nemo-lead` delegates via `send_to_agent` and writes no product code; every agent reads `docs/meta/agents-v3/SHARED.md` first and follows root [CLAUDE.md](../../CLAUDE.md). Delegation format: [PROMPT-TEMPLATES.md#delegate](../PROMPT-TEMPLATES.md#delegate). Definitions, models per role and setup: `docs/meta/agents-v3/README.md`, `docs/meta/agents-v3/SETUP.md`.

## Roster and delegation matrix

| Agent           | Area (paths)                                                                                                                                                                                                                                                                                                                    | Always together with                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `nemo-lead`     | routing gate, delegation (≤ 4 threads, follow-ups in the open thread), priorities and splitting (former po), CHATS/board/PR-format checks (former triage, or bundled to `nemo-docs`); no product code, no merge                                                                                                                 | Opus advisor for cut/conflict/security calls |
| `nemo-builder`  | bounded fixes across `web/src/**`, `server/**`, `mcp/**`, `web/src-tauri/**`, `extension/**`, `packages/vault-core`, UI texts (de/en), tests; loads only the area `CLAUDE.md` of touched paths; never contracts, `.github/**`, tokens, dependency bumps                                                                         | `nemo-reviewer` with the lens its paths need |
| `nemo-reviewer` | every PR: correctness lens always; security lens for every path outside the SHARED.md light-path allowlist (`Security lens applied: <paths>`); design/a11y lens on `*.module.css`, `ui/`, `layout/`, `home/`, widgets, heads                                                                                                    | –                                            |
| `nemo-ops`      | modes `ci` (workflow changes as a patch in the PR text, never pushed), `deps` (pins, lock files by tools, `gen:licenses`, `cargo tree -e features`, audits), `perf` (before/after, `docs/perf/**`, baseline only on approval)                                                                                                   | `nemo-reviewer` (security lens)              |
| `nemo-docs`     | `docs/**`, `README*` pairs, website texts, `docs/CHATS.md` tables, `docs/MANUAL-TESTS.md` checklist, board housekeeping, decision bullets after the maintainer decided                                                                                                                                                          | –                                            |
| `nemo-merge`    | merges merge-ready PRs into `develop` (standing order 2026-11-07): green checks, non-stale `MERGE-READY yes` + head SHA (+ `Security lens applied` for every path outside the light-path allowlist), note or `no-changelog`; trivial conflicts only, everything else back to builder/ops; never `main`/tags/releases/force-push | `nemo-reviewer`                              |
| `nemo-auditor`  | the maintainer's independent audit (own session, never in the lead's roster); asks builder/reviewer/ops/docs read-only, never `nemo-merge`                                                                                                                                                                                      | –                                            |

Dropped without replacement: `nemo-creativity` (ideas → a Fable chat in Claude Code) and `nemo-architekt` (contracts are planned in a Claude Code chat; the lead declines contract/schema work per WORK-ROUTING). The other 14 roles live on as lenses or modes of the seven above.

Merge: `nemo-merge` is the only agent that merges PRs (maintainer's standing order 2026-11-07, [decisions/meta.md](../decisions/meta.md)); every other agent, incl. the lead, never merges.

**Light path** (correctness lens only) only when every path is on the allowlist in `docs/meta/agents-v3/SHARED.md` (plain user/status docs and `.changes/**` only; UI texts and tests get the lens); every other path gets the reviewer's security lens. `docs/meta/agents-v3/**`, `docs/meta/WORK-ROUTING.md` and `scripts/agents/**` are merged by the maintainer himself, never by an agent (SHARED.md).

Agent prompts live in the repo: `docs/meta/agents-v3/nemo-*.json` (source) → `nemo-*.md` (`ant apply`, generated by `scripts/agents/to-ant.mjs`); shared rules `docs/meta/agents-v3/SHARED.md`; IDs in `claude-lock.json`.

## Sandbox start (every session)

| Step                    | How                                                                                                                                                                                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repo                    | mounted at `/workspace/schweizer-taschenmesser` on `develop` (session resource `checkout: develop`, set by `scripts/agents/session.mjs`); still `git fetch origin` and work from `origin/develop`                                                                               |
| Parallel agents         | the clone belongs to the lead's branch; each agent runs commands in its own worktree: `git worktree add --detach /workspace/wt-<agent> origin/develop`, and writes notes/results to its own directory                                                                           |
| Push                    | `git push` uses the mounted repository's credential; `$GITHUB_TOKEN` is an egress-substituted placeholder for REST calls (`Authorization: Bearer` header only, never printed). GitHub actions (PRs, reviews, checks) via GitHub MCP; on 403 REST                                |
| Verification            | `npm run check` + touched specs locally; CI runs `npm test`/E2E on every PR (the truth: read check runs, report run ids). Long commands via `nohup … > /tmp/<job>.log 2>&1 &` and poll (tool-call timeout ≈ 5 min, unverified in the docs)                                      |
| Playwright              | `/opt/pw-browsers/chromium` exists (symlink); no env vars needed; never `playwright install`                                                                                                                                                                                    |
| Rust                    | `cargo fmt`, crate tests (e.g. `-p taschenmesser-local-api`) work; the shell crate (`tests/commands.rs`, clippy, Tauri build) needs gtk/webkit – not in the sandbox (Ubuntu 24.04, Node 22, Rust stable, 8 GB RAM, 10 GB disk); no Windows/Android target                       |
| `npm ci`                | per package: `web/`, `server/`, `mcp/`, `extension/`, `packages/vault-core` (extension resolves vault-core from `src`, no build first)                                                                                                                                          |
| Source of truth for PRs | GitHub (`list_pull_requests`), not the "Wartet auf Sven" table                                                                                                                                                                                                                  |
| Budget and threads      | one budget class per session (S/M/L, set at start, not raised to keep going – a new task = a new session (exception: SETUP §4)); ≤ 25 child threads at a time – the lead sends follow-ups into existing threads instead of new delegations, at most 4 child threads per session |

## Rules for this file

Which agents are live is the maintainer's `ant apply`: until the v3.1 definitions are applied, running agents may still follow the earlier roster ([agents-v3/README.md](agents-v3/README.md)). Set up on 2026-11-07, v3.1 roster in this file since 2026-11-10 (docs diet; re-creating the agents with `ant apply` stays the maintainer's step, [agents-v3/SETUP.md](agents-v3/SETUP.md)). Changes to this file, the agent prompts (`docs/meta/agents-v3/*.json`, `SHARED.md`), or root CLAUDE.md need a maintainer decision (docs/decisions/meta.md) – agents do not change them on their own. Prompt changes: edit JSON → `node scripts/agents/to-ant.mjs` → `node scripts/agents/validate.mjs` → `ant apply` (lead and auditor last, they pin subagent versions).
