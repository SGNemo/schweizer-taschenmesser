# P5 – Reminders, deadlines, delete safety (`feat/qa-reminders-safety`)

Source: `docs/qa/CONSOLIDATED.md` (B19, B08, B09, V05, V08, V10, V15, V20). State: **phase 1 (plan), waiting for "Plan freigegeben"**. Nothing is built yet.

## Findings from the code (verified)
- **Android app:** schedules OS alarms itself (`scheduleUpcoming`, 14 days, max 100, `allowWhileIdle`), rebuilt on start, every 10 min, on outbox/ack/mute change. Exact-alarm permission, boot persistence and battery limits are **not verifiable in the repo** (manifest is generated by `tauri-plugin-notification`; `native.md` says "not verified on a device") → device test below.
- **PWA:** local scheduler only while open; closed app only via Web Push through the user's sync server; no Notification Triggers. **Windows:** only while running (tray ok).
- **Wrong text (B19):** `notifications.intro` and the Push card are shown on every platform; on Android they claim "closed app only with push" and "browser has no Web Push". The exact-alarm/battery hint exists only in the setup step.
- **"Weitere Erinnerungen · N"** is the hourly-cap summary from `policy.ts` `applyLimit` (body = first 3 titles), not the Reminders tab. It lands as one row in the bell.
- **Unterlagen (`vault`) delete:** no undo; `deleteBlob` hard-deletes the file (documented exception in `decisions/ui-components.md`). Dialog `dirty` exists but no form passes it; `ui/useDraft.ts` exists (30 s, memory), unused by forms.
- **Subscriptions:** `nextCancelDeadline` only looks forward → a missed deadline is invisible; no `attention`. 31-day grid = `RecurrenceEditor` (monthly day). `vault` has statuses `expired|act-now|soon|ok` and attention.
- **Tombstones:** `deletedAt` + `repo.restore` exist; `purgeTombstones` (90 days, only after a successful sync) exists although docs say "no GC". No shifts ("Schichten") model exists anywhere.
