# Own map from OpenStreetMap data (module `maps`) – feasibility, phase 0

Goal: a map built from real OpenStreetMap data, stored on the device, built rarely (city by city, on click), offline afterwards, in two levels (lean / full), with a calm progress line. No app code yet: this note compares the options and proposes packages. Current module: [maps.md](maps.md). Decisions: [decisions/maps.md](../decisions/maps.md). Rules: [FOCUS-GUIDELINES](../design/FOCUS-GUIDELINES.md), [DATA-FLOWS](../legal/DATA-FLOWS.md).

**Numbers:** the build sandbox has no network to any map service. Every figure is marked **(doc)** = from the service's documentation or download page as remembered, **(est)** = our estimate from formulas, **(measure)** = the maintainer measures it with the first package. Nothing here was measured.

## Status

- **Package 1 `feat/map-own-tiles` – store and draw (done):** `web/src/modules/maps/own/` – `mvt.ts` (MVT writer/reader), `cut.ts` (features → tiles: projection, clipping, simplification, ring orientation), `style.ts` + `palette.module.css` (style table, palette from tokens), `render.ts` (canvas renderer: areas, lines with casing, labels with halo and collision check, overzoom), `draw.ts` (OffscreenCanvas / canvas), `local.ts` (tile source with memory cache), `theme.ts`, `sample.ts` (fixture town for tests). Collections `maps_region` / `maps_tile` (`local: true`), setting `offlineOnly` ("Nur eigene Karte (offline)"), `TileMap` `resolve` seam, page wiring. Tests: `__tests__/maps.own.*.test.ts`, page test, e2e "the own map draws its stored tiles itself". Nothing leaves the device in this package; no new data flow.
- **Package 2 `feat/map-own-build` – lean build from Overpass (done):** `own/overpass.ts` (query per cell, parser incl. multipolygons), `own/plan.ts` (z13 cells, stored zooms, cap of 64 cells around the centre, cell margin), `own/pyramid.ts` (lower zooms from the stored tiles, never from the network), `own/work.ts` + `worker.ts` + `compute.ts` (parse/cut/encode in a Worker, inline fallback), `own/builder.ts` (one region at a time, retries 5/15/45 s on a busy server, calm pause with a reason, pause/resume/remove, `settle` after a restart), `components/RegionsCard.tsx` (one line per region with the next step), progress line under the map (setting `showBuildProgress`), button "Eigene Karte erzeugen" on a search hit with an area (`Hit.bbox` from Nominatim), notice `maps-build`, data-flow row, netlog host `overpass-api.de`, setting `overpassUrl`, strings in 5 languages, fixture answer `own/fixtures.ts` for unit, page and e2e tests. The Overpass answer shape was written from the API docs, not checked live (sandbox): first device run = hand test.
- **Package 3 `feat/map-own-full` – full level, extend, sizes (done):** "Genauer machen" on a finished lean region builds it again at the full level (`builder.upgrade`: z14 cells, tiles down to z16 with buildings, paths, POIs and street names, the overview redrawn); "Hier erweitern" under the map when the shown area (`viewportBbox`, `TileMap` `onSize`) has cells no own map holds (`createAndStart` with `skipBuilt`: built cells are left out via `region.skipCells`, a covered area creates nothing); size and date per region (`own/format.ts`); "Alle Karten löschen" (two clicks) when there is more than one region. Same data flow as package 2.
- **Next (optional, after the maintainer's call):** package 4 `feat/map-own-regions` (prebuilt PMTiles region files from an own host) and package 5 `feat/map-own-search` (local search in built regions). Open: a level choice before the first build (today lean first, "Genauer machen" afterwards); progress for the overview phase if a big city turns out slow there.

**ODbL attribution:** "© OpenStreetMap-Mitwirkende" with the copyright link stays on the map (already there). Data stored on the device and not passed on carries no further duty. The moment the maintainer _distributes_ prebuilt tiles (§7), the tile set is a derivative database: attribution plus share-alike (publish the build recipe and data date, or the files) per the OSMF community guidelines (Produced Work, Regional Cuts) – a checklist item for `docs/legal`, not legal advice.

## 2. Who builds the map on the device

| Option                                                                                                                                                   | PWA / Android / Windows                         | Dependency                                        | Effort (est)                                          | Verdict                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **A. TypeScript in a Web Worker** (pattern exists: `tools/regex/worker.ts`; WASM is not needed): Overpass JSON per cell → clip to tiles → encode → store | all three the same                              | none                                              | parser + clipper + encoder ≈ 900 lines, fixture tests | **recommended**                                                                        |
| B. Rust in the Tauri shell (a crate like `disk-scan`)                                                                                                    | desktop + Android only; the PWA would have none | probably `osmpbf` / `protobuf` = a Cargo question | a second implementation to keep equal                 | no (now)                                                                               |
| C. Prebuilt region file download (PMTiles)                                                                                                               | all three                                       | none (own reader ≈ 250 lines)                     | small, but needs a host                               | **later, for scale** (§7); the tile format of A is chosen so that C reads the same way |

Planetiler (Java) runs only on the maintainer's machine or in CI: it belongs to C, never to the app.

**Why A works on a phone:** the build is cut into Web Mercator cells: z13 (3.2 km × 3.2 km at 49.6° N) for lean, z14 (1.6 km) for full. One Overpass query per cell returns 1–15 MB JSON (est); `JSON.parse` of that needs ≈ 5× heap for a moment (est ≤ 80 MB), inside WebView limits. Each cell is stored when done, so the build is resumable and the map fills visibly. Erlangen: lean ≈ 16 cells, full ≈ 56 cells (est). Wall time is dominated by the server: 1–15 s per query (est) → lean 0.5–4 min, full 2–15 min; on-device work per cell < 1 s desktop, 1–3 s phone (est, measure).

## 3. How it is drawn

|                    | Own Canvas renderer on `logic.ts`                                                                                                                  | MapLibre GL JS + PMTiles                                                                         |

| Dependencies       | none                                                                                                                                               | two (`maplibre-gl` ≈ 1 MB JS + CSS, `pmtiles`), WebGL required, glyph and sprite files to bundle |
| Fits `TileMap.tsx` | yes: a local tile is rendered to an `OffscreenCanvas` → `blob:` URL → the existing `<img>` tile pipeline; markers, route line, pins stay untouched | replaces the map component; markers and lines re-done through its API                            |
| Look               | our tokens (light and dark map for free), a calm style table (≈ 30 classes), horizontal labels, no rotation or tilt                                | curved street names, rotation, tilt, very polished                                               |
| Effort (est)       | ≈ 800–1 200 lines + style table; label placement is the hard 20 %                                                                                  | ≈ 400 lines glue + style JSON; bundle size, CSP, e2e with WebGL (SwiftShader, slow)              |
| Tests              | unit (geometry, style), e2e pixel checks                                                                                                           | e2e only; WebGL in headless Chromium is fragile                                                  |

**Recommendation:** own Canvas renderer. Store tiles as **Mapbox Vector Tiles (MVT 2.1, protobuf)**, written and read by our own ≈ 450 lines: MapLibre (plan B if the labels disappoint) and prebuilt PMTiles (§7) read the very same data, so nothing is thrown away if the decision flips after package 1.

## 4. Storage

- **Where:** two device-local collections in the `maps` manifest, `local: true` (framework support exists in `core/db/repo.ts`: no sync, no JSON backup, no data API, `purge`): `maps_region` (`id, name, bbox, level, cells {done, total}, status, builtAt, bytes`) and `maps_tile` (`id = "z/x/y"`, `regionId`, `z`, `bytes: ArrayBuffer` = gzip-MVT via `CompressionStream`, `size`). Written only via `createRepo`; never in `aiSchema` (it names collections explicitly, `privacy.test.ts` stays green), never synced, never in a bug report. `npm run db:bump` + `schema-history.json`.
- **Why not OPFS:** `navigator.storage.getDirectory()` (Chrome 86+, Safari 15.2+, Firefox 111+; WebView2 and Android WebView are Chromium; doc) is faster for one big file, but it is a second storage class outside Dexie: "Alle Daten löschen", the health check, the `fake-indexeddb` tests and the diagnostics size line would all need a second path. Dexie `bulkPut` of ≈ 1 000 rows × 20–50 KB per city takes 1–3 s (est). Switch to OPFS only if measured write time or quota hurts (then one file per region, the same MVT inside).
- **Limits (doc, from memory):** Chromium (PWA, WebView2, Android WebView): per origin up to ≈ 60 % of the disk; best-effort data can be evicted under pressure, and the app already calls `navigator.storage.persist()` at start (`core/startup.ts`). Firefox: ≈ 10 % of the disk (max 10 GiB) best-effort. Safari is stricter (≈ 1 GiB, prompts), but iOS is not a target. The module shows the used size per region (`navigator.storage.estimate()` as in the diagnostics export).
- **Clean-up:** settings → Karten & Orte: one row per region (name · level · size · date) with "Karte löschen" (purge tiles by `regionId`, remove the region) and "Alle Karten löschen"; a map is never refreshed by itself, "Neu erzeugen" is a click. Switching the module off keeps the files (one calm sentence says so); "Alle Daten löschen" removes them like every table.

## 6. Progress and cancelling (FOCUS checklist)

- **Only on click:** "Karte erzeugen" for a searched city (bbox from the `boundingbox` of the Nominatim hit) or for the current viewport ("Hier erweitern"). Nothing starts by itself: not after a restart, not when scrolling. The connection log lists every Overpass request (reason `maps`).
- **One calm line** on the map while building: "Die Welt baut sich langsam auf · 14 von 56" with one action ("Pause"); no percentage animation, no toast chain. Built cells appear as they finish, unbuilt cells stay the plain background. A region shows its date, never "veraltet seit …".
- **Off switch:** module setting "Fortschritt auf der Karte zeigen" (default on; off → the line lives only in the settings row).
- **Survives an interruption:** every finished cell is a row; `maps_region.status` is `building | paused | done | error`. After a restart the region row offers "Weiter" and nothing else. Cells are idempotent, repeating one is harmless.
- **Pause vs delete:** "Pause" keeps the finished cells (they are usable); "Karte löschen" purges. Server busy (429 / 504): three retries with back-off, then paused with "Der Kartendienst ist gerade ausgelastet. Später weitermachen." – no loop.
- **Tests:** pure logic (cell plan, state machine, encoder) unit-tested; e2e (desktop + pixel-7) with a mocked Overpass host and a tiny fixture answer: build, pause, resume, delete.
- **Stimulus load:** one line, one button, no new colour; wording per `FOCUS-WORDING.md`.

## Risks

- **Overpass is donated:** limits and outages hit the build; a wide release needs package 4 first. The default stays one instance (setting), no mirror rotation.
- **Memory on phones** if a cell answer is unusually big (dense centre, full level): split the cell (z15) when the answer exceeds a threshold; `[maxsize:]` per query.
- **Label quality** of the own renderer (horizontal names only): judged after package 1; plan B MapLibre reads the same MVT.
- **Quota / eviction** in the browser build: `persist()` is best effort; the size line and a calm "Die Karte wurde vom Browser entfernt. Neu erzeugen?" cover it.
- **No live check in the sandbox:** parser and query shapes are written from the Overpass docs with fixtures, like the Transitous package; the first device run is a hand test.
- **Licence step** when prebuilt files are distributed (§1).

## Decided by the maintainer (2026-10-31)

1. **Renderer:** own Canvas renderer on `logic.ts`; tiles stored as MVT so MapLibre could read the same data if ever needed.
2. **Scaling path:** own prebuilt PMTiles region files on an own static host (package 4 is planned); MVT is the tile format from package 1 on.
3. **Source default:** `https://overpass-api.de/api/interpreter`, https-only URL setting, User-Agent rule as today.
4. **Online fallback:** OSM raster tiles outside built regions (as today), module switch "Nur eigene Karte" for offline-only.

Packages 1–3 are released; 4 and 5 follow after 3.
