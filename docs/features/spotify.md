# Spotify connector – "Läuft gerade"

A widget card on the Overview under the weather: cover, `Läuft gerade: Titel – Interpret`, album, progress bar with times, Zurück / Pause / Nächster; a tap on the card opens the **player** (below). Nothing is visible until Spotify is connected with "Anzeigen"; while nothing plays one quiet row "Spotify: gerade läuft nichts. [Player öffnen]". Switch on the Overview: Anpassen → Karten → "Läuft gerade (Spotify)" (key `core:nowplaying` in the home layout's hidden list, on by default). No colour, no motion. The title is a link (`rel="noreferrer noopener"`). Rules: [FOCUS-GUIDELINES](../design/FOCUS-GUIDELINES.md). Decision: [decisions/features.md](../decisions/features.md). User guide: [user/spotify.md](../user/spotify.md).

## Behaviour
- Connector `web/src/connectors/spotify/` (`authType: 'oauth-pkce'`, `platforms: ['desktop']`; elsewhere the card says "only in the Windows app"). The user brings their **own Client ID** (Settings → Verbindungen → Spotify; stored via `getPlatform().secrets`, never in the repo; PKCE, no secret field).
- Features with their own scopes: **Anzeigen** (`user-read-currently-playing`, `user-read-playback-state`), **Steuern** (`user-modify-playback-state`), **Playlists** (`playlist-read-private`, off by default) and **Lieblingssongs** (`user-library-read`, off by default); a new feature needs a reconnect.
- **Fixed redirect port 38417.** Spotify compares the redirect URI exactly, so the user registers `http://127.0.0.1:38417/callback`. `oauth_listen_start` got an optional `preferred_port`: free → taken, busy → error `port-busy: …` (shown as "Port belegt …"), never a silent other port. `OAuthLoopback.start({ preferredPort? })` is additive; the web platform is unchanged. No new Tauri command, no capability change.
- Data path: additive `ConnectorDef.nowPlaying?: NowPlayingSource` (`read(ctx)` → `{ title, artist, playing, trackUrl } | undefined`, `control(ctx, 'pause'|'play'|'next')`). `home/NowPlayingLine.tsx` reads it through the connector registry; the poller (`core/connectors/nowPlaying.ts`) asks at most every 30 s and **only while `document.visibilityState` is visible** (no timer when hidden, one read on return, at most once per 30 s).
- **Player** (`home/SpotifyPlayer.tsx`, wide Dialog, opens on a tap): big controls (previous, play/pause, next, shuffle, repeat), position slider (seek), volume (when the device has one), device name (`GET /me/player`, read when the dialog opens and after a command). Three ways to start something, each with one tap: **Playlists** (feature "Playlists"), **Lieblingssongs** (new feature "Lieblingssongs", scope `user-library-read`, latest 50, the tapped one plays inside that list), **Suchen** (tracks, playlists, albums; runs on submit only, the words go to Spotify and nowhere else, nothing is kept). A missing feature names itself with a link to Settings → Verbindungen; without "Steuern"/Premium the player only shows what plays. Names of playlists/songs/results live in memory while the dialog is open.
- **Cover:** from Spotify's image host only (`https://i.scdn.co/image/…`, checked by `COVER_URL`), fetched through the platform fetch (connection log sees it, "Netzwerk sperren" applies) and shown as a local `blob:` URL, so the app's `img-src` policy (CSP) is unchanged; any failure = a music icon. The progress bar advances locally between the 30 s reads (a 1 s tick only while playing and visible).
- Errors, all quiet: 204 = nothing plays (the card gives way to the quiet row); 401 → fresh token via `ctx.accessToken({ refresh: true })`, one retry, then status "Abgelaufen" (card shows it, line gone); 429 → `Retry-After` is honoured (capped at 10 min); 403 `PREMIUM_REQUIRED` on a control → controls hidden for a day (`tm-spotify-no-premium`), one toast "Steuern braucht Spotify Premium.", the display stays; 404 (no active device), offline, 5xx → last reading stays, no message. Error text goes through `redact()`.
- Last reading: device-local `localStorage` `tm-spotify-now` (Zod-checked, shown only when younger than 10 min before the first fresh read); disconnect and "reset this device" remove it.

## Music in the focus round (package 2)
Off by default, device-local (`tm-spotify-focus`: mode, playlist id, end switch – no names). Settings → Fokus & Aufmerksamkeit → Weitere Einstellungen → one folded line "Musik in der Fokus-Runde: Aus", **only visible while Spotify is connected with "Steuern" and Premium has not been ruled out**.
- **Beim Start weiterspielen:** `play` without body (resumes, starts nothing new). **Playlist starten:** pick from your own playlists (`GET /me/playlists`, up to 4 pages of 50 via the `next` links, scope `playlist-read-private` = opt-in feature "Playlists", not ticked by default; the list is read when the row is opened, kept in memory, only the id is stored), start = `PUT /me/player/play {context_uri}`. **Am Ende pausieren** (switch, default on).
- `core/focus/music.ts` is the only code that steers the player in a round: `onFocusStart` (from `beginFocus`) and `onFocusEnd` (time up in `FocusWatcher`, "Fertig", "Runde beenden"; once per round). Never in between (pinned by `music.test.ts`).
- Failure never disturbs the round: no toast, only the line "Musik: nicht erreichbar" on the focus screen (`focus-music-status`). A 403 `PREMIUM_REQUIRED` hides the row for a day (same flag as the Overview line).

## Privacy
Title and artist are user data: never to the AI (the connector cannot import `core/ai`, `privacy.test.ts` untouched), not in diagnostics (canary in `core/diagnostics/diagnostics.test.ts`), not synced (device-local only), not in logs. Data flow `spotify` in [DATA-FLOWS](../legal/DATA-FLOWS.md) and Settings → Über Nemo → Rechtliches.

## Spotify's limits (as documented, re-check before relying on them)
Apps in development mode need an owner with Premium and allow only a few named users (the user's own account must be added under "User management"); one Client ID per developer. Playback control needs the *listener's* account to be Premium. Not built: playback inside Nemo (no Web Playback SDK), queue editing, Android/PWA.

## PWA login (browser) and what Android still lacks
- `oauth.browserLogin: true` lets the PWA log in too: `core/connectors/oauthRedirect.ts` stores the PKCE verifier and `state` in `sessionStorage` (`tm-oauth-pending`, this tab, 10 min, used once), the page goes to Spotify, Spotify returns to **`<app origin>/oauth/callback`** (route `pages/OAuthCallback.tsx`), which checks `state`, exchanges the code (browser `fetch`, no secret) and stores the refresh token like the desktop login. The address is replaced afterwards; a wrong or unknown `state` is ignored.
- The user registers `<their Nemo address>/oauth/callback` at Spotify (shown on the card). Only `https://` (and `http://127.0.0.1`) pages offer the button; the card says so otherwise. The E2E build mocks Spotify (`e2e/connector-spotify.spec.ts`).
- Not verified against the real service from the build sandbox: that `accounts.spotify.com/api/token` and `api.spotify.com` answer a browser `fetch` with CORS headers (Spotify documents PKCE for browser apps; hand test S6).
- **Android app (Tauri webview):** still no login. Its origin is not an https address Spotify accepts, and a deep link (`nemo://` registered at Spotify) needs a Tauri plugin (new Cargo dependency, maintainer's decision). Use the PWA in the phone's browser meanwhile.
