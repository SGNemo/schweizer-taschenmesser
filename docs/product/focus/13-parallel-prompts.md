# Focus round 2 – five parallel chat prompts (2026-10-17)

Maintainer decision: build the next improvements first, then the week of use with the diary. Five chats run in parallel, each on its own branch and PR, without questions back. The prompts are in German (they are pasted into chats); the file areas are disjoint so the PRs do not collide. Rows "(announced)" in [../../CHATS.md](../../CHATS.md). Not in this round (next): weather widget, screenshot tool, shortcut sheet with F-keys, grouping of the Darstellung settings ([11-plan-2.md](11-plan-2.md) column 3).

Order and conflicts: all five can start at once. Chats 3 and 4 both touch `core/notifications`; whoever merges second brings `develop` in (logic conflict = stop, as the header says). Chat 4 relies on the updated reminder rule in [../../design/FOCUS-GUIDELINES.md](../../design/FOCUS-GUIDELINES.md) (user-set reminders may repeat until answered): merge this docs PR first or add that sentence to the prompt.

## Common header (paste first into every chat)
```
Lies CLAUDE.md und docs/README.md, dann nur die Docs deines Bereichs. Git: docs/PROMPT-TEMPLATES.md#git · Regeln: #hard-rules · Docs: #knowledge · PR-Text: #pr-text.
Arbeitsweise: Du arbeitest allein und stellst KEINE Fragen. Wo eine Entscheidung offen ist, wähle die sicherere, ruhigere Variante (docs/design/FOCUS-GUIDELINES.md: kein Druck, keine Schuldtexte, alles abschaltbar), schreibe die Entscheidung als ein Bullet in docs/decisions/<bereich>.md und in den PR-Text unter "Entschieden ohne Rückfrage". Nur bei hartem Blocker (Sicherheitsregel würde verletzt, Konflikt in Datenmodell/Registry): stoppen und den PR-Text mit dem Stand ausgeben.
Pflicht: Zeile in docs/CHATS.md im ersten Commit (die "(announced)"-Zeile deines Branches übernehmen), im letzten Commit entfernen. Alle UI-Texte in 5 Sprachen (npm run check:i18n). Nichts am Datenschutz der KI ändern (nie Nutzerdaten an die KI, privacy.test.ts), keine neuen Abhängigkeiten, keine Tests löschen oder abschwächen. Jede Änderung mit Unit-Tests; E2E für sichtbares Verhalten (Desktop + pixel-7). Vor Abschluss develop mergen, `npm run check`, `npm test`, `npm run e2e` grün. Ein PR gegen develop, nicht mergen. Schlussmeldung: 3 Punkte + PR-Link.
Dateibesitz: nur die im Prompt genannten Bereiche; fremde Dateien nur klein und additiv, kein Umbau.
```

## Chat 1 – voice key for the AI input (`feat/voice-ask`)
```
Ziel: Eine Taste, bei der man mit der KI reden kann (Push-to-talk): gedrückt halten oder einmal drücken = sprechen, loslassen/erneut drücken = Text geht in die vorhandene KI-Eingabe (layout/assistant, core/ai) und wird wie getippt behandelt.
Aufgaben: (1) Prüfe, was auf jeder Plattform ohne neue Abhängigkeit geht: Web Speech API (PWA/Android-WebView) und Windows-WebView2 (src-tauri); dokumentiere das Ergebnis kurz in docs/features/voice.md. Wo Spracherkennung nicht verfügbar ist, ist die Taste ausgeblendet oder zeigt freundlich "hier nicht verfügbar", nie ein Fehler. (2) Taste: in der App ein einstellbares Kürzel (Standard F4; core/keyboard/shortcuts.ts, im ?-Blatt anzeigen) plus Mikrofon-Knopf in der KI-Eingabe. (3) Desktop: optional globale Taste über das vorhandene Plugin tauri-plugin-global-shortcut (Vorbild: Schnellerfassung in src-tauri/src/capture.rs; Standard aus, einschaltbar in den Einstellungen; neue Tauri-Befehle nur mit build.rs COMMANDS + capabilities/desktop.json). (4) Datenschutz: Spracherkennung kann Audio an den Browser-Anbieter schicken: Standard AUS, beim ersten Einschalten ein klarer Hinweis, Sprache folgt der UI-Sprache, nichts wird gespeichert, kein Audio in Logs/Diagnose. Texte in strings.ts + 4 Sprachen. Nicht anfassen: core/notifications, modules/calendar, home.
Fertig wenn: Taste startet/beendet Aufnahme mit sichtbarem, ruhigem Zustand (kein Blinken, Reduced Motion), Ergebnis landet in der KI-Eingabe, Abbruch mit Esc ohne Verlust, Tests für Zustandsmaschine und Verfügbarkeitslogik (Erkennung gemockt).
```

## Chat 2 – reminders from an AI sentence (`feat/ai-reminders`)
```
Ziel: "Erinner mich um 15 Uhr an die Wäsche", "in 20 Minuten Pizza rausnehmen", "morgen früh um 8 an Zahnarzt anrufen" in der KI-Eingabe (getippt; Sprache liefert ein anderer Chat als Text) erzeugt eine Erinnerung (calendar, kind=reminder), die später als Benachrichtigung erscheint.
Aufgaben: (1) Prüfe die vorhandene Kette: core/ai/intent/parser.ts, core/ai/write (rules, prepare, commit, eval.test), modules/calendar/ai.ts, reminders.ts, notifications.ts, Schnellerfassung-Parser. Schreibe zuerst eine Tabelle von mindestens 30 deutschen Beispielsätzen (absolut: "um 15 Uhr", "15:30", "Viertel nach drei"; relativ: "in 20 Minuten", "in zwei Stunden", "heute Abend", "morgen früh", "Montag um 9", "übermorgen"; mit/ohne Titel) in die Eval-Tests und lass sie laufen: was schlägt fehl? Behebe das mit deterministischen Regeln (Zeiten rechnet der Code, nicht die KI; now() aus core/time/now.ts). (2) Vorschau vor dem Speichern (WritePreview) zeigt Datum/Uhrzeit groß und klar, "Ändern" und "Speichern"; nichts wird ohne Bestätigung geschrieben; fehlende Uhrzeit bekommt ohne Rückfrage einen sinnvollen Standard (z. B. 09:00) mit sichtbarem Hinweis. (3) Nach dem Speichern: Kontrolle, dass die Erinnerung wirklich als Benachrichtigung erscheint (collectDue, in-App, Android-Schedule); Test mit festgesetzter Uhr. (4) Privatsphäre: die KI sieht nur den Satz, nie bestehende Termine. Nicht anfassen: core/notifications/policy.ts und service.ts, layout/assistant außer WritePreview.
Fertig wenn: die 30 Sätze grün, ein E2E "Satz eingeben → Vorschau → gespeichert → erscheint zur Zeit".
```

## Chat 3 – quiet ping in game mode with the app's own sound (`feat/quiet-ping`)
```
Ziel: Läuft ein Spiel (Vollbild), kommt eine Erinnerung leise: kein Windows-Benachrichtigungston, sondern ein eigener, leichter Ton der App; sonst der normale, ruhige Weg.
Aufgaben: (1) Erkennung "Spielmodus" nur auf dem Desktop (Windows): Rust-Befehl nach SHQueryUserNotificationState (D3D-Vollbild / Präsentationsmodus / beschäftigt) in crates/system-info oder src-tauri/src/capture.rs; neuer Tauri-Befehl nur mit build.rs COMMANDS + capabilities/desktop.json; Zugriff nur über core/platform (getPlatform()). Dazu ein manueller Schalter "Spielmodus" (geräte-lokal wie "Stumm" in core/notifications/mute.ts), falls die Erkennung nicht greift. (2) Zustellung im Spielmodus: OS-Benachrichtigung ohne Systemton (silent), dafür ein eigener kurzer Ton aus der App (mit Web Audio synthetisiert, kein Asset, keine Lizenz; Lautstärke und 3 Klänge in Einstellungen → Benachrichtigungen, Testknopf). Prüfe und dokumentiere, ob der Ton bei minimiertem Fenster/Tray in WebView2 spielt (Autoplay-Regeln, Timer-Drosselung); wenn nicht, nutze die Rust-Seite (Windows PlaySound/Beep über das vorhandene windows-Crate) und begründe. (3) Android/PWA: dieselbe Einstellung wirkt als leiser Kanal (vorhandener Kanal nemo-quiet). (4) Keine Spielerkennung per Prozesslisten oder Fenstertiteln (Datenschutz); nichts verlässt das Gerät. Eigene Dateien: core/notifications/service.ts, neue core/notifications/sound.ts, Einstellungs-Sektion; policy.ts/collect.ts nur additive Felder (ein anderer Chat besitzt die Wiederholungslogik).
Fertig wenn: Tests für die Zustandslogik (Erkennung gemockt), Ton nur im Spielmodus statt Systemton, Reduced Motion/Stumm respektiert, Eintrag in docs/MANUAL-TESTS.md (Handtest mit Vollbild-Spiel).
```

## Chat 4 – reminder repeats until answered (`feat/reminder-repeat`)
```
Ziel: Wird eine Erinnerung nicht beachtet, kommt sie nach 30 Minuten wieder, und wieder, bis sie verschoben ("Später") oder abgehakt ("Erledigt") wird. Entschieden vom Maintainer; docs/design/FOCUS-GUIDELINES.md "Notification limits" erlaubt das für explizit gesetzte Erinnerungen.
Aufgaben: (1) Baue auf dem vorhandenen Nachhaken (focus.followUp) und core/notifications (policy.ts, collect.ts, ack.ts, snooze.ts, scheduler.ts, nativeSchedule.ts, pushPayload.ts) auf: aus "einmal" wird "bis beantwortet", Abstand einstellbar (Standard 30 Min; 10/30/60), bei jedem Kanal gleich (in-App-Karte, Android-Schedule, Web Push). (2) Ruhe-Leitplanken (verbindlich): Obergrenze pro Erinnerung (Standard 6, einstellbar; danach ein höfliches Ende, in der Benachrichtigungs-Zentrale sichtbar), Ruhezeiten respektiert, Stumm und Max-pro-Stunde gelten weiter, Wiederholungstext neutral ("Noch offen: …", nie "du hast vergessen"), Schalter in Einstellungen → Benachrichtigungen → Ruhige Erinnerungen, Standard an für explizit gesetzte Erinnerungen, aus für automatische Extras. "Erledigt" und "Später" beenden die Folge sofort auf allen Geräten. (3) Reine Logik zuerst (pure Funktionen in policy.ts) mit dichten Unit-Tests (Zeitreihen, Ruhezeit-Grenze, Antwort mitten in der Folge, mehrere Erinnerungen gleichzeitig, zwei Geräte), danach Verdrahtung. Nicht anfassen: service.ts (anderer Chat baut dort den Ton), modules/calendar/ai.ts.
Fertig wenn: Test "Erinnerung 10:00, keine Reaktion → 10:30, 11:00 …, Abhaken 11:10 → Ende", E2E mit festgesetzter Uhr, kurze Doku in docs/features/.
```
