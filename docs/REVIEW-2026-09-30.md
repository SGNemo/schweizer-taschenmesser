# Review – Nemo rebrand and overall state (2026-09-30)

Scope: the merged rebrand (PR #9, commit `8e40ebe`) and the state of `develop` at that commit. Read-only review; fixes follow in later phases of the same PR (`chore/nemo-review-polish`). Findings are sorted by severity. Each has a location and a proposed fix. Verified numbers are at the end.

**Verdict:** the rebrand is correct where it matters. No internal identifier was renamed, old backups import, old installations still find updates. What is wrong or missing is visible, not structural: the README download buttons are dead until the next stable release, the Android APK most likely never carried the project's launcher icons (before and after the rebrand), the Android notification icon is generated but unused, and a handful of docs still say "Taschenmesser" where users read them. No critical (data-loss, security, broken-update) finding.

## Rebrand completeness (summary)
- **Visible surfaces:** UI strings, window titles, tray tooltip, push titles, PWA manifest, `index.html`, `productName`, About, export names (`nemo-backup-*`, `nemo-accounts-*`), release title "Nemo x.y.z", README/CLAUDE/docs: **done**. Left-overs are L1–L2 (docs and comments) only.
- **Intentionally internal (must stay):** Tauri identifier, updater endpoint/pubkey, Cargo/npm names, Android packages/namespaces, `TaschenmesserDB`/`DB_NAME`, `tm-*` storage keys, `tm_` token prefix, backup format ids, AAD strings, MCP name/env vars, `.gitignore` legacy patterns, legacy release asset names, `latest.json` target. **All unchanged.** No identifier was wrongly renamed.
- **Update chain:** a v0.2.0 client finds `Taschenmesser-Portable.exe` via `latest.json` and `Taschenmesser.apk`; a new client accepts both names and prefers Nemo. Signature key id unchanged. **Works** (unit-tested both sides). Gaps: M3, M4.
- **Backups:** old `taschenmesser-backup` files import (fixture `legacy-format-2026-01-01.json`, `backup.test.ts:118-135`); encrypted/vault legacy fixtures missing (M2).
- **Assets:** every raster regenerated by `8e40ebe`, no knife icon left; ICO has 7 frames (16–256), maskable icon within safe zone, monochrome layer present. Gaps: H2, H3, L7, L9, M7.

## Design implementation (state before Phase 3)
- Tokens are applied well in CSS modules: 3 raw colours (2 justified: QR white/black), 6 radius/shadow literals, 4 font-size literals (2.5rem/3rem heroes). `tokens.test.ts` guards AA for the main pairs and dark-block parity.
- Debt: module re-implementations of Segmented (calendar, finance ×2, invoices), row buttons (5 pages), progress bars (3), inputs (shopping, packing, todos 22 px checkbox), 133 inline styles, `--accent-hover` unused (no primary hover), badge tones unused, `Skeleton` unused, "…" loading texts, 8 widgets with own empty text, calendar without `EmptyState`.
- Motion: keyframes are transform/opacity only; transitions animate width (3), background/border colour (10), box-shadow (1); `itemIn` stagger delay is not reset under reduced motion (items invisible up to 150 ms). Dialog backdrop blurs the full viewport; `background-attachment: fixed` costs scroll repaints on mobile; sheets are solid although the rule says glass.
- Touch targets below 44 px: `ui` Segmented (36), calendar day numbers (32), month chips (~20), todo checkbox (22).
- Missing token scales: z-index (7 ad-hoc values), font weight (6 values), hairline gaps (2px ×22), focus ring, opacity, icon sizes.
- axe (`e2e/a11y.spec.ts`) covers 25 routes in light/dark and reduced motion, desktop and Pixel 7, but only empty states, not `data-theme` or accent variants.
