# Identity v3 – audit, phase 1: findings (2026-11-04, `review/identity-v3-audit`)

Whole-picture check of identity v3 on `develop` (73da10c4): foundation (#414) plus the four group chats – Planen + Geld (#443), Haushalt/Tresor/Wissen/Medien/Dienste (#442, #448, #453), Einstellungen + Bibliothek (#444, #449), Werkzeuge (#445–#447). Rules under test: [MODULE-IDENTITY.md](../MODULE-IDENTITY.md). Phase 2 (proposals) and the fix packages follow in `02-packages.md`.

## Method
- Dev-Preview build with seed scale `medium`, fixed clock 2026-09-29. Tours: `web/e2e/screenshots/identity-v3.spec.ts` (every module entry page, overview, library, tools, settings × 1280·1920·2560·412 × light/dark, reading aid on at 1920/412) and the audit spec [`tools/identity-audit.spec.ts`](tools/identity-audit.spec.ts) (blind crops, empty states, toolbox, overview head). Sheets: [`tools/grid-audit.mjs`](tools/grid-audit.mjs). Contrast matrix: [`tools/contrast.mjs`](tools/contrast.mjs); mapping seams: [`tools/seams.mjs`](tools/seams.mjs).
- **Blind test:** 147 crops (24 heads + 30 widgets at 1920 light and dark, 19 heads + 20 widgets at 412), title text blacked out (h1, eyebrow, sub-navigation labels, widget titles), random file names, key read only after scoring ([`blind-test.txt`](blind-test.txt)). Limitation: the same reviewer had seen the labelled sheets first, so the raw hit rate is inflated; the honest figure is "recognised by form" below.
- Overflow and centring: `measure--*.json` of the tour (document/main scroll width, elements beyond the window) at all four viewports.

## Findings
Severity: **S1** breaks the promise "recognisable without reading" for several modules or fails an accessibility rule · **S2** one module or one seam clearly off · **S3** polish. Cause: **foundation** (shell, tokens, contract, rule), **group** (a module chat), **seam** (between chats, nobody's rule).

## Foundation decisions – verdicts
| Decision | Verdict | Why |
| --- | --- | --- |
| Palette v3 (ten hues, 25° inside an area, ≥ 25° from state colours) | **nachschärfen** | Inside an area it holds (T05). Across areas every hue is used 2–3× and three pairs share hue and head or widget variant (F04); `--info`/`--focus` outside the rule (F08); area colours repeat member hues (F07). Rule to add: same hue → different head *and* widget variant, app-wide. |
| Nine head variants, two heights | **ändern** | The frame draws two silhouettes (paper, framed) and one height class; the other seven variants exist only as a name (F02). Either the frame gives each variant a real shape (grid areas, signature slot with a size), or the list shrinks to what the frame can show and `signature` carries the rest. The content column must stop growing with the page (F01). |
| Layout rules (one width per area, centred, no overflow, container queries) | **bestätigt** | No overflow or off-centre page at any of the four viewports (T01). Nachschärfen: module chats still use window queries (F15); the overview grid stretches cards (F09). |
| Stripe rule | **bestätigt** | `noStripes.test.ts` green, nothing seen. |
| Widget frame (B: white body, tinted head zone, plate, pattern) | **nachschärfen** | The frame is consistent and calm, but it carries no shape; with six `kennzahl` bodies the icon is the only cue (F05). The variant should bend the body (figure size, sparkline, tile grid, rings) through shared blocks, not module CSS. |
| Sidebar v3 (favourites bar, tinted groups, capsule, rail) and scrollbars | **nachschärfen** | Reads well at 1440p and above; at 1080p three groups hide behind the fade (F06). Scrollbars: thin, no width taken, fade masks present – confirmed. |
| Overview head (greeting, attention cards, agenda) | **bestätigt** | Greeting, "Jetzt wichtig" cards with plates and figures, three day columns: clear at 1920, 2560 and 412. Only the widget grid below needs the row fix (F09). |
| Contract: `identity` fields, `SIGNATURES`, `check:modules` | **nachschärfen** | The checker passes while `signature: 'none'` sits on modules with a strong hero (G12) and 16 of 21 signature ids have no shared block (F12). The checker should know what the frame can render. |

## Open questions for the maintainer (phase 1 stop)
1. **Head silhouettes (F01, F02):** a foundation package that gives every variant a real shape in `AreaFrame` (fixed grid areas, a signature slot with a size, content column capped at the `content` width or the signature anchored beside the figure), *then* the module chats adjust – or only a documentation clarification and each chat fixes its heads? **Recommendation:** foundation package first; it touches one file set and every module benefits without a second rebuild.
2. **Dieser PC (G01):** own small package (head with the drive rings, widget rings in the module hue, drive-kind palette on tokens) or part of the foundation package? **Recommendation:** own package, after the foundation package, together with the downloads polish; it is the only module nobody owned.
3. **E-Mail vs Finanzen (F04, G13):** move mail back to the concept's `schreib` head and a `notiz`-style widget (paper + stamp, no teal `kennzahl`), or change mail's hue? **Recommendation:** `schreib` + stamp; every free hue collides somewhere else, the shape does not.
4. **Empty states (F11):** an `EmptyState motif` prop in `ui/Misc` and port the 13 module-local motifs onto it (fish stays the fallback), with the plan and money modules getting a motif each – one package for all four groups? **Recommendation:** yes, one package; it removes 13 copies and closes the group split in one go.

Everything else (F03 muted-on-tint token, F05–F10, G02–G17) does not need a decision to become a proposal; phase 2 lists effort and risk per finding.
