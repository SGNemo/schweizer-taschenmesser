# LAN sync concept – Fable check (second opinion before package 1)

Checked 2026-11-07 against `develop` b900e52a (PR #505 merged). Scope: CONCEPT.md, NOTES.md, PACKAGES.md, `proto/`, decisions bullet, the three spots named in the PR. No product code was touched; only this report and the line-reference fixes in NOTES.md/STATUS.md.

## Verdict

**With these changes.** The facts hold (10/10 spot checks correct, prototype 10/10 checks on my run), the threat model and the Noise choice are sound, and variant (b) is the right shape for "PC is the server, nothing typed". Before package 1 starts, one design question must be answered that the concept did not ask – whether the hub needs an LWW store at all (append-only mailbox with ack-based GC, finding F1) – because package 1 builds exactly that store; and package 2 is too large for one chat. Everything else is should/nit.

| F1 | **Missing variant: hub as an append-only mailbox, no third LWW copy.** The hub only needs to number ops (`seq`) and hand them out; the prototype already works that way (`proto/hub.mjs` keeps an append-only log, CONCEPT §9 "LWW in the hub's store left out"). LWW then stays where the contract checks it (`mergeOps`, `ops.ts:55`). The only reason for LWW in the store is compaction. Compaction can instead be ack-based: drop everything below `min(cursor)` of all trusted, non-revoked devices; a device unseen for 90 days (same bound as `TOMBSTONE_RETENTION_MS`, `web/src/core/sync/tombstones.ts:14`) is flagged in the list anyway and can be revoked to unblock GC; a new device gets its data because the hub PC re-pushes everything at pairing (`markAllDirty`). | F6 | **Noise claims (PR spot 1) – confirmed against the spec.** `IKpsk1` = `-> e, es, s, ss, psk / <- e, ee, se`: the PSK is mixed before message 1's payload is encrypted, so the responder's payload decryption fails on a wrong PSK before anything is stored – matches `proto/channel.mjs:165-166` (`open(...)` then `burn()`). ## The three spots from the PR

1. **Pairing handshake** – holds (F6); one missing test (window renew race) and one sentence (KCI).
2. **"Only the home network" on Windows** – replace the gateway-MAC heuristic by Windows' own network id + category (F3); exclude virtual adapters; firewall behaviour stays a real-machine check (F16).
3. **Android "comes home"** – state the expected outcome (minutes, not hours; F8) so question 3 is answered knowingly; the later background path is feasible without a headless WebView.

If you want to skip the comparison: (b) as planned is safe, only more code to keep in step.
