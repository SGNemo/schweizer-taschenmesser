# Planner hub 2 – accessibility of every new surface

WCAG 2.1 AA, reviewed against the hand-offs and mockups (not against code: every package runs `design:accessibility-review` on what it built and adds its state to the planner's axe pass in `web/e2e/a11y.spec.ts`). Shared rules: targets ≥ 44 × 44 px (`--touch`), visible focus (`--focus` ring as built), colour never alone, motion transform / opacity only and 0 ms under `prefers-reduced-motion`, text ≥ 4.5 : 1 (`--text-3` on `--surface-2` is 4.5 : 1 by token – the compartment's meta text sits exactly there, so no lighter colour inside a compartment).

## Keyboard paths

| Surface | Path | Notes |
| --- | --- | --- |
| Row, expand (4) | Tab to the title button → Enter / Space toggles → Tab walks into the compartment (it follows the row in the DOM) → Esc closes and returns focus to the title | the row's existing keys stay: `M` move, `L` lock, Space on the lead ticks |
| Panel lines | each tick is a checkbox (Space); a line's end action is a button; no roving tabindex – a panel is short and capped at 8 / 12 lines |  |
| After „Bezahlt“ / last tick | focus goes to the next row's title; if none, to the planner's field | announced by the toast (`role="status"`, as built) |
| Pile (2) | as a row; a member's `▸` is a button with `aria-expanded`; Esc closes the member first, then the pile | two levels at most |
| Offer line (2) | text, button „Als eine Zeile zeigen“, button ✕ (name „Nicht mehr anbieten“) | not a live region; it is there when the page loads |
| Steps (5) | tick lines as above; sorting 5b: `SortableList`'s keyboard mode as built (Space lifts, arrows move, Space drops, Esc cancels) plus „Nach oben / Nach unten“ in the line's ⋯ |  |
| „Los“ (5) | focus lands on „Fertig · weiter“ (a member step without a tick: on its panel's first control); Enter advances; `S` skips; `P` pauses – the letter keys only while focus is outside a text field (WCAG 2.1.4); Esc = „Zurück zum Plan“ (the round keeps its place) | keys listed once under the buttons as `--text-meta` text, hidden on touch |
| „Bündeln …“ dialog | focus in the name field (text selected); Enter = „Bündeln“; Esc cancels; focus returns to the selection bar | shared `Dialog` |
| Share page (1) | the radio group of targets, named by the page's subline (arrows), chips, „Ablegen“; afterwards focus on „Fertig“ | first focus: „Ablegen“ (the choice is preselected) |
| Field preview (3) | typing never moves focus; Enter stores the line's kind; Alt+Enter = „Als Aufgabe eintragen“; the button is also Tab-reachable after the field |  |
| Errand places (6, struck) | as steps; „Ort …“ opens a `Dialog` with a search field and a list box (arrows, Enter) |  |
| Appointment (9) | blocker title is a button; „Vorbereiten …“ moves focus into the field; the lead chip is a button before the input in the tab order (Backspace in the empty field removes it) |  |
| Topic (11) | chooser: combobox (`aria-autocomplete="list"`), arrows through topics, Enter chooses or creates; filter line: „Alles zeigen“ is a button |  |
| Waiting (7, struck) | dialog as above; folded line = disclosure button; „Zurückholen“ a button per line |  |

## Focus order per new surface (top to bottom, never trapped outside dialogs)

- **Row:** select box (selection mode only) → lead → title → link chips → lock → ⋯ → compartment content → compartment foot (left to right) → next row.
- **Pile panel:** part 1 members (each: `▸`, then its open panel) → part 1 jump → part 2 … → foot.
- **Bundle panel:** steps in order (tick, then `▸` / ⋯ of the line) → „Los“ → ⋯ → „Ganz öffnen“.
- **„Los“:** (member's panel if the step has one – it stands under the title and takes the first focus) → „Fertig · weiter“ → „Überspringen“ → „Pause“ → „Zurück zum Plan“.
- **Share page:** card (text, not focusable) → the targets → day chips (S10) → „Ablegen“.
- **Field with preview:** lead chip (if any) → input → „Eintragen“ → „Als Aufgabe eintragen“.

## Target sizes

Everything interactive is ≥ 44 × 44 px: title button (full row height, min 44), chevron is part of it; panel ticks 22 px glyph in a 44 px box; quiet text buttons get 44 px min-height and ≥ `--space-2` side padding; `▸` in pile and bundle lines 44 × 44; „Los“ stage buttons 48 px high; chips in the share page and dialogs use the shared `DateChips` / `Chip` (44 px on touch). Adjacent quiet buttons keep `--space-2` between them.

## Findings of the review (all folded into the hand-offs)

| # | Severity | Finding | Fix (where) |
| --- | --- | --- | --- |
| 1 | major | Title turned from link to expand button: keyboard users lose „open the thing“ as the default action. | „Ganz öffnen“ is always the last control of the compartment and stays the first entry of ⋯ („Öffnen“). (04) |
| 2 | major | A count that changes („4 warten“ → „3 warten“) would chatter in a live region. | Pile meta is plain text; only the toast of his own action is announced. (02) |
| 3 | major | „Los“ changes the page's main content without a navigation. | Polite announcement of the new step; focus stays on „Fertig · weiter“. (05) |
| 4 | minor | Done steps struck through: strike-through alone is a colour-free cue but hard to read. | Done lines also carry the ticked checkbox and `--text-3`; text stays ≥ 4.5 : 1. (05) |
| 5 | minor | Preview line appearing under the field can be missed by magnifier users on 412. | It stands above the field there, directly over the caret line. (03) |
| 6 | minor | A nested box for an open pile member read as a hole in dark mode. | No box: `--space-5` indent, the open member's title in 600, and the structure in the DOM (`group` in `group`). (02) |
| 7 | minor | Dashed „Vorschlag“ chips and plain chips differ by outline only. | The word „Vorschlag:“ leads the chip, as built. (03) |
| 9 | minor | The pay step's chips and field need visible labels (WCAG 3.3.2). | „Bezahlt am“ and „Betrag“ are visible, small. (04) |
| 8 | note | Mail body in the panel could be long and in another language. | Clamped to 6 lines (4 on the phone), `lang` taken from the message when the mail module knows it. (04) |
