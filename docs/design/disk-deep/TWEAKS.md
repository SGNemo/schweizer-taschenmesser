# Dieser PC – "Windows-Einstellungen": the catalogue (p3)

Code: `web/src-tauri/crates/pc-tune/src/tweaks.rs` (catalogue, rules, tests). Texts: `disk.tweaks` in `web/src/strings.ts`. Plan: [PLAN.md](PLAN.md).

## Admission rule

A setting is admitted only when all hold: (1) Windows offers it itself in Settings or the Control Panel, per user (the power plan is the one per-machine exception, changeable without admin); (2) Microsoft documents the mechanism – an API, or a registry value named in a Microsoft article – and the entry carries that URL; (3) no administrator rights; (4) fully taken back by restoring the state from before; (5) the text says what it does and promises no speed. Risk is `none` or `low`, nothing above. No policy key is ever written (Windows would show "managed by your organisation").

Three mechanisms: a `REG_DWORD` below `HKCU\Software` through the `Registry` seam; a documented on/off API (`Flag`); the active power plan. Where a documented API exists it is used instead of the registry value behind it: the API is what Microsoft documents, and Windows stores and announces the change itself.

**The sources were written from memory without web access.** "Sure" below says how confident the author is that the page documents the mechanism; check each URL once before release.

Notes: for the two registry values the state while the value is missing is not documented, so the page says "Standard von Windows" and offers "Einschalten" / "Ausschalten" instead of a switch. The `SystemParametersInfo` and shell calls make Windows write its own per-user storage (partly outside `HKCU\Software`); Nemo itself writes no registry value there, and the undo goes through the same API.

In a remote desktop session the three `SystemParametersInfo` settings are not offered: Windows can report them as off there although the stored setting is on, and an undo would then store the wrong state.

A registry value that exists but cannot be read exactly is shown as not changeable and never written (no value from before, no way back). The values from before are stored device-local in `<app local data>/pc-care/journal.json` (setting ids and old values only; never synced, backed up or reported).

## Rejected or open

| Candidate                                                                                               | Why not (now)                                                                                                | Recommendation                                                      |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Transparency effects (`…\Themes\Personalize` `EnableTransparency`)                                      | No Microsoft page known that documents the value                                                             | Out until a source is found                                         |
| Game Mode (`…\GameBar` `AutoGameModeEnabled`)                                                           | The switch is documented, the value name is not                                                              | Out; link Windows' own page if wanted                               |
| Tailored experiences (`…\Privacy` `TailoredExperiencesWithDiagnosticDataEnabled`)                       | The article is believed to name only the policy value (`Policies\…\CloudContent`), which is never written    | Check the article; admit only if it names the non-policy user value |
| Tips and suggestions (`ContentDeliveryManager` `SoftLandingEnabled`, `SystemPaneSuggestionsEnabled`, …) | Named in the article for Windows 10; unclear which value the Windows 11 switches read – risk of a dead value | Open; needs a check per Windows version                             |
| File extensions / hidden files as raw `HideFileExt` / `Hidden`                                          | No Microsoft page known that documents the values; the documented API does the same                          | Solved through `SHGetSetSettings`                                   |
| Language list for websites (`HKCU\Control Panel\International\User Profile`)                            | Documented, but outside `HKCU\Software`                                                                      | Out by rule                                                         |
| Telemetry level, background apps                                                                        | Machine-wide or policy, needs admin                                                                          | Leave to Windows Settings                                           |
| Creating, importing or unhiding power plans ("Ultimate Performance")                                    | Not a setting Windows offers on that machine                                                                 | Never                                                               |
| Other visual-effect flags (menu, tooltip, combo-box animation, shadows, font smoothing)                 | Documented `SPI_*`, admissible, but each adds a switch few people need                                       | Add on request, one line each                                       |
