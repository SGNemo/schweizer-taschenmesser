# Device exchange – messages, links, images and files between phone and PC (concept)

Branch `design/device-exchange`, 2026-11-16. Status: **concept, decided by the chat** (no questions to Sven before building; "Noch offen" in §11 carries a recommendation each). No product code; prototype in [`proto/`](proto/). Packages and prompts: [PACKAGES.md](PACKAGES.md). Rules it builds on: root `CLAUDE.md` "LAN sync", "Remote control", "AI privacy", "Platform", "Local API"; [RULES.md](../../RULES.md); [rules/remote-control.md](../../rules/remote-control.md); [sync-lan/CONCEPT.md](../sync-lan/CONCEPT.md); [remote-control/CONCEPT.md](../remote-control/CONCEPT.md).

Sven's wish: „Eine Möglichkeit, Daten von Handy und PC hin- und herzuschicken, plus Chat: Nachrichten vom PC ans Handy, Bilder, alles. Vielleicht beim Chat mit einbauen, sonst neues Modul.“

## 0. In one paragraph

A new module **„Austausch“** (id `exchange`, area System, desktop + Android) shows one conversation per paired device: notes, links, copied text, images and files as cards. It travels over the existing LAN hub: a **fourth handshake mode** (`MODE_EXCHANGE = 4`) on the hub's own listener, same keys, trust list, home-network rule and limits as sync and remote control, never mixed into a sync or input session. The phone always dials (it never listens), so the PC keeps an **outbox per device** and hands it over on the next session the phone opens; while the page is open the phone keeps that session open, so PC → phone feels instant. Files go in 64 KB frames with progress, cancel, resume and a SHA-256 check, are written **only to disk** (PC: `Downloads/Nemo`, phone: app storage with „Teilen“ / „Speichern unter“), **never** into IndexedDB, sync or a backup; Nemo never opens or runs them by itself. Messages are a device-local table (`local: true`: not synced, not backed up, not searchable, no `aiSchema`, `dataApi: false`), so nothing from it can reach the assistant. Exchange is its own per-device permission at the PC, separate from remote control.

## 4. Transport

**Mode 4 on the hub's listener** – the remote-control pattern (`remote-control/CONCEPT.md` §3 option b): own handshake mode byte in the prologue, same `Noise_IK`, trust list, per-address handshake limit; no new listener, port, bind or firewall prompt. Accepted **only on a bind flagged home** (as mode 3; a bind that exists only for a pairing window elsewhere drops it with the authenticated `unknown-device`). A sync session refuses exchange tags, an exchange session refuses sync and input tags (both close); the exchange handler never touches the store, its mutex or the input gate. Rule test `exchange_sync_input_stay_apart`.

**Who dials.** Android never listens (rule). So: phone → PC is a push on a session the phone opens; PC → phone waits in the PC's **outbox** and goes out on the next exchange session that phone opens. The phone opens one when: the app starts or comes to the foreground; the Wi-Fi changes while the app lives (`lanWatch`, as sync); every 60 s while the app is in the foreground (one handshake ≈ 3–5 ms, prototype); and it **keeps it open while the Austausch page is visible** (duplex client like `input_client.rs`, `ping` every 60 s against the 120 s idle close). With the app closed nothing arrives until it opens – said in the user docs; a background fetch is §11.

**Wire** (tags `0x30–0x3f`, a test asserts no collision with sync `0x10/0x11` and input `0x20–0x2b`; binary records with explicit lengths, no JSON, every string UTF-8-checked and capped):

| Tag                                                                    | Direction         | Content                                                                                                                   |
| ---------------------------------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `0x30 open`                                                            | phone → PC        | `[version, features]` after `hello`                                                                                       |
| `0x31 opened` / `0x32 refused {code}`                                  | PC → phone        | `opened {grant, autoLimitMb, features}`; codes `exchange-off` (module off at the PC), `not-granted`, `paused`, `full`     |
| `0x33 item`                                                            | both              | `id (16 B) · kind (text, link, clip) · body ≤ 16 KiB`                                                                     |
| `0x34 ack`                                                             | both              | `id · state (stored, refused)` – an item counts as sent only after its ack                                                |
| `0x35 offer`                                                           | both              | `id · size u64 · sha256 (32 B) · name ≤ 255 B · mime ≤ 64 B`                                                              |
| `0x36 accept {id, from}` / `0x37 wait {id}` / `0x38 refuse {id, code}` | receiver          | `from > 0` resumes; `wait` = needs _Annehmen_ (size over the limit); codes `too-large`, `full`, `declined`, `not-granted` |
| `0x39 chunk`                                                           | sender            | `id · offset u64 · bytes` (≤ 65 494 B: 65 535 minus tag, header and the 16-byte AEAD tag)                                 |
| `0x3a end {id}` / `0x3b result {id, ok, code}`                         | sender / receiver | `ok` only when length and SHA-256 match                                                                                   |
| `0x3c cancel {id}`                                                     | both              | either side, any time                                                                                                     |
| `0x3d ping`                                                            | phone → PC        | keeps the open page's session                                                                                             |

Frame cap of an exchange session: 256 B until the first authenticated frame, then 65 535. One file transfer at a time per session (the next waits; a text item may go between two chunks), at most 3 queued offers per direction in flight.

**Integrity and resume.** The receiver writes `<id>.part` in a hidden subfolder of the target (`.nemo-incoming`), hashes while writing (re-hashes the existing part on resume), compares length and SHA-256 at `end`, then renames to the cleaned unique name; a mismatch deletes the part and says so. A part is kept 24 h for a resume (same `id`, `accept.from` = its length), then deleted. Offsets must be contiguous (an out-of-order chunk closes the session).

**Limits.** Per file 4 GB (v1). Sender queue on the phone ≤ 2 GB of pending files. Receiver: refuses with `full` when free space would drop below 1 GB (PC) or 500 MB (phone); the phone's inbox in app storage is capped at 2 GB (oldest received files are offered for cleanup, never deleted silently). Without asking up to **100 MB per file** (setting at the receiver: 25 / 100 / 500 MB / _Immer fragen_); above that the receiver's card asks. Rate: at most 300 items per hour per device (a flood closes the session with `limit`, the cards stay).

**Bandwidth.** Measured (prototype, §10): the exchange layer itself (64 KB frames, ChaCha20-Poly1305, SHA-256) moves ≈ 300 MB/s on one host, so real speed is set by the Wi-Fi: unsicher, expected 5–40 MB/s (802.11ac/ax at home) – a 100 MB video in ≈ 3–20 s. Sync and remote control keep their own connections and are never blocked by a transfer; on a slow Wi-Fi a running transfer may add latency to the touchpad (TCP shares the air) – package 2 measures the touchpad latency with a transfer running. **unsicher:** the hub's outbound path is polled on the 200 ms tick today (`poll_outbound`); PC → phone files must not be capped by that tick (package 2 writes chunks until the socket would block, then waits for writability, and measures).

**Home network only.** Same rule as LAN sync; what it means for phone → PC: nothing goes while the phone is away, the item waits (§2). No relay through the own sync server in v1 (§11).

## 6. Security

**Permission.** Pairing is not permission. At the PC, per paired device: _Austausch erlauben_ (Settings → Geräte → device, and the module's first-run step). Stored in the hub's device-local `trust.json` (`exchange: { on, paused, autoLimitMb }`), never synced, never changeable by a network message (rule test as `no_frame_from_the_network_reaches_a_setter`). Writers, complete list: two desktop-only Tauri commands (`exchange_set_device`, `exchange_set_folder`). **Default: off**; the module's first run on the PC (module switched on, at least one paired device) shows the paired devices with the switch **preselected on** and one button _Austausch einschalten_ – one deliberate click at the PC for the user's own devices, nothing automatic. Why not a native dialog per widening as remote control: that dialog protects against a controlling phone clicking Nemo's own UI with simulated input; exchange cannot click, and a phone that controls the PC at full level can already do anything a user can. Why not on by default: a device paired only for sync (an old laptop, a family phone sharing the hub) should not drop files into `Downloads` unasked. The phone side needs no grant: it only receives on sessions it opens itself, with the module on.

**Never open or run.** Nemo never opens a received file by itself. _Öffnen_ (the OS default app) appears only for the risk class `plain`; `dangerous` = the last extension is in the list (`exe com scr pif bat cmd ps1 psm1 psd1 vbs vbe js jse wsf wsh hta msi msix msixbundle msp mst appx appxbundle appinstaller lnk url scf inf reg cpl dll sys jar apk xapk apks iso img vhd vhdx library-ms settingcontent-ms`, prototype `risk`) and gets only _Im Ordner zeigen_ plus the line „Programme und Skripte öffnet Nemo nicht. Nur öffnen, wenn du die Datei selbst geschickt hast.“; the card always shows the full name with extension (`Rechnung.pdf.exe`). On Android Nemo never asks for `REQUEST_INSTALL_PACKAGES`. Office macro formats (`docm`, `xlsm`) count as `plain` – the Herkunftsmarke makes Office open them protected.

**Proposed hard-rule line** (root `CLAUDE.md`; full text in a new `docs/rules/device-exchange.md`; own PR, Sven merges – „Im Nachhinein klären“, §11):

> - **Device exchange (phone ↔ PC):** only in the LAN hub's exchange session (mode 4: same listener, keys, trust list and home-network rule; never the sync or input session, a new listener or the Local API); only for a device granted at the PC (off by default, device-local, never set over the network); files only on disk, never in IndexedDB, sync or backup, paths only in Rust; names cleaned, nothing opened or run by Nemo, risky types only with a warning; no `aiSchema`, search or data API; never log contents or names. Full text: `docs/rules/device-exchange.md`.

- **One conversation per device**; with one paired device there is no device picker (the common case); with more, a `Segmented`/select in the head row.
- **Cards**, not bubbles with tails; direction by alignment and the line „vom Handy“ / „vom PC“ (colour never alone). Kinds: Text (_Kopieren_), Link (title/host, _Öffnen_ in the browser, _Kopieren_), Zwischenablage (_Kopieren_), Bild (thumbnail, _Öffnen_ / _Im Ordner zeigen_ or phone _Teilen_ / _Speichern unter_), Datei (icon by type, risk line). States as text + icon: „Wartet aufs Heimnetz“, „Wartet auf deinen PC“, „Wird gesendet · 34 %“, „Gesendet“, „Pausiert“, „Abgebrochen“, „Kam nicht vollständig an“. No „gelesen“ ticks, no typing indicator.
- **Send:** field + _Senden_ (Enter on desktop); _Datei_ (picker); desktop drag & drop onto the page (drop zone appears only while dragging); phone _Zwischenablage senden_ in the field's menu.
- **Share target (phone, package 3):** „An PC senden“ as the first target in `ShareTarget` when exchange is on and the PC paired (label with the PC's name: „An PC-Sven senden“ once renamed); files and images from the system share sheet (`ACTION_SEND`/`ACTION_SEND_MULTIPLE`, `image/*`, `*/*`).
- **„An Handy senden“ in other modules (package 3):** a core helper `core/exchange/send.ts` (`canSendToDevice()`, `sendToDevice({kind, text, title})`) emits an event on the bus; the module subscribes in its `services`. Merkliste, Notizen, Browser add one menu entry each; no module imports `exchange`, no manifest contract change.
- **Notification:** one per burst (30 s), quiet, through the notification policy (quiet hours, per-hour limit, game mode silent): „Neu vom Handy: 2 Dateien“; switch _Benachrichtigen bei Eingang_ in the module settings, **on** (the user triggered it on the other device; it replaces walking over to look) – §11. PC also: the tray tooltip line. Nothing when the page is open and focused.
- **Focus checklist:** 1 stimulus: one page, one field, no counters in the head; 2 off switch: module off by default, notification switch, per-device pause; 3 next step: every waiting state names it („Wartet aufs Heimnetz“); 4 wording: no „noch nicht gelesen“, no red, no exclamation; 5 interruption: queue and resume survive app switch, Wi-Fi loss and restart; 6 tests: §8 per package; 7 readability: direction and state in text; 8 clicks: link PC → phone 2, photo phone → PC via share sheet 3; 9 removed instead: the „mail it to myself“ / messenger-to-self detour; inside Nemo the Tastatur-paste workaround of remote control for longer texts.

## 8. Tests (across packages)

Rust (`crates/lan-sync`): mode 4 only on home binds; refused without grant/paused/module off; tags apart (sync, input, exchange); cap 256 → 65 535 only after `hello`; no network frame reaches a grant setter; out-of-order chunk closes; resume from part; checksum mismatch deletes; limits (size, rate, free space). Shell/crate: name cleaning table (prototype cases + Windows-specific), unique names, `Zone.Identifier` written (Windows check), risk table. Web: privacy test (no `aiSchema`/`searchable`/`dataApi`, blocked id), item states, retention, unit tests of cards; e2e with a fake `exchange` service (desktop: drop, progress, cancel; phone viewport: share target, waiting states). Hand tests (MANUAL-TESTS, ids `AX1…`): real phone + Windows PC (link both ways, 1 GB file with Wi-Fi off/on, app closed, dangerous file, clipboard sensitive flag).

## 9. Out of scope (v1)

Phone ↔ second PC directly; exchange outside the home network (relay via server, Tailscale); folders (ZIP hint); Android background delivery with the app closed; group sends to several devices at once; editing/deleting a card on the other side („zurückholen“); read receipts; end-to-end encryption at rest of received files (they are the user's files on their disk).

## 10. Prototype

[`proto/`](proto/), run `node docs/design/device-exchange/proto/run.mjs` (Node ≥ 20, no install). `pc.mjs` (own process, listener) receives into a temp folder; `run.mjs` plays the phone. Channel: X25519 + HKDF + ChaCha20-Poly1305 per frame with a u16 length prefix and the 65 535-byte Noise frame limit – a stand-in for the hub's `snow` session, whose handshake and trust checks [sync-lan/proto](../sync-lan/proto/) already exercises. Measured 2026-11-16, container, both processes on one host over the interface address (not real Wi-Fi), 5 rounds, Node v22.23.4, Xeon 2.1 GHz:

| Measure                                                           | median   | p95 / range | n     |
| ----------------------------------------------------------------- | -------- | ----------- | ----- |
| Text message phone → PC, sent → ack (open session)                | 0.18 ms  | p95 0.55 ms | 1 000 |
| Message PC → phone on the open session                            | 0.24 ms  | p95 0.64 ms | 50    |
| Message on a new connection (connect + key exchange + send + ack) | 3.0 ms   | –           | 1     |
| 1 MB file, 65 494 B chunks                                        | 97 MB/s  | 67–109      | 5     |
| 16 MB                                                             | 254 MB/s | 230–366     | 5     |
| 64 MB                                                             | 308 MB/s | 272–315     | 5     |
| 256 MB, 16 KiB chunks                                             | 266 MB/s | 231–277     | 5     |
| 256 MB, 65 494 B chunks                                           | 308 MB/s | 278–376     | 5     |
| SHA-256 at the receiver (re-read), 256 MB                         | 391 ms   | –           | 5     |

Checks, all ok: `resumeFromPart` (cut at 40 %, resumed from the part's length), `resumeChecksumOk`, `corruptionCaught` (one flipped byte on disk → refused, part deleted), `fileNames` (13 cases), `dangerousExtensions`, `uniqueName` (`../Foto.jpg` → `Foto.jpg`, again → `Foto (2).jpg`). Reading: the exchange layer costs < 1 ms per message and moves ≈ 300 MB/s on one core, an order above home Wi-Fi; the largest frame is worth it (+16 % over 16 KiB); hashing while writing (product) saves the re-read. **unsicher:** real Wi-Fi throughput and the phone's JS → Rust path for the share sheet – package 2 measures on a device (MANUAL-TESTS AX row).

## 11. Für Sven entschieden / Noch offen / Im Nachhinein klären

**Entschieden (vom Chat, mit Grund):**

1. Eigenes Modul „Austausch“ im Bereich System, nicht im KI-Chat, nicht in der Fernsteuerung (§3).
2. Modus 4 auf dem Listener des Hubs, eigene Tags, nur Heimnetz; PC wählt nie, Ausgang je Gerät am PC (§4).
3. Nachrichten gerätelokal (`local: true`), nicht synchronisiert, nicht im Backup, 30 Tage Standard (§5).
4. Dateien nur auf der Platte (`Downloads/Nemo`, Handy App-Speicher), Pfade nur in Rust, PC → Handy per Referenz (§5).
5. Freigabe je Gerät am PC, Standard aus, beim ersten Einschalten ein Klick mit vorausgewählten eigenen Geräten; kein nativer Dialog (§6).
6. Ohne Rückfrage bis 100 MB je Datei, darüber _Annehmen_ beim Empfänger; nie öffnen/ausführen; Herkunftsmarke unter Windows (§6).
7. Zwischenablage nur auf Tipp senden, am PC nie automatisch übernehmen (§6).

**Noch offen (Empfehlung zuerst):**

1. **Benachrichtigung bei Eingang standardmäßig an?** an (vom Nutzer selbst ausgelöst, ein Hinweis je Schwung, Ruhezeiten gelten) · aus wie andere automatische Hinweise.
2. **Handy bei geschlossener App:** nichts, beim Öffnen holen (empfohlen für v1) · Hintergrund-Abruf über WorkManager wie LAN-Sync-Paket 5 (Akku, eigener Paket-Aufwand).
3. **Unterwegs:** nur Heimnetz (empfohlen, wie LAN-Sync) · über den eigenen Sync-Server weiterleiten (Ende-zu-Ende, aber Dateien auf dem Server – eigene Regel nötig).
4. **Name:** „Austausch“ (empfohlen) · „An mich“ · „Hin & her“.

**Im Nachhinein klären:** die Hard-Rule-Zeile (§6) als eigener Doku-PR, den Sven merged; bis dahin halten sich die Pakete an den Vorschlag (er verschärft nur, er lockert keine bestehende Regel). Option „Zwischenablage gleich übernehmen“ (Paket 4, aus). Ordner als ZIP automatisch packen.
