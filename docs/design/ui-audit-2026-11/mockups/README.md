# Mockups – Identity 4.0 (Zielform, kein App-Code)

Drei Seiten als HTML auf der Basis der Identity-v3-Mockups (`docs/design/identity-v3/mockups/`, Palette v3 und Marken unverändert), mit der Ebene `v4.css`, die die fünf 4.0-Regeln zeigt: Tonstufen statt Schatten, eine Titelzeile mit Tabs, Navigation in einer Ebene (keine Sub-Navigation am Desktop, eine Modul-Zeile unter dem Kopf am Handy), am Desktop ein neutrales „Neu“ (Schnellerfassung) plus die eine gefüllte Modul-Aktion im Kopf, am Handy nur die Modul-Aktion (Schnellerfassung über das Suchfeld), kein FAB und kein Inline-Feld, Dichte je Gerät (Master–Detail, Lesemaß, Inhalt ab Bildschirm 1). Rendern aus `web/`: `node ../docs/design/ui-audit-2026-11/mockups/render.mjs` → `web/.screens/ui-audit/mockups/` (gitignored). Die Bilder liegen auf dem Branch `shots/ui-audit-2026-11`:

Was die Mockups **nicht** zeigen: die „Bühne“-Variante (Wetter, Musik), Leerzustände, Dialoge, die Einstellungen; sie sind eine Zielform für die Council-Bewertung von „modern“ und „ruhig“, keine Spezifikation der Pixel. Gemessen am Mockup (412×915, dunkel): Kopf mit Titelzeile, Modul-Zeile und Tabs 138 px (Ziel ≤ 9 rem = 144 px) statt 344 heute; Inhalt ab y 206 (Ziel ≤ 220) statt 834 (Finanzen) bzw. 584 (ToDos); jedes Ziel in Kopf, Modul-Zeile und Tabs 44 px hoch. h1: 28/600 Desktop, 22/600 Handy. Nicht gezeigt: die 36-px-Zeilen unter `pointer: fine` am Desktop (Regel 5 zeigt dort nur Master–Detail und Lesemaß).
