# Architecture reference – Nemo

Detailed design notes, moved out of `CLAUDE.md` unchanged so the working guide stays short. Read the section that matches the area you are changing; keep it current when a decision changes.

## Architecture decisions

**Modules.** Each module is `web/src/modules/<id>/` with a `manifest.ts` (`ModuleManifest`, see `core/modules/types.ts`). Manifests are discovered with `import.meta.glob` (eager, tiny); routes and widgets are `import()`-lazy. State (enabled/disabled) is in the synced `_modules` table; without an explicit choice `defaultEnabled` applies. Disabling asks: keep data (hidden) or delete (tombstones, so the deletion syncs). `devOnly` modules (the `example` module) are only listed in dev builds / with `VITE_INCLUDE_EXAMPLE=true` (`.env.e2e`).

**Isolation.** Modules never import each other (enforced by ESLint `no-restricted-imports` and by `registry.test.ts`, which scans the source). They communicate via

- the typed **event bus** (`core/events`, catalogue in `events.ts`),
- **manifest contributions** (`contributions.quickAdd`, `calendarItems`, `notifications`; loaders are lazy `() => import()` so manifests stay free of DB imports; collected by `core/modules/contributions.ts`),
- the only exceptions (read-only `public.ts`, enforced by ESLint + `registry.test.ts`): `finance` may import `subscriptions/public.ts` and `invoices/public.ts`; `budgets` may import `finance/public.ts` (expense categories, spending per category and month).

**Data.** One Dexie table per collection, named `<moduleId>_<collection>`; system tables `_meta`, `_outbox`, `_secrets` (local only) and `_settings`, `_modules` (synced). Table schemas are derived from all manifests (`core/db/schema.ts`); `schema.snapshot.json` holds the committed Dexie version + stores and a test fails when they drift → run `npm run db:bump`.

- IDs: `crypto.randomUUID()`. Money: integer minor units. Date-only values: `'YYYY-MM-DD'` strings, times of day `'HH:mm'` (local wall clock – calendar events and reminders use date + time strings instead of epoch ms so they stay put across timezones and recurrence works on plain dates); epoch ms only for technical timestamps (`createdAt`, `completedAt`, notification `at`).
- **Every synced record carries an envelope**: `id, createdAt, updatedAt, deviceId, deletedAt (tombstone), _f` (per-field HLC stamps → field-level last-write-wins).
- **Writes only via `createRepo(table, zodSchema)`** (`core/db/repo.ts`): validates, stamps changed fields with an HLC (`core/db/hlc.ts`), soft-deletes, queues into `_outbox`. Modules must not import `@/core/db/db` (ESLint). Reads: `repo.active()` (live records) / `repo.table` (read-only view, includes tombstones) with `useLiveQuery`.
- Inside Dexie transactions never await non-Dexie promises; keep row builders pure (see `repo.ts`).
- Module data migrations: `manifest.migrations[toVersion]`, run by `core/modules/migrate.ts`; installed version is device-local (`_meta`).
- Time: use `now()` / `today()` from `core/time/now.ts` (injectable in tests), never `Date.now()` in logic.

**Shared building blocks (Phase 2).**

- `core/recurrence`: Zod `recurrenceSchema` (`freq, interval, byWeekday (ISO 1=Mon), byMonthDay (1–31 or -1), monthOfYear, until, count`), `occurrencesBetween / nextOccurrence / firstOnOrAfter / datesInRange` on `'YYYY-MM-DD'` strings, "every 31st" clamps to month end, `describeRecurrence()` (German) and `<RecurrenceEditor>` for forms. Editing a recurring item changes all occurrences (no per-occurrence exceptions yet).
- `core/time/dates.ts`: string-date helpers (`addDaysStr`, `formatDay` with the German locale, `toEpoch`, …).
- `CalendarItem` (in `core/modules/types.ts`): every module can put items on the calendar via `contributions.calendarItems`; the calendar module never imports other modules. `useCalendarItems(range)` is live.
- `core/notifications`: `NotificationService` interface + local implementation (uses `registration.showNotification`, falls back to `new Notification`). `startNotificationScheduler()` (started in `main.tsx`) checks every 30 s / on visibility for notifications in `(cursor, now]` from `contributions.notifications`, cursor in local `_meta.notifyCursor`, catch-up limited to 24 h, dedupe through the notification `tag`. Works while the app is open only.
- Dashboard: `pages/dashboard/` – widgets from active manifests, order/hidden in synced `_settings` scope `dashboard` (`layout.ts` is pure and unit-tested), dnd-kit with keyboard sensor and German announcements. `ModuleManifest.order` sorts navigation, library and default widget order.

**Money & finance (Phase 3).**

- Money is integer cents everywhere (`core/money.ts`: `formatMoney`, `parseMoney` for "12,50" / "1.234,56", `formatMoneyInput`); one currency (EUR) app-wide for now. Forms keep the amount as text and parse on submit.
- **Invoices → finance without importing each other:** `invoices/actions.ts` emits `invoice.paid` / `invoice.unpaid` on the bus. Finance runs a _module service_ (`contributions.services`, started/stopped by `core/modules/services.ts` for exactly the enabled modules) that books the expense with the deterministic id `inv-<invoiceId>` (idempotent, convergent across devices, restores a tombstone; a re-announcement after editing a paid invoice only updates amount/date/payee/note and keeps the user's account/category). Reopening removes the expense. Paying while finance is disabled books nothing (not reconciled later). Deleting an invoice keeps its expense.
- **Sanctioned cross-read:** `finance/summary.ts` imports only `invoices/public.ts` (`listOpenInvoices`, `sumOpenInvoices`) and `subscriptions/public.ts` (`listSubscriptionCharges`, `subscriptionTotals`); ESLint (regex allowlist) and `registry.test.ts` enforce this. Data of disabled modules is never read (checked via `useModuleStates`).
- **Available money** = balance (bookings up to today) − open invoices − subscription charges until month end (each part switchable in the finance settings, only counted when that module is enabled). The hero figure shows "Verfügbar" only when something is actually deducted, otherwise "Kontostand".
- **Subscriptions are forecasts, not bookings:** they are never turned into transactions automatically. Cost per month/year is normalised from the recurrence (`chargesPerYear`), rounded once at the end. Cancellation deadline = next charge − `cancelNoticeDays`; shown on the calendar (kind `cancel`) and as a notification (`cancelRemindDaysBefore`, 09:00).
- Finance seeds a default account (`acc-main`) and categories with fixed ids once (flag in the synced settings scope `module.finance`); the invoice category is `cat-invoices`. The first account (by `order`) receives automatic bookings.
- **Charts** (`finance/components/Charts.tsx`, Recharts, lazy chunk only loaded on the overview) follow the dataviz skill: nominal categories → one colour for all bars (sorted, value at the bar tip, ≤ 24 px, 4 px rounded data end); two series → tokens `--viz-1` (turquoise) / `--viz-2` (orange) from `ui/tokens.css` (Nemo palette; ≥ 3:1 on the surfaces, asserted in `ui/tokens.test.ts`; the skill's `validate_palette.js` colour-vision check was not re-run after the rebrand – see STATUS); legend above, grouped columns with 2 px gap, hairline solid grid, text in text tokens, tooltip with line key + value first, and a **table twin** for every chart (toggle button). Re-validate if `--surface` or the viz tokens change. Bars grow in over 240 ms (off under reduced motion).

**State.** Data = Dexie + `useLiveQuery`. Zustand (`stores/ui.ts`) = UI-only state (theme, palette, quick add, toasts). Theme lives in `localStorage` + inline script in `index.html` (no flash).

**UI.** CSS Modules + tokens (`ui/tokens.css`), light/dark, `prefers-reduced-motion` respected. Primitives in `web/src/ui` (Button, Dialog on native `<dialog>`, Fields, Card, Toaster…). Icons: `lucide-react` via `ui/icons.tsx` (`IconName`). Sidebar ≥ 900 px, bottom nav below, quick-add FAB, command palette (Ctrl+K). Touch targets ≥ 44 px, visible focus. **Page layout:** the shell has no width cap; every page sits in `layout/PageContainer` (variants `narrow` 45rem · `content` 70rem (default) · `wide` 100rem · `full`), chosen by `manifest.layout` (or `route.layout`) – modules never set their own `max-width`. The container is a CSS size container named `page`: use `@container page (min-width: …)` for inner layouts (card grids, columns), `useMediaQuery` / `useSplitView` only for structural changes (side panel vs. dialog). On desktop (≥ 900 px) `main` scrolls, not the window; pages that should fill the height are flex children of `.page`. Dialog autofocus: use `data-autofocus` (React `autoFocus` runs before `showModal()`).

**PWA.** `vite-plugin-pwa` with `injectManifest` (`src/sw.ts`), update prompt via toast. Android Chrome has no `new Notification()` → notifications must go through `registration.showNotification`.

**Sync & backup (Phase 4).**

- **Model:** field-operation store. `FieldOp = {collection, id, field, hlc, value}` (`core/sync/types.ts`); `null` = field removed, `deletedAt` = tombstone. Per `(collection,id,field)` the op with the **greatest HLC string wins, equal/older ops change nothing** – implemented twice on purpose, in `core/sync/ops.ts` (`mergeOps`, pure) and in the server's single SQL upsert (`server/src/store.ts`), and pinned by the shared fixtures in `contract/lww-cases.json` (each case also runs with reversed arrival order). The server never merges values; it only assigns a monotonic `seq` to accepted ops (pull cursor).
- **Layers:** `StorageAdapter` (`core/storage`, Dexie impl: outbox, `applyRemote`, cursor/epoch in `_meta`) ⟷ `runSync` in `core/sync/engine.ts` ⟷ `SyncAdapter` (`push`/`pull`; `adapters/selfHosted.ts`; `googleDrive.stub.ts` documents the unbuilt second backend). `core/sync/service.ts` holds config (`_secrets.syncConfig`, local only), `connect/disconnect/resetServer`, `syncNow` (serialised per tab and via Web Locks across tabs) and `startSync` triggers (start, 60 s, online, visibility, debounced after outbox changes); UI status in `useSyncStatus`.
- **Cycle:** pull first, then push. A response `epoch` that differs from the stored one (first contact, server reset/replaced) restarts the cursor at 0 and queues **every** local record (`markAllDirty`), so a new server is filled automatically. The cursor only advances after a page was applied. Outbox entries carry a write counter `rev`; an entry is cleared only if `rev` is unchanged, otherwise the record is pushed again in the same round. Remote-applied data is not re-queued. `applyRemote` calls `clock.receive()`, so later local edits sort after remote stamps even with a skewed clock. Ops for unknown collections are skipped; malformed ops, reserved envelope fields and `__proto__`-like names are ignored by `mergeOps`. `createdAt` of remote-created records is derived from the oldest stamp, `updatedAt`/`deviceId` from the newest.
- **Which tables sync:** `syncedTableNames()` = module collections + `_settings` + `_modules`. `_meta`, `_outbox`, `_secrets` never do.
- **Encryption (optional):** PBKDF2-SHA-256 (600 000 iterations) → non-extractable AES-GCM key, stored as `CryptoKey` in `_secrets` (the passphrase itself is not stored). Each op value is encrypted separately (`enc:v1:<iv>:<ct>`, AAD = `collection/id/field`, so values cannot be swapped); collection/id/field/hlc stay readable because the server needs them. The server keeps a _vault_ (`salt` + encrypted check string, first writer wins, `PUT /v1/vault`) so other devices can verify the passphrase without any data. Encryption can only be started on an empty server; unencrypted data on the server → explicit `POST /v1/reset` (confirm `"RESET"`) → new `epoch`. Wrong key → `decrypt`, encrypted data without key → `no-key`; nothing is applied and the cursor does not move.
- **Server API** (`server/src/app.ts`, all but health need `Authorization: Bearer`): `GET /v1/health`, `GET|PUT /v1/vault`, `POST /v1/push` (≤ 5000 ops, strict JSON schema, unknown properties rejected), `GET /v1/pull?since&limit`, `POST /v1/reset`. Tokens (≥ 16 chars, hashed + `timingSafeEqual`) from `SYNC_TOKEN(S)`; refuses to start without one. CORS (`CORS_ORIGINS`, default `*`), rate limit, `cache-control: no-store`; with `WEB_DIR` it serves the PWA with SPA fallback (plugins are registered _before_ routes – `buildApp` is async for that reason).
- **Backup** (`core/backup`): JSON `{format:'taschenmesser-backup', version, exportedAt, tables}` of all synced tables incl. tombstones and stamps, validated with Zod on import; secrets are never included. _Merge_ = same LWW rule as sync. _Replace_ = tombstone records not in the backup, write every backup record as a fresh edit (new stamps, also for fields that must disappear) and queue everything, so the restore wins on other devices too. Tables missing from the file are left alone.
- **Not built / known limits:** Google Drive adapter; binary attachments; no tombstone GC (grows forever); the server is single-tenant (all tokens share one data set); the Docker image could not be built in the dev sandbox (no daemon) – the compiled server, static serving, persistence and token checks were verified by running it directly.

**AI assistant (Phase 5)** – `web/src/core/ai/`, UI in `layout/CommandPalette.tsx` + `layout/assistant/`.

- **One format, three tiers.** Every question ends as a Zod-validated `Intent` (`query/schema.ts`): `query` (module, collection, filters `eq|ne|lt|lte|gt|gte|in|contains|between`, `range` with absolute or relative dates, sort, limit ≤ 100, `aggregate: count | sum:<field>`), `agenda` (calendar-style timeline of the enabled modules via `collectCalendarItems`, incl. recurring items), `computed` (named views), `create`, `fulltext`, `message`. Tiers, cheapest first (`assistant.ts`): **1** local German parser `intent/parser.ts` (0 tokens; every word must be vocabulary or filler, otherwise it stays silent – "heute", "offene Rechnungen", "Kontostand", "Was kosten meine Abos?", "suche X" …); short free text (≤ 2 content words) → **full text** (`search/fulltext.ts`, minisearch over the manifests' `searchable` fields, index rebuilt per search); **2** cache of the _validated intent_ (`_aiCache`, key = SHA-256 of normalised question + date + schema hash – deliberately NOT provider/model, so fallbacks and provider changes share hits – 30 days; results are never cached, they are recomputed from live data); **3** model call via `AiProvider`. Without a configured model, longer questions fall back to full text plus a hint.
- **Executor** (`query/executor.ts`, `validate.ts`): runs locally against the Dexie tables of _enabled_ modules only; module/collection/field whitelist from `aiSchema`, operator-per-type table, value coercion, local repairs (letter case, snake_case field names, `"true"` strings; money must be integer cents). Anything else throws `AiQueryError` (code → German message in `t.ai.errors`, fallback text otherwise). Nothing the model returns is evaluated as code, and no result goes back to the model (no second call).
- **Stage 2 privacy.** `prompt.ts` sends only: instructions, the compact `aiSchema` text of enabled modules (`field:type`, `@` date field, `!` required for create, enum values, `computed` names), tool definitions (`run_query`, `show_agenda`, `run_computed`, `create_entry`; module ids as enum) and per request "Heute: <date> (<weekday>)" + the question. Tests assert that seeded user data never appears and that the schema text stays within a token budget (adding fields/modules costs tokens on every call – keep `aiSchema`s tiny). One tool call is requested by instruction; `tool_choice` is deliberately _not_ forced (newer Claude models reject it) and no sampling/thinking parameters are sent.
- **Providers:** see "Multi-provider AI (Phase 12)" below (Anthropic, OpenAI-compatible presets, Ollama, fallback router). Token usage per call/cache hit/failure lives in `_aiUsage`; the palette answer shows a tier badge ("Lokal · 0 Token" / "Aus dem Cache" / "KI · in + out Token").
- **Creating entries** (`query/create.ts`): the model only proposes field values; they are whitelisted, coerced, defaulted by the module (`contributions.aiCreateDefaults`: todos → inbox/first list, finance → primary account) and validated with the collection's real Zod schema. The palette shows a confirmation card; only "Anlegen" writes, through the module's `createRepo` (`commitCreate`). Nothing is stored before that (also when the intent comes from the cache).
- **Manifest hooks for the assistant:** `aiSchema.collections[c].fields` (new field type `'recurrence'`: settable on create, not filterable), `aiSchema.computed` + `contributions.aiComputed` (finance `balance`, subscriptions `costs`, invoices `open`; return already formatted German lines), `contributions.aiCreateDefaults`. `titleField`/`dateField`/`searchable` must be fields; result rows show the date field first, then up to 3 more non-empty fields.
- **Palette UX:** options = matching navigation commands, then "Assistent fragen" (default target when no command matches), "Mit KI fragen" (only with a configured model; skips the local shortcuts), then live full text hits (AND only, debounced). Enter on the first option therefore never jumps to a fuzzy hit.
- Test fixtures for the assistant: `core/ai/testing.ts` (fixed Tuesday 2026-09-29, seeded data through the module repos, global test DB).

**Multi-provider AI (Phase 12)** – `web/src/core/ai/`, settings UI `pages/settings/AiSection.tsx`.

- **Adapters** (`providers/`), all behind `AiProvider { id, model, complete(req) }` and all using `PlatformService.fetch` (native shell: no CORS; PWA: subject to the provider's CORS behaviour – shown as a hint in the UI, **untested against the real endpoints**): `claude.ts` (official SDK, lazy chunk), `ollama.ts` (native `/api/chat`), **`openai.ts`** (OpenAI-compatible `POST {base}/chat/completions`; the response is Zod-validated – anything unexpected is `invalid-response`; HTTP 401/403 → `auth`, 429 → `rate-limit` with `Retry-After` (seconds or date), 5xx → `server`, other 4xx → `bad-request`, transport → `network`; `max_tokens` vs `max_completion_tokens` per entry; optional **`toolMode: 'json'`** for small/free models without tool calling: the tools are described in the system prompt and the model answers `{"tool", "input"}`, extracted from prose/code fences, a broken JSON attempt is `invalid-response`). `presets.ts`: Ollama, OpenRouter (`:free` model), Groq, Gemini (OpenAI-compatible endpoint), Mistral, OpenAI, Anthropic, custom (base URL + key + model) with tier (`local|free|paid`), default prices/limits and a `mayTrainOnInputs` flag (free tiers → badge "Eingaben können vom Anbieter für Training genutzt werden"). Model names, prices and limits are **only defaults the user edits** – verify them when adding a provider.
- **Config** (`config.ts`, `_secrets.aiConfig`, local only): `{ v: 2, providers: ProviderEntry[] }`, array order = priority. New providers are inserted local → free → paid; the UI reorders with up/down buttons, enables/disables, edits model/base URL/tool mode/limits (requests per day, USD per month)/prices. **No secret in the list:** API keys live in `PlatformService.secrets` (`core/secrets`, `SecretStore`: `secret:ai-key:<providerId>` rows encrypted with AES-256-GCM under a non-extractable WebCrypto device key stored in `_secrets.deviceKey`; AAD binds each value to its name); the entry only carries `keySet`. Honest limit: this protects a copy of the database (backup, disk image), not code running inside the app profile – the OS keystore (step 11b) would replace the implementation behind the same interface. The old single-provider config (clear-text `anthropicKey`) is migrated on first load (key → SecretStore, row rewritten). Sync tokens are still stored as before (`_secrets.syncConfig`, the service worker reads it).
- **Router** (`router.ts`, an `AiProvider` with id `router`, created per question by `createRouterProvider` from all _usable_ entries – enabled, model set, key present): walks the list in priority order; skips providers in **cooldown** (in-memory: rate limit → `Retry-After`, default 60 s, max 1 h; rejected key 30 min; bad request 5 min; server/network/invalid answer 30 s; saving the provider or a successful connection test clears it – a reload also resets it) and providers whose **local limits** are used up (`usageWindow` over `_aiUsage`: calls that reached the provider today – failed ones count, cache hits do not – and USD this month); fallback on every error except `aborted`, and also when `req.check` rejects the answer (the assistant passes "is this tool call a well-formed intent?" so a garbled answer moves on to the next provider). Result carries `providerId`, `costUsd` (provider price, else known-model price) and `attempts`; errors: a single failing provider keeps its own code (`auth`, …), several → `exhausted`, only limits → `limit-reached`, none configured → `not-configured` (all with German texts in `t.ai.errors`).
- **Accounting** (`usage.ts`): `_aiUsage` rows now carry `outcome` (`ok`/`error`), `errorCode`, `viaFallback`, `costUsd`; the assistant records failed attempts as error rows. Settings show per provider: requests, errors, times it stood in for another provider, tokens, estimated cost, pause status; plus totals and cache clearing. "Verbindung testen" (`testConnection.ts`) sends a `ping` with no tools/schemas/data.
- **Privacy is unchanged and tested for every adapter** (`privacy.test.ts`): Anthropic, Ollama and each OpenAI-compatible preset (native and JSON mode) are run through the real `ask()` pipeline with a recording `fetch` against a database full of recognisable data – the request contains the question, the date and the schema text, never user data, and the key only in its header. `accounts` is invisible to all of it (Phase 11).
- Not verifiable in the sandbox: the real provider endpoints (CORS from the PWA, tool support of free models, current model names/limits) – only the request/response shapes are pinned by fixtures and mocked E2E (fallback from 429 to a second provider, statistics, connection test, key not stored in clear text).

**Extra modules & polish (Phase 6).**

- **Off by default** (`defaultEnabled: false`, orders 70–150): `bookmarks` (Merkliste: kinds, tags, filters, done; PWA **share target** `/bookmarks?title&text&url` opens the prefilled create dialog; manifest shortcuts), `notes`, `shopping` (quantity parsing "2 Milch", duplicates ignored, "Gekauftes entfernen"), `birthdays` (month/day/optional year, 29 Feb → 28 Feb in common years, yearly calendar items + notification), `habits` (`habit` + `check` with deterministic id `<habitId>:<date>`, weekday schedule, streak that skips unscheduled days and does not break on an open today), `contracts` (kind contract/insurance/warranty, end date + `noticeDays` → cancellation deadline on the calendar and as notification, status act-now/soon), `budgets` (`budget` per finance category + `goal` + `deposit` (signed); saved = sum of deposits; reads finance only via `finance/public.ts` and only when finance is enabled), `packing` (lists/items, reset, duplicate as template), `vault` ("Dokumente": metadata synced, **files local-only** in `_blobs`, ≤ 10 MB, orphan files pruned on page open).
- **Local-only binary storage:** `core/blobs.ts` + system table `_blobs` (`synced: false`, stored as ArrayBuffer); never in sync or backup.
- **Shared UI kit for module pages:** `ui/Patterns.tsx` (`PageHeader`, `Toolbar`, `Segmented`, `Form`/`FormActions`, `ItemList`/`ItemRow`, `Chip(s)`, `Progress`, `Stat`) and `ui/WidgetList.tsx`. New modules should use them (see `modules/notes`, the smallest complete example). Module `ai.ts` files: only list collections whose data the assistant should query/create.
- **Web Push (optional).** Server: `server/src/push.ts` + routes `GET /v1/push/key`, `PUT /v1/push/subscription`, `POST /v1/push/unsubscribe`, `PUT /v1/push/schedule` (replaces the whole schedule of a subscription, ≤ 500 items, payload ≤ 4000 chars, opaque), `POST /v1/push/test`; tables `push_subscription`, `push_item`, `push_sent` (a sent marker for 7 days stops a stale upload from re-sending); a service ticks every 30 s, sends due items with `web-push` (VAPID keys generated once and kept in `meta`, or from env), drops subscriptions on 404/410, retries other errors ≤ 5 times, skips items > 24 h late; `POST /v1/reset` clears schedules but keeps subscriptions. Client: `core/notifications/push.ts` (`enablePush`, `disablePush`, `syncPushSchedule`, `startPushSync`; config in `_secrets.pushConfig`; uploads the next 14 days from `collectNotifications`, refreshed at start / every 10 min / when visible / after outbox changes; re-registers the subscription when the server forgot it; a changed server key → resubscribe). Payloads are JSON `{title, body, url}` or, with sync encryption on, AES-GCM ciphertext bound to `push/<notification key>` (`pushPayload.ts`); `sw.ts` handles `push` (decrypts with the key stored in `_secrets.syncConfig`, tag = notification key so it de-duplicates with the local scheduler). Settings: `pages/settings/PushSection.tsx`. Push can only be verified end-to-end on a real HTTPS deployment (headless Chromium has no push service); unit tests use fakes, `web-push`'s `generateRequestDetails` checks the encryption/VAPID headers.
- **A11y:** `e2e/a11y.spec.ts` runs axe-core (WCAG 2.0–2.2 A/AA, light and dark) on every page of every module and on the palette, assistant answer and create dialogs; it includes a self-test that axe really reports violations. Keep it green when adding modules (add the route to `PAGES` and the module id to `MODULES`).

**Native distribution (Phases 7–10).**

- **Shell:** `web/src-tauri` (identifier `io.github.sgnemo.taschenmesser` – never change it, Android updates depend on it; product name "Nemo" (window title, app label; the identifier and update endpoints keep the old name); **Windows ships as one portable executable, no NSIS/MSI** (`tauri build --no-bundle`); plugins notification, http, dialog, fs, clipboard-manager, opener; capabilities in `capabilities/default.json` are the minimum `core/platform/tauri` uses). The frontend is the unchanged web app (`frontendDist: ../dist`). Native builds are recognised by the Tauri CLI env `TAURI_ENV_PLATFORM`: `vite.config.ts` then drops the PWA plugin (no service worker, no manifest) and aliases `virtual:pwa-register/react` to `pwa/register-stub.ts`. The PWA build is unaffected and remains the fallback.
- **Data:** the native app has its own WebView origin → its own IndexedDB. Moving data from the PWA = JSON backup (Settings → Backup) or sync. `use_https_scheme` stays default (http scheme) so plain-http LAN sync servers work.
- **`PlatformService` (`core/platform/`)** is the only place that differs between browser and native shell: `fetch` (native = `plugin-http`, no CORS), `notifications` (`NotificationService`; native permission state is cached because the plugin check is async), `saveFile` (browser download / save-as dialog + `plugin-fs`; needed on Android where blob downloads do not work), `clipboard.writeSensitive` (clears after N ms unless the user copied something else), `app.version/openUrl`, `lifecycle.onBackground`. `initPlatform()` (called first in `main.tsx`) picks the implementation – the only place that looks for `__TAURI_INTERNALS__`; the Tauri adapter is a lazy chunk. Everything else calls `getPlatform()`. **ESLint enforces it:** `@tauri-apps/*` imports only in `core/platform/tauri/**`, `__TAURI*` only in `core/platform/**`. Tests swap it with `setPlatform()`; the Tauri adapter is unit-tested with `vi.mock` of the plugin modules.
- **Versioning:** `web/package.json` is the single source. `tauri.conf.json` has `"version": "../package.json"`; `Cargo.toml`/`Cargo.lock` mirror it (`version:sync`, checked by `version:check` in CI). `core/update/semver.ts` (parse/compare/`androidVersionCode`, erasable TS so Node scripts import it directly) derives the Android `versionCode = ((major*1000+minor)*1000+patch)*100 + rank` (release 99, `alpha.N` 0–29, `beta.N` 30–59, `rc.N` 60–89) – monotonic in SemVer order, unlike Tauri's default derivation which ignores pre-releases. Only `alpha|beta|rc` pre-release labels are accepted. Release bump: `npm run version:set -- 0.2.0` (updates package.json, lock file, Cargo files).
- **Conventional Commits from now on** (`feat(scope): …`, `fix: …`, `feat!:` / `BREAKING CHANGE:`). `scripts/changelog.mjs` (+ tested `scripts/lib/changelog.ts`) renders release notes: breaking changes, features, fixes, performance, refactoring, docs, build/CI; chore/test/style and merges are hidden; older non-conventional commits appear under "Other changes". Range = previous release tag (for a stable release) or previous tag of any kind (pre-release) up to HEAD.

**Password vault "Accounts" (Phase 11).**

- **Crypto (`web/src/core/crypto/`)** – only established primitives, no home-made ones: **Argon2id** (`hash-wasm`, WASM; defaults 64 MiB / t = 3 / p = 1, stored in every header so they can be raised; headers below 19 MiB / t = 2 or above 1 GiB / t = 32 are refused – downgrade and DoS guard; relaxed only when `import.meta.env.MODE === 'test'`) and **AES-256-GCM** via WebCrypto with a fresh random 96-bit nonce per encryption and AAD binding (`seal/open`, token `v1.<nonce>.<ct+tag>`). `keychain.ts`: master password → KEK (Argon2id, salt in header) wraps a random 256-bit **DEK**; the DEK encrypts the entries. Changing the master password only re-wraps the DEK (`rewrapKeychain`). Keys are non-extractable `CryptoKey`s; the raw KDF output and raw DEK bytes are overwritten right after import/wrap (`wipe` – JS cannot guarantee no other copy exists; documented limit). `passwordBlob.ts` = password-encrypted JSON (backup file). `random.ts`: `randomInt` with rejection sampling (no modulo bias), `shuffled`. Tests cover roundtrip, wrong key, flipped ciphertext/nonce, AAD swap, nonce uniqueness, NFKC password normalisation, parameter bounds, "logs nothing".
- **Module `accounts`** (`defaultEnabled: false`, order 160). Collections `accounts_vault` (one record `vault`, ONE synced field `header` = JSON `{v, vaultId, kdf{alg,m,t,p,salt}, wrappedDek, check}` (`check` = a known text sealed with the DEK: `verifyDek` proves that a key is _this vault's_ key) – a single field on purpose, so field-level LWW can never mix two vaults' salts/keys) and `accounts_entry` (ONE field `data` = ciphertext of the whole entry JSON; AAD = `vaultId/entryId/1`, so a ciphertext cannot be moved to another record or vault; conflicts replace the entry as a whole). Title, user, password, URL, notes, tags and TOTP secret are **all inside the ciphertext**; only `id`, timestamps and tombstones are plaintext metadata. Sync and backups therefore carry ciphertext only (tests grep the backup JSON and the `MemoryServer` dump; the two-device E2E checks the real server). If two devices set up a vault in parallel the newer header wins and the other vault's entries show up as "undecryptable" (deletable in the UI) – set the vault up on one device first, then sync.
- **Session** (`session.ts`, zustand, memory only): status + DEK + header. `lockVault()` drops them; `useEntries()` decrypts live and hands out nothing while locked; the page swaps to the lock screen so decrypted state unmounts. Reload = locked. Wrong-password delay in `vault.ts` (`lockoutMs`: free tries, then 1 s, 2 s … 30 s; UX only – offline attackers are limited by Argon2id, not by this).
- **Locking** (`autolock.ts`, started by the module _service_ `service.ts` while the module is enabled, stopped + locked when it is disabled): inactivity timer (settings `autoLockMinutes` 1/5/15/30, reset by pointer/key/wheel/touch), background lock via `PlatformService.lifecycle.onBackground` (`backgroundLock`: `now` | `30s`, coming back cancels the grace period), manual "Sperren". Settings live in the synced scope `module.accounts`. Clipboard: `copySecret` → `PlatformService.clipboard.writeSensitive(value, 30 000)` (cleared only if the clipboard still holds our value).
- **Functions:** entry CRUD + search (in memory, unlocked only), generator (`generator.ts`: length 8–128, classes guaranteed present, avoid look-alikes, passphrase mode with the EFF large word list – CC BY 3.0 US, notice in `wordlist-notice.md`, lazy chunk), strength via `@zxcvbn-ts` (German translations, lazy chunk, input capped at 100 chars), TOTP via `otpauth` (RFC 6238 vectors for SHA1/256/512 in tests; clock = `core/time/now`), Bitwarden CSV import/export (`csv.ts`, RFC 4180 parser; export is plaintext → confirmation switch), encrypted JSON backup (`backup.ts`, own password, Argon2id + AES-GCM; import skips duplicates). UI strings `t.accounts`.
- **AI exclusion (hard requirement):** `ModuleManifest.aiSchema` is now **optional**; a module without it does not exist for the assistant. The single filter is `core/ai/scope.ts` (`aiModules`), applied in `ask()` (manifests _and_ `known`, so a model asking for `accounts` gets `unknown-module`), the prompt/tool builders and full-text search; other AI code uses `aiSchema?.`. The `accounts` manifest has no `aiSchema`, no widgets, no calendar/notification/quick-add/AI contributions (only its own auto-lock service). `accounts/__tests__/exclusion.test.ts` proves it with an unlocked vault: schema/prompt/tools/hash identical with and without the module, no full-text hits, no vault strings in what is sent to a model, `unknown-module` for a model that asks for it. Never add an `aiSchema`, `searchable`, widget or calendar item to this module.
- **Step 11b – OS keystore, biometrics, screenshot protection (built, device behaviour unverified – see "Manuelle Tests offen").** Local Tauri plugin `src-tauri/plugins/secure-store` (Rust + Kotlin, id `io.github.sgnemo.taschenmesser.securestore`): `available`, `set/get/delete` (keystore), `biometric_seal/unseal/has/delete`, `set_secure_window`; names are validated (`[A-Za-z0-9-_.:]`, ≤ 200) and values ≤ 2 KiB before they reach an OS API. **Desktop:** `keyring` crate → Windows Credential Manager (macOS Keychain / Linux keyutils for development); the biometric gate is **Windows Hello consent verification** (`UserConsentVerifier` via the window-handle interop, `windows` 0.61 + `windows-future`) in front of the sealed vault key. **Honest limit:** on Windows this is a _consent gate_, not a cryptographic binding – code running as the same Windows user could read the credential without the prompt; it keeps other people at an unlocked PC out, the master password stays the real protection. **Android:** the Android Keystore – secrets are AES-GCM-encrypted with a hardware-backed key (no user auth, AAD = name) in SharedPreferences; the vault key is sealed with a _second_ key that needs a **strong biometric for every use** (`BiometricPrompt` + `CryptoObject`, `setInvalidatedByBiometricEnrollment(true)`): changing the enrolled fingerprints destroys the key → status `invalidated` → the seal is dropped and the master password is needed again. `FLAG_SECURE` is set while the Accounts page is open (blank app-switcher preview, no screenshots) and cleared when leaving it. **TS side:** `PlatformService` gained `biometrics` (`available/seal/unseal/has/remove`, results `ok|cancelled|missing|invalidated`) and `screen.setSecure`; Nothing is logged. `src/local_api.rs` wires the commands `local_api_start|stop|set_tokens|respond` (app commands, no capability entry); `PlatformService.localApi` wraps them (`core/platform/tauri/localApi.ts`), the browser/Android report `supported: false`.
  - **App side (`web/src/core/localapi/`):** `config.ts` – device-local `_meta` `localApi.config` (enabled, port 47631, tokens: id, name, SHA-256 hash, created, expiry, per-module `{read, write}` grants, `autoCommit`); tokens are `tm_` + 32 random bytes, shown once, never stored; all changes are read-modify-write inside one Dexie transaction (a revoke can never be undone by a concurrent write). `service.ts` (started in `main.tsx`) follows the config with `liveQuery`: start/stop/restart on switch or port change, `setTokens` on every token change (revocation is immediate). `handler.ts` re-checks token + switch, maps routes (`GET /v1/modules`, `GET /v1/openapi.json`, `GET /v1/{module}/items?collection&limit≤200&cursor&q`, `POST /v1/{module}/import[?dryRun=true]`, `GET /v1/batches`, `GET|DELETE /v1/batches/{id}`, `POST /v1/batches/{id}/commit`) and rights: modules = `apiModules` (switched on, not blocked) ∩ token grants; everything else – `accounts`, unknown or system names – answers the same 404 `unknown-module`, a missing right 403. Error bodies are fixed codes + fixed German texts. `log.ts` keeps the last 50 requests (time, token name/id, method, route pattern, module, status, count – no content, no query values).
  - **Batches (phase 3):** a non-dry import becomes a batch in `_imports` with `status: 'pending'`, `origin: 'api'`, token id/name, the checked `rows`, the reported `result` and a SHA-256 of the body (202). Same token + `Idempotency-Key` + same body → the same batch (200); other body → 409. At most 20 waiting batches per token (then 429 `too-many-pending`). Nothing importable (all duplicates/invalid) → no batch (`status: 'nothing'`). A banner (`layout/PendingImports.tsx`) opens the review dialog with the shared `ImportPreview` (also used by the wizard); confirming re-runs `buildPreview` on the stored candidates (fresh duplicate check) and writes through `commitImport` → repos → outbox → sync. `POST …/commit` only for tokens with `autoCommit` (then also right away on import, 201) and never for batches containing changes; `DELETE` rejects a waiting batch or undoes a committed one (idempotent). Batches of other tokens and wizard imports answer 404. `_imports` rows written before have no `status` = committed/undone (`batchStatus`); no index change, no migration.
  - **Changes of existing entries:** an item with the `id` of an active record of the same collection is a change: merged with the stored data, validated with the real schema, `before`/`after` hold only the changed fields, `lines` the formatted diff; `null` clears an optional field. Changes are never pre-ticked and never auto-committed; on commit a change is skipped (counted as `conflicts`) when the record no longer holds `before`. Undo restores `before` only while the record still holds `after`; created records are removed only while unedited. There is no endpoint that deletes entries.
  - **User guide:** [`docs/AI-IMPORT.md`](AI-IMPORT.md) (German: setup, PowerShell/curl examples, endpoints, errors, security). Its prompt block is `core/localapi/prompt.ts#buildApiPrompt` verbatim – the button „Anleitung für KI kopieren“ copies the same text with the configured port; `prompt.test.ts` keeps both in sync.
  - **MCP wrapper (`mcp/`, phase 5):** separate Node project (like `server/`: own `package.json`, Vitest, ESLint, Prettier, CI job `mcp`). `@modelcontextprotocol/sdk` 1.x, `McpServer.registerTool` + `StdioServerTransport`; eight tools, each exactly one API call (`list_modules`, `get_schema`, `read_items`, `import_items` with required `dryRun` and an automatic `Idempotency-Key`, `list_batches`, `get_batch`, `commit_batch`, `undo_batch`). No data access of its own; module/batch ids are checked with the API's own patterns before a path is built; `TASCHENMESSER_URL` must be `http://127.0.0.1|localhost:<port>` (the token is never sent elsewhere), `fetch` uses `redirect: 'error'`; stdout is the protocol, messages go to stderr without the token. Tests drive the real SDK client over `InMemoryTransport` with a fake `fetch`. Not shipped in `release.yml` (release/audit steps unchanged); users build it from the repo (`docs/AI-IMPORT.md` → C).
  - **UI:** Settings → „KI-Zugriff“ (`pages/settings/LocalApiSection.tsx`): switch, port, status, tokens (create with name/expiry/rights/auto-commit warning, shown once with copy via `writeSensitive` 60 s, renew, revoke), last requests. E2E uses `core/platform/fakeLocalApi.ts` (only in `--mode e2e` builds; the branch is compiled out otherwise) which mirrors the token check and calls the real handler.
- **HelpHint:** `?` button (44 px target) that toggles a popover on tap/click, opens on hover/keyboard focus, closes on Esc (the handler also calls `preventDefault`, otherwise a surrounding native dialog would close too) or an outside tap; text in `t.help`. The bubble has `transition: none` on purpose: the global reduced-motion rule sets every transition duration to 0.01 ms, which turns the default `transition: all 0s` into a real transition, and the viewport check then kept measuring the old position (infinite update loop). E2E: `e2e/onboarding.spec.ts`, wizard + hint in `e2e/a11y.spec.ts`.

**Connectors, calendar sync, bank import (Phase 13, step 3)** – `web/src/core/connectors/` (framework), `web/src/connectors/<id>/` (one folder per service), `server/src/proxy.ts`.

- **Isolation (lint + `connectors/isolation.test.ts`):** a connector talks to one outside service and returns plain data. Code in `src/connectors/**` must not import modules, `@/core/db/*`, `@/core/sync|backup/*` or **`@/core/ai/*`** (what was read from a mailbox can never reach a model); modules must not import connectors; `core/ai` must not import `core/connectors`. Modules receive data through manifest contributions – the calendar module's `contributions.externalCalendar` is an `ExternalCalendarSink` (`apply / clear / count / knownKeys`), and the importers of invoices, subscriptions, contracts and calendar accept `ImportInput` kind `connector` (`MailFinding[]`).
- **`ConnectorDef`** (`core/connectors/types.ts`): `id, name, authType (oauth-pkce|none|…), platforms, oauth endpoints, features[] (each with its own OAuth scopes), calendar? {listCalendars, sync}, mail? {scan}, isConfigured?, settings?` (lazy extra UI). `ConnectorContext` hands the connector `fetch` (platform), `accessToken()` (refreshes on demand, in-memory cache), `fetchPublic(url)` (native: direct; browser: through the sync server proxy, else `no-proxy`), scoped `secrets` and `redact()`.
- **State & secrets:** status per connector in local `_meta` `connector.<id>` (`disconnected|connected|expired|rate-limited|error`, features, `lastSyncAt`, `retryAt`, redacted German message); sync tokens/selected calendars in `_meta` `connector.<id>.*`. Secrets only in `PlatformService.secrets` (OS keystore): `oauth:<id>:refresh|client-id|client-secret`, `connector:<id>:*`. `core/connectors/redact.ts` strips tokens, client secrets, JWTs and secret iCal addresses from every error text; tests assert no token appears in stored status or messages. `scripts/lib/audit.ts` additionally fails a release build containing a `GOCSPX-…` client secret.
- **OAuth (`oauth.ts`, `service.ts`):** PKCE S256 + `state`; the desktop shell binds a one-shot **loopback listener** (`src-tauri/src/oauth.rs`: `oauth_listen_start` returns the port, `oauth_listen_wait` waits ≤ 5 min for `/callback`, ignores foreign `state`, German result page; commands are app commands, no capability entry needed), the system browser does the login (`app.openUrl`), the token exchange goes through `PlatformService.fetch`. `PlatformService.oauth` is `supported: false` in the browser and on Android (later step). `invalid_grant` ⇒ status `expired` + "Neu anmelden"; 429/quota ⇒ `rate-limited` with `retryAt` (backoff 1–60 min); the copied events stay untouched. The user brings their **own Google OAuth client** (type "Desktop app"): client id/secret are typed into Settings → Verbindungen and go straight into the keystore – nothing is shipped in the repo or binary.
- **Calendar sync (`service.syncCalendars`):** background loop (`startConnectorSync`: start, every 5 min while visible; a connector syncs when ≥ 30 min old), manual "Jetzt abgleichen". Google: `calendarList`, then per selected calendar `events.list` with `singleEvents=true`; first sync = window today −60 d … +400 d, later `syncToken` (cancelled events arrive as removals, **410** ⇒ full window again), etag unchanged ⇒ no write; all-day end is exclusive → inclusive; timed events converted to the device's local wall clock; HTML notes stripped. ICS subscriptions (`ics` connector, `authType: none`, address = secret): full sync of the feed each time (RRULE subset via `core/io/ics`). Events land in the **synced** collection `calendar_external` (ids `ext-<source>-<sha256(calendar,extId)>`, so all devices converge; read-only in the UI with an "extern" badge and detail dialog "Im Kalender-Dienst öffnen"); a calendar switched off or removed at the source takes its events with it; disconnect asks "keep or delete copied events". They appear in `useCalendarItems`, the dashboard widget and the assistant's agenda without further code; `aiSchema` lists the collection (field names only).
- **Gmail scan (`gmail.readonly`, separate feature switch):** `messages.list` with a keyword query + `after:` date (1/3/6/12 months, ≤ 300 messages), then `messages.get?format=metadata` for `From/Subject/Date/List-Unsubscribe` + the preview snippet – the body is never requested (test asserts the `format` and header list). `connectors/google/heuristics.ts` (pure, invented fixtures) recognises invoice (amount, due date), subscription (amount, rhythm, next charge), appointment/ticket (date, time, place) and contract (end, notice period); newsletters (`List-Unsubscribe`) only count as invoices with amount **and** due date; repeated monthly mails are de-duplicated. The wizard shows what was read ("N Mails … Absender, Betreff, Datum, Vorschauzeile"), the user confirms each suggestion; only extracted fields + a link to the mail are stored, calendar suggestions are de-duplicated against own and synced events.
- **Proxy `GET /v1/proxy?url=`** (`server/src/proxy.ts`, injectable `ProxyDeps` like push): needed by the PWA for ICS (and later RSS). Deliberately narrow because it is an SSRF hazard: http(s) only, no URL credentials, ports 80/443/8080/8443, every hop resolves the host and refuses loopback/private/link-local (metadata)/CGNAT/ULA/multicast/reserved addresses also in IPv4-mapped, NAT64 and 6to4 form (if any answer is blocked, all are), the socket is **pinned** to the checked address (custom `lookup`, no second DNS query), manual redirects ≤ 3 re-checked per hop, 2 MB / 10 s, feed-like content types only (never HTML/JSON/script), `content-security-policy: sandbox`, route rate limit 60/min, `If-None-Match`/`If-Modified-Since` forwarded (304), CORS exposes `etag`/`last-modified`. Errors: 400 `invalid-url`, 403 `blocked`, 413, 415, 502, 504.
- **Bank statements (`core/io/bank.ts`, `subscriptionDetect.ts`):** CSV of the savings banks' "CSV-CAMT" export (semicolon, `dd.MM.yy`, German amounts; header names are matched tolerantly) and CAMT.052/.053 XML (namespace-agnostic `Ntry` parsing). Finance importer `bank` (option: target account) books expenses/income; duplicates are detected by date+amount+payee+purpose (the n-th identical booking of a file gets its own key, so two coffees on a day are not "duplicates" but a second import of the file is); subscriptions importer `bank` finds recurring debits (≥ 3, same normalised payee, median gap ≈ weekly/monthly/quarterly/yearly, ≥ 75 % regular gaps, amount ±10 %). **The column names were written from the documented export layout, not from a real file** – check with a real export (see "Manuelle Tests offen").
- **Not built / limits:** Google login on Android (needs its own authorization plugin), two-way calendar sync, Sparkasse FinTS/PSD2, mail body parsing, attachments.

**News module (Phase 13, step 4)** – `web/src/modules/news/`, `core/io/feed.ts`, `core/net/fetchPublic.ts`, `core/ai/newsBrief.ts`.

- **Data:** `feed` (synced: url, title, category `nachrichten|technik|wissenschaft|natur|sonstiges`, active), `article` and `feedstate` (**local collections**, see below). New building block **`CollectionDef.local`**: same envelope and repo API, but `createRepo(..., { local: true })` (or `createCollectionRepo(manifest, collection)`) never queues anything in `_outbox`, and `syncedTableNames()` leaves the table out, so sync and JSON backup ignore it. `Repo.purge(ids)` really deletes rows and is allowed for local repos only. Article ids are deterministic (`art-<feedId>-<hash(guid)>`), so a refetch updates instead of duplicating; the read flag survives updates.
- **Fetching (`fetch.ts`):** `core/net/fetchPublic` = direct `platform.fetch` in the native app, `/v1/proxy` of the sync server in the browser (`no-proxy` error without one). Conditional GET with the stored `ETag`/`Last-Modified` (`feedstate`), 304 = unchanged; failures → per-feed exponential backoff (5 min … 6 h) and a German reason in the feed manager; feeds run three at a time. `core/io/feed.ts` reads RSS 2.0, RSS 1.0 (RDF) and Atom into plain data: every text goes through an inert `DOMParser` (script/style text removed, no markup survives), only http(s) links without credentials, ≤ 200 items, titles ≤ 200 and teasers ≤ 300 characters, future dates clamped. Module service (`services.ts`): first fetch 3 s after start, then every 5 min check, only while the page is visible, feeds refresh when older than the setting (30 min / 1 h / 3 h, default 1 h). Retention: 30 days and 500 per feed, saved articles stay.
- **UI:** `/news` – category segments (only topics in use), Unread/All, search, keyword filter and mute list from the module settings (local, per word), "Alle als gelesen", per article "Für später" and read toggle; opening an article marks it read and opens the link in the system browser. **"Für später"** emits the bus event `bookmark.requested` (`core/events`); the bookmarks module has a service that stores it once per address; with bookmarks off the page shows a hint instead. Dashboard widget "Schlagzeilen" (five newest unread). Start data: template importer "Startpaket" (nine feeds in four topics, `starter.ts` – **addresses unverified**, see manual tests) and a form importer that fetches an address once to validate it and take its title.
- **KI-Tagesüberblick (explicit button only):** `core/ai/newsBrief.ts` sends a fixed German instruction plus ≤ 30 lines `[Quelle] Titel` (each ≤ 160 characters) through the same router as the assistant – no tools, no schema, no date, no article text, no user data; the result is shown and not stored; usage and fallback attempts are recorded in `_aiUsage`. `privacy.test.ts` runs it through every adapter with a recording `fetch` against the seeded database. The news module deliberately has **no `aiSchema`** (public third-party text is neither queried nor created by the assistant).
- **Layout note:** `PageHeader` wraps (`flex-wrap`): three or four header buttons had widened the whole page on a phone.

**Toolbar & tools (Phase 13, step 5)** – `web/src/tools/<id>/`, `core/tools/`, `core/calc/`, `layout/ToolsSheet.tsx`, `pages/ToolLibrary.tsx`.
- **Tools are not modules:** small self-contained helpers (no data of their own, nothing synced except *which* are on and their order). Each is `tools/<id>/manifest.ts` (`ToolManifest`: id, name, icon, description, `group` basis|extra|dev, `offline`, `defaultEnabled`, `order`, lazy `component`), discovered by `import.meta.glob` in `core/tools/registry.ts`. State = synced `_settings` scope `tools` `{ enabled: Record<id,bool>, order: id[] }` (`layout.ts` pure and tested; `useTools()`). **Isolation:** tools may not import modules, connectors, `core/db`, `core/ai` (ESLint block for `src/tools/**` + `tools/isolation.test.ts`, which also forbids tool→tool imports except `shared.ts`); modules may not import tools. Persisting anything goes through `useSettings` (scope `tools.<id>`, e.g. the scratch pad).
- **UI:** top-bar button "Werkzeuge" opens `ToolsSheet` (a `Dialog variant="sheet"`, tile grid of the enabled tools; a tile opens the tool in the same sheet, the dialog title becomes the tool name; "Werkzeuge verwalten" → `/tools`). `/tools` (`ToolLibrary`) = switches, offline badge, up/down order, "open". Tool components are lazy (one chunk each, created once outside render).
- **Shipped tools.** Basis (on by default): `calc` (history in `localStorage`), `percent` (part / share / VAT net↔gross), `currency` (Frankfurter = ECB reference rates `api.frankfurter.dev/v1/latest?base=EUR`, cached in `localStorage` `tm-currency-rates`, works offline with the cache; **the only online tool**), `timer` (timer/stopwatch/pomodoro; a zustand engine keeps them running while the sheet is closed, notification when done), `qr` (`qrcode-generator` → SVG, save via `PlatformService.saveFile`; scan with `BarcodeDetector` + camera where supported), `scratch` (one synced note). Extra (off): `units`, `split` (bill split + tip), `dates`, `dice` (uses `core/crypto/random`, rejection sampling). Dev (off): `base64` (UTF-8 base64 incl. URL-safe input, URL encode/decode), `json`, `uuid`, `hash` (WebCrypto SHA-1/256/512).
- **Calculator engine (`core/calc/expr.ts`):** hand-written recursive-descent parser, **never `eval`/`Function`**: numbers (German `1.234,56` and `12.5`; the thousands rule is `^[1-9]\d{0,2}(\.\d{3})+$`), `+ − × ÷ ^`, parentheses, `%` (`a ± b%` is relative to `a`, otherwise `b/100`), `sqrt`, `π`; `-2^2 = -4`; typed errors (`syntax`, `divide-by-zero`, `range`, `empty`). `phrases.ts` adds "19% von 240" and "30 von 200 in prozent" and `looksLikeCalculation` (a bare number or a date is a search, not a sum).
- **Palette calculator:** `layout/CommandPalette.tsx` offers a `calc` option ("240 + 19% = 285,6") after the matching commands and before "Assistent fragen"; Enter copies the number (decimal comma) and keeps the palette open. Purely local, 0 tokens, never reaches the assistant/cache.
