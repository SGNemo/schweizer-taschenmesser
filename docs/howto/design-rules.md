# Design rules (look "Klar", flat, calm)

For every new module, tool and component. Moved unchanged from CLAUDE.md. Token mechanics and brand pipeline: [design-brand.md](design-brand.md). Index: [HOW-TO](../HOW-TO.md).

## The short list (hard rule "UI", moved unchanged from root CLAUDE.md, 2026-11-10)

texts via `t.…` read at render time (registries: getters), dates/numbers via `core/i18n/format`, never a fixed `'de-DE'`; CSS Modules + tokens from `ui/tokens.css` (no hex, own radius/shadow/z-index/weight), shared `@/ui` components, `data-autofocus`, touch ≥ 44 px, `manifest.layout` (no module `max-width`), motion transform/opacity only, AA contrast; colour only with meaning and always with text/icon (`ui/semantics.ts`), reading aid is automatic via the JSX runtime `core/text/readjsx` (secrets: wrap in `NoReadAid`; never inputs/numbers/code), lists grouped via `GroupedList`.

## Details

- **Tokens, never hard-coded values.** Colours, radii, shadows, spacing, type sizes, weights, z-index, durations come from `web/src/ui/tokens.css` (`var(--…)`). No hex/rgb in module CSS, no own `border-radius`/`box-shadow`/`z-index`/`font-weight` numbers (use `--weight-medium/semibold/bold`, `--z-*`, `--text-3xl` for hero numbers). Modules inherit the look through `@/ui`: Button, Card, Fields (`TextField` with `labelHidden` for inline add rows), Dialog, Patterns (`Segmented`, `ItemRow`, `Progress`, `Chip`, layout utilities `patternStyles.hstack/plainList/gapBottom/inlineForm`), Misc (`Badge`, `EmptyState` incl. `compact`, `Skeleton`), `WidgetList` for dashboard widgets. Never re-implement a segmented control, progress bar or input in a module; no inline `style={{}}` for layout or colour.
- **Surfaces (Identity 4.0, tone steps):** solid cool `--bg` page; a group on it is `--surface-raised` (`Card`, `ListSurface`, panels: no border, no shadow), a recess is `--surface-sunken` (control tracks, disabled controls); at most two levels, never a card in a card. `--surface` stays for dialogs and inputs, `--surface-2` for quiet areas and chips. Shadows only for what floats: `--shadow-1` a small lift (selection bar), `--shadow-2` menus, dialogs, sheets, toast. `--border` = hairline between the rows of a list or a form, never a frame; form controls use `--border-strong`. New code in `ui/` may not add `--shadow-1` (`ui/surfaces.test.tsx`); pages lose their frames and shadows with their area package (ratchet values `borders`/`shadows`, [ci.md](ci.md)). Radii: sm 8 / md 12 / lg 16 / xl 20. Focus = 2 px `--focus` outline + 2 px offset (no ring shadow). Meta text `--text-3` at `--text-meta`; list rows `min-height: var(--row-h)`, grid gaps `var(--grid-gap)` (density setting).
- **One accent, one job:** filled `--accent` only for the page's primary action (desktop: the `PageAction` in the head; phone: the plus in the bottom bar); `--accent` as text colour only for the one active state (the open tab). Links are `--link` with `--link-line` (neutral ink, underlined: never told by colour alone), a chosen filter (`Segmented`, `Chip`) is a surface and a weight (UI audit 2026-11, B7). Status colours `--danger/--success/--warning/--info` (+ `-soft` = 15 % `color-mix`, never hex), charts `--viz-1/--viz-2`. Amounts and dates: `font-variant-numeric: var(--font-num)`. The ocean gradient (`--ocean-from/to`) is brand only (splash, empty states, images), never a page background.
- **Contrast:** WCAG AA (4.5:1 text, 3:1 UI). `ui/tokens.test.ts` checks the palette incl. `--text-3`, `--border-strong` on `--surface-2` and the status mixes; a new colour token needs a light and a dark value and an entry in that test. Touch targets ≥ 44 px (`--touch`), inline checkboxes 24 px; the one exception is the sidebar on a low window with a mouse and no touch at all (`(max-height: 1100px) and (pointer: fine) and (not (any-pointer: coarse))`: 36 px rows), plus the time under the tile in the collapsed rail, which is a 24 px high link for a mouse (44 px on any touch screen).
- **Motion:** CSS only, `transform`/`opacity` only (progress bars scale, nothing animates width, colour or shadow), 120–250 ms (`--dur-fast/--dur/--dur-slow`, `--ease-out`), no endless animation except the `Skeleton` shimmer. Everything must be fine with `prefers-reduced-motion`. Loading: `Skeleton`, not spinners or "…".
- **Empty and error states:** `EmptyState` (page) or `EmptyState compact` / `WidgetList empty` (widgets): the faded Nemo fish, one sentence, at most one button; a page `EmptyState` may take the module's own `motif` (outline drawing, `aria-hidden`, in grey) instead of the fish, the compact variant always keeps the fish; no icon prop. Loading = `Skeleton`/`SkeletonRows`, errors inline with `ErrorState` (sync errors in the shell banner).
- **Brand:** the fish and the NEMO pill are defined once in `design/logo-v2/final.params.mjs`; `node export.mjs` (in `design/logo-v2/`) writes `web/brand/*.svg` and the generated blocks in `Logo.tsx` and the splash, `brand-sync.test.ts` enforces they agree (and that the logo colour is the `--accent` token). Icons: `docs/HOW-TO.md` → Icons. Special styles (QR black/white) need a comment and an entry in `docs/DECISIONS.md`.
- **Checking a design change:** `SCREENS_SCHEME=dark SCREENS_VIEWPORTS=1280x720,412x915 SCREENS_PAGES='^(dashboard|finance-overview)$' npm run screenshots` renders invented data; `SCREENS_CSS=<file>` injects token overrides for experiments; `npx playwright test e2e/a11y.spec.ts` runs axe in both themes.
- **Navigation (Klar 2):** every module declares `area` (`plan|money|household|knowledge|vault|system`); areas group the sidebar/rail/bottom nav and, on the phone only, show as the one module row in the page head (`layout/AreaFrame`), nothing else – never import across modules for it. The module head is one title row with the page's `Tabs` at its lower edge (`PageHeader`: `views`, and the page's one action as `PageAction`); the top bar's "Neu" is neutral, there is no FAB: below 900 px the plus in the bottom bar is the entry and the head holds no control ([MODULE-IDENTITY](../design/MODULE-IDENTITY.md) "Identity 4.0 – draft"). Pages never set their own sidebar/rail assumptions; split views use `SplitView` (from 1200 px) and `useSplitView`. Page width is `manifest.layout`: `narrow`, `content`, `wide`, `full`, `reading` (one column, 56–64 rem) or `split` (master–detail; the list at the page width, the detail in the `SplitView` panel). Favourites ≤ 5 via `core/settings/nav.ts`.
- **Components (Klar 2, Phase 3):** buttons `primary` (once per view) · `secondary` · `ghost` (quiet) · `danger` (confirm dialogs) · `quietDanger` (row delete) · `size="sm"`; lists are `ItemList` + `ItemRow` (flat rows on a `ListSurface`, `layout="grid"` = tiles; a `GroupedList` group holds such a surface), the views of a page `Tabs` (it takes the props of `Segmented`; a `Segmented` in the `views` slot is on the baseline `segmented-views`), filters `Segmented`/`Chip`; a disabled control is sunken and grey, never faded (no `opacity` on `:disabled`, `ui/Button.test.tsx`), forms `TextField`/`DateField`/`SelectField`/`Checkbox`/`Switch` with `error`; a `Dialog` is a bottom sheet on phones (`dirty` asks before discarding, `useDraft` keeps a draft 30 s; `backdrop="opaque"` covers the page with `--bg` instead of dimming it – only the capture sheet in `layout/QuickAdd.tsx` uses it). Every state-changing list action goes through `undoableWithToast` (`core/undo`): toast with "Rückgängig" + Ctrl+Z; deletes use `deleteWithUndo`, single changes (pause, count ±) `changeWithUndo` (`check:modules` fails on a direct `xRepo.remove(` in `components/`/`routes/`; an automatic clean-up carries the comment `comfort-allow-delete`). Keyboard hooks on rows: `data-row` (set by `ItemRow`), `data-row-edit`, `data-row-tick`; list search gets `data-list-search`. Selection: `useSelection` + `SelectionBar`; touch: `onSwipeRight/Left` on `ItemRow`. All of it is on the dev page `/dev/components` (Dev-Preview/E2E only).
