# CI – stimulus ratchet: key, merge check, Sven's steps

Part of [CI and Dev-Preview](ci.md) ("Stimulus budget and ratchet"). Commands run in `web/` unless stated.

- **One-time setup (state 2026-11-10):** done: key pair made with `openssl` only (`openssl genpkey -algorithm ed25519 -aes256 -out ~/.nemo/ratchet.pem`, `openssl pkey -in ~/.nemo/ratchet.pem -pubout`; in Git Bash with `winpty` in front, or the passphrase prompt hangs), its public line is `RATCHET_PUBLIC_KEY` in `web/scripts/ratchet.mjs`; the workflow change is merged (#630; its own run went red on its own hit and green after the label `stimulus-raise` and "Re-run failed jobs", as designed; it was merged by Sven without a signed comment, no console at the time). Open, Sven: (1) rule 7 is in `docs/meta/agents-v3/nemo-merge.json`: it takes effect when the agent is created again from it ([SETUP](../meta/agents-v3/SETUP.md)); (2) once, before the first real use: one run of `--pr` in the `nemo-merge` sandbox and one dry run of the signing command below (`gh auth login` once on your machine); (3) the local deny rules for chats: `Read(~/.nemo/**)` and the commands that set the label `stimulus-raise` (hygiene).
- **At the merge (the trust root):** `nemo-merge` rule 7, wording of the spec (its file reference left out): "vor dem Merge in `/workspace/wt-merge`: `git fetch origin develop <head-sha> && git show origin/develop:web/scripts/ratchet.mjs > /tmp/ratchet.mjs && NODE_USE_ENV_PROXY=1 node /tmp/ratchet.mjs --pr <n> --head <head-sha>`; Exit-Code ≠ 0 → kein Merge, die Ausgabe in den Merge-Kommentar; gemergt wird genau dieser `<head-sha>` als `expectedHeadSha`, das Skript endet mit Exit ≠ 0, wenn der Live-Head davon abweicht – keine Lücke zwischen Prüfung und Merge". The same holds for **every** merger ([RULES](../RULES.md)): no merge into `develop` while the `develop` version of `ratchet.mjs --pr` exits ≠ 0. `--pr` needs: the PR is open against `develop` and no other open PR has the same head; exactly one merge base; live head = `--head`; the check run **Web (lint, types, unit, E2E)** of the `pull_request` run of `ci.yml` on that head is `success` (required context; the run must name this PR with base `develop`, so a PR from a fork never passes: Sven pushes its branch into the repo and opens the PR from there; read with `filter=latest`, commit statuses are never read); and no hits, or an approval for exactly this hit table.
- **The approval is a signature, not the label.** A PR comment whose whole text is `stimulus-raise SGNemo/schweizer-taschenmesser#<n> <hash> <signature>`: `<hash>` = SHA-256 over the sorted hit lines, `<signature>` = Ed25519 over `stimulus-raise SGNemo/schweizer-taschenmesser#<n> <hash>`, checked against `RATCHET_PUBLIC_KEY` in the `develop` version of the script. Author, edits and the label play no part; every validly signed comment for the current hash counts. A push that changes the hits (also a second change of an approved file) needs a new comment; merging `develop` in does not, as long as `develop` did not touch a hit file. Empty key = nothing is mergeable.
- **Sven's steps on a hit PR** (Git Bash; always the `develop` version, never the PR's; no repo script ever touches the key):

```bash
git fetch origin develop && git show origin/develop:web/scripts/ratchet.mjs > /tmp/ratchet.mjs && GITHUB_TOKEN=$(gh auth token) node /tmp/ratchet.mjs --pr <n>
```

```bash
printf '%s' 'stimulus-raise SGNemo/schweizer-taschenmesser#<n> <hash>' > /tmp/ratchet-msg.txt && openssl pkeyutl -sign -rawin -inkey ~/.nemo/ratchet.pem -in /tmp/ratchet-msg.txt -out /tmp/ratchet-sig.bin && openssl base64 -A -in /tmp/ratchet-sig.bin; echo
```

  Run both in your clone of the repo. The first prints the hit table, the hash, the message and the second command ready to copy; at this point `Not mergeable yet` (no signature, Web check red) is expected. The second asks for the passphrase and prints the signature (message and signature go through files: OpenSSL 3.0 cannot sign Ed25519 from a pipe; if it hangs at the passphrase in Git Bash, put `winpty` in front of `openssl pkeyutl`). Post message + space + signature as one comment, set the label `stimulus-raise` (CI only), "Re-run failed jobs"; when the run is green, the first command must end with `Mergeable: head …`. After a push with new hits: the same again. The PR text names every hit.
- **Key:** made and used with `openssl` only (commands under "One-time setup"), kept like the updater key (never lost, never committed); local chats get the deny rule `Read(~/.nemo/**)`. A new public key changes `ratchet.mjs` (a hit): that one PR Sven merges himself after his own review, with a decision bullet (the named exception to rule 7). Key lost: make a new pair and do the same; open hit PRs then need a new signed comment.
- **Agents:** never set the label `stimulus-raise` and never post an approval line; say every hit in the PR text and wait.
