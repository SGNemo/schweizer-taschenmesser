# Icons, branding and design tokens

Logo/icon pipeline and token rules. Index: [HOW-TO](../HOW-TO.md). Commands run in `web/` unless stated.

## Icons / branding
- Change the logo (one source): edit `design/logo-v2/final.params.mjs` (`MARK`: body, tail (`style: 'lobe'`), fins, bands `at/width/bend/rim`, eye, `soften`, tile radius, scale and `style: 'duo'`, Android scale; `WORD` + `LOCKUP`: the NEMO lettering and the pill; the safe-zone radii). The colours are tokens: `COLORS` in `design/logo-v2/mark.mjs` must equal `--accent` / `--accent-contrast` / `--accent-hover` (dark) / `--ocean-from` / `--ocean-to` in `web/src/ui/tokens.css` (the export stops if not). Then
  1. `cd design/logo-v2 && node export.mjs` (needs `cd web && npm ci` once: it renders with Playwright's Chromium) checks the mark against the master by rendering both, writes `web/brand/*.svg` (mark, mono, app icon, maskable, Android foreground / background / monochrome, the wordmark pill in two files), the marked block in `web/src/ui/Logo.tsx` (`// brand:begin … // brand:end`) and the splash in `web/index.html` (`<!-- brand:begin --> … <!-- brand:end -->`). Do not edit those blocks by hand. Then `cd ../../web && npx prettier --write index.html src/ui/Logo.tsx` (the generated splash markup is not prettier-formatted).
  2. `cd web && npx tauri icon brand/app-icon.svg && npm run gen:icons` regenerates the Tauri set (`icon.icns`, Android legacy mipmaps) and re-renders PWA icons (192/512/maskable), `favicon.svg/.ico/-32.png` (the tile), `pwa-badge-96.png`, `icon.ico`, the Android adaptive/monochrome/notification layers and the launcher background (the ocean gradient as `drawable/ic_launcher_background_gradient.xml`, plus the plain colour as fallback), the browser extension's icons (`extension/static/icons`), the README headers (light + dark, English + German) and the social preview, and deletes the unused iOS/appx sets.
  3. `npm test` (`brand-sync.test.ts`: the same paths in the SVGs, `Logo.tsx` and the splash; the accent and ocean values equal `tokens.css`; the one-colour files keep the rim; the wordmark keeps its aspect; SVG ids unique per file), commit the results. If the accent token changes, also `ANDROID_ICON.iconColor` in `core/platform/tauri/index.ts` (+ `tauri.test.ts`) and `nemo_shortcut_background` in `src-tauri/plugins/share-intent/android/src/main/res/values/colors.xml`.
  Trying a change first: copy `design/logo-v2/rounds/9/variants.mjs` to a new round folder and run `node render.mjs rounds/<n>`: it renders a preview sheet (16–512 px, light/dark, true pixels, the mark montaged into the real sidebar and phone top bar, taskbar/tray, Android masks + safe zone + themed icon, favicon tab, palette check) without touching the app. `node tools/app-shots.mjs context` refreshes the shell screenshots the sheet uses; `node tools/app-after.mjs <dir>` takes the "after" screenshots of the running seeded app (needs `npm run build:e2e-seed && npm run preview:e2e-seed`). Exploration rounds 1–8 are in `design/logo-v2/rounds/archive/` (sheets only, see its README).
- Mark: the fish follows `--accent` in the app (`Logo.tsx` fills with `var(--accent)` and still honours `--logo-ink`, "Logo in Themenfarbe"); the static files carry the token's two values (`LOGO_ACCENT`). The bands have two widths (24 and 34), but `Logo.tsx` has one stroke-width constant: the wider band is exported as two offset strokes (same shape within 0.1 unit). In the one-colour mark the bands are cut inside the body only (clip path = the body) and a stroke of `LOGO_RIM` on the body outline puts the rim back, so the fish stays one piece; the app icon is the two-colour fish instead (accent, white filled bands, ocean gradient top to bottom – keep it vertical, a diagonal gradient multiplies the PNG sizes). The favicon is the tile, not the transparent mark: the mark in the deeper accent has too little contrast on dark tab strips.
- Wordmark: the pill with the mark and NEMO. The lettering is an own drawing (`design/logo-v2/wordmark.mjs`: stroked stems, bars, diagonals and a circle, no font, no third-party outlines). `logo-wordmark.svg` follows the system colour scheme inside the SVG (light accent / dark accent; an `<img>` cannot read the app theme, so a forced theme that differs from the system shows the other variant, still legible); `logo-wordmark-light.svg` is the fixed dark-surface version (README banner). Both keep the old wordmark's aspect ratio (1368:401) with the pill left-aligned at 36 of the 44 px sidebar head, so `ui/Wordmark.tsx` and the sidebar markup needed no change. The collapsed rail shows the mark only (`<Logo size={32} />`), the expanded sidebar the pill (`<Wordmark height={44} />`).
- Banner (README header light/dark + social preview): composed in `scripts/gen-icons.mjs` from the wordmark SVGs (view box cut to the pill), a faint school of marks and the claim (backronym of NEMO, English for the repo and German `*.de.png`; the lists are in `gen-icons.mjs`).
- Android: the launcher layers reach the APK through the copy step after `tauri android init` in `release.yml`; the status-bar icon is `ic_notification` (referenced from `core/platform/tauri/index.ts`).

## Design tokens
- Colours, radii, shadows, type scale, weights, z-index, motion live in `web/src/ui/tokens.css` only. Change a semantic token there; components pick it up. The dark palette exists twice in the file – edit both (`tokens.test.ts` fails if they differ) and keep the contrast pairs AA (the test checks them, incl. `--border-strong` on `--surface-2`). Do not put `--name:` patterns into comments inside the file (the test's parser reads them as declarations).
- New accent colour: add a `:root[data-accent='<name>']` block with `light-dark()` pairs (`--accent`, `-hover`, `-contrast`, `-soft`), extend `ACCENTS` in `web/src/stores/ui.ts`, the `settings.accentOptions` strings and the inline script in `web/index.html`; `tokens.test.ts` lists the variants to check.
- Trying a look before changing tokens: write overrides into a CSS file and render invented data with `SCREENS_CSS=<file> SCREENS_SCHEME=dark npm run screenshots` (see `docs/design-proposals/variant-*.css`). Compare against the README pictures (`docs/assets/screenshots/`) or a plain `npm run screenshots` run (`web/.screens/`).
- Layout helpers instead of inline styles: `patternStyles.hstack/hstackCenter/hstackWrap/grow/plainList/gridList/gapTop/gapBottom/spacer/fieldset/inlineForm` (`web/src/ui/Patterns.module.css`).
