## Stimulus budget and ratchet
Decided with UI audit 2026-11, package 0a-1a ([why](../decisions/meta.md), spec: [PACKAGE-0](../design/ui-audit-2026-11/PACKAGE-0.md)). In force on `develop` since 2026-11-10: script and measurement (PR #627), the maintainer's public key, and the workflow (PR #630): the job `Stimulus budget` blocks, `e2e-seed` runs on every PR that can change the web app, both count for the check `Web`.
- **What is measured:** `npm run check:stimulus` (in `web/`) runs `e2e/screenshots/stimulus.spec.ts` (measuring only, writes `inventory.json`) on the seeded build: every parameter-free module route, the library, the overview calm and detailed and a few sub-pages (`e2e/screenshots/stimulusPages.ts` reads the routes from the manifests, so a new module is measured without an edit there), at 1920×1080 (`d1920--`, desktop platform faked) and 412×915 (`p412--`, without the desktop-only modules), all modules and previews on. Per page: `height`, `buttons`, `links`, `icons`, `firstScreenActions`, `borders` (frame on all four sides, ≥ 40×24 px), `shadows` (blurred or offset, not floating things, not rings), `surfaceLanguages` (frames and shadows: 0–2), `colouredAboveFold`, `signatureBlocks`. Formulas: `measurePage()` in `scripts/lib/stimulusBudget.ts` (one fixture test each); runner: `scripts/check-stimulus.mjs`; budget: `e2e/stimulus-budget.json`.
- **Strict on both sides:** a value above its band is over budget, a value below it is red too ("lower the baseline"). Band: height ±10 % or ±50 px (the larger), counts ±10 % but at least ±1; `borders`, `shadows`, `surfaceLanguages`, `signatureBlocks` exact; `colouredAboveFold` ±1. Also red: a page in the budget that was not measured, a measured page without a budget, a missing metric key.
- **Signature blocks:** the only framed blocks that stay are marked with `signatureBlock="…"` on the row (`data-signature-block`), listed in `scripts/baselines/signature-blocks.json`. A marked element is at most 480 × 320 px and frames nothing inside (except the count the file writes down for it: `pantry-label` 1, its amount stepper, until package 0b-5); its own frame is not counted in `borders`, everything inside it is.
- **Lowering a budget (the only way):** the job `Stimulus budget` prints the measured values of its run into the job summary, in the form of the budget file. Take those numbers into `e2e/stimulus-budget.json`. Never commit a local measurement: local and CI values differ and several bands are exact. A new page: push, then copy only that page's keys from the job summary. `npm run stimulus:baseline` rewrites every entry with local numbers: use it to look, not to commit.
- **Seed rows:** all values are measured on the test data, so `scripts/baselines/seed-rows.json` holds the rows per table at `scale: 'medium'` (`scripts/lib/seedRows.test.ts`). More rows: `UPDATE_SEED_ROWS=1 npx vitest run scripts/lib/seedRows.test.ts` and commit. Fewer rows are a ratchet hit.
- **Baselines that only shrink (package 0a-1b; `segmented-views` since 0b-1):** `scripts/baselines/{max-width,grouped-list,own-h1,css-motion,segmented-views}.json` hold today's hits per file, counted by `scripts/lib/{maxWidth,groupedList,ownH1,cssMotion,segmentedViews}.ts` (`grouped-list` reads every component file of a module, not only `routes/`; `css-motion` counts transitions and `@keyframes` in module stylesheets that move something else than `transform`/`opacity`; `segmented-views` counts a `Segmented` in the `views` slot of a page header: the views of a page are `Tabs`) and held by the test of the same name in `web-unit`, strict on both sides (a new hit is red, a removed one is red until the file is lowered). Lower: `UPDATE_BASELINES=1 npx vitest run scripts/lib/<name>.test.ts` and commit; that command also writes a raised number, which is a ratchet hit. What counts as a hit stands at the top of each counter. Next to them, without a baseline: `motionSource` (no `.animate(` / `startViewTransition` outside a motion helper; a helper lies in `src/ui/motion*` **and** is named in `MOTION_HELPERS` of `motionSource.test.ts`, so a new one is a ratchet hit), `src/layout/pageTitle.test.tsx` (one `PageTitle` h1 per module route, in the head) and the ESLint blocks against a fixed `'de-DE'` (`eslint-rules/no-fixed-locale.js`) and against `autoFocus` in JSX (`eslint-rules/no-autofocus.js`; use `data-autofocus`).
