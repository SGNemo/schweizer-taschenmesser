# Dependency audit – 2026-11-08

Read-only review of the dependency advisories that apply to `origin/develop` (`311e30e2`). No dependency was changed, no alert dismissed; every row is a proposal for the maintainer.

**Limit of this report:** the Dependabot alerts API answers `403 Resource not accessible by personal access token` for the session token, and no MCP tool lists alerts. So the GitHub alert list (numbers, GitHub severity, `main` vs `develop` state) is **not** covered. The findings below come from `cargo audit` 0.22.2 (RustSec DB of 2026-11-06) and `npm audit` on the lock files of `develop`; Dependabot normally reports the same advisories per manifest. To map them to alert numbers, run with a token that has `security_events`/Dependabot read access:
`curl -H "Authorization: Bearer $TOKEN" "https://api.github.com/repos/SGNemo/schweizer-taschenmesser/dependabot/alerts?state=open&per_page=100"`.

Alerts are computed on `main` (default branch). Differences on `develop` that matter: `ringbuf` (torrent crate) exists only on `develop`; `server/` has `@fastify/static` 10.1.8 (`main` 10.1.5); `web/` has `vite-plugin-pwa` 2.0.0 (`main` 1.3.0). Versions of all other affected crates and packages are the same on both branches (verified from the lock files).

## How "real" was judged

- **Runtime** = compiled into the Windows exe / Android APK or installed in the sync-server image (`npm prune --omit=dev`). **Dev/build only** = `npm audit --omit=dev` is clean for it.
- Reachability: `cargo tree -i <crate> --target x86_64-pc-windows-msvc` and `aarch64-linux-android` (Cargo parts verified here; the shell crate itself cannot be built in the sandbox), `npm ls --package-lock-only`, and reading the calling code.
- CI jobs with signing secrets (`release.yml`, `dev-preview.yml`): secrets are set only on the sign/audit/publish steps (step-level `env`); the `npm ci`, `tauri build` and `tauri android build` steps run without them (verified by reading the workflows). `eslint`/`typescript-eslint` are not run in these workflows; `npm run build` there runs the licence check, `tsc` and `vite build` (which runs `workbox-build`). All steps share one runner, so a compromised dev package could still leave files behind for the later signing steps – none of the advisories below is such a compromise (they are DoS or prototype-pollution bugs with developer-controlled input).

## Proposed order (each its own `chore(deps)` PR, then `npm run gen:licenses` for the npm ones)

2. `cargo update -p tauri-plugin-updater` (closes `zip`), with `nemo-security` review.
3. `server/`: `npm update @fastify/static`.
4. Dismiss with reasons: `ringbuf`, `webpki-root-certs` ("not used"); `minimatch` dev, `glob` (web), `deepmerge`, `basic-ftp` ("tolerable risk").
