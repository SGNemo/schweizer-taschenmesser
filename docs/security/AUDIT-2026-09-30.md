## Findings

### Vault (`web/src/core/crypto`, `modules/accounts`)
Good: Argon2id 64 MiB / t=3 / p=1 with stored parameters, floor and ceiling checks against tampered headers (`kdf.ts`); AES-256-GCM with a fresh random 96-bit nonce per call and AAD bound to the record (`aead.ts`); random DEK wrapped by a password-derived KEK, non-extractable `CryptoKey`s, raw bytes wiped (`keychain.ts`); auto-lock on idle and on background with grace period (`autolock.ts`); clipboard cleared after 30 s (`copy.ts`). Only weakness: random 96-bit nonces with one long-lived DEK are fine up to ~2^32 messages per key, far beyond a personal vault. JS memory cannot be zeroed reliably (documented in code). **S19 (low):** clipboard clearing depends on the running app; fix: also clear on lock/background (small).

### Tokens and keys
AI provider keys and connector refresh tokens go through `getPlatform().secrets` (OS keystore on native, WebCrypto device key on web) – good. **S5:** `syncConfig` (URL, bearer token, CryptoKey) and the push config are written directly into `_secrets`, so on native the sync token skips the keystore. The service worker also reads `_secrets.syncConfig` (`sw.ts`). Fix: store the token via `SecretStore` and keep only non-secret fields in `_secrets` (needs care for the SW; medium effort, Phase 4 candidate if small). Logs: `console.*` calls log error objects only, no tokens/bodies found; the local API logs no tokens or bodies *(agent)*. Sync error messages are codes (`SyncError`), not payloads. A test asserting "no secrets in logs, backup or sync payload" is planned.

### Sync client and server
- **S1:** E2E is opt-in (`connect(... encrypt)`) and can only be enabled on an empty server (`service.ts`). Fix: make "encrypt" the UI default and warn clearly when off; do not change the protocol.
- **S3/S4:** `server/src/auth.ts` compares hashed tokens in constant time (good) but all devices share `SYNC_TOKEN(S)`. There is no device registry, so "lock/sign out a device" (Phase 3) needs new, backward-compatible server endpoints (per-device tokens issued by an admin token, revocable, stored hashed). `/v1/reset` needs only the shared token; fix: require an admin-scope token or a confirmation header, keep the old behaviour for legacy tokens behind an opt-in env.
- **S6:** `sync/crypto.ts` PBKDF2-SHA256 600k iterations (meets OWASP minimum). Migration to Argon2id would change the vault format on the server: option only, needs your approval (see Options below).
- **S7:** `engine.ts` `pullAll` counts `rejected` but still advances the cursor; a single corrupted/forged op is skipped forever. Fix: surface rejected ops in the status (Phase 3), do not treat as silent success.
- **S8:** `app.ts` registers `@fastify/rate-limit` with the default IP key; `index.ts` sets no `trustProxy`. Fix: `TRUST_PROXY` env (default off), stricter bucket for 401s. Backward compatible.
- Input validation is good: JSON schemas with `additionalProperties: false`, ops ≤ 5000, value ≤ 1 MB, HLC and collection patterns, body limit 8 MB. Minor: value size is checked after full parse (bounded by body limit).
- **S9:** even with E2E, the server sees collection/table names, record ids, field names, HLC (incl. device id), sizes and timing. Inherent in server-side LWW; document it.
- **S10:** `docker-compose.yml` publishes `${PORT}:8787` on all interfaces, CORS default `*`. Fix: document `127.0.0.1:8787:8787` behind `tailscale serve`, default `CORS_ORIGINS` to same-origin; README already explains Tailscale/HTTPS.
- **S17:** `logger: true` logs URLs; Fastify does not log headers by default (token safe). Fix: redact the `url` query of `/v1/proxy` via a serializer.
- SSRF (`server/src/proxy.ts`): well done. http/https only, ports 80/443/8080/8443, no credentials, per-hop DNS resolution with all answers checked, socket pinned to the checked address, IPv4-mapped/NAT64/6to4 handled, redirects ≤ 3 re-checked, 2 MB / 10 s, feed content types only, stricter rate limit, CSP sandbox on the response. No finding.

### Local import API *(agent)*
Loopback-only bind (no setting), Host and Origin/Sec-Fetch-Site checks, SHA-256-only token storage with constant-time comparison, per-module scopes, no delete, confirmation preview for writes, 1 MB body / 16 KB header limits, 120 req/min per token, no logging of tokens/bodies. Findings: S16 (global auth-failure bucket → local DoS; fix: count failures per peer and check the budget only after a failed auth), scopes enforced only in TS (design boundary is the webview).

### Update path *(agent)*
Desktop: minisign verification via `tauri-plugin-updater`, endpoint locked to this repo's `latest.json`, portable swap re-verifies and rolls back, SemVer downgrade check, mandatory pre-update data backup (aborts on failure). Android: HTTPS, size cap, SHA-256, install only from cache dir; the OS enforces signature and versionCode. **S13:** SHA-256 lives next to the APK. Fix (Phase 4 candidate, touches release signing → only with your approval): verify a minisign signature of the digest in the app. Low: make `sha256` mandatory in the plugin, restrict download host to github.com. Signing/keystore/updater key are not touched by this work.

### Tauri capabilities, Android *(agent)*
S12: CSP lacks `base-uri`, `form-action`, `object-src 'none'`; `connect-src` open to any host; `http:default` allows any URL (feeds, AI providers and sync need arbitrary hosts – trade-off; option: user-approved host allowlist). S18: narrow `fs` scope to needed subfolders (`$APPDATA/backups/**`), drop `clipboard-manager:allow-read-text` if unused. Plugin manifests only request `REQUEST_INSTALL_PACKAGES` and `USE_BIOMETRIC`, FileProvider not exported. S15: add a CI assertion after `tauri android init` for `allowBackup="false"` and cleartext off (CI change, ask first).

### Database at rest (assessment only)
IndexedDB (Dexie) stores module data unencrypted; only the vault entries, API keys and sync key are protected. Anyone with disk access to the browser/WebView profile reads notes, finance data etc. Options:
1. **OS disk encryption (BitLocker / Android file-based encryption) + documentation** – zero code, covers lost devices. *Recommended baseline.*
2. **Field-level encryption of selected collections** with the vault DEK – breaks search, AI queries and sync unless unlocked; large migration.
3. **Whole-database encryption** (e.g. SQLCipher via Tauri) – strongest, but a different storage engine and no PWA equivalent.
Recommendation: option 1 now; encrypted backups (Phase 2) cover the copy-of-data case.

### Backups
**S2:** `backup/backup.ts` and `update/backup.ts` write plaintext JSON (module data, tombstones, field stamps). Secrets, sync token, keys and API keys are correctly excluded (test planned). Fix: Phase 2 encrypted format via `crypto/passwordBlob.ts` (Argon2id + AES-GCM); plain JSON import stays supported.

### Supply chain *(agent)*
S14: pin all Actions to commit SHAs, add Dependabot, add `cargo audit`/`npm audit` steps, use `--locked` for cargo. Workflow permissions are read-only by default, secrets only in job env, no `pull_request_target`, gitleaks + artifact audit present. Gradle plugin deps are old (`core-ktx 1.9.0`, `biometric 1.1.0`) but without known critical issues; no dependency verification file.

Tombstone cleanup: synced tombstones are removed locally after 90 days (only after a successful
sync, never while unsynced). A device offline for longer than that could resurrect a deleted record;
the device list flags devices unseen for that long. The server cannot clean tombstones itself because
it cannot read values under end-to-end encryption.

## Options needing your decision
- **Sync vault KDF (S6):** keep PBKDF2 (documented), or add a versioned `vault v2` with Argon2id, keeping v1 readable. Needs a server/protocol addition.
- **Device tokens (S3):** new endpoints `POST /v1/devices` (admin token), `GET /v1/devices`, `DELETE /v1/devices/:id`; legacy shared tokens keep working. Protocol change, additive and versioned.

S4 (reset needs admin token, opt-in legacy), S7 (report rejected ops), S8 (`TRUST_PROXY`, auth-failure bucket), S17 (URL redaction), S19 (clear clipboard on lock), S10 docs. Everything else is reported here only.
