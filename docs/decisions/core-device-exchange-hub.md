# Decisions in full – Core – device exchange: hub session

Part of [core](core.md). Index of areas: [DECISIONS](../DECISIONS.md). Concept: `docs/design/device-exchange/CONCEPT.md` (PR #1011).

- **Device exchange package 1a: exchange session in the LAN hub (2026-11-16, `feat/exchange-hub`):** `crates/lan-sync` only. Handshake mode `MODE_EXCHANGE = 4` (`Mode::Exchange`, own prologue byte, cap 65 535 after the first authenticated frame, no `lastSeen`); `handle_first_on(wire, input_ok, exchange_ok)` admits each home-only mode with its own `home && wired` check; the router has its own `Kind::Exchange` arm (never the sync handler) and closes exchange sessions on home-network loss like input. A newer exchange session replaces the device's older one only at its **accepted `open`** (never at message 1, which anyone who saw it can replay). `src/exchange/`: `wire` (tags `0x30..=0x3f`, `0x35..=0x3c` reserved for files; `Item` fields private, built only by `Item::new`: text/clip ≤ 16 KiB with CRLF/CR normalised to LF, links ≤ 16 KiB, plain `http(s)` whose authority starts with a host character and has no `@` or backslash, no whitespace, controls or bidi/zero-width characters), `control` (`Exchange`: switch + per-device `ExchangeGrant {on, paused}` in `trust.json`, default off; writers `set_enabled`/`set_device` for the PC's controls only; sliding 300 stored items/h per device in memory; `connected(peer)`; traits `ExchangeInbox` (idempotent per device and id, also after the web view took an item over – the shell keeps the seen ids at least an hour: delivery is at least once) and `ExchangeOutbox` (`next` from memory, `answered` with `Stored`/`Refused`/`Rejected`)), `session` (refusals `exchange-off`, `not-granted`, `paused`, `limit` + minutes left, also at `open`; an item is acked only after the inbox stored it; a readable id with a body this side cannot take is answered `rejected` so it never blocks a queue; one PC → phone item in flight; after `refused` the head is offered again on the phone's next `ping`; switch/grant re-checked on every frame and tick). Device side `exchange_client` (duplex, reader thread; keep-alive is the caller's, who decides the session's lifetime). Rule tests: `exchange_sync_input_stay_apart`, `no_frame_from_the_network_reaches_an_exchange_setter`, hub parts compiled out on mobile. The shell must wire `Exchange` on every desktop and let the switch decide, so a module that is off reaches the phone as `exchange-off`, not as an unknown device (package 1b). Follow-ups: shared duplex client code with `input_client`, a neutral switch module (package 2).
- **Device exchange package 1b-1: shell wiring and platform seam (2026-11-16, `feat/exchange-shell`):** the PC wires `Exchange` into the hub's router on every desktop (`src/exchange.rs`; the switch in `lan-sync/exchange/switch.json` decides, so a module that is off reaches the phone as `exchange-off`). Delivery state in `src/exchange_store.rs`, keyed by (device, id): `inbox.json` (items kept until the web view confirmed them; seen ids per device kept 2 h, also after the hand-over) and `outbox.json` (PC → device queue, and the devices' answers until the web view confirmed them; delivered/rejected leave the queue, `full` stays); temp file synced, then renamed; a file that cannot be read is moved aside (`*.broken`), never overwritten; a failed inbox write is answered `refused`, nothing is acked. The files are opened from the app's data folder whether the hub runs or not. Commands PC (`exchange_status`, `_send`, `_take`, `_confirm`, `_set_enabled`, `_set_device`) desktop-only; widening (switch on with a stored grant, device on, un-pause) asked in a native Rust dialog behind remote control's ticket (refused if a mouse/keyboard session is open or was opened at any moment since the question was put); unpairing a device drops its queue (at the revoke and at every hub build; renewing the key keeps pairings and queues). Phone (`src/exchange_client.rs`, mobile-only commands, all off the main thread): open/send/ping/close (closing takes the session out of the shared slot, so it really ends), received items stored in the phone's own `inbox.json` before the ack; the page keeps its own sent items as waiting until `delivered` and resends them on the next session (the PC stores an id once). Web seam `platform.exchange` (`side: 'pc' | 'phone' | null`), Tauri wrapper, a fake for e2e builds, `noExchange` in the browser. `tests/commands.rs` pins which side has which command and that nothing of it logs.
- **Device exchange package 1b-2: module „Austausch“ (2026-11-16, `feat/exchange-module`):** module `exchange` (desktop + Android, `maturity: 'preview'`, off by default), table `exchange_item` `local: true` (not synced, not backed up, not searchable, no `aiSchema`, `dataApi: false`, in `BLOCKED_MODULES` and the vault exclusion list); the repo is `local` too (nothing reaches `_outbox`); cards keep only `peer`, `itemId`, direction, kind, body (≤ 16 KiB UTF-8, checked before a card is made; the link/text rules mirror `Item::new`), state and `unseen`; the sweep (start + hourly, while the module is on) **purges** cards past 30 days and removed own cards one day after removal; removed received cards stay as markers until they expire, so a late resend cannot revive them (tombstones of local tables are never cleaned elsewhere). Switching the module off (here or by sync) switches the PC's exchange off when its service stops and the stored module state is off (a plain quit leaves it on; narrowing, no dialog), so phones hear `exchange-off`. Open: a module switched off by sync while the PC app is closed, or taken out of a device's defaults (no stored row), is reconciled only on the next start with the module on (follow-up: a core hook that runs for disabled modules). Taking items over runs one at a time and dedupes against removed cards too. `waiting` → `sent` never steps back over an answer; the PC retries its `waiting` cards on each tick, errors that cannot heal (`bad-*`) mark a card „Kam nicht an.“ The PC page lists every paired device with its one action (Einschalten / Pausieren / Fortsetzen; widening asks natively, pausing never). Removing a PC card that still waits does not take it back from the shell's queue (accepted for 1b). The page takes items from the shell (`take` → write → `confirm`), so a crash between the two at most shows an item again, never loses one; sent items stay „wartet“ until `delivered` and go again on the next session. Links open and text is copied only on a click. **Area Knowledge, hue ocean / hue2 fern (deviates from the concept's System / teal):** in System every free hue is taken by a settings category head (identity v3.1 test) and slate is taken by „Dieser PC“ (`check:modules`), so no System pair was free; Knowledge has notes and links next door. Signature `handoff` is new.
- **Device exchange package 2a: file records (2026-11-16, `feat/exchange-files`):** package 2 is cut in three: **2a** (`crates/lan-sync` only: file records and received names), **2b** (transport loop with an input-latency test, session flow, receiver store with part/resume/hash/limits/daily counter/`Zone.Identifier`, phone client), **2c** (shell commands by token, dialogs, drag-drop/picker, thumbnails, cards). Records in `exchange/wire.rs`: `offer`/`accept`/`wait`/`refuse`/`chunk`/`end`/`result`/`cancel`; `Offer` only via `Offer::new` (size ≤ 4 GB, raw name 1–255 bytes UTF-8 without NUL, media type `type/subtype` of RFC 6838 token characters ≤ 64 or empty – a receiver that cannot read it takes it as unknown); a decoded offer over 4 GB is `TooLarge` (answered `refuse {too-large}`), an unreadable one `Unusable` (answered `refuse {rejected}`); a sender passes its local name through `name::clean` (always a valid offer name); `Debug` shows no name, type or size; `chunk_header` lets the sender read a file straight behind the header; `accept.from` and `chunk.offset` ≤ 4 GB (no overflow in 2b); a chunk fills exactly one 65 535-byte frame; `FEATURE_FILES` defined but not offered, so a session still closes on a file tag.
- **Device exchange package 2a: received names (2026-11-16, `feat/exchange-files`):** `exchange/name.rs`. `clean`: every prototype case plus Windows specials; NFC before and after filtering; tab, line breaks and line separators become one space; controls, format characters and every default-ignorable code point go (accepted: ZWJ/ZWNJ go too, so an emoji sequence or a Persian joiner in a name falls apart – the threat, bidi and zero-width, is in the same class); blank-looking letters and `<>:"/\|?*` become `_`; the stored name is cut **at the end** to ≤ 120 bytes with its extension kept (the card cuts in the middle, package 2c); a cut never creates an extension the name did not have (`a….exe.bbbb…` → `a….exe_`; the prototype gave `.sc` for its `.scf…` case); device names with `_`; shortcut and theme types (now with `pif`) and the whole name `desktop.ini` get `_` on the final name; fallback `Datei` (2b/2c: a localized fallback or an extension from the media type); a trailing `_` (defused or cut) is explained on the card in calm words (2c). Every Unicode space becomes one plain space. `risk`: allow-list. `candidates`: the name, then " (2)" … " (9999)" before the last extension within 120 bytes (`Backup.tar (2).gz`, accepted) – the store creates each create-new and takes the first that works; `unique` wraps it with an existence check. `part`: device key and id only. NFC and the categories come from `icu_normalizer`/`icu_properties` 2.3 (range, not pin) – the versions the shell already locks through `url`/`idna`, so the app gains two dependency edges and no library. The downloader's `name.rs` stays as it is.
