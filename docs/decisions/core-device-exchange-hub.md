# Decisions in full – Core – device exchange: hub session

Part of [core](core.md). Index of areas: [DECISIONS](../DECISIONS.md). Concept: `docs/design/device-exchange/CONCEPT.md` (PR #1011).

- **Device exchange package 1a: exchange session in the LAN hub (2026-11-16, `feat/exchange-hub`):** `crates/lan-sync` only. Handshake mode `MODE_EXCHANGE = 4` (`Mode::Exchange`, own prologue byte, cap 65 535 after the first authenticated frame, no `lastSeen`); `handle_first_on(wire, input_ok, exchange_ok)` admits each home-only mode with its own `home && wired` check; the router has its own `Kind::Exchange` arm (never the sync handler), closes exchange sessions on home-network loss like input, and a newer exchange session of a device replaces its older one (`SessionRegistry::close_exchange`). `src/exchange/`: `wire` (tags `0x30..=0x3f`, `0x35..=0x3c` reserved for files; items text/link/clip ≤ 16 KiB, links only plain `http(s)` without whitespace, controls or bidi/zero-width characters), `control` (`Exchange`: switch + per-device `ExchangeGrant {on, paused}` in `trust.json`, default off; writers `set_enabled`/`set_device` for the PC's controls only; 300 items/h per device in memory; traits `ExchangeInbox`/`ExchangeOutbox`), `session` (refusal codes `exchange-off`, `not-granted`, `paused`, `limit`; an item is acked only after the inbox stored it; one PC → phone item in flight, removed only on `ack stored`; switch/grant re-checked on every frame and tick). Device side `exchange_client` (duplex, reader thread, `ping` keeps it against the idle close). Rule tests: `exchange_sync_input_stay_apart`, `no_frame_from_the_network_reaches_an_exchange_setter`, hub parts compiled out on mobile. Nothing wired in the shell yet (package 1b).
