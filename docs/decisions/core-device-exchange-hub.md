# Decisions in full – Core – device exchange: hub session

Part of [core](core.md). Index of areas: [DECISIONS](../DECISIONS.md). Concept: `docs/design/device-exchange/CONCEPT.md` (PR #1011).

- **Device exchange package 1a: exchange session in the LAN hub (2026-11-16, `feat/exchange-hub`):** `crates/lan-sync` only. Handshake mode `MODE_EXCHANGE = 4` (`Mode::Exchange`, own prologue byte, cap 65 535 after the first authenticated frame, no `lastSeen`); `handle_first_on(wire, input_ok, exchange_ok)` admits each home-only mode with its own `home && wired` check; the router has its own `Kind::Exchange` arm (never the sync handler) and closes exchange sessions on home-network loss like input. A newer exchange session replaces the device's older one only at its **accepted `open`** (never at message 1, which anyone who saw it can replay). `src/exchange/`: `wire` (tags `0x30..=0x3f`, `0x35..=0x3c` reserved for files; `Item` fields private, built only by `Item::new`: text/clip ≤ 16 KiB with CRLF/CR normalised to LF, links ≤ 16 KiB, plain `http(s)` whose authority starts with a host character and has no `@` or backslash, no whitespace, controls or bidi/zero-width characters), `control` (`Exchange`: switch + per-device `ExchangeGrant {on, paused}` in `trust.json`, default off; writers `set_enabled`/`set_device` for the PC's controls only; sliding 300 stored items/h per device in memory; `connected(peer)`; traits `ExchangeInbox` (idempotent per device and id, also after the web view took an item over – the shell keeps the seen ids at least an hour: delivery is at least once) and `ExchangeOutbox` (`next` from memory, `answered` with `Stored`/`Refused`/`Rejected`)), `session` (refusals `exchange-off`, `not-granted`, `paused`, `limit` + minutes left, also at `open`; an item is acked only after the inbox stored it; a readable id with a body this side cannot take is answered `rejected` so it never blocks a queue; one PC → phone item in flight; after `refused` the head is offered again on the phone's next `ping`; switch/grant re-checked on every frame and tick). Device side `exchange_client` (duplex, reader thread; keep-alive is the caller's, who decides the session's lifetime). Rule tests: `exchange_sync_input_stay_apart`, `no_frame_from_the_network_reaches_an_exchange_setter`, hub parts compiled out on mobile. The shell must wire `Exchange` on every desktop and let the switch decide, so a module that is off reaches the phone as `exchange-off`, not as an unknown device (package 1b). Follow-ups: shared duplex client code with `input_client`, a neutral switch module (package 2).
- **Device exchange package 1b-1: shell wiring and platform seam (2026-11-16, `feat/exchange-module`):** the PC wires `Exchange` into the hub's router on every desktop (`src/exchange.rs`; the switch in `lan-sync/exchange/switch.json` decides, so a module that is off reaches the phone as `exchange-off`). Delivery state in `src/exchange_store.rs`: `inbox.json` (items kept until the web view confirmed them; seen ids per device kept 2 h, also after the hand-over) and `outbox.json` (PC → device queue with the last answer; delivered/rejected leave it, `full` stays); atomic file writes; a failed inbox write is answered `refused`, nothing is acked. Commands PC (`exchange_status`, `_send`, `_take`, `_confirm`, `_set_enabled`, `_set_device`) desktop-only; widening (switch on with a stored grant, device on, un-pause) asked in a native Rust dialog and refused while a mouse/keyboard remote session is open (checked before and after the dialog); unpairing a device drops its queue. Phone (`src/exchange_client.rs`, mobile-only commands): open/send/ping/close, received items stored in the phone's own `inbox.json` before the ack; the page keeps its own sent items as waiting until `delivered` and resends them on the next session (the PC stores an id once). Web seam `platform.exchange` (`side: 'pc' | 'phone' | null`), Tauri wrapper, a fake for e2e builds, `noExchange` in the browser. `tests/commands.rs` pins which side has which command and that nothing of it logs.
