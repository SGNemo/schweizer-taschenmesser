# Decisions – shell – identity v3 audit and v3.1

Part of [ui-shell](ui-shell.md). Index of areas: [DECISIONS](../DECISIONS.md).

## Identity v3 audit (2026-11-04, `review/identity-v3-audit`)

- **Verdicts on the foundation:** layout rules, stripe rule and the overview head confirmed; palette, widget frame, sidebar and contract need sharpening; the nine head variants change – the frame gets fixed grid areas and a sized signature slot beside the figure with the content column capped at 70 rem (maintainer, mockups in `docs/design/identity-v3-audit/mockups/` (removed 2026-11-10, in the git history)). Full table: `docs/design/identity-v3-audit/01-findings.md`.
- **Mapping changes decided:** E-Mail back to `schreib` + stamp with one "Posteingang" widget; Dieser PC gets its `fortschritt` head, slate rings and a token palette; empty states through an `EmptyState motif` prop with every module ported; four fix packages, foundation first (`02-packages.md` (removed 2026-11-10, in the git history)).
- **Rules sharpened** (MODULE-IDENTITY "Clarifications from the audit"; the hue rule is superseded by the v3.1 block below): only `--text` on tinted surfaces until `--text-on-tint` exists, same hue across areas needs a different head and widget variant, signatures shrink on the phone and never hide, `signature: 'none'` only for an empty head, widget titles unique app-wide.

## Identity v3.1 – foundation fix package (2026-11-05, `feat/identity-v3-frame`)

- **The head is a grid with a signature slot:** row 1 eyebrow + actions, then a content column capped at `--page-content` (70 rem, aligned to the page) with the h1 and one row figure | signature slot | extra. The head variant sets the slot size (S 4 rem · M 36 rem · L full; `himmel` none); the frame draws `identity.signature` from the one library (`@/ui/identity`, modules and tools) until the page fills the slot (`HeroSlot area="signature"` claims it). Phone: the slot scales, never hides. `ui/HeadSurface` is the one tinted surface under the band, the settings head and the tool stage.
- **Contract:** `widgetType` and `feedback` dropped (nothing read them); `SIGNATURES` lists only ids with a drawing; app-wide rule in `scripts/lib/checkIdentity.ts` (same hue never with the same head and widget, a shared head or widget needs a signature of its own), run on the source by `check:modules` and on the runtime registry by the registry test; the angle loop and the tokens.css parsing are gone (the palette pins 26°). Mapping: E-Mail → `schreib`/`notiz`, Unterlagen widget → `kennzahl`, Zeiterfassung → `hourStrip`.
- **Tokens:** `--text-on-tint` (84 % / 94 % of `--text` over the surface – the task's 80/82 % fell short of 4.5:1 on orchid and fern) is the only quiet ink on tinted heads; `--font-serif`, `--weight-light`, `--head-h-*`, `--card-pad`, light `--focus` on the accent hue, `[data-hue2]` rules, `--area-pattern: none` in the quiet modes. Accent variants cannot be 25° from every module hue (ten hues span 234°): their overlaps are pinned, not hidden.
- **Overview and chrome:** widget sizes are heights, not row stretch; `spreadVariants` dropped; bars and rings fill with the module hue; sidebar and library group tints neutral (area colour only in rail and bottom navigation), sidebar density on low pointer screens; settings category heads without area pattern and never a module's hue + area pair (Module → sky, Verbindungen → slate); library heads slate; widget titles unique (Gewohnheiten "Heute geschafft", Browser "Browser-Lesezeichen").
- **Identity v3.1 package 4 (2026-11-06):** every overview widget head draws its module's `SignatureMark` (form, not colour; `aria-hidden`); overdue labels name the day, never a count (`dueState`, FOCUS-WORDING); raw `font-weight` numbers fail `check:modules`; sidebar areas folded except the current page's, hand choice remembered (maintainer, F06); phone write button shows the short verb (maintainer, C31); timetrack signature id `stopwatch`.
- **Settings identity v3.1 package 1 (2026-11-06, `design/settings-identity`):** variant B – tab heads stay compact, a tab's state and its one filled action live in one `StatusCard` tinted in the tab's hue (at most one tinted card per tab); groups carry headings, never step numbers; "Einrichtung" is its own tab, first in "Persönlich", hue fern (diagnosis and before/after: [settings-v3/ROUND-1.md](../design/settings-v3/ROUND-1.md)).
- **Settings identity v3.1 package 2 (2026-11-08, `design/settings-identity-2`):** on a settings tab no group is a card (`data-groups="plain"` on the category page, one rule in `ui/SettingsParts.module.css`); module settings pages keep cards. Connector cards never carry a filled button ([settings-v3/ROUND-2.md](../design/settings-v3/ROUND-2.md)).
- **Settings identity v3.1 package 3 (2026-11-08, `design/settings-nav`):** on the desktop the settings search heads the category column, hits overlay the content (variant B; A – one row with the quick bar – wraps at the app's width). The setup tab's progress shows in the category list while steps are open ([settings-v3/ROUND-3.md](../design/settings-v3/ROUND-3.md)).
- **Identity 4.0 foundation (2026-11-10, package 0b-1, `feat/ui4-0b-1-foundation`; plan: [PACKAGES](../design/ui-audit-2026-11/PACKAGES.md)):** depth is told by tone steps. `--surface-raised` (light `#ffffff`, dark `#1b2126`) and `--surface-sunken` (`#e9ecee` / `#0c0f12`) are the mockup values; text, muted and meta ink keep AA on both. `Card`, `ListSurface` (what `ItemList` renders, so also the rows of a `GroupedList` group) and `Segmented` lost their shadow; `--shadow-1` stays in `ui/` only on the list in `ui/surfaces.test.tsx` (head band, signature blocks, widget body, selection bar, switch thumb), each with the package that removes it. Not done here on purpose: the hairline between the groups of a `GroupedList` (DESIGN-SPEC § 7b) and its newspaper columns stay as they are.
- **Calm colour mode uses its own grey (same date):** `--calm-ink` (`#565a5e` / `#9da2a6`) replaces `--text-3`/`--text-muted` as the stand-in for every hue and for success/warning/info. Why: the text greys have a blue cast (saturation 0.19–0.21), and the stimulus measurement reads a mark filled with them as colour, which is what the 0a-1b measurement found (calendar 58, budgets 15, pantry 13, planner 12); every `--mod-*` was already grey. "Modulfarben: Aus" uses the same grey for the module hues (the promise spec `e2e/identity.spec.ts` holds the two modes alike); its bank card keeps `--text-3`. The guard counts as "danger and today elements" the hits of the measurement on the hue of `--danger` or `--accent` (±12°, so amber stays out); it runs in the light theme only (the dark neutral steps are bluish themselves and count as colour in the measurement) and excuses one thing by name: the calendar's 6-px marks filled with a text grey, until package 0b-4.
- **Disabled is a state, not a fade (same date, AE1):** buttons, checkbox, switch and the file picker sink to `--surface-sunken` with `--text-3`; no `opacity` on a disabled control in `ui/` (`ui/Button.test.tsx`). Area patterns in the dark theme: `--pattern-head` 0.03, `--pattern-widget` 0.02 (AE2, token part).
- **`reading` and `split` are layouts, not only widths (same date):** `reading` = `--page-reading` (56 rem, growing to 64 rem on a wide window), `split` = the wide width with the `SplitView` panel `--split-detail`; `frameVariant` keeps both as declared. `Tabs` takes the props of `Segmented`, so a view switch moves over without a rewrite; the ten view switches still built with `Segmented` stand on the baseline `segmented-views`.
- **Answers to package 0b-1 (Sven, 2026-11-10, PR #664):** an ungrouped `ItemList` does not fall under "lists through `GroupedList`" (no second key in the `grouped-list` baseline; grouping belongs where time or status orders a list, decided per page in the area packages). The calm guard stays as built (hue of `--danger`/`--accent`, calendar marks excused until 0b-4). The two leftovers the finding table gave 0b-1 move: B7 (link underline, accent only for main action and active state) to 0b-2, B10 (sheet with a fixed foot, date/time field in `@/ui`) to 0b-3.
- **Collapsed sidebar = app icon tile, grey icons (2026-11-10, council, direction E).** *Why:* the bare mark was squeezed onto half pixels, the time read as two numbers, seven hues without text were noise. *Decision:* `<Logo tile />` (`LOGO_TILE`, 2.75rem like the nav tiles), the time as one line (12-hour locales: digits only, the label keeps AM/PM), icons `--text-muted` with the hue only on the active area, a CSS tooltip from `aria-label` on hover and keyboard focus; the narrow phone top bar shows the same tile. *Rejected:* a simplified small fish, a soft plate, captions, an edge bar. Source: `feat/rail-brand-tile`.
