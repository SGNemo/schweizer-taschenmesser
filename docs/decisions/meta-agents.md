# Decisions – chats and docs process – agent team

Part of [meta](meta.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Agent team set up and frozen (2026-11-07):** roster, delegation matrix and sandbox start live in [meta/AGENTS.md](../meta/AGENTS.md). Changes to it, the agent prompts or root CLAUDE.md need a maintainer decision here; agents do not change them on their own. The onboarding PR was a one-off exception; afterwards root CLAUDE.md changes again only with a root rule change, own PR, maintainer approval.
- **Maintainer standing order (2026-11-07):** merge-ready PRs are merged without asking by `nemo-merge` only: merge commit + verified head SHA (`expectedHeadSha`), base `develop`, never `main`/tags/releases. MCP merge first; on 403 REST `PUT /pulls/{n}/merge` with the session token. A reviewer's written MERGE-READY verdict with the reviewed head SHA counts as approval (GitHub refuses self-approval when the token owner authored the PR). The lead never merges.
- **One token for all agents (2026-11-07):** all agents run with one token with admin rights (no separate devops token); the prompt hard limits (never `main`/tags/releases/branch protection/force-push) are the guard. Why: maintainer's choice for simplicity.
- **Agent team v3 (2026-11-08, `review/agents-v3`, maintainer took all four recommendations):** agent prompts live in the repo (`docs/meta/agents-v3/nemo-*.json` → `nemo-*.md` via `scripts/agents/to-ant.mjs`, folder renamed to `docs/meta/agents/` at the switch-over), the shared rule block in `SHARED.md` is read once per thread; the lead (Opus 5.5 high, no advisor) delegates through a `multiagent` block to 19 predefined subagents (inline agents and workflows off); models per role (Opus for lead/security/architect/reviewer, Sonnet for implementers, Haiku for triage/docs/i18n, Fable 5.1 for creativity with Opus as fallback if not budgetable). Why: v2's lead had no `multiagent` block and would have done everything itself; one source for the prompts instead of 20 forms ([meta/agents-v3/REVIEW.md](../meta/agents-v3/REVIEW.md)).
- **Light path for small PRs (2026-11-08):** docs-/test-/i18n-only PRs go `nemo-reviewer` → `nemo-merge` only; everything under `.github/**`, RULES.md areas, secret-holding build inputs (`web/scripts/**`, `build.rs`, gradle, `tauri*.conf.json`, lock files), `CLAUDE.md` and `AGENTS.md` take the full path with `nemo-security`; `docs/meta/agents*/**` and `scripts/agents/**` are merged by the maintainer himself. Why: v2 sent docs-only PRs through five agents and full local suites; CI runs them on every PR anyway.
- **Token scope and rulesets (2026-11-08, replaces "One token for all agents"):** one fine-grained PAT for this repository without `Administration`, `Workflows` and Actions write; ruleset on `develop` (PR, 0 approvals); `main` and tags `v*` have no ruleset yet (verified by GET); releases stay prompt-guarded until the signing secrets move into a GitHub Environment with the maintainer as reviewer; the MERGE-READY/SECURITY verdict lines plus the lead's thread hand-over replace GitHub approvals. Consequence: once the `develop` ruleset exists, `scribble/` changes go by small PR for every chat (root CLAUDE.md line changes in the switch-over PR). Why: a shared token cannot be split per agent (vault credentials apply to every thread of a session); rulesets are the technical lock the prompts cannot be. Observed 2026-11-08 with Workflows + Actions write (a workflow push and artifact deletes succeeded); the intended state is without them, kept as an open item for Sven (CHATS "Wartet auf Sven").
- **Seven more agents, same frozen rules (2026-11-07):** `nemo-deps` (dependencies/supply chain), `nemo-perf` (measurements before/after, reports in `docs/perf/`), `nemo-triage` (CHATS.md/MANUAL-TESTS/scribble housekeeping, docs only), `nemo-i18n` (de/en texts, glossary, `strings.ts` block rule), `nemo-a11y` (accessibility review, small fixes), `nemo-merge` (merging), `nemo-creativity` (ideas and second opinions on the Fable model, `docs/product/ideas/`). Roster rows in [meta/AGENTS.md](../meta/AGENTS.md); prompts live outside the repo in the agent form, like the first twelve. Why: these duties were done ad hoc by the lead or by generic agents (e.g. "Merge Conflict Resolver") and kept slipping (forgotten `gen:licenses`, stale "Wartet auf Sven" rows, no before/after numbers on dependency bumps).
- **Dependency hygiene is one agent's duty (2026-11-07):** security-critical crates (LAN sync/Noise, vault bridge, Local API, SQLite, randomness) are pinned exactly and checked with `cargo tree -e features` for pure-Rust backends; `cargo audit`/`npm audit` run by `nemo-deps` each session until a CI job exists (as of 2026-11-07 no workflow runs them, and `extension/` is missing from `dependabot.yml` – `nemo-devops` to decide); `npm run gen:licenses` is part of every dependency commit; lock files only by tools. Why: a forgotten licence list broke CI once, and the sync crypto path must not pick up a C backend or an extra network stack unnoticed.
- **Idea briefs have a home (2026-11-07):** `docs/product/ideas/` (new; one ranked file per round, row in `docs/product/README.md`) holds `nemo-creativity`'s briefs; `nemo-po` moves accepted ones into ROADMAP/STATUS. Earlier rounds stay where they are (`docs/product/next/01-ideas.md`). Why: ideas were scattered over ROADMAP, STATUS and chat transcripts; one place with a fixed brief format (problem, fit, risks, smallest step) keeps them checkable against the hard rules.
- **Agent token diet (2026-11-08, `fix/agents-token-diet`, after one lead session cost 215 M tokens / 82 USD):** lead on Sonnet 5.5 high with an Opus 5.5 advisor for decisions only; one session = one request (afterwards: new session, never raise the budget to keep chatting); delegations bundled per agent; no full local suites, CI is the only full run; outputs via `tail`/`grep`/`--stat` first; thread messages ≤ 15 lines; `session.mjs` defaults to a 10 USD budget, warns at 70 %, needs `--yes-expensive` above 30 USD. Why: context growth and repeated full runs, not the work itself, drove the cost.
- **Agents may dismiss alerts with a written reason (2026-11-08):** Dependabot alerts may be dismissed as `not_used` or `tolerable_risk` (as [howto/release-deps.md](../howto/release-deps.md) allows) with a written reason, after `nemo-security` concurs; CodeQL alerts only as a real false positive with justification, also after `nemo-security` concurs. Why: a dismissal silences the alert for everyone.
- **Signing secrets into GitHub Environments: TBD before the public launch (2026-11-08):** PR #542 (draft) stays paused until Sven decides. Why: an environment with a reviewer locks the signing secrets without relying on agent prompts.
