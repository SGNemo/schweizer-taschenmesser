# Decisions – shell – settings and libraries

Part of [ui-shell](ui-shell.md). Index of areas: [DECISIONS](../DECISIONS.md).

## Settings: categories and registry (2026-10-02, PR `feat/settings-overhaul`)

- **Registry instead of a page.** Every setting belongs to a _section_ with a _category_ (`core/settings/registry`). The page, the search, the palette commands ("Einstellung: Hotkey") and the deep links all read that list, so nothing can be added "at the bottom"; a section without a valid category fails `registry` tests and `check:modules`. Module settings keep their schema/keys (`pages/settings/inventory.test.ts` pins every key and default); the manifest may choose another category (`accounts` → Sicherheit). Restructuring is presentation only: no key moved, no migration.
- **Routes:** `/settings/<category>#<section>[--<field>]` (`settingsPath`), old `/settings#sync` anchors are redirected. Page width `content` (list 16 rem + 44 rem), master–detail from 900 px. **Phone: category list as the first level** (icon + one line), then the content with a back link; this replaces the chip row of the first design spec. A category without a visible section (e.g. Entwickler in a stable build) does not exist.
- **Palette:** settings commands only appear once the query starts with "einst…", otherwise long setting labels would take Enter away from natural-language questions to the assistant. _(Superseded 2026-10-11, see "Settings comfort".)_
- **Über Nemo** shows one source (`core/about/info.ts`): version, build date + commit (`vite` define), channel, platform, install kind, data folder (desktop commands `desktop_data_dir`/`desktop_open_data_dir` take no argument, the app decides which folder), changelog of this version (build-time extract of `CHANGELOG.md`), generated licence list (`npm run gen:licenses`, test keeps it current), links, diagnostics export (in-memory error log, last 50 entries, shortened and redacted, no stack traces, no data folder path, no settings values or secrets).
- **Danger zone:** "Alle Daten auf diesem Gerät löschen" asks twice (the second "yes" only works 0.6 s after "Bist du sicher?" appears, so a double click is not two confirmations; typing `LÖSCHEN` was dropped on the maintainer's request, 2026-10-13, same as for disk deletes); it removes the database, the device's secrets (AI keys, backup password, connector secrets by name) and `tm-*` preferences, then reloads. Server data and backup files stay. Secrets that cannot be enumerated (none known) would survive in the keystore.

## Settings comfort (2026-10-11, PR `feat/comfort-settings`)

- **Palette finds settings without a prefix** – hits come from the registry search (all words must match, synonyms and keywords included), at most 5, listed after the assistant entries, so Enter on a question ("offene Rechnungen") still asks the assistant (quick-switch commands like "Farbschema: Dunkel" are commands and come first); "Einstellung …" still works as a lead-in word. Replaces the "einst…" rule above.
- **Quick switches are an allow-list** (`core/settings/quick.ts`: theme, density, reading aid, colour mode, home view) – a palette command per value and a bar at the top of Settings, always with a toast that undoes it. Nothing security related can be listed (tested). Fewer ways, not more options: no new setting was added.
- **"Häufig genutzt" is device-local and shares the existing switch** – "Verlauf in der Suche" turns it off and "Verlauf löschen" empties it; no new option, nothing synced. A section needs two visits.
- **Reset per section is opt-in** (`SettingsSectionDef.reset`): look, reading aid, focus aids, calm reminders. Undo toast instead of a dialog. Keys and defaults stay untouched.
- **Context gear** (`SettingsLink`) in the module header and widget head: with a mouse it shows on hover/focus (stimulus load), on touch it is always visible. Deep-link schema `nemo://…` is internal only; no OS handler (attack surface, platform work).
- **"Stumm"** is decided separately, see [focus.md](focus.md) ("Stumm: a pause, not a switch-off").

## Library comfort (2026-10-13, `feat/comfort-library`)

- **One card for both libraries** – `@/ui` `LibraryCard` (icon, name, badges, description, actions, deep-link anchor) is used by the module and the tool library; search matches name, description and the module's settings words (so "Abo" or "Rechnung" find the module by purpose).
- **"Neu" / "Aktualisiert"** is device-local (`tm-library-seen`, `core/modules/librarySeen.ts`): nothing on the very first look, later a new module or a higher `version`; the mark goes once the library was looked at. No counter, no nag.
- **Start data on the card** of an enabled module (same button as in Settings); the card has a switch (`role=switch`, "<Name> einschalten") instead of enable/disable buttons. Switching off a module **without data** (`moduleHasData`) needs no dialog – a toast offers undo; with data the keep/delete dialog stays. E2E uses `moduleSwitch(card)` from `e2e/helpers.ts`.
- **Not done:** preview widget in the card (stimulus load; superseded in part by "Libraries in identity v3": a drawn sketch, decoration only, hidden on the phone, grey in "Ruhig"; never the live widget), navigation order by drag and drop (favourites keep their buttons).

## Settings in identity v3 (2026-11-04, `feat/identity-v3-settings-library`, package 1)

- **A local `PageHead` instead of the shell band.** The head band is private to `layout/AreaFrame` and only renders on area paths, so settings (and later the libraries) build the same ingredients from the same tokens (`data-hue`, `data-area`, `--head-gradient`, `--area-pattern`, plate, text always `--text`) as a rounded card inside the page container. Proposal for later: lift it into a shared `ui/PageBand` once the shell owner agrees (no overflow, no bleed needed there).
- **Colour is display-only.** `pages/settings/categoryLook.ts` maps each category to a hue and an area pattern, and `NAV_GROUPS` splits the category list into five headed groups (contiguous slices of the registry order, so the navigation order does not change). The registry and `categories.ts` stay colour-free; `categoryLook.test.ts` pins coverage, neighbours and order.
- **Status head = six states.** Security, sync, backup, updates, AI, storage (same hooks and texts as the overview cards before; backup is new as its own tile). Each tile has one state line and one context line, a jump into its category, `attention` as an accent hairline plus words, never red. The overview keeps look, notifications and modules as cards; e2e count: 6 tiles + 3 cards.
- **"Differs from the default" is a quiet dot** next to the category in the list (reuses `isChanged` of the sections' reset plans) with a `sr-only` text; nothing new is stored. No left rails remain in settings (sub-groups, table of contents, security note).
- **Unchanged on purpose:** registry, keys, defaults (`inventory.test.ts` untouched), security sections and their confirmations, module files.

## Libraries in identity v3 (2026-11-04, `feat/identity-v3-library`, package 2)

- **Cards show the module, not a generic tile.** `LibraryCard` takes an optional `hue` (tinted head and plate) and `preview` (a drawn sketch of the module's widget variant, `pages/library/WidgetMiniature`: boxes and bars, no text, no data). The sketch instead of the real widget is deliberate: widgets read live data, would load every module's code on one page and, for the vault, would show entries. Without the new props the card is unchanged.
- **Head with figures, toolbar with filters.** `PageHead` (the settings one) carries "n active · n available · n new"; the toolbar has the search, a status filter (all / active / off / new when there is something new) and an area select. Filters are component state, not stored. Sections stay one per navigation area, tinted in the area colour with its pattern and "n of m active".
- **Detail page `/library/:moduleId`** (one child route in `router.tsx`): the module as a small page, with the same switch as the card. On/off is one hook (`pages/library/useModuleSwitch`): start-data offer once per device, keep/delete dialog when there are entries, undo toast otherwise; unchanged behaviour.
- **Tool library** uses the same head, figures, filter and tinted groups; cards take the tool's own hue (`tool.identity.hue`).
- **Edge cases kept calm:** a card switched under the Aktiv/Aus filter stays until the search or filter changes (focus does not fall to the page), also a preview module that leaves the catalogue when switched off; an empty result says why and offers "reset search and filter"; the detail page resolves through the same catalogue as the library (a hidden preview module stays hidden).
- **Fixed on the way:** the card list was one column because `.list` (flex) came after `.grid` in `Page.module.css`; the libraries have their own grid now. The area-colour dot (`libStripe`) and a dead `.moduleIcon` rule are gone.
