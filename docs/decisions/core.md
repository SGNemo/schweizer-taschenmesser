# Decisions in full – Core: data, sync, AI

Full text (decision, reason, source). One-line summary table: [DECISIONS](../DECISIONS.md).

## Product & data
- **Local-first, IndexedDB as source of truth; sync is a separate optional layer.** Data stays on the device; a self-hosted server only relays field operations. Source: CLAUDE.md intro; architecture.md "Sync & backup".
- **One Dexie table per collection, every synced record has an envelope (`id, createdAt, updatedAt, deviceId, deletedAt, _f`); writes only via `createRepo`.** Validation, HLC stamping, tombstones and outbox in one place. Source: architecture.md "Data".
- **Money = integer cents; dates `YYYY-MM-DD`, times `HH:mm` (local wall clock).** Calendar/reminders stay put across time zones and recurrence works on plain dates. Source: architecture.md "Data".
- **`now()` / `today()` instead of `Date.now()`.** Injectable clock makes date logic testable. Source: architecture.md "Data".
- **German-only UI, all texts in `web/src/strings.ts`; code/comments/commits English.** Source: CLAUDE.md.
- **Modules are manifest-driven and isolated (event bus + manifest contributions; only read-only `public.ts` exceptions).** Modules can be switched on/off and stay independent; enforced by ESLint and `registry.test.ts`. Source: architecture.md "Isolation".
- **Subscriptions are forecasts, never auto-booked transactions.** Source: architecture.md "Money & finance".
- **Local-only collections (`CollectionDef.local`, `_blobs`)**: news articles, feed state, vault files never enter outbox/sync/backup. Source: architecture.md "News module", "Extra modules".

## Sync
- **Field-level last-write-wins by greatest HLC; rule implemented twice on purpose** (`core/sync/ops.ts`, `server/src/store.ts`), pinned by `contract/lww-cases.json`. The server never merges values, only assigns a monotonic `seq`. Change both or neither. Source: architecture.md "Sync & backup".
- **`SyncAdapter` abstraction** (`selfHosted` built; `googleDrive.stub.ts` documents the unbuilt second backend). Source: architecture.md "Layers".
- **Optional E2E encryption of each op value (PBKDF2 → AES-GCM, AAD = `collection/id/field`)**; ids/fields/HLC stay readable because the server needs them. Source: architecture.md "Encryption".
- **Server is single-tenant, no tombstone GC** – accepted known limits. Source: architecture.md "Not built / known limits".
- **Home-network sync with the PC as server (2026-11-06, `design/sync-lan-concept`; maintainer chose all recommendations 2026-11-07, Fable check pending):** variant (b) a Rust hub in the desktop shell (`crates/lan-sync`), star topology with exactly one hub, Noise `IK` (hub key only in the QR; `IKpsk1` pairing that checks the current single-use secret in message 1, 6-digit code on both screens, trust list), QR with a single-use 2-minute secret (no long-term secret), E2E always on with a random data key handed over in the channel, raw keys owned by Rust in the OS keystore, binds only private addresses on a positively identified home network (fail-closed, except an open pairing window; Local API rule unchanged), key rotation wipes the hub store, third LWW copy pinned by `contract/lww-cases.json` plus a small paging contract, server path stays, Android syncs on open/Wi-Fi change while the app runs. Source: [design/sync-lan/CONCEPT.md](../design/sync-lan/CONCEPT.md) §10–11.
- **LAN sync hub store: variant (b) (Rust store with LWW), (b′) append-only mailbox rejected (2026-11-07):** see [CONCEPT §3](../design/sync-lan/CONCEPT.md). Built in package 1: `crates/lan-sync/src/store.rs` is the third LWW copy (one SQL upsert, HLC compared as text), pinned by `contract/lww-cases.json`; the paging the engine assumes of a store (cursor/`more`, refused ops use no `seq`, epoch on reset, `hlc-drift`, ops limit) is pinned by `contract/sync-paging-cases.json` with levels `store` (Node store test, Rust) and `handler` (Node server now, hub in package 2b). The Sync rule now says "three copies"; the hub rule line follows with package 2a.
- **LAN sync package 2a: Noise channel, pairing window, trust list (2026-11-07, `feat/lan-sync-noise`):** `crates/lan-sync` `noise` (`snow` 0.10.0 pinned `=`, pure Rust ChaChaPoly/BLAKE2s/X25519, no `std` feature because it enables `ring`), `pairing`, `trust`, `endpoint`; no sockets yet (2b). Pairing `IKpsk1`, sessions `IK`, prologue carries the mode; only `TransportState`. SAS = first 8 bytes of the handshake hash mod 10^6. Policy: window 120 s, renewed only by the open dialog; a wrong code, wrong attempt id or timeout ends the attempt (fresh secret, no retry); confirm deadline = `min(burn + 120 s, window open + 240 s)`, all deadlines checked lazily on every entry point (monotonic `Instant`); first message 1 that cannot be authenticated, a stale one, or a key already trusted gets no reply; a **revoked key is never trusted again** (tombstone, stricter than CONCEPT §5 row 2: "Neu koppeln" needs a new key on the device). KCI accepted and keys never logged (`tests/rules.rs`). Static key only via `StaticKeyStore` (OS keystore, fail-closed, no fallback). **Residual risk accepted by Sven (2026-11-07): `snow` has no independent audit.** Overturned by: an audit preference for rustls with pinned certificates plus a separate PSK proof and SAS (CONCEPT §5). Hub modules compile out on Android/iOS.
- **LAN sync package 2b-1: hub core without sockets (2026-11-07, `feat/lan-sync-hub-core`; Sven approved the plan with all four recommendations):** (1) 2b is split – 2b-1 is the pure core (`crates/lan-sync/src/hub`: push validation, handler, rotation, per-connection router, handshake admission, address policy; no new dependency, no Tauri), 2b-2 the OS side (listener, mDNS, network list, keystore, commands, firewall). (2) The hub-local client and remote clients use one request/response JSON shape (`handler.rs` header) and every request carries `keyVersion`; a mismatch answers `stale-key-version` before anything else, under the store lock, and rotation to n+1 wipes the store, new epoch, closes all sessions in that one lock. (3) The data key and static key will live in the OS keystore via `keyring`, fail-closed, after checking that the desktop `secrets` implementation cannot be reused (2b-2). (4) v1 binds and accepts IPv4 RFC 1918 + link-local only; CGNAT, loopback, wildcard and all IPv6 are refused; no listener unless a window is open or a device is paired, and only on interfaces with a default route in a Private network (home network id when no window). Push validation mirrors the Node server (counts, `^\d{13}-\d{4}-[a-z0-9]{1,32}$` HLC, value size) and adds `enc:v1:` for every value including `deletedAt` tombstones (the client encrypts all ops); a refused batch stores nothing, takes no `seq`, keeps the epoch. The 16-byte QR secret is zero-extended to 32 bytes; hub and client are pinned by a golden value test.
- **LAN sync package 2b-2: the hub gets its network (2026-11-07, `feat/lan-sync-hub-net`):** sockets exist only in `crates/lan-sync/src/transport` (`std::thread`, no async; frame = u16 length + Noise message; listeners only on the exact addresses of `netpolicy::decide`, refused otherwise even in `Server::start`; caps per address and in total, handshake/frame/idle deadlines); a `Supervisor` re-decides every 2 s and tears all sockets down before any restart on a change of network, address, wish or UTC day; mDNS (`mdns-sd` 0.21.7, desktop target table only) announces on the bound interfaces only with TXT `v`,`h` (HMAC-SHA256 hint written out over `sha2`, pinned to the prototype). Raw hub keys (static key, versioned data key) live in the OS keystore through `keyring` (same crate as the secure-store plugin, service name `<bundle id>.lan-sync` so Dev-Preview and stable never share them); any keystore error means no hub, a corrupt entry is never replaced. The trust list and the single home network are JSON files in the app data folder, replaced atomically, unreadable = no hub. LAN values are capped at 60 000 B so a pull of one max-size op always fits one frame (larger values would need fragmentation). Windows identifies the home network via the network list (id + category Private) and `GetAdaptersAddresses` (default route); other systems cannot identify one and never listen (the gateway-MAC fallback is not built). Commands: `lan_hub_start/stop/status`, `lan_pair_open/confirm/cancel`, `lan_devices`, `lan_revoke`, `lan_hub_rotate`, `lan_hub_request`, `lan_home_set`, desktop capability only.

## AI
- **Never send user data to the model.** Only instructions, compact `aiSchema` of enabled modules, the date and the question; results are computed locally, no second call. Guarded by `privacy.test.ts` for every adapter. Source: architecture.md "AI assistant"; CLAUDE.md rules.
- **Three tiers, cheapest first:** local German parser (0 tokens) → full text → intent cache → model. Goal: as few tokens as possible. Cache key excludes provider/model so fallbacks share hits. Source: architecture.md "AI assistant".
- **Model output is never evaluated; it is a Zod-validated `Intent` executed against a field whitelist.** Creating entries needs an explicit confirmation card. Source: architecture.md.
- **Multi-provider router with fallback, cooldowns and local limits;** presets are only editable defaults (names/prices unverified). API keys live in `PlatformService.secrets`, never in the config list. Source: architecture.md "Multi-provider AI".
- **`accounts` (password vault) is invisible to AI, search, dataapi and local API** (no `aiSchema`, `dataApi: false`, id block; `exclusion.test.ts`). Source: architecture.md "Password vault"; CLAUDE.md.
- **Connectors must not import `core/ai`; news has no `aiSchema`.** Mail/feed text can never reach a model except via the explicit news-brief button (headlines only). Source: architecture.md "Connectors", "News".

- **AI writes (2026-10-05): stage order rules → local model → cloud, every write only after the preview.** Reason: tokens and privacy – most sentences are fully determined by the module words and the extractors (stage 0 handles 94 % of the 154 entries of the eval set exactly, 0 wrong module, 0 false positives on 30 searches/questions; run `npm run ai:eval`); the cloud is the last resort and only with the sentence, the date and field schemas. Actions are declared per module (`aiSchema.actions`, validated by `validateAiActions`), so a new module needs no core change. Deletes and changes show before/after, are one undoable group, and skip entries edited since the preview. Update/delete/mark targets are the user's own words matched on the device, so no candidate list is sent. Modules without actions and the vault stay read-only/invisible. Claude subscriptions cannot be used by third-party apps (Anthropic terms); the supported path for a subscription is Claude Code on the PC driving the local API / MCP ([AI-IMPORT](../AI-IMPORT.md)). Source: `core/ai/write/`, `docs/architecture/ai.md`.

## Test data / seeds (2026-10-02)
- **Seeds are part of every module (`seed` in the manifest is required by the type).** New modules cannot be merged without test data, because the Dev-Preview, E2E tests and screenshots depend on it; `core/seed/registry.test.ts` and `check:modules` fail otherwise. Alternative (optional field + warning) rejected: parallel chats would skip it.
- **Metadata in the manifest, code in `modules/<id>/seed.ts` loaded by glob.** A function in the manifest would end up in the stable bundle; the glob is only reachable through `loadSeed`, which the build replaces with `undefined` unless `VITE_RELEASE_CHANNEL=dev` (`devFlag.test.ts` builds both flavours and greps the output).
- **Own mulberry32 generator instead of faker.** No new dependency or supply-chain surface, tiny bundle, output cannot change with a library update. One stream per module (`hash("42:<module>")`), so adding a module never shifts the others.
- **Seed rows go through `createCollectionRepo` (valid envelope, HLC) but are registered in the local table `_seeds` first.** Outbox, "upload everything" and backup skip registered rows (also in stable builds, so a stable app opening a dev database cannot leak them); the dev switch "Seed-Sync erlauben" (default off) queues them once, and removal then writes tombstones. Modules switched on for the seed are registered too.
- **Demo vault: fixed visible passphrase `nemo-demo-tresor` (10+ characters, `createVault` requires it), dev build only, never overwrites a vault.** Crypto unchanged; the entries use placeholder passwords.
- **E2E for the dev flavour is a separate Playwright project (`seed-dev`, build mode `e2e-seed`, :4174).** The regular specs stay on the stable build so the stable path stays covered.
- **Diagnostics and bug reports run only on user action (2026-10-06):** no crash-reporter service, nothing is sent; the report is a text file the user previews and attaches to a prefilled GitHub issue. Everything passes one `scrub()`; the vault is not even counted. A defective database gets a recovery screen that first keeps a copy of the broken state; safe mode is per start and writes nothing.
- **Bilingual new texts (2026-10-06):** UI stays German in `strings.ts`; new features define German + English together with `defineBundle` (`core/i18n`, e.g. `strings.i18n.ts`), the compiler enforces equal shape, language is a per-device choice (`localStorage`, Settings → Über). Retrofitting old strings is a separate decision.
- 2026-10-24: the empty-state link "Einrichtung öffnen" lives once in `StartDataButton`, as a ghost button next to the start-data button (no banner), only when `setupStepIdForModule` finds a step (module-owned, else `core.startdata`); it opens the assistant on click at that step, never by itself, and is left out where the button already sits inside the assistant, library or module settings.
- Calendar (QA P4 B): end time and repeat rule sit in the event dialog, not behind "Mehr Felder"; shifts are not stored templates but the last four title/start/end slots (`calendar/recentSlots.ts`); a multi-day entry names its end on the first day (`CalendarItem.endDate`) and marks later days `continued`.
- **Plain backups carry an optional `checksum` (SHA-256 of `tables`); typed search questions are never stored; a weak master password needs one explicit yes.** The checksum catches damage and accidental edits only (no key), so the encrypted backup stays the recommended one and old files without it stay importable (reported "unprotected"). Calendar addresses must be public https on the client (the server proxy still decides after DNS). Crypto of vault and backup unchanged. Source: `docs/qa/CONSOLIDATED.md` P6 (B23, B24, B26, V06, V22, V23).
- Quick capture (QA P4): targets `subscription`, `birthday`; weekly slot + time = event, only daily stays reminder; deadline verbs = ToDo; unsure keeps the typed title. Yardstick `quickCapture/parser/corpus.ts` (`MIN_HITS` only rises).
- **The connection log wraps `platform.fetch` and lists host, reason and size only; "Netzwerk sperren" refuses before sending.** Session memory by default, opt-in `localStorage` copy that never reaches Dexie, sync, backup or diagnostics. Requests the Rust side makes announce themselves through `assertNetworkAllowed`. Why: the privacy text must be checkable in the app (QA V21). Source: `features/connection-log.md`.
- Focus steps (QA P4 D): "Schritte aus einer Vorlage" = local templates per keyword of the title, per language (`todos/stepTemplates.ts`, `focus.mode.stepSets`); a preview first, stored only on "Übernehmen"; never a model, the title never leaves the device. A running round is only replaced after a question (`beginFocus` returns false). Bank import suggests the category of an earlier booking of the same payee.
- Home (QA P4 C): `home/AgendaBlock` ("Heute · Morgen · diese Woche", key `core:agenda`) lists 7 days of calendar items in both densities; the "Heute" card keeps the time-to-next line but no appointment list. Calm/all are labelled Ruhig/Ausführlich with a switch on the page. `danger` attention items are never folded into "Wartet noch".
- **"Mit Partner teilen" is an encrypted file plus a six-word code, merged through the backup/LWW path; the vault and core settings are never part of it.** No server, no account, nothing leaves without the person carrying the file. Source: `features/partner-share.md`, QA V09.
- **The sync server's failed-login limit only slows wrong tokens; a valid token always passes.** Authentication runs first, then the per-address failure counter and its `429`. Why: clients behind one reverse-proxy address or LAN must not lock each other out; guessing stays capped by the per-address request limit and the ≥ 16-character tokens. Source: QA P6 (Tom, F-05); `server/test/devices.test.ts`.
- "Für" (QA P4 E, V14): ToDos and appointments carry an optional `personId` (People record; a client is a person). Core reads the people table (`core/people`), so no module imports another; `CalendarItem.personId` is the only manifest-contract change. The field and the "Für wen" filter appear only with people in use; `personId` is `internal`, never in an `aiSchema`.
- **"Zuletzt gelöscht" = a read-only view on tombstones (2026-10-30, P5 package D, ROADMAP K4):** deleted records of an allow-list (`core/trash`) stay restorable for 30 days (`core/db/trash.ts`); restore is a repo write, "Endgültig löschen" the local tombstone clean-up done early (waits for the outbox when a sync server is set up). Switch `trash.keep` (default on) because it keeps data longer; off shrinks the window to 10 minutes. The stale "no tombstone GC" notes elsewhere are wrong: `purgeTombstones` runs after 90 days.
- **Editors save only what changed; trash restores children (2026-11-05, QA round 4 X01/X06):** an editor keeps the record as it opened it and writes `changedFields(opened, values)` (`core/db/patch.ts`), so a field changed meanwhile in another tab or by sync is not set back (with a new stamp it would win everywhere). "Zuletzt gelöscht" also lists finance accounts, hand-made bookings (not `imp-…` imports – bank, AI or data-API alike –, not `sourceRef` bookings; a transfer is one entry), habits and time entries; an account/habit brings back the bookings/days deleted with it (≤ 60 s before), and a child row is listed on its own only while its parent is active. Sources: [qa/round-4/chaos/FINDINGS.md](../qa/round-4/chaos/FINDINGS.md).
- **Precache without tool views, chat view and zxcvbn dictionaries (2026-10-31):** they load on first use; the SW runtime cache keeps them offline; never loaded + offline = calm note, no error. Details, rule, budget: `perf/COLD-START-2026-10.md`.
- **Command palette loads on first opening (2026-11-03):** `layout/AppShell.tsx` mounts `CommandPalette` as `lazy()` only after `paletteOpen` was true once (the shortcut and the voice key only set the store flag, so they work before the chunk is there). Measured with `check:bundle`: critical path 667.5 → 635.8 KB gzip, 86 → 82 requests. Tried and dropped: lazy `ask`/`searchEntries` inside `useAssistant` and lazy `OnboardingWizard` alone (−2.6 KB, more requests: the pieces just move into shared chunks). Settings sections stay eager until the settings chat splits the registry (`scribble/perf-bundle-findings.md`).
- **Backlog harvest 2026-11** ([list](../meta/BACKLOG-HARVEST-2026-11-03.md)): CSV exports neutralise formula cells (`neutralizeCsvCell`; the Bitwarden-format vault export opts out). Notice periods entered in whole months count calendar months (`cancelNoticeMonths` v5, `noticeMonths` vault v3; days stay months × 30; month count used only while it matches the days). Backup import: size cap 64M characters, rows with wrong envelope types skipped and counted. Sync server: unexpected errors answer a generic body. Android `allowBackup="false"` via `scripts/android-manifest.mjs`; cleartext left alone (plain-HTTP LAN sync). `logError(tag)` for surprising silent catches.
- **Contribution hooks share one live query per input (2026-11-04, `perf/live-queries`):** `core/modules/sharedQuery.ts` `useSharedLiveQuery(key, querier)`: instances with the same key run the module sources once and re-run once per write (the home page mounted `useCalendarItems` 5×, `useAttentionItems` 3×, each with its own full scans); the query stops 50 ms after the last subscriber left. Behaviour as `useLiveQuery` (`undefined` first, previous result kept while another key loads, errors thrown to the boundary). The key must contain every input of the query. The function given to Dexie's `liveQuery` has to be a native `async` function, otherwise Dexie loses read tracking across `await` and the query never re-runs (found by `e2e/now-strip.spec.ts`). The lazy sources are loaded first (`prepare`), because a first run that awaits a still-pending `import()` loses tracking too (`calendar/__tests__/nextWidget.test.tsx` showed it). Measured: `perf/DATA-BASELINE-2026-11-03.md`.
- **Full text search keeps an in-memory index (2026-11-04, `perf/search-index`):** `core/ai/search/index.ts`, one MiniSearch (already a dependency, no new package) per database and set of enabled `aiSchema` collections, built by the first search and kept current from Dexie's `storagemutated` (also other tabs and sync): a changed table is re-read and only changed documents are replaced. No `updatedAt` watermark: rows applied by sync can be older than the newest local one, so it would miss them. Not persisted (nothing to migrate, sync or back up), dropped after 5 idle minutes, only collections with `searchable` in `aiModules`, so `accounts` is never in it. A worker was left out (documents would be copied to it). Measured: `perf/DATA-BASELINE-2026-11-03.md`.
- **Sync storage adapter works in batches (2026-11-04, `perf/sync-backup-batch`):** `readOutbox` and `applyRemote` read a chunk with one `bulkGet` per collection and write merged records with one `bulkPut` per collection; `markAllDirty` writes the outbox in slices of 5,000. Same results and order as before (tests in `core/storage/dexie.test.ts`); the merge rule `mergeOps` stays the single LWW implementation (client and server change together or not at all). Restore keeps one transaction (atomic); parsers stay on the main thread (small inputs, a worker copy would cost what it saves). Measured: `perf/DATA-BASELINE-2026-11-03.md`.
- **Data-layer reads use the index they declare (2026-11-04, `perf/finance-data`):** measured with 33k rows (`perf/DATA-BASELINE-2026-11-03.md`), a read of a whole table (`repo.active().toArray()`) is the dominant cost, not memory or size. Where a read only needs a range, it uses `repo.table.where('date').between(…)` + `notDeleted` (finance month sums, subscription price window). `balances()` is one pass (was quadratic). Shared-snapshot caches of bookings were rejected for now: sync writes bypass module repos, so a cache cannot be invalidated safely at module level; sharing happens at the live-query/contribution level (next package). No new index without a reader.
- **Awaited `module.disabling` before the state and the wipe (2026-11-05, planner package 1):** `disableModule` emits `module.disabling` and awaits it before writing `enabled: false` and before a delete-policy wipe, so a module can hand foreign records back (the planner restores the ToDos' own dates). `bus.emit` swallows handler errors: a throwing listener never keeps a module switched on. No existing listener changed; `module.disabled` keeps firing afterwards.
- **`syncSettled()` and the pull-complete flag (2026-11-05, planner package 1):** `core/sync/service.ts` `syncSettled()` is true without a sync configuration, otherwise only when this tab's sync chain is idle (a running round is awaited first – bounded by the queued rounds) and the last pull ended complete – `pullAll` clears a device-local `_meta` flag (`sync.pullComplete`, `StorageAdapter.setPullComplete`, optional for test doubles) when a pull starts and sets it after the last page. A paged or failed pull can split one record's field ops, so a consumer that acts on another device's fields (the planner on a ToDo's `plannedFor` + `planMark`) waits for the flag; nothing else touches `navigator.locks`. `core/db/metaKv.ts` (`getMeta`/`setMeta`/`deleteMeta`, optional database) holds device-local state, so modules never import `db`.
- **Undo entries can carry a scope (2026-11-05, planner package 1, council):** `undoable(label, fn, scope?)` tags an entry with a module id and `forgetUndo(scope)` drops those entries – a module that is switched off (and maybe wiped) must not be replayed into by Ctrl+Z or a toast's Rückgängig. Only the planner uses it so far.
