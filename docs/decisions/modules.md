# Decisions – modules and tools (package 1 "Aufräumen", 0.4.0)

Index: [DECISIONS](../DECISIONS.md). Plan: [product/MODULE-PLAN.md](../product/MODULE-PLAN.md).

## Retired modules
- **Why not delete the tables:** a sync pull skips ops for unknown tables and the cursor moves on (the data never returns); Dexie drops tables that leave the schema together with their data; the server accepts any table name, so an older device keeps writing. Hence `retired` keeps `schema.ts`, `repo.ts`, `migrations.ts`, `manifest.ts`.
- **Contract (`validateRetired`):** no routes, widgets, `aiSchema`, `area`, `contributions`, `defaultEnabled`; `seed: { none: 'retired' }` and no `seed.ts`. `visibleManifests` (and so `availableManifests`, library, router, nav, AI, services) skips them; `allManifests` keeps them for schema, sync, backup, setup "has data". `apiCollections` returns `[]` (import API closed). Old paths `/news`, `/habits`, `/timetrack` redirect to `/` (`router.tsx`).
- **Removed with news:** `core/ai/newsBrief.ts`, start package, `e2e/news.spec.ts`, manual tests N1–N4. Kept: `core/io/feed.ts`, `core/net/fetchPublic.ts`, proxy `/v1/proxy`.
- **Tables left in package 6 (0.9.0)**, schema v18: 15 tables (`news_*`, `habits_*`, `timetrack_*`, `reminders_reminder`, `shopping_item`, `packing_*`, `launcher_link`, `birthdays_birthday`, `gifts_idea`, `contracts_contract`); all 10 module folders and the `0.5.0`–`0.7.0` app-migration steps are deleted (the runner stays, `APP_MIGRATIONS` is empty). Allow-list `REMOVED_ON_PURPOSE` in `schema-upgrade.test.ts`. A backup from before 0.5 still imports: unknown tables are skipped and the restore preview names how many (`core/backup/removedTables.test.ts`). Old URLs keep redirecting (`LEGACY_REDIRECTS`).

## Tools
- IDs: percent/split → `calc`, base64/json/uuid/hash → `dev`, scratch dropped. `migrateToolIds` maps on read (explicit choice for the new id wins, otherwise "on" if any source was on); nothing is written until the next normal save.
- Tools may not import each other (`tools/isolation.test.ts`), so the merged logic moved into `calc/` and `dev/`.

## Notizzettel
- `scratch` note: id `scratch`, title "Zettel", pinned, sorted first, no delete (only "Zettel leeren"). `notes/services.ts` copies `_settings` `tools.scratch.text` once (not if the note exists, deleted ones count as existing, not for empty text) and re-checks on every change of that row (covers sync pull and backup import). Notizen is off by default; the copy runs when it is on.

- **Notes = notebook, body is Markdown (2026-11-01, `feat/notes-editor`, package 1 of 3):** editor is TipTap v3 (ProseMirror, MIT) with `@tiptap/markdown`, loaded lazily with the `/notes` route only (no critical-path or precache cost). Chosen over Milkdown for keyboard/Android-IME maturity and a smaller custom surface; fidelity is held by roundtrip tests (`notes/__tests__/editor.test.ts`). Highlight tones are `=={tone}text==` (tones = semantic tokens; plain `==text==` stays valid). `manifest.version 2` migrates plain-text bodies with `plainToMarkdown` (single line breaks become hard breaks). Pictures are device-local only (`_blobs` key `notes:img:<id>`, `![alt](nemo-img:<id>)` in the text; other devices show a note); `pruneBlobs` ignores `notes:` keys. A new page is created with its first text (no empty rows); autosave is debounced (600 ms) plus blur/hide/unmount, and a `localStorage` draft restores text after a crash. Packages 2 (notebooks, tabs, history) and 3 (links, export, AI append, seeds) follow.

## Dieser PC
- **2026-10-02 – more facts, same rules.** Drive cards (type, interface, model, health/temperature, history), quick overview and live system tiles stay read-only and local. Health, temperature and history are **session-only**: Windows data is read on demand with access 0 (no admin), "nicht verfügbar" says why; the history for sparklines and "belegt seit letztem Scan" is kept in memory only (`history.ts`, `live.ts`) – no collection, no `_meta` row, nothing synced or backed up. The block list, plan/confirmation and recycle-bin-first delete are untouched; the recycle bin is only measured (emptying stays in Explorer). The public IP is asked for **only on a click** (`api.ipify.org`, noted next to the button, answer shown not stored) – the one deliberate exception to "no request", and it never runs on its own. GPU detection merges DXGI with the display-class registry key so the Basic Render Driver is never shown instead of the real card. Android keeps no Dieser PC (a mobile variant is in the ROADMAP).
- `disk` is "Dieser PC" with tabs Laufwerke · System (`?tab=`). Widgets `disk:status` and `disk:system`. Still no data, no aiSchema, blocked twice for the data API (`BLOCKED_MODULES` no longer lists `system`).
- Disk clean-up uses the **last change** (newest file in a folder), never the last access: Windows does not keep access times reliably. Age buckets (< 1 month … > 3 years) are computed in Rust per node (`ageBytes`) relative to the scan start; the map is coloured by age by default; "long unchanged" lists each old folder once (`topmost`) so sums never double count. Deleting from that list goes through the same plan, block list and confirmation as everything else.
- **2026-10-13 – "Zuletzt gespielt" for Steam games.** The change date says little for games (updates reset it, playing does not), so the scan reads Steam's own text files – app manifests and each user's `localconfig.vdf` – and takes the newer `LastPlayed`. Read-only and on request only; matched to install folders inside the scan by node id, never a free path; no date = "Kein Spieldatum von Steam" (no guessing). The list hints that uninstalling in Steam is cleaner than deleting the folder.
- **2026-10-13 – "Zuletzt geöffnet" only where Windows keeps it.** The scan collects the newest file access per node anyway (no extra syscall), but the UI offers "Gemessen an: letztem Öffnen" and the details row only when the volume is NTFS and `NtfsDisableLastAccessUpdate` has updates on; elsewhere the date might just be the copy date, so it is hidden rather than shown with a caveat. Folders' own access times never count (the scan itself touches them). The help text says virus scanners/thumbnails can make a file look newer, never older – the safe direction for clean-up.
- **2026-10-13 – age = last use where Windows keeps access times** (maintainer's call: "dann ist es wirklich die letzte Benutzung"). On trusted volumes the scan buckets ages by the newer of access and change (`tree::last_use`, same rule in `logic/age.ts`), the map/legend/details say "Benutzung", and "Lange nicht benutzt" measures by opening by default (switch to change stays). Untrusted volumes keep the change date unchanged – no guessing from a copy date.
- **The disk map fills up while the scan runs** (like SpaceSniffer): the walk adds what each folder holds to a small live tree of the top two folder levels (`crates/disk-scan/src/live.rs`, one short lock per folder; 1 M files still scan in < 1 s on 4+ cores); the page polls `disk_scan_live` every 0.5 s and draws it read-only. Opening, selecting and deleting stay with the finished tree, so the delete path never sees half-counted sizes.

## App migrations and Listen (0.5.0)
- **Runner** (`core/db/appMigrations.ts`, steps in `appMigrationSteps.ts`): copies rows between collections with the source HLCs (1:1 fields keep their stamp, derived fields get the row's newest stamp, made-up rows `BASE_HLC`) via `applyRemote(…, { markDirty: true })`. Every device writes identical ops, so a second run, a second device or a sync echo changes nothing; edits of the target win; an edit of the source on a not-yet-updated device flows in on the next run. Tombstones are copied, sources never deleted. Not `createRepo.create` (fresh stamps per device would diverge).
- **Triggers:** end of `initCore`, after a sync pull that applied rows, after a backup import (`restamp` after "replace" so copies beat the tombstones the restore left). Serialised, errors swallowed (retry next run). Marker `_meta` `app.migrations.<id>` is informational only.
- **Steps:** `shopping_item` → `lists_item` (list `shopping-default`, made up with `BASE_HLC`, a tombstone counts as existing), `packing_list` → `lists_list`, `packing_item` → `lists_item` (`packed` → `done`), `launcher_link` → `bookmarks_item` (`kind: link`, `tags: [group]`).
- **Listen** (`lists`): kinds shopping | packing | checklist; the `shopping.requested` event stays (Pantry checks `moduleStates.lists`); quick capture type "Einkauf" (`l`). **Lesezeichen** are not a module but a view (`?view=links`); the eight launcher presets are gone, mailto:/tel: links are re-saved as http(s) only. Old paths redirect (`LEGACY_REDIRECTS`).
- Old devices keep writing the old tables (no backward sync): all devices must update.

## Unterlagen and Personen (0.6.0)
- **Unterlagen** = `vault` + contracts: `document` gets `category 'warranty'`, `provider`, `startDate`, `endDate`, `noticeDays`; `expiresOn` stays readable (`endOf`), is never written, and the module migration v2 renames it. One status function (`act-now`/`expired`/`soon`/`ok`/`open-ended`: deadline within 30 days, end within 60 days without a deadline). Two reminder leads (`remindDaysBefore` 30, `remindDaysBeforeDeadline` 14); a service carries the old `module.contracts` lead over once.
- **Personen** = `birthdays` + `gifts`: `person {name, birthday?, note, tags}` and `gift {personId, …}`; `aiSchema` for `person` only (gifts are surprises). Birthday notification keys keep the `birthday:<id>:<date>` form. Settings of `module.birthdays` are carried over once.
- **Steps:** `contracts_contract` → `vault_document` (`kind` → `category`), `birthdays_birthday` → `people_person`, `gifts_idea` → `people_gift`. A gift joins the person (former birthday, smallest id) with the same name (trimmed, lower case, one space); otherwise a person `person-<slug>` is made up (`ensure`, `BASE_HLC`), named after the first spelling. No fuzzy matching. A gift migrated before its birthday has synced keeps the made-up person (rare, left as is).
- Runner gained `prepare(database, rows)` and `ensure(rows, ctx)` for steps that read other tables.

## Zeit (0.7.0)
- **Erinnerungen** are calendar events of the kind `reminder` (`kind` missing = event, no data migration) with `notify {minutesBefore, enabled}`; paused = `enabled: false` (stays in the tab, off the calendar). Calendar notification source: key `event:<id>:<date>T<time>`, all-day events at `allDayNotifyTime`. Step `0.7.0-reminder` copies `reminders_reminder` (`time` → `startTime`, `active` → `notify.enabled`). The scheduler cursor is time-based and the Android list is rebuilt as a whole, so old `reminder:` keys need no carry-over. The `module.reminders` default time moves to `defaultReminderTime` once.
- **Assistant:** "Erinnerung" queries the calendar with `kind = reminder`; the quick-capture type `reminder` writes such an event.
- **ToDos:** `recurrence?` – ticking off keeps the task (history) and creates the next one (with copies of its subtasks, open again, due dates moved along) with the deterministic id `<first id>:<due date>` (`createMany` skips existing ones, so two devices never duplicate); reopening removes the open next one. `someday` keeps tasks out of open views, widget, "Jetzt wichtig" and calendar; open recurring tasks show their later occurrences on the calendar.
- Comfort package 5c (2026-10-13): a repeating invoice creates its successor when it is paid (no background job, no future invoices piling up); the successor links back with `repeatOf` (internal, not in the import format) so paying twice stays idempotent and reopening removes an untouched successor. Recurring bookings are not covered: they need a trigger at app start.
- Comfort package 5b (2026-10-13): "gekündigt zum" is the recurrence end (`recurrence.until`), not a new field, so every consumer (calendar, deadlines, notifications, widget) already honours it; totals take `today` and drop ended subscriptions. The price history is a new optional list (`manifest.version` 2, migration sets `[]`), appended on save when the amount changed.
- Comfort package 5a (2026-10-13): booking search looks through all months while a text is typed (a month filter would hide the hit); the gift overview lives in `people` as a second view and keeps gifts invisible to the assistant. Both need no schema change.
- Comfort package 6 (2026-10-13): a repeating booking (rent, salary) books its missed follow-ups once at module start, with a toast and undo; ids derive from the series root and date (`rep-<root>-<date>`), so two devices converge, and at most 12 periods are booked per start. Rare, so the field sits in Erweitert.
- **File imports:** notes (tags and Keep labels become a final `#tag` line; no ZIP) and ToDos (done tasks off by default, repeats only as note text). [notes](../features/notes-import.md), [todos](../features/import-todos.md)
- **Missed cancellation deadline = calm status, not an alarm (2026-10-29, P5 package B):** `vault` status `missed` ("Frist vorbei am …", muted, no red, not in "Jetzt wichtig"); subscriptions: cycles ≥ a quarter until the charge, shorter cycles (monthly with long notice) for 7 days after the deadline (`missedDeadline`). Notice periods are typed as amount + days/weeks/months but stay stored as days (no migration; a month = 30 days, so "3 Monate" = 90). Why: the QA found no place that said "you missed it", but a red alarm would be guilt text (FOCUS-GUIDELINES).
- 2026-10-30 **Currency per account and invoice, no conversion** – optional ISO 4217 `currency` (none = EUR; manifest version 3, nothing rewritten). Finance shows one currency at a time, sums never mix, "available" deducts invoices of that currency only; subscriptions and budgets stay euro. A paid invoice books to the first account of its currency (an account named after the code is created if none).
- 2026-10-30 **Currency on subscriptions, budgets and goals** – same optional `currency` as accounts/invoices (subscriptions v3, budgets v2, no-op migrations). Subscription totals are per currency (euro first); finance's "available" deducts only subscriptions of the account's own currency (`listSubscriptionCharges(from, to, currency)`); a budget's spending counts only accounts in its currency (`expensesByCategory(month, currency)`); goals and their deposits share the goal's currency. Still no conversion anywhere.
- 2026-10-31 **Bank import without a schema change (T2):** formats by content (OFX before CAMT); bank layouts are data (`BankCsvLayout`, `finance/bankPresets.ts`), a preset and a remembered column assignment are the same thing. Dedupe key unchanged (+`#n`); FITID only drops repeats inside one file. Assignments and rules in `_meta` (device-local, do not sync; no schema/settings change). Importers get an additive `slot` (+`extras`, `legacyEncoding`); `ImportPreview.tsx` untouched; rule chips reuse the `warning` badge. [bank-import](../features/bank-import.md)
- 2026-10-31 **Rules only from suggestions:** never silent, default off, ≤ 5 lines per import, only for payees with a subscription of the user, a provider from the shipped list (no second list) or ≥ 2 earlier bookings in one category; the rule is written after "Importieren"; declined ones are not remembered; removing a rule changes no booking.
- 2026-10-31 **Paid invoice → booking keeps default on** (the booking existed unconditionally; default off would remove behaviour); skipped with a repeating booking of same payee and amount. **"Preis erhöht"** = one accent notice (not red) for rises of the last 30 days, 3 days from first sight, then never (`_meta`); both have a setting.
