# Decisions – shell and navigation areas

Index: [DECISIONS](../DECISIONS.md). Tokens and brand: [ui-brand.md](ui-brand.md).

## Design "Klar 2" – shell and areas (2026-10-02, PR `feat/design-shell`)

- **Areas are navigation only.** `ModuleManifest.area` (required, validated) groups modules for sidebar, rail, bottom nav and the tab row above module pages; modules stay separate in code and data, paths stay (`/finance`, `/todos`, …) so deep links, notifications, PWA shortcuts and E2E keep working. Area pages (`/planen`, `/geld`, `/haushalt`, `/wissen`, `/tresor`, `/geraet`) have no content: they redirect to the module last used in the area (`tm-area-last`, device-local), else the first by `order`. The System area is `/geraet`, so it does not collide with the former `/system` path (now a redirect to `/disk?tab=system`).
- **Assignment** (since 0.4.0): plan = calendar, todos, people · money = finance, invoices, subscriptions, budgets, contracts · household = shopping, pantry, packing, gifts · knowledge = notes, bookmarks, launcher · vault = accounts, vault · system = disk ("Dieser PC"). Retired modules (habits, news, timetrack) have no area. An area without an enabled module is hidden; later packages move modules (e.g. Erinnerungen into Kalender) by editing `area` only.
- **Favourites:** max 5, synced (`_settings` scope `nav`, `favourites: string[]`, unset = Kalender, ToDos, Finanzen), toggled by the star on sidebar items (hover/focus) or the switch list in Einstellungen; disabled modules are filtered at read time. Sixth favourite is refused with a toast.
- **Shell:** sidebar 248 px (Heute, Favoriten, collapsible Bereiche, Bibliothek, Einstellungen) or 76 px rail (areas as icon + label, Werkzeuge, Einstellungen); the rail is automatic below 1200 px and a user choice above (`tm-sidebar`, Einstellungen → Darstellung). Top bar: search, one filled "+ Neu" (desktop; the FAB exists only below 900 px), Werkzeuge with label. Bottom nav: Heute + the first three areas + Mehr (rest of the areas, Werkzeuge, Bibliothek, Einstellungen).
- **Master–detail** from a 1200 px viewport (was 1500); panel `clamp(22rem, 30%, 30rem)`, 32 rem from 2200 px. Modules adopt `SplitView` per module in the design-5 PRs.
- **Page switches** crossfade for 120 ms (no slide); the full motion pass stays Phase 6.

## Module identity (2026-11-02, PR `feat/module-identity`)

- **Chosen look: "Plättchen" plus edge.** The maintainer picked variant A (icon chip in the module hue) and added the 4 px left edge of variant C: both on widget cards, the module frame (`AreaFrame`) and the calendar's today column; the active navigation icon takes the hue, the text keeps the accent. Area colours stay only on group heads. No tinted header bands, no per-module motifs.
- **Contract:** `ModuleManifest.identity: { hue, widgetType }` is required (`validateManifest`, `check:modules`, generator template). `hue` comes from the fixed ten-hue palette `--mod-*` (light + dark; ≥ 3:1 on the surfaces, ≥ 25° of hue away from danger/accent/warning/success so a module colour can never read as a state; slate is the grey). `widgetType` names the catalogue base type of the main widget. No two modules of one area share a hue (registry test).
- **Application through tokens only:** `data-hue` on a widget card, a module page (`PageContainer`) and a nav item sets `--module-color`; inside it the first chart series follows the module. Semantic colours keep priority: urgency stripes and badges are unchanged and sit inside the card, the edge sits on its border.
- **Off switch:** Einstellungen → Darstellung → Farben → "Modulfarben" (`tm-module-colors`, `data-module-colors='off'`) and the "Ruhig" mode both turn every hue into `--text-3`; chip, edge and icon stay, so the module is still recognisable without colour.
- **Cockpit figures from modules:** `contributions.headline` (one formatted figure per module; finance = balance) feeds the cockpit's "Großanzeige" with the module's chip and edge.

## Module identity v2 (2026-11-03, PR `feat/module-shell-identity`)

- **Supersedes v1's "no tinted header bands, no per-module motifs".** The maintainer picked variant **B** of three (A subtle, B pronounced, C between; mockups in `docs/design/identity-v2/`): a tinted head with a gradient in the module hue, the content stays neutral. v1's chip and edge remain the fallback for the "Ruhig" mode.
- **One frame for every module** (`layout/AreaFrame.tsx`): the head carries chip, area, tabs, the page's h1 (`PageHeader`/`PageTitle` portal into it; no module has an own head), headline figure or signature and the gear; slots `notice`, `backdrop`, `figure`, `extra` (`@/ui/identity` `HeroSlot`). Dialogs only for short tasks. On the phone the head is sticky and folds to one line after 96 px (`core/shell/heroCollapse.ts`).
- **Contract:** `identity` gains required `head` (`figure|cover|compact`), `surface`, `signature` and optional `hue2`, `type`, `shape`, `feedback`; validated by `validateManifest` + `check:modules`. The empty-state motif is the signature in grey (no own field). Hues stay ten (the planned extra hues were not needed: weather = indigo, music = orchid).
- **Colour rules:** text on a tint is always `--text` (AA for every hue and theme, `tokens.test.ts`); the tint is 40 % → 10 % of the hue over `--surface` (`--head-tint-*`); "Ruhig" and "Modulfarben: Aus" flatten it to 12 % / 5 % and grey the hue; a dynamic colour (cover) goes through `safeTint` at run time; the sky has its own tokens and a night ink.
- **Navigation:** the active sidebar entry is tinted in the hue (icon in the hue, text `--text`), a 3 px stripe in the hue runs along the sidebar edge; widgets get a tinted head band (65 % of the head tint) with the icon chip.
- **Weather and music are modules** (`weather` in Planen, `music` in Wissen), no longer features of the overview: the dialogs, the overview line "Wetter", the "Läuft gerade" card and the `core:nowplaying` switch are gone; the widgets show only today / what plays, the page has the rest. `music` is `preview` like its connector and off by default, but the connector (`ConnectorDef.enablesModule`) switches it on once when Spotify is first connected, never against an explicit choice (`enableModuleIfUnset`); `weather` is on by default. No collections, `seed.none: 'live-data'`, `dataApi: false`.
- **Weather hints** (`modules/weather/warnings.ts`) are computed from the forecast days (thunderstorm, gusts ≥ 70 km/h, ≥ 20 mm, ≥ 32 °C, ≤ −5 °C), not official warnings, and say so. **More places:** settings `weather.extra` (≤ 2, optional, older stored settings keep working), forecast of an extra place kept per session only.
- **Music without a device:** the head offers the devices ("Hier abspielen"), the Spotify app (`spotify:` link; in the desktop app the platform opens it through a scoped opener grant, PR `feat/spotify-app-link`; in browsers and on Android the OS handles it) and the web player (`open.spotify.com` through `openUrl`); Premium note only without "Steuern".

## Cockpit mode (2026-11-01, PR `feat/cockpit-mode`)

- **A shell flag, not a route.** `cockpit` lives in the UI store (device-local, remembered; "Mit Cockpit starten" optional). The shell drops its chrome and renders the overview as the background; every other path shows in a panel on top with the router as the single source of truth (`navigate('/')` closes it), so deep links, quick capture targets and `?new=1` keep working and no module is rendered twice.
- **Own layout scope** `cockpit` in `_settings` (same schema as `home` plus `dense`, `stats`); the overview's arrangement is never touched from the cockpit.
- **Keys:** F10 is the rebindable `cockpit` F-key action; the settings page gave up its default F10 (all seven assignable keys were taken; Ctrl+K "Einstellungen" stays one keystroke away). Esc closes the panel first, then the cockpit, never while a dialog is open. F11 asks the platform for real full screen only inside the cockpit.
- **Big figures from core only** (clock, next appointment, "Jetzt wichtig" count); module figures such as the balance wait for a `contributions.headline` in the identity package, so the manifest contract changes once.
- **Platform:** a separate `DisplayService` (full screen, Android immersive, keep-awake) instead of widening `ScreenService` (screenshot protection stays untouched); Android gets its own tiny `screen-mode` plugin.

## Settings: categories and registry (2026-10-02, PR `feat/settings-overhaul`)

- **Registry instead of a page.** Every setting belongs to a _section_ with a _category_ (`core/settings/registry`). The page, the search, the palette commands ("Einstellung: Hotkey") and the deep links all read that list, so nothing can be added "at the bottom"; a section without a valid category fails `registry` tests and `check:modules`. Module settings keep their schema/keys (`pages/settings/inventory.test.ts` pins every key and default); the manifest may choose another category (`accounts` → Sicherheit). Restructuring is presentation only: no key moved, no migration.
- **Routes:** `/settings/<category>#<section>[--<field>]` (`settingsPath`), old `/settings#sync` anchors are redirected. Page width `content` (list 16 rem + 44 rem), master–detail from 900 px. **Phone: category list as the first level** (icon + one line), then the content with a back link; this replaces the chip row of the first design spec. A category without a visible section (e.g. Entwickler in a stable build) does not exist.
- **Palette:** settings commands only appear once the query starts with "einst…", otherwise long setting labels would take Enter away from natural-language questions to the assistant. _(Superseded 2026-10-11, see "Settings comfort".)_
- **Über Nemo** shows one source (`core/about/info.ts`): version, build date + commit (`vite` define), channel, platform, install kind, data folder (desktop commands `desktop_data_dir`/`desktop_open_data_dir` take no argument, the app decides which folder), changelog of this version (build-time extract of `CHANGELOG.md`), generated licence list (`npm run gen:licenses`, test keeps it current), links, diagnostics export (in-memory error log, last 50 entries, shortened and redacted, no stack traces, no data folder path, no settings values or secrets).
- **Danger zone:** "Alle Daten auf diesem Gerät löschen" asks twice (the second "yes" only works 0.6 s after "Bist du sicher?" appears, so a double click is not two confirmations; typing `LÖSCHEN` was dropped on the maintainer's request, 2026-10-13, same as for disk deletes); it removes the database, the device's secrets (AI keys, backup password, connector secrets by name) and `tm-*` preferences, then reloads. Server data and backup files stay. Secrets that cannot be enumerated (none known) would survive in the keystore.

## Settings comfort (2026-10-11, PR `feat/comfort-settings`)

- **Palette finds settings without a prefix** – hits come from the registry search (all words must match, synonyms and keywords included), at most 5, listed after the assistant entries, so Enter on a question ("offene Rechnungen") still asks the assistant (quick-switch commands like "Farbschema: Dunkel" are commands and come first); "Einstellung …" still works as a lead-in word. Replaces the "einst…" rule above.
- **Quick switches are an allow-list** (`core/settings/quick.ts`: theme, density, reading aid, colour mode, home view) – a palette command per value and a bar at the top of Settings, always with a toast that undoes it. Nothing security related can be listed (tested). Fewer ways, not more options: no new setting was added.
- **"Häufig genutzt" is device-local and shares the existing switch** – "Verlauf in der Suche" turns it off and "Verlauf löschen" empties it; no new option, nothing synced. A section needs two visits.
- **Reset per section is opt-in** (`SettingsSectionDef.reset`): look, reading aid, focus aids, calm reminders. Undo toast instead of a dialog. Keys and defaults stay untouched.
- **Context gear** (`SettingsLink`) in the module header and widget head: with a mouse it shows on hover/focus (stimulus load), on touch it is always visible. Deep-link schema `nemo://…` is internal only; no OS handler (attack surface, platform work).
- **"Stumm"** is decided separately, see [focus.md](focus.md) ("Stumm: a pause, not a switch-off").

## Library comfort (2026-10-13, `feat/comfort-library`)

- **One card for both libraries** – `@/ui` `LibraryCard` (icon, name, badges, description, actions, deep-link anchor) is used by the module and the tool library; search matches name, description and the module's settings words (so "Abo" or "Rechnung" find the module by purpose).
- **"Neu" / "Aktualisiert"** is device-local (`tm-library-seen`, `core/modules/librarySeen.ts`): nothing on the very first look, later a new module or a higher `version`; the mark goes once the library was looked at. No counter, no nag.
- **Start data on the card** of an enabled module (same button as in Settings); the card has a switch (`role=switch`, "<Name> einschalten") instead of enable/disable buttons. Switching off a module **without data** (`moduleHasData`) needs no dialog – a toast offers undo; with data the keep/delete dialog stays. E2E uses `moduleSwitch(card)` from `e2e/helpers.ts`.
- **Not done:** preview widget in the card (stimulus load), navigation order by drag and drop (favourites keep their buttons).

## Toolbox comfort (2026-10-13, `feat/comfort-toolbox`)

- **Tools answer in the search bar** – optional `ToolManifest.expression` (pure, cheap parse): "timer 10m" starts a countdown, "umrechnen 5 km" lists conversions and Enter copies; only while the tool is on; local, nothing sent. The calculator keeps its own path (`core/calc/phrases.ts`).
- **"Zuletzt benutzt" row above the tiles, the tiles never move** – up to three tools used last (`tm-tools-recent`, device-local, off with "Verlauf in der Suche", emptied by "Verlauf löschen"), shown once more than four tools are on. A grid that reorders itself costs more than it saves.
- **Tool library on the shared `LibraryCard`** with search; "copy result" in the unit converter.
- **Tool order by drag and drop** in Einstellungen → Werkzeuge via the shared `@/ui` `SortableList` (dnd-kit, same sensors and screen-reader texts as the home widgets); the up/down buttons stay as the plain alternative. Keyboard: Space, arrows, Space.
- **Not done:** pinning the popover open (the toolbox is a dialog; a second window needs platform work), detachable/always-on-top tool windows and a background timer on Android (platform; see ROADMAP).

- **Palette key caps are not part of the option name (2026-10-24):** `<Keys decorative>` sets `aria-hidden` inside `role="option"`, so the name is the label only ("Timer", not "Timer T dann T"); the key is not repeated in a hidden text because the `?` sheet lists every key. The voice key sorts among the F-keys there when it is an F-key.

- **Phone header: content before chrome (2026-10-31):** below 900 px `AreaFrame` is one grid line (area label, scrollable tabs ≥ 44 px, actions), the page title is one step smaller (`--text-2xl`), and the topbar folds away on scrolling down > 48 px (transform/opacity, `--dur-fast`) and returns on scrolling up, at the top, on keyboard focus in the bar, or while a palette/dialog/on-screen keyboard is open. With less motion (system or in-app) it stays fixed; no new setting. Pure decision in `core/shell/topbarCollapse.ts`. `pageChrome.advancedInMenu` lets a page with a "⋯" menu take the "Erweitert" switch out of the header; the six pages without a menu keep it next to the title. Dev `SeedBanner` is one dismissible line.
- **Planen group, package 1 (2026-11-03, `feat/plan-calendar`):** holidays are computed (`calendar/holidays.ts`, Easter algorithm + rule table), never fetched, and off by default (`holidayRegion`); regional community holidays are left out rather than guessed. A removed single occurrence of a recurring event is `exdates` on the event (`manifest.version 3`, no data rewrite; `expandEvent` and the notification source honour it). Overlaps are marked by a dashed edge plus text, not by colour. Habits and Zeiterfassung return as new modules in later packages (reversal of the 2026-10-01 retirement, new collection names).
- **Calendar depth (2026-11-03, same package):** named calendars are a collection of their own (`calendar_calendar`, db v27) with a palette index, never a free hex colour; hidden = filtered in the item source, not deleted. Drag editing is pointer + `Alt+arrow` with 15-minute snap, own single-day events only; series stay in the editor so "only this one / all" remains a deliberate choice. The reminder time ring reuses `Ring` and never animates.
- **ToDos depth (2026-11-03, `feat/plan-todos`):** the four views are computed from the dates, not stored (only `someday` is a flag); an undated open task counts as "Irgendwann", a future `startDate` puts a task under "Demnächst". Board moves write dates through `movePatch` and tick through `setDone`. Projects are lists with `kind: 'project'` (no new collection); links store only id + title and are filled through the event bus (`todo.requested.link`). The view bar uses touch-size chips instead of the shared `Segmented` (32 px on desktop would break the 44 px target test).

- **Settings v2, package 1 (2026-11-03):** `/settings` is an overview of eight status cards (one line of state, one context line, a jump); the category list stays as the left column (desktop) or below the cards (phone). Sub-groups are the second navigation level (`registry/groups.ts`; a section names its `group`, core sections are placed in that file; ids and texts in `strings.settings2.ts`); a breadcrumb sits in the content (wide), a table of contents on the right from 1440 px. A module's settings are a page of their own, `/settings/module/<id>`, with the fixed blocks General · Display · Notifications · Data · Advanced, placed by the optional `SettingField.group`/`level` (unknown values fail `check:modules`); module identity in the head is the chip and edge in the module hue only. `settingsPath('module', 'module-<id>', field)` and the old `#module-<id>` anchors lead there. This supersedes "no Erweitert" for the settings (comfort plan 05): the Erweitert fold per category follows in package 2. No new tokens or `@/ui` components (Breadcrumb and a disclosure are proposals, built locally in `pages/settings/`). Keys and defaults are untouched (`inventory.test.ts`).
