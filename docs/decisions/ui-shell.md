# Decisions – shell and navigation areas

Index: [DECISIONS](../DECISIONS.md). Tokens and brand: [ui-brand.md](ui-brand.md).

## Design "Klar 2" – shell and areas (2026-10-02, PR `feat/design-shell`)
- **Areas are navigation only.** `ModuleManifest.area` (required, validated) groups modules for sidebar, rail, bottom nav and the tab row above module pages; modules stay separate in code and data, paths stay (`/finance`, `/todos`, …) so deep links, notifications, PWA shortcuts and E2E keep working. Area pages (`/planen`, `/geld`, `/haushalt`, `/wissen`, `/tresor`, `/geraet`) have no content: they redirect to the module last used in the area (`tm-area-last`, device-local), else the first by `order`. The System area is `/geraet`, so it does not collide with the former `/system` path (now a redirect to `/disk?tab=system`).
- **Assignment** (since 0.4.0): plan = calendar, todos, people · money = finance, invoices, subscriptions, budgets, contracts · household = shopping, pantry, packing, gifts · knowledge = notes, bookmarks, launcher · vault = accounts, vault · system = disk ("Dieser PC"). Retired modules (habits, news, timetrack) have no area. An area without an enabled module is hidden; later packages move modules (e.g. Erinnerungen into Kalender) by editing `area` only.
- **Favourites:** max 5, synced (`_settings` scope `nav`, `favourites: string[]`, unset = Kalender, ToDos, Finanzen), toggled by the star on sidebar items (hover/focus) or the switch list in Einstellungen; disabled modules are filtered at read time. Sixth favourite is refused with a toast.
- **Shell:** sidebar 248 px (Heute, Favoriten, collapsible Bereiche, Bibliothek, Einstellungen) or 76 px rail (areas as icon + label, Werkzeuge, Einstellungen); the rail is automatic below 1200 px and a user choice above (`tm-sidebar`, Einstellungen → Darstellung). Top bar: search, one filled "+ Neu" (desktop; the FAB exists only below 900 px), Werkzeuge with label. Bottom nav: Heute + the first three areas + Mehr (rest of the areas, Werkzeuge, Bibliothek, Einstellungen).
- **Master–detail** from a 1200 px viewport (was 1500); panel `clamp(22rem, 30%, 30rem)`, 32 rem from 2200 px. Modules adopt `SplitView` per module in the design-5 PRs.
- **Page switches** crossfade for 120 ms (no slide); the full motion pass stays Phase 6.

## Settings: categories and registry (2026-10-02, PR `feat/settings-overhaul`)
- **Registry instead of a page.** Every setting belongs to a *section* with a *category* (`core/settings/registry`). The page, the search, the palette commands ("Einstellung: Hotkey") and the deep links all read that list, so nothing can be added "at the bottom"; a section without a valid category fails `registry` tests and `check:modules`. Module settings keep their schema/keys (`pages/settings/inventory.test.ts` pins every key and default); the manifest may choose another category (`accounts` → Sicherheit). Restructuring is presentation only: no key moved, no migration.
- **Routes:** `/settings/<category>#<section>[--<field>]` (`settingsPath`), old `/settings#sync` anchors are redirected. Page width `content` (list 16 rem + 44 rem), master–detail from 900 px. **Phone: category list as the first level** (icon + one line), then the content with a back link; this replaces the chip row of the first design spec. A category without a visible section (e.g. Entwickler in a stable build) does not exist.
- **Palette:** settings commands only appear once the query starts with "einst…", otherwise long setting labels would take Enter away from natural-language questions to the assistant.
- **Über Nemo** shows one source (`core/about/info.ts`): version, build date + commit (`vite` define), channel, platform, install kind, data folder (desktop commands `desktop_data_dir`/`desktop_open_data_dir` take no argument, the app decides which folder), changelog of this version (build-time extract of `CHANGELOG.md`), generated licence list (`npm run gen:licenses`, test keeps it current), links, diagnostics export (in-memory error log, last 50 entries, shortened and redacted, no stack traces, no data folder path, no settings values or secrets).
- **Danger zone:** "Alle Daten auf diesem Gerät löschen" needs the typed phrase `LÖSCHEN`; it removes the database, the device's secrets (AI keys, backup password, connector secrets by name) and `tm-*` preferences, then reloads. Server data and backup files stay. Secrets that cannot be enumerated (none known) would survive in the keystore.
