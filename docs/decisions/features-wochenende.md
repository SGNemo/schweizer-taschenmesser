# Decisions in full – features – use case „Wochenende retten“

Part of [features](features.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Use case „Wochenende retten“ (2026-11-14, maintainer answers in `docs/design/usecases/wochenende/TARGET.md` §5, packages in `PACKAGES.md`):** (1) one entry „Tage einteilen“ – a sheet in three steps (things → time per day as chips → planner preview → take), reached from the welcome card and the empty planner, switches the planner on only on tap and never switches a module off; (2) the order of a day is said with optional day parts Vormittag/Nachmittag/Abend per plan item (planner's own row and `core/plan` only, no `plannable` change; the engine orders inside a day only, a part never changes the day), a break is a blocker that shows its own length and is never totalled, summed across days or rated; (3) sleep is a planner „Tagesende“ (optional per weekday group, caps the day's capacity, things that do not fit move on; an in-app head line near the end, no notification), no sleep data, no habit code (a habit „Ins Bett bis …“ is only pointed to); (4) Sunday/Monday reminders: only what the person sets, once at its time, never repeated – every reminder made by the quick capture or the planner field carries „einmal“ (calendar field `once`, visible on the row), a timed line becomes a reminder only with a trigger word („erinnere mich“, „falls nötig“, „ggf.“); the deadline reminder „1 Std vorher“ is opt-in per deadline; reminders set in the calendar dialog keep the global repeat rule. Health: the app stores only the typed title, no field, category or inference. Not now: a shared Google OAuth client (W15), auto-enabling time tracking (W14), WhatsApp access.
