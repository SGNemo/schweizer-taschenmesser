# Decisions – modules and tools – Dieser PC, app migrations, Unterlagen

Part of [modules](modules.md). Index of areas: [DECISIONS](../DECISIONS.md).

## Dieser PC

- **2026-10-02 – more facts, same rules.** Drive cards (type, interface, model, health/temperature, history), quick overview and live system tiles stay read-only and local. Health, temperature and history are **session-only**: Windows data is read on demand with access 0 (no admin), "nicht verfügbar" says why; the history for sparklines and "belegt seit letztem Scan" is kept in memory only (`history.ts`, `live.ts`) – no collection, no `_meta` row, nothing synced or backed up. The block list, plan/confirmation and recycle-bin-first delete are untouched; the recycle bin is only measured (emptying stays in Explorer). The public IP is asked for **only on a click** (`api.ipify.org`, noted next to the button, answer shown not stored) – the one deliberate exception to "no request", and it never runs on its own. GPU detection merges DXGI with the display-class registry key so the Basic Render Driver is never shown instead of the real card. Android keeps no Dieser PC (a mobile variant is in the ROADMAP).
- `disk` is "Dieser PC" with tabs Laufwerke · System (`?tab=`). Widgets `disk:status` and `disk:system`. Still no data, no aiSchema, blocked twice for the data API (`BLOCKED_MODULES` no longer lists `system`).
- Disk clean-up uses the **last change** (newest file in a folder), never the last access: Windows does not keep access times reliably. Age buckets (< 1 month … > 3 years) are computed in Rust per node (`ageBytes`) relative to the scan start; the map is coloured by age by default; "long unchanged" lists each old folder once (`topmost`) so sums never double count. Deleting from that list goes through the same plan, block list and confirmation as everything else.
- **2026-10-13 – "Zuletzt gespielt" for Steam games.** The change date says little for games (updates reset it, playing does not), so the scan reads Steam's own text files – app manifests and each user's `localconfig.vdf` – and takes the newer `LastPlayed`. Read-only and on request only; matched to install folders inside the scan by node id, never a free path; no date = "Kein Spieldatum von Steam" (no guessing). The list hints that uninstalling in Steam is cleaner than deleting the folder.
- **2026-10-13 – "Zuletzt geöffnet" only where Windows keeps it.** The scan collects the newest file access per node anyway (no extra syscall), but the UI offers "Gemessen an: letztem Öffnen" and the details row only when the volume is NTFS and `NtfsDisableLastAccessUpdate` has updates on; elsewhere the date might just be the copy date, so it is hidden rather than shown with a caveat. Folders' own access times never count (the scan itself touches them). The help text says virus scanners/thumbnails can make a file look newer, never older – the safe direction for clean-up.
- **2026-10-13 – age = last use where Windows keeps access times** (maintainer's call: "dann ist es wirklich die letzte Benutzung"). On trusted volumes the scan buckets ages by the newer of access and change (`tree::last_use`, same rule in `logic/age.ts`), the map/legend/details say "Benutzung", and "Lange nicht benutzt" measures by opening by default (switch to change stays). Untrusted volumes keep the change date unchanged – no guessing from a copy date.
- **The disk map fills up while the scan runs** (like SpaceSniffer): the walk adds what each folder holds to a small live tree of the top two folder levels (`crates/disk-scan/src/live.rs`, one short lock per folder; 1 M files still scan in < 1 s on 4+ cores); the page polls `disk_scan_live` every 0.5 s and draws it read-only. Opening, selecting and deleting stay with the finished tree, so the delete path never sees half-counted sizes.
- **2026-11-05 – the running scan blocks nothing and shows what it knows.** One status line (Pause, Abbrechen; a new figure at most once a second) replaces bar, counters and path, and the drives page shows the same line while a scan runs. The live picture is **polled** (`disk_scan_live`, 1.5 s, only while the scan page is open, canvas-derived `minBytes`), not pushed: measured 0.02–0.13 ms and 55–70 KB per poll at `LIVE_DEPTH` 2 against 0.4–2.2 MB (1–4 ms parse) per pushed snapshot without canvas knowledge, so no new command or capability. Each live node carries `pending` until its walk returns (the finished tree never does); pending shows as text and shape, never colour alone. Deleting still needs the finished tree. Numbers: [features/disk-live-scan.md](../features/disk-live-scan.md).
- **2026-11-05 – drive cards show the core, the rest folds.** Maintainer feedback on the drives page (cluttered, uneven cards): a card is ring · name (+ Systemlaufwerk badge) · one numbers line · one advice line · one muted kind line (model · type · file system) · last scan · Scannen; health, temperature, session history and the live read/write rate wait behind a native `<details>` "Details". Two equal-height columns from 56 rem. The module's scan shows its state in its drive's card (the line above the grid stays only for clean-up places). The quick overview is one list (name · hint · size · Scannen) instead of five cards. No tokens, no head: the `fortschritt` head with the drive-ring signature stays package 3 (`feat/identity-v3-disk`) after the v3.1 foundation.

## App migrations and Listen (0.5.0)

- **Runner** (`core/db/appMigrations.ts`, steps in `appMigrationSteps.ts`): copies rows between collections with the source HLCs (1:1 fields keep their stamp, derived fields get the row's newest stamp, made-up rows `BASE_HLC`) via `applyRemote(…, { markDirty: true })`. Every device writes identical ops, so a second run, a second device or a sync echo changes nothing; edits of the target win; an edit of the source on a not-yet-updated device flows in on the next run. Tombstones are copied, sources never deleted. Not `createRepo.create` (fresh stamps per device would diverge).
- **Triggers:** end of `initCore`, after a sync pull that applied rows, after a backup import (`restamp` after "replace" so copies beat the tombstones the restore left). Serialised, errors swallowed (retry next run). Marker `_meta` `app.migrations.<id>` is informational only.
- **Steps:** `shopping_item` → `lists_item` (list `shopping-default`, made up with `BASE_HLC`, a tombstone counts as existing), `packing_list` → `lists_list`, `packing_item` → `lists_item` (`packed` → `done`), `launcher_link` → `bookmarks_item` (`kind: link`, `tags: [group]`).
- **Listen** (`lists`): kinds shopping | packing | checklist; the `shopping.requested` event stays (Pantry checks `moduleStates.lists`); quick capture type "Einkauf" (`l`). **Lesezeichen** are not a module but a view (`?view=links`); the eight launcher presets are gone, mailto:/tel: links are re-saved as http(s) only. Old paths redirect (`LEGACY_REDIRECTS`).
- Old devices keep writing the old tables (no backward sync): all devices must update.

## Unterlagen and Personen (0.6.0)

- **Unterlagen** = `vault` + contracts: `document` gets `category 'warranty'`, `provider`, `startDate`, `endDate`, `noticeDays`; `expiresOn` stays readable (`endOf`), is never written, and the module migration v2 renames it. One status function (`act-now`/`expired`/`soon`/`ok`/`open-ended`: deadline within 30 days, end within 60 days without a deadline). Two reminder leads (`remindDaysBefore` 30, `remindDaysBeforeDeadline` 14); a service carries the old `module.contracts` lead over once.
- **Personen** = `birthdays` + `gifts`: `person {name, birthday?, note, tags}` and `gift {personId, …}`; `aiSchema` for `person` only (gifts are surprises). Birthday notification keys keep the `birthday:<id>:<date>` form. Settings of `module.birthdays` are carried over once.
- **Steps:** `contracts_contract` → `vault_document` (`kind` → `category`), `birthdays_birthday` → `people_person`, `gifts_idea` → `people_gift`. A gift joins the person (former birthday, smallest id) with the same name (trimmed, lower case, one space); otherwise a person `person-<slug>` is made up (`ensure`, `BASE_HLC`), named after the first spelling. No fuzzy matching. A gift migrated before its birthday has synced keeps the made-up person (rare, left as is).
- Runner gained `prepare(database, rows)` and `ensure(rows, ctx)` for steps that read other tables.
