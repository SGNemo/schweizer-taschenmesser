# Decisions in full – Phone with one hand (2026-10-24)

One-line summary: [DECISIONS](../DECISIONS.md) → UI section. Split from [focus.md](focus.md) (budget). Results: [12-results-2.md](../product/focus/12-results-2.md) → "Mobile".

- **Phone with one hand (`feat/phone-one-hand`):** decided without asking, calm variant, no new element, no new route.
  - **Back closes what is open first.** `core/shell/backStack.ts` keeps one `history.pushState` marker per open `Dialog`/`RowMenu` (by id, never twice). A button close removes the marker again (`history.back()` only when ours is on top); a marker left behind by a route change is stepped over. A dialog with a draft asks first, a second Back at the question means "keep editing" (Back never discards by itself). Rejected: a Back stack inside the router (`AppShell`/`router.tsx` stay untouched).
  - **Keyboard.** The page already resizes with it (`interactive-widget=resizes-content`); `visualViewport` is only the fallback: `--kb-inset` lifts bottom sheets, a focused `data-keep-visible` add field is scrolled into view (no animation). ToDo and capture fields keep the focus after saving.
  - **Thumb zone.** The footer of a phone sheet is sticky at the bottom edge (main action bottom right); a row menu opens upwards when there is no room below it (above the bottom bar).
  - **Measured.** Ten paths in `e2e/phone-paths.spec.ts`: no path has more steps than before; stimulus inventory and touch-target gaps unchanged (0).
  - **Editors ask after typing (2026-10-29).** `Dialog askAfterTyping` (notes, ToDo editor, quick add) notices typing itself: an empty editor closes at once on Back/Esc/backdrop, one with typing asks "Entwurf verwerfen?" once; Back at the question = keep editing. Explicit "Abbrechen" and a successful save are unchanged. No stored value, no new element. Rejected: lifting every editor's field state into a `dirty` flag (many files, same effect).

- 2026-11-23 **Nothing on the lock screen by default; secrets marked in the clipboard (security package 9, NS6, NS8):** a notice's own `visibility` never reaches Android (the notification plugin's Rust `NotificationData` drops it), so the **channel** decides: by default every Android notice (Android 8+, which has channels; on 7.x Android's own setting still decides) goes through `nemo-hidden` / `nemo-quiet-hidden` (no vibration, as the plugin's default) (lock screen "secret": nothing shown; in the shade after unlocking). Settings → Notifications → "Inhalt auf dem Sperrbildschirm zeigen" (Android only, device-local `tm-lock-screen-content`, off) switches to the plugin's `default` channel / the older `nemo-quiet` (Android's own lock-screen setting decides); a change rebuilds the scheduled alarms. Our channels sound as notifications, the plugin's default as an alarm (Do Not Disturb may differ). Secrets reach the clipboard through `writeSecret` (sensitive flag on Android 13+, no history/cloud clipboard on Windows; only a hint on Linux/macOS). NS5 stays a proposal (protected path).
- 2026-11-23 **No device-to-device transfer of Nemo's data (NS5):** next to `allowBackup="false"` the generated manifest points at `data_extraction_rules.xml`, which excludes every domain from cloud backup and device transfer (Android 12+ ignores `allowBackup` for the transfer). Moving to a new phone goes through Nemo's own encrypted backup.
