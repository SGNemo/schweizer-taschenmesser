# Decisions – modules and tools – maturity, importers, default set

Part of [modules](modules.md). Index of areas: [DECISIONS](../DECISIONS.md).

- 2026-10-31 **Maturity `stable | preview` (T3)** – a required field on modules, tools, widgets (tightening only) and settings sections; `preview` hides in catalogues until "In Arbeit anzeigen" (device-local, off), never routes, data, enabled modules/tools, pinned widgets or sections in use (`previewInUse`). Decided without asking: the filter sits next to `availableManifests()` (`catalogManifests`), not inside it, so routes, seed, sync and the AI scope keep an enabled preview module; the switch lives in Darstellung → "Mehr Felder anzeigen" (the only "Erweitert" section); `defaultEnabled` stays "off but listed"; setup steps (T1's files) keep listing everything until a follow-up.
- 2026-11-03 **Importers for other apps (`feat/importers`):** sources are plain-data units in `web/src/importers/<source>/` (detect + targets + pure parsers); they plug into the existing per-module wizard instead of a second preview/commit path, so duplicates, batch id, undo and the report stay in one place. A multi-part export (Takeout) runs one wizard per module under one `groupId`. Unpacking and heavy parsing run in a Worker (`fflate`, small dependency) and a cancel only drops a read – nothing is written before the preview is confirmed, and `commitImport` takes its own writes back on failure. Attachments are counted, never stored (notes hold text only). Vault CSVs (KeePass, 1Password) are mapping only in `accounts/csv.ts`; crypto and the unlock requirement are untouched. Microsoft To Do is read through Outlook's CSV because To Do has no export.
- 2026-11-04 **Notion import (`feat/importers-notion`):** read from the Markdown & CSV ZIP only (no API token, nothing leaves the device); a database becomes its row pages, the CSV table itself is counted as not supported rather than guessed into a module; the property block stays as plain text so no meaning is lost, links between exported pages become wikilinks.
- 2026-11-10 **Default set of a fresh installation is device-local, never a `_modules` row (`feat/ui4-v1-defaults`, UI audit package V-1, Sven: question 2 A and approval 2 of 2026-11-09):** a new installation starts with lists, budgets and (desktop app) downloads. `_modules` syncs, so a row written by a default would switch the module on for every device of the household by last-write-wins; the set therefore lives in `_meta` (`defaults.version`, written once when the installation is fresh, never raised; `defaults.off` only from the setup's profile step) and only fills the gap where no row exists (`core/modules/defaults.ts`, `resolveStates`). Every explicit choice writes a row as before and wins everywhere. Accepted consequences: a new device shows the set even if the household never used those modules, until someone switches one off (a household choice); an old device sees lists only after an explicit choice. Sync core, `applyRemote` and the LWW contract are untouched. Downloads is `stable` from here on (torrents stay opt-in). The test builds keep the set off by their build mode (`e2e`, `e2e-seed`), not by the variable `VITE_DEFAULTS_OFF` the spec names: same behaviour, and the protected `web/.env.e2e*` stay unchanged.
