# Decisions – shell – settings v2

Part of [ui-shell](ui-shell.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Settings v2, package 1 (2026-11-03):** `/settings` is an overview of eight status cards (one line of state, one context line, a jump); the category list stays as the left column (desktop) or below the cards (phone). Sub-groups are the second navigation level (`registry/groups.ts`; a section names its `group`, core sections are placed in that file; ids and texts in `strings.settings2.ts`); a breadcrumb sits in the content (wide), a table of contents on the right from 1440 px. A module's settings are a page of their own, `/settings/module/<id>`, with the fixed blocks General · Display · Notifications · Data · Advanced, placed by the optional `SettingField.group`/`level` (unknown values fail `check:modules`); module identity in the head is the chip and edge in the module hue only. `settingsPath('module', 'module-<id>', field)` and the old `#module-<id>` anchors lead there. This supersedes "no Erweitert" for the settings (comfort plan 05): the Erweitert fold per category follows in package 2. No new tokens or `@/ui` components (Breadcrumb and a disclosure are proposals, built locally in `pages/settings/`). Keys and defaults are untouched (`inventory.test.ts`).
- **Settings v2, package 2 (2026-11-03):** the "Erweitert" fold per category replaces the October "no Erweitert for settings": only rarely needed sections go behind it (`registry/meta.ts`), never help, diagnostics, reset, legal, sync, backup or anything that runs; its state is device-local per category (`tm-settings-adv`), default from "Alle Module Erweitert". The reset button shows only while a section differs from its default ("Vom Standard abweichend"); module fields reset one by one or all at once, always with undo. Each section says where its values live (device only / synced) as a text line. Previews live inside open groups, not at rest (stimulus budget). Security-relevant weaker choices get a calm note (`core/settings/warnings.ts`), no dialog. Missing one-sentence explanations of module fields are supplied by `strings.settingsHelp.ts` until the module writes its own.
- **Settings v2, package 3a (2026-11-03):** three sections under Allgemein → "Verwalten". **Profiles** switch an allow-list of look and reminder choices (`core/settings/values.ts`) in one step: three built-ins (Ruhig, Arbeit, Abends), own ones synced, schedules device-local and only while the app is open (a switch by hand holds until the next scheduled time); the active one is derived, not stored. **Export/import** is one JSON file the person handles, without the vault, supporter code, secrets, sync data or any web address; import validates every value, previews the count and the changes, and undoes in one step. **History** keeps the last 30 changes on the device (off with one switch), never from the vault, supporter, AI switch or secrets; a profile switch or an import is one entry. Security-relevant settings stay out of all three by construction (allow-list, pinned by tests). The settings split for the bundle stays after package 3, see the perf decision "Settings stay in the start bundle".
- **Settings v2, package 3b (2026-11-03):** **Alerts per module and channel** are a switch-off in the synced `focus` scope (`notifyChannels`), read in `collectDue` by channel (bell list vs. notice at the due time); `policy.ts` is untouched, the app's own notices always pass, and a module's own reminders stay visible in the module. **Storage** is a read-only page plus one safe action: emptying the runtime cache (`nemo-lazy-v1`), never the precache, never data. **Accessibility** is a category that bundles text size, motion, reading aid and the focus aids (Lesehilfe and Fokus moved from Appearance; old links follow). **Shortcuts:** the F-keys stay editable with conflict refusal; the shell's own shortcuts are listed as fixed and global hotkeys may not take them. Making the fixed shortcuts editable is not done: their handlers sit in the shell (`AppShell`, `useShortcuts`) and would need a rework of their own. The bundle split of the settings sections follows after this package.
- **Settings sections load when opened (2026-11-03, `feat/settings-split`):** the registry (`sections.tsx`: id, title, search words, order, visibility) stays in the start bundle, the section components are `lazyOnline` chunks (`pages/settings/sectionChunks.ts`); the one `render()` call sits in a `Suspense`. This replaces "Settings stay in the start bundle" (perf, 2026-10) for all sections except **Sync and Backup**, which stay eager because the offline sync E2E (and a person looking at a queued change without network) opens them without a service worker. Offline without the chunk: the calm `lazyOnline` note. A deep link keeps its target in view for 1.5 s while sections above it load (ResizeObserver, stops at the first wheel/touch/key). Critical path 667 → 612 KB gzip, 83 → 71 requests; budget re-baselined.
- **Settings search, package 4 (2026-11-03):** one index for the settings page and the palette (`registry/search.ts`). Sub-groups are found by name and open their first section; every hit shows its whole path ("Category › Group › Section", module settings add the page block: "Modules › To-dos › General"). A hit for one of the **quick switches** (`core/settings/quick.ts`, the same allow-list as the quick bar and the palette: theme, density, reading aid, colour mode, home view) carries the switch itself and changes the value without leaving the page; nothing else is switchable from a hit, security fields never (pinned by `search.test.ts`). Synonyms for the 3a/3b sections in five languages (`strings.comfort`, same keys check as before).
