# Decisions – Karten & Orte

- **Module, not a connector (2026-10-30):** places and routes are the user's own data (Dexie `maps_place`, `maps_route`, synced, no `aiSchema`), so it is a module with a widget; the map and search are services it calls on demand.
- **No map library:** a hand-drawn Web Mercator tile map (`logic.ts` + `TileMap.tsx`, about 300 lines, tested) instead of Leaflet / MapLibre: no new dependency, tiles stay under our network rules. Raster tiles of OpenStreetMap (light use, attribution shown); the tile URL is a setting so a heavy user can bring an own server. Vector tiles would need MapLibre and are left out.
- **Tiles as `blob:` URLs through the platform fetch:** the connection log and "Netzwerk sperren" apply and the CSP `img-src` stays strict. Memory only, 300 tiles.
- **Nothing is requested until the user opens the Karte tab or submits a search** (lists, widget, Overview make no request); first use shows the one-time notice (`maps` in `core/legal/notices.ts`, data flow `maps`, connection-log reason). Search is Nominatim-compatible, on submit only, one request per 1.1 s; coordinates are parsed locally.
- **Routes are saved ends + mode, opened in apps in package 1** (OpenStreetMap with the FOSSGIS engines per mode, Google Maps incl. stops and transit, Apple Karten); OpenStreetMap has no transit routing, so that entry is hidden for transit. In-app routing (package 2, OSRM) and public transport (package 3, Transitous/MOTIS) follow as own PRs.
- **In-app routing is one explicit click per route (package 2):** OSRM (FOSSGIS instances, per-mode profile in the URL, `routingUrl` setting) answers with distance, time, GeoJSON line and steps; the answer is shown, never stored, so there is nothing to sync or go stale. Own notice `maps-route` (it sends where you want to go, which is more than a tile request), reason "Karte und Ortssuche" in the connection log. Transit is not faked with a car route: it stays with the apps until package 3.
- **Public transport = Transitous (MOTIS), own notice `maps-transit` (package 3):** open timetable data, no key, replaceable by `transitUrl`. Connections start "now" (no date/time picker yet: calmer, one click, the apps cover planning ahead); stops on the way are not sent. Where Transitous has no data the card says so and points to the map apps instead of showing a made-up route. The package is stacked on #323 (`feat/maps-routing`).
- **Straight-line distance is labelled as such** ("Luftlinie etwa …") until real routing exists.
- **The native shell names itself to OpenStreetMap, the browser does not:** OSM's tile and search servers ask clients to identify themselves and refuse anonymous ones; the Tauri HTTP client sends no User-Agent. `maps/agent.ts` adds `User-Agent: Nemo (…)` only when `isNative` (in a browser a custom header would force a cross-origin preflight). A refused tile now shows its HTTP status in the calm "some parts could not be loaded" line. Not reproducible in the build sandbox (no network, no desktop shell): needs a hand test on the exe.
- **Own map, phase 0 = report only (2026-10-31):** the path to an own offline map from OSM data is laid out in [features/map-own.md](../features/map-own.md) (Overpass per Mercator cell → own MVT tiles in device-local collections `maps_region` / `maps_tile` (`local: true`) → own Canvas renderer on `logic.ts`; MVT so that MapLibre or prebuilt PMTiles could read the same data later). No app code before the maintainer's yes; the open questions (renderer, hosting path, source default, online fallback) are in the report.
- **Own map, answers (2026-10-31):** own Canvas renderer (no MapLibre), tiles as MVT, own PMTiles region files on an own host as the scaling path (package 4), `overpass-api.de` as the default source with an https URL setting, OSM raster tiles as the fallback outside built regions with a "Nur eigene Karte" switch. Packages 1–3 released ([features/map-own.md](../features/map-own.md)).
- **Own map, package 1 = store and draw (2026-10-31, `feat/map-own-tiles`):** tiles are Mapbox Vector Tiles written and read by `maps/own/mvt.ts` (no library), stored in the device-local collections `maps_region` / `maps_tile` (`local: true`: no sync, backup, data API or AI; id `z/x/y`, a newer build of an overlapping area replaces the tile and its `regionId`). `maps/own/render.ts` draws them on a canvas into the existing `blob:` tile pipeline through a `resolve` seam in `TileMap` (own map first, online tiles after, nothing at all with the setting "Nur eigene Karte"); zooms deeper than the stored data come from the parent tile (overzoom ≤ 5). Colours are read from token classes through a hidden probe (`palette.module.css`, `color-mix` with plain-token fallbacks) and redrawn on a theme change; the map waits for the region query so no online tile is ever requested for a covered area. The invented town `own/sample.ts` serves tests only; a real build (Overpass) is package 2.
- **Own map, package 2 = lean build from Overpass (2026-11-01, `feat/map-own-build`):** one POST per z13 cell (query in the body, 64 MiB / 60 s server limits, a small margin around the cell) through the platform fetch; the answer is parsed, cut and encoded in a Worker, the tiles are written per cell so the map fills visibly; the lower zooms (8–12) come from the stored z13 tiles (`own/pyramid.ts`), never from a second request. One region builds at a time, a second waits; a busy server (429/503/504, overload remark) is retried after 5, 15 and 45 s, then the build pauses with a reason; a blocked network pauses at once. Nothing resumes by itself after a restart (`settle` → "Weiter"). Large areas are cut to 64 cells around the centre ("the centre first"). Own notice `maps-build` (it sends the area you build). Removing a region purges its tiles (two clicks, no undo: it is a cache).
- **Own map, package 5 = local search (2026-11-01, `feat/map-own-search`):** the names of a cell are indexed when the cell is written (from its deepest tiles, in the worker), into the device-local collection `maps_name` with a multi-entry index on the words; the search field asks that index first and shows its hits under "Aus deiner Karte", so a query leaves the device only when the own map knows nothing about it or on the click "Online weitersuchen" (never by itself with "Nur eigene Karte"). Regions built before the index existed are indexed from their stored tiles on the first search (local work, once, `indexedAt` marks it); "Genauer machen" rebuilds the index with the full cells. No search-as-you-type (one click, as everywhere), no new setting.
- **Own map, package 4 = prebuilt region files (2026-11-01, `feat/map-own-regions`):** PMTiles v3 is read by `maps/own/pmtiles.ts` without a library (header, root and leaf directories, range requests; gzip tiles kept as stored, inflated on draw) so an own host can serve whole regions as one static file. A region file is a second build source, not a second map: with `regionUrl` set and the place inside the file's bounds, the builder copies the file's tiles into the same device-local tables (per z13 cell down to the file's deepest zoom ≤ 16, then the lower zooms from the file; no pyramid step), the region carries `source: 'file'`, `sourceUrl` and the `credit` from the file's metadata, and "Genauer machen" is not offered. Outside the file or without an answer from its host the build falls back to Overpass and the note says why; nothing is downloaded whole, nothing without a click. Level of a file region = full when it holds z15+.
- **Own map, package 3 = full level, extend, sizes (2026-11-01, `feat/map-own-full`):** the first build is always lean; "Genauer machen" rebuilds a finished region at the full level in place (same id, z14 cells, tiles down to z16, the overview from the new tiles) instead of a second region. "Hier erweitern" builds the shown area as a new lean region and skips cells any region already holds (`skipCells`, stored so a resume stays deterministic); a fully covered area creates nothing and says so. Size and date are shown per region (bytes of its tiles, date of the last finished build); "Alle Karten löschen" appears from two regions on, two clicks, no undo.
