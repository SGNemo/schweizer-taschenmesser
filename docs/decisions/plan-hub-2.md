# Decisions – Day and week planning – planner hub 2 (everything linked, fewer rows)

Part of [plan](plan.md). Index of areas: [DECISIONS](../DECISIONS.md). Design: [design/planner-hub-2](../design/planner-hub-2/README.md). Packages add their bullets below.

- **Principle 1 is a gate (2026-11-23, design round; the maintainer's decision on the open points 2026-11-24):** an idea is built only if the measuring script (`web/e2e/usecases/planner-hub-2.spec.ts`) shows fewer rows or fewer module switches. Struck: 7 „Warte auf Antwort“ (today's move to a day already takes the rows off the sheet in 7 handles without a switch), of 6 the places and the map (no figure), and pictures in the share path (the one new entry surface, no figure beyond text). Parked by the figures: 5b, bundles of things with the errand round (one row and three working handles less against 14 / 13 handles once and a trip to Listen). Built although it lowers neither rows nor switches, on the maintainer's decision of 2026-11-24: 8 „echte Dauer“ (after 5a). Concept, hand-off and prompt of 7, 6's places and 5b are kept; each needs the maintainer's explicit yes. Source: [ANALYSIS §4](../design/planner-hub-2/ANALYSIS.md).
- **One thing, one home, one „Erledigt“ (2026-11-23):** the plan row of an invoice, a list or a subscription is that thing (`<module>:<id>`), never a ToDo about it; a carrier ToDo exists only for targets without a done of their own (mail thread, note, appointment). Why: „ticked in one place counts everywhere“ then needs no syncing between modules or devices. Source: [CONCEPT §0](../design/planner-hub-2/CONCEPT.md).
- **The planner still writes nothing in other modules; a module's own panel is mounted in the row (2026-11-23):** the planner writes its own collections, `_links` (through `addLink` / `removeLink`), its own settings record and its device-local `_meta` keys (as today), and it may create a thing through a core capture target (`saveCapture`) – only on his tap and inside the planner's one undo entry. Nothing else. `contributions.planPanel`, mounted by core. `decisions/plan-links.md` L7 stays (the route `?do=pay` writes nothing); paying in the row is the invoices module's `PayStep`. Why not a command over the bus: every module would need a second write path with its own undo.
- **The expanded row is a compartment under the row, not a side panel (2026-11-23, confirmed by the maintainer 2026-11-23):** one grammar on 1920 and 412, nothing covers the plan; the side panel is a sheet on the phone, which is the jump the order wanted gone. The title becomes the expand button; „Ganz öffnen“ is the old jump. Source: [DESIGN §2](../design/planner-hub-2/DESIGN.md).
- **Steps belong to the source, a bundle only brackets (2026-11-23, confirmed by the maintainer 2026-11-23):** `PlannableItem.steps` + `onStepDone` (ToDo checklist, list items, routine steps); a bundle of several things (5b, parked 2026-11-24) would be `planner_bundle` plus two fields on `planner_item` – no copies of things in the planner (keeps L1 of planner hub). „Los“ is a step mode of the focus page: only the next step. Rejected: steps always visible in the sheet (no row fewer). Source: [DESIGN §3](../design/planner-hub-2/DESIGN.md).
- **A topic is a planner row with links, not a tag (2026-11-23):** `planner_topic` + one `topic` link per member in `_links`. Why: tags exist in four modules as strings and in none of invoices, mail, calendar; a cross-module tag would be a field in every module. Tags stay what they are; the planner never reads them.
- **No migration for the mark (2026-11-23, council):** bookmarks and subscriptions keep `inPlan` / `plannedDeadline` as their request to the plan; only the display moves to the shared mark, which reads the planner (matching occurrence keys by prefix). Rejected: a one-time step turning the fields into planner rows – it would write and place at app start and revive excluded things on a fresh device.
- **Piles are offered, never switched on (2026-11-23):** „Finanzen checken“, „E-Mails durchgehen“ fold only things without a day and only after his tap on the offer or the switch; a count is muted text that falls as he works, never a badge.
- **Kinds in the field are decided by a visible line before Enter (2026-11-23):** only „sure“ readings show „Wird: …“; no line means a task as today; local rules only, no model.
- **The link contract grows, the request events stay (2026-11-24, package 10a):** `LinkRel` gains `before`, `after` (a ToDo → an appointment) and `topic` (`planner:t_<id>` → a thing); `wait` and `place` belonged to struck ideas and are not added; older apps read the new values as `about`. `contributions.linkTarget` for `subscriptions` (name; no `done` – an ended subscription is no „Erledigt“), `bookmarks` (title, never the URL – an untitled import reads as its kind; its own `done`), `vault` and `routines` (name): own data only, the thing's id (not an occurrence key), anything else `gone`. `PlannableItem.entityId` names the thing behind an occurrence row (subscriptions, Unterlagen, routines); a link stores `entityRefOf(module, item)`. Unterlagen: the link title is the plan row's own title (`modules/vault/titles.ts` `docTitle`, the category's wording, „Vertrag kündigen“) – never the document's name (`detail`), a file name or a custom category name; reusing the row's function adds no word and the row test pins the link. `plan.requested` / `todo.requested` get nothing new (type-pinned in `types.test.ts`): the new relations are written only by the planner's own undoable actions through `addLink` (9, 11), never into a ToDo's frozen `links[]`. Source: [CONCEPT §1](../design/planner-hub-2/CONCEPT.md).
- **The title opens, „Ganz öffnen“ is the old jump (2026-11-24, package 4a):** a row's title is a disclosure button (`aria-expanded`, X1); its compartment holds the thing's panel, mounted by `core/modules/PlanPanelHost` only (lazy, a boundary that logs the module id and the error name only, never for `accounts`); „Zeilen aufklappen“ off brings back the jump. The planner writes its own collections, `_links` (through `addLink` / `removeLink`), its own settings record and its device-local `_meta` keys (as today), and it may create a thing through a core capture target (`saveCapture`) – only on his tap and inside its one undo entry; nothing else: opening and closing writes nothing, a tick in a panel is the module's own write with the module's own undo toast (write spy in `RowCompartment.test.tsx`). Why: one undo per action and per owner, no second write path per module.
- **Paying and cancelling are the modules' own steps in the row (2026-11-25, package 4b):** the invoice panel mounts the module's `PayForm` (the page's pay step as one line, same writes, same undo), the subscription panel the module's first cancel step. „Gekündigt am …“ writes the day (`cancelledOn`) and the end before that deadline's charge (`recurrence.until`), so reminders, calendar and overview follow without a new reader; „Läuft weiter“ marks only that deadline (`keptDeadline`): the planner source and the reminders skip it, the next period's comes as usual (the page's deadline card and the calendar still show the date as a fact). Cancelled after a passed deadline, the end is before the next charge that can still be avoided. `?do=cancel` now opens the step and still writes nothing by itself. L7 holds: the planner writes nothing here.
- **A planned mail is answered in its row, mail's code all the way (2026-11-25, package 4c):** a ToDo whose first `origin` link is a thread gets mail's panel from the host, its own checklist under it; the text comes from this device's cache as plain text, „Antworten“ opens mail's own compose window over the planner, and both that window and the 10-second send window live in mail's `planPageFoot`, so closing or losing the row never takes a typed reply or hides „Zurückziehen“. The planner hands over a ref and never reads, copies, searches or logs mail content (`privacy.test.ts`). On the phone the row says X5 + X6 and keeps the ToDo's own lines – no button, not even „Ganz öffnen“ (the prompt's „kein Knopf“; its links stay). „Beantwortet?“ in the panel also reads the sender address when a background refresh dropped the cache flag; the mail list still reads only the flag (follow-up: one rule for both).
- **Collective rows are counted, never stored (2026-11-25, package 2):** „Finanzen checken“ and „E-Mails durchgehen“ are things of the planner's own source, handed over without a due date or detail, so a count that changes – also to 0 – never reruns or writes; what the row shows (parts, members, „nichts wartet“) is folded on every reading from the modules' `pile` parts. Members fold only while they have no day and no lock, are never proposed one by one, and stay single rows past 40. The switches are two flat optional settings (`undefined` = never asked); the offer's undo sets the value back explicitly, since the undo journal holds no settings. „Wieder einzeln zeigen“ only switches the area off: a placed pile's row stays, and the pile comes back on that day when switched on again.
- **Steps belong to their source, „Los“ to the planner (2026-11-25, package 5a):** a ToDo's checklist, a list's entries and a routine's steps of the turn are handed over as `steps` (display and „Los“ only, never in the input hash); a tick goes back through `onStepDone`, read fresh so another device's change to a sibling step stays. „Los“ shows only the next step; each tick is its own undo, and the last „Fertig“ finishes the step and ticks the thing in one undo entry. „Als Routine speichern“ sends the existing `routine.requested` inside the planner's `act` (the routines handler now hands back its write), after a name lookup through the generic manifest repo. A „Los“ from the plan starts the round fresh (skips and the pause cleared, ticks kept); only a reload keeps the skips and the pause. A step list over `STEPS_MAX` is dropped in core: the thing is then a plain row. „Fertig“ on the last step the stage shows ticks the thing even if another device reopened a step a moment before (one undo brings both back); no fresh re-read.
- **Measured time proposes, never corrects (2026-11-25, package 8):** a focus round's „Erledigt“ (worked time, pauses out) and each „Los“ step's „Fertig · weiter“ / „Fertig“ (from when the step showed, a pause shifts it) record minutes in `planner_measure` inside the same act, pruned to five per key; key = `entityId` when the thing comes back, else the title as `pastePlan.sameTitle` reads it; a step by its title. Only a thing typed in the field without minutes takes the median of ≥ 2 records, as the plan's own length marked `measured` (Z1) – its ToDo keeps no estimate, nothing existing changes. The switch off records and proposes nothing, keeps what was measured. A measured length gives way as soon as the source has an estimate of its own (`planLength`); a thing split into sessions shows plain minutes. A reload of „Los“ restarts the step's clock (time away is never a step). The collection is `personal` (new `CollectionDef` flag): synced and in his own backup, never in a share file, a diagnosis count, the data API or a home count; „Gemessene Zeiten löschen“ sits right after its switch (`ModuleSettings.extra.after`).
- **A shared thing lands in the planner on the capture card's own button (2026-11-26, package 1):** with the planner on, the share page's form starts with the kind `plan` (no new list, chips or button); under `plan` a shared http/https address of ≤ 2 048 characters is the first line of the ToDo's note, also without the tick, and the page says so (S16) – any other address is shown, never stored (S19); any other kind keeps the built note. After „Speichern“ as `plan` the page stays: S8 with „Ansehen“ / „Rückgängig“ / „Fertig“, following the ToDo live (S14 once it is gone). The ToDos source hands the address over as `PlannableItem.url` only from a bare first note line of a task with no links of its own; the chip S7 opens it only on a tap, `core/net/webAddress` gates it where read, drawn and opened; display only (never hash, copy text or titles). „Fertig“ opens the planner on every device – no new native command; „Fertig“ and „Ansehen“ replace the share page in the history, so going back never offers the same share again. With the planner on, the form's line – and under `plan` the ticked rest, line by line – is screened: every address-like token (`http(s)://`, `www.`, any case) the gate rejects leaves it with its trailing punctuation, so the parser never keeps one as a title; other words that merely look like a scheme (`javascript:` inside running text) stay plain title text – never linked, never opened. The gate measures the stored (encoded) form. Every external address a planner chip opens passes `webAddress` (one canonical `href` for storing, drawing and opening). A shared line with a typed time keeps the capture's built note order (the time line first), so its address is stored but gets no chip.
- **The field shows a kind before it stores one (2026-11-26, package 3):** a line the local rules read as surely an invoice (the word „Rechnung“ and an amount, never „Mahnung“), a shopping entry („… kaufen“, „Einkauf: …“, or a whole line the shopping list or pantry already knows – exact, case-blind, `knownShoppingNames`), an appointment (a said day and a clock time), a note („Notiz:“ / „Idee:“), a link (one http/https address) or a task with steps („Name: a, b“) shows K1 first; nothing else changes the field. The planner's own readings stay first (a pasted plan, „Pause …“, „heute nur …“, lock words, every stage-0 instruction); a kind's module off means a ToDo, never the next kind. Enter is one `runUser` action: `saveCapture(<kind>)`, the planner's own item row only for an invoice or the shopping list and only when none exists (never `excluded`, never a day row), a task with steps through `addFromField` with `CaptureFields.checklist`; a thing its source then does not list is taken back. No model call and no network; the local model stage never runs for a line with K1. Switch `kindsInField` (on). An invoice without a said deadline takes the capture's 14 days, at most the last planned day (so the plan lists it), shown on K1 – the horizon setting can shorten it; follow-up: list it through the item row instead.
