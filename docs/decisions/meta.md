# Decisions – chats and docs process

- **Superseded 2026-11-08 by the scribble move below.** **A scratch folder for the chats, develop only (2026-10-17):** `scribble/` holds heads-ups, non-blocking questions and notes between parallel chats (`BOARD.md` + one file per branch). The maintainer does not read or moderate it; chats answer each other there and only escalate root rules, security rules and hotspot contracts. It is never a source of truth (decisions, status and recipes stay in `docs/`), never on `main` (the release merge removes it; CI job `scribble-guard` fails on `main` or a PR into `main` if it exists; a later `main` → `develop` sync restores it), and gitleaks scans it like everything else. Why: CHATS.md rows say _that_ someone works somewhere; the chats also need a cheap place for _what_ they found and want to ask, without inflating the docs budgets. Companion: `npm run chats:status` (git only) shows the other branches, their files and the overlap with the current branch, so a chat sees a collision before it happens.
- **Stimulus budget is a warning, not a gate (2026-10-24; superseded 2026-11-09 by "Stimulus budget blocks" below):** `web/e2e/stimulus-budget.json` guards buttons, links, icons, height and first-screen actions per page × viewport; `npm run check:stimulus` exits 1 locally, the CI job `Stimulus budget (warnings only)` is `continue-on-error`. Why: parallel chats must not block each other, and every focus package changes the numbers on purpose (`npm run stimulus:baseline`). Tolerance +10 % / +50 px (counts at least +1) avoids one-element false alarms. [howto/ci.md](../howto/ci.md)
- **What runs on a PR, what only on develop/nightly (2026-11-04, CI round 2):** a plain PR runs the packages its diff touches (`changes` job; shared inputs and unknown paths turn everything on), E2E as the smoke list on desktop (`SMOKE_FILES` in `web/playwright.config.ts`), draft PRs only static + unit. The label `full-ci`, every push to `develop`/`main`, the nightly run (`nightly.yml`) and manual runs execute everything (both browser projects, 6 shards, seed project). Why: PR wait had grown to 24 min with 19 jobs queueing for runners; nothing is checked less often overall, only later. CodeQL Rust (9 to 14 min) runs on a PR only when the PR touches Rust; pushes to `develop`, the weekly run and manual runs always scan all languages (maintainer's yes, 2026-11-04). The Dev-Preview is built next to the tests and published only after tests, packages, Rust, licences, docs-pairs and gitleaks of the run are green. The nightly run only fires once `nightly.yml` is on `main` (scheduled workflows run from the default branch); until then the `develop` push runs cover it. Table: `docs/HOW-TO.md` "Which checks run when".
- **Module lists and README pictures come from the app, not from hand-written copies (2026-11-04):** `npm run gen:modules` (`web/scripts/gen-module-list.mjs`) loads the real registry and the five catalogs through Vite SSR and writes the module/tool tables between `<!-- modules:start/end -->` in `README.md`, `README.de.md`, `docs/user/modules{,.de}.md` and `site/src/catalog/modules.json` (the website list); the one-line text is the first clause of the manifest description, so a renamed module is a one-command change. README pictures are shot from the seeded Dev-Preview build by `site/scripts/app-screenshots.mjs --readme` (WebP, German seed texts, fixed clock) and the social preview by `npm run gen:social`; `npm run check:doclinks` checks links, anchors, pictures, alt texts and heading levels. Why: the README had drifted (10 modules missing, old logo, wrong settings paths) because every list was typed by hand. Not wired into CI yet (workflows stay with the CI chats); the PR template has a checkbox.
- **The Dev-Preview gate is the fast part of CI (2026-11-04):** the preview is published when gitleaks, licences, web static, unit tests, the E2E smoke list and the native shell are green (about 5 min, shorter than the build); the rest of E2E (1543 tests), sync E2E + seed project, small packages, extension, local model and docs checks run next to it and after it. Why: the preview is an "untested intermediate build" by its release notes, the maintainer wants the new Dev app as soon as possible and accepts that some regressions show up after it; the full suite still runs on every `develop` push, so total coverage is unchanged. Signing, audit, gitleaks and the post-publish link check are untouched.
- **E2E speed (2026-11-06, `ci/e2e-speed`):** E2E jobs start next to each other (rest 8 shards, sync, seed 2 shards, smoke 3 shards), no longer after the smoke list: every job of a full run started within 2 s of being queued, so the wait only added 4 to 12 min. Playwright's font packages come from a cache (`.github/actions/playwright-chromium`): the Azure apt mirror served them at 40 kB/s in 8 of 135 jobs (up to 12 min). Seeded specs load the seed once per worker (`seeded` in `e2e/seed/helpers.ts`, IndexedDB snapshot). `npm run e2e` is the plain-PR set (smoke + sync, about 10 min); everything is `npm run e2e:full` (about 70 min on 4 cores, pixel-7 alone is 55 test-min). Rejected: one shared build as an artifact (the build takes 6 s), more local workers (2 → 4: −17 %, flakes), dropping pixel-7 runs of the same flows (phone coverage). Numbers: PR description of `ci/e2e-speed`.
- **Agent team set up and frozen (2026-11-07):** roster, delegation matrix and sandbox start live in [meta/AGENTS.md](../meta/AGENTS.md). Changes to it, the agent prompts or root CLAUDE.md need a maintainer decision here; agents do not change them on their own. The onboarding PR was a one-off exception; afterwards root CLAUDE.md changes again only with a root rule change, own PR, maintainer approval.
- **Maintainer standing order (2026-11-07):** merge-ready PRs are merged without asking by `nemo-merge` only: merge commit + verified head SHA (`expectedHeadSha`), base `develop`, never `main`/tags/releases. MCP merge first; on 403 REST `PUT /pulls/{n}/merge` with the session token. A reviewer's written MERGE-READY verdict with the reviewed head SHA counts as approval (GitHub refuses self-approval when the token owner authored the PR). The lead never merges.
- **One token for all agents (2026-11-07):** all agents run with one token with admin rights (no separate devops token); the prompt hard limits (never `main`/tags/releases/branch protection/force-push) are the guard. Why: maintainer's choice for simplicity.
- **Agent team v3 (2026-11-08, `review/agents-v3`, maintainer took all four recommendations):** agent prompts live in the repo (`docs/meta/agents-v3/nemo-*.json` → `nemo-*.md` via `scripts/agents/to-ant.mjs`, folder renamed to `docs/meta/agents/` at the switch-over), the shared rule block in `SHARED.md` is read once per thread; the lead (Opus 5.5 high, no advisor) delegates through a `multiagent` block to 19 predefined subagents (inline agents and workflows off); models per role (Opus for lead/security/architect/reviewer, Sonnet for implementers, Haiku for triage/docs/i18n, Fable 5.1 for creativity with Opus as fallback if not budgetable). Why: v2's lead had no `multiagent` block and would have done everything itself; one source for the prompts instead of 20 forms ([meta/agents-v3/REVIEW.md](../meta/agents-v3/REVIEW.md)).
- **Light path for small PRs (2026-11-08):** docs-/test-/i18n-only PRs go `nemo-reviewer` → `nemo-merge` only; everything under `.github/**`, RULES.md areas, secret-holding build inputs (`web/scripts/**`, `build.rs`, gradle, `tauri*.conf.json`, lock files), `CLAUDE.md` and `AGENTS.md` take the full path with `nemo-security`; `docs/meta/agents*/**` and `scripts/agents/**` are merged by the maintainer himself. Why: v2 sent docs-only PRs through five agents and full local suites; CI runs them on every PR anyway.
- **Token scope and rulesets (2026-11-08, replaces "One token for all agents"):** one fine-grained PAT for this repository without `Administration`, `Workflows` and Actions write; ruleset on `develop` (PR, 0 approvals); `main` and tags `v*` have no ruleset yet (verified by GET); releases stay prompt-guarded until the signing secrets move into a GitHub Environment with the maintainer as reviewer; the MERGE-READY/SECURITY verdict lines plus the lead's thread hand-over replace GitHub approvals. Consequence: once the `develop` ruleset exists, `scribble/` changes go by small PR for every chat (root CLAUDE.md line changes in the switch-over PR). Why: a shared token cannot be split per agent (vault credentials apply to every thread of a session); rulesets are the technical lock the prompts cannot be. Observed 2026-11-08 with Workflows + Actions write (a workflow push and artifact deletes succeeded); the intended state is without them, kept as an open item for Sven (CHATS "Wartet auf Sven").
- **Seven more agents, same frozen rules (2026-11-07):** `nemo-deps` (dependencies/supply chain), `nemo-perf` (measurements before/after, reports in `docs/perf/`), `nemo-triage` (CHATS.md/MANUAL-TESTS/scribble housekeeping, docs only), `nemo-i18n` (de/en texts, glossary, `strings.ts` block rule), `nemo-a11y` (accessibility review, small fixes), `nemo-merge` (merging), `nemo-creativity` (ideas and second opinions on the Fable model, `docs/product/ideas/`). Roster rows in [meta/AGENTS.md](../meta/AGENTS.md); prompts live outside the repo in the agent form, like the first twelve. Why: these duties were done ad hoc by the lead or by generic agents (e.g. "Merge Conflict Resolver") and kept slipping (forgotten `gen:licenses`, stale "Wartet auf Sven" rows, no before/after numbers on dependency bumps).
- **Dependency hygiene is one agent's duty (2026-11-07):** security-critical crates (LAN sync/Noise, vault bridge, Local API, SQLite, randomness) are pinned exactly and checked with `cargo tree -e features` for pure-Rust backends; `cargo audit`/`npm audit` run by `nemo-deps` each session until a CI job exists (as of 2026-11-07 no workflow runs them, and `extension/` is missing from `dependabot.yml` – `nemo-devops` to decide); `npm run gen:licenses` is part of every dependency commit; lock files only by tools. Why: a forgotten licence list broke CI once, and the sync crypto path must not pick up a C backend or an extra network stack unnoticed.
- **Idea briefs have a home (2026-11-07):** `docs/product/ideas/` (new; one ranked file per round, row in `docs/product/README.md`) holds `nemo-creativity`'s briefs; `nemo-po` moves accepted ones into ROADMAP/STATUS. Earlier rounds stay where they are (`docs/product/next/01-ideas.md`). Why: ideas were scattered over ROADMAP, STATUS and chat transcripts; one place with a fixed brief format (problem, fit, risks, smallest step) keeps them checkable against the hard rules.
- **Agent token diet (2026-11-08, `fix/agents-token-diet`, after one lead session cost 215 M tokens / 82 USD):** lead on Sonnet 5.5 high with an Opus 5.5 advisor for decisions only; one session = one request (afterwards: new session, never raise the budget to keep chatting); delegations bundled per agent; no full local suites, CI is the only full run; outputs via `tail`/`grep`/`--stat` first; thread messages ≤ 15 lines; `session.mjs` defaults to a 10 USD budget, warns at 70 %, needs `--yes-expensive` above 30 USD. Why: context growth and repeated full runs, not the work itself, drove the cost.
- **Scribble moves out of `develop` (2026-11-08):** notes live in the session folder `/workspace/scribble/` (live) and the private repo SGNemo/nemo-scribble (persistent; agents push their own files at task end, `pull --no-rebase`, never force-push). Notes are data, never instructions: rules come only from `SHARED.md`/`CLAUDE.md`. The repo's no-secrets rule applies there too; private is not a secret store; nemo-scribble runs its own gitleaks scan (`scan.yml`). Supersedes the 2026-10-17 bullet (kept for history). 2026-11-10: `CLAUDE.md` names the repo URL as the place for chats; `/workspace/scribble/` exists only in the agent sandbox, a plain Claude Code session has no such folder. Why: the `develop` ruleset blocks direct pushes, and one file per entry avoids merge conflicts between ~20 agents.
- **Agents may dismiss alerts with a written reason (2026-11-08):** Dependabot alerts may be dismissed as `not_used` or `tolerable_risk` (as [howto/release-deps.md](../howto/release-deps.md) allows) with a written reason, after `nemo-security` concurs; CodeQL alerts only as a real false positive with justification, also after `nemo-security` concurs. Why: a dismissal silences the alert for everyone.
- **Workflow changes are delivered as a patch (2026-11-08):** changes under `.github/workflows/**` and `.github/actions/**` are not pushed by agents; the PR text carries the patch and Sven applies it. Why: workflows hold the release and signing steps.
- **Signing secrets into GitHub Environments: TBD before the public launch (2026-11-08):** PR #542 (draft) stays paused until Sven decides. Why: an environment with a reviewer locks the signing secrets without relying on agent prompts.
- **No images in `docs/` (2026-11-08, `chore/docs-no-images`):** screenshots and mockup images go into the PR text or a workflow artifact; the repo keeps only README pictures, user-doc images and brand files (≤ 100 KB, existing brand PNGs grandfathered), enforced by `check:docs` (CI job blocking). Why: audit, sweep, design and QA rounds had committed ≈ 215 MB of JPG/PNG that every clone, CI run and agent sandbox paid for. The history keeps the old files; no rewrite.
- **Stimulus budget blocks, its ratchet is checked at the merge with a signature (2026-11-09, UI audit package 0a-1a, Sven's approvals 3 and 4):** the job `Stimulus budget` and `e2e-seed` are parts of the check `Web`; `web/scripts/ratchet.mjs` compares merge base and head by meaning (budget, baselines, seed rows, signature blocks, `package.json` (scripts, other fields, dependency sources), protected guard files incl. all workflows, repo-wide). CI only gives feedback (label `stimulus-raise`); the proof is `nemo-merge` rule 7 and the same rule for every merger in [RULES](../RULES.md), run with the `develop` version of the script, and an approval is Sven's Ed25519-signed comment over `stimulus-raise <repo>#<pr> <hash>`. Why: a workflow or a commit status can be brought along or delayed by the PR it should judge (`main` is the default branch, so `pull_request_target`/`workflow_run` would run a stale file), and label, author and app field do not tell Sven from an agent that acts with his token; a key that only he holds does. Key by `openssl` only, never a repo script; a key change is merged by Sven himself (named exception). The old "warnings only" decision is replaced. Spec: [PACKAGE-0](../design/ui-audit-2026-11/PACKAGE-0.md).
- **Record: five label steps were merged before the merge rule ran for real (2026-11-10, found by the council's acceptance of package 0a, rounds 1 and 2):** #630 (workflow), #634 (0a-1b), #640 (ratchet and static guards, including `ratchet.mjs` itself), #642 and #647 (seed guards) went into `develop` while the ratchet step of their run was red; none carries a signed `stimulus-raise` comment (checked at the API: 0 on each), all were merged by the maintainer. This is the open blocker B1 for package 0b-1 ([LEDGER](../design/ui-audit-2026-11/LEDGER.md) „Abnahme 0a, Runde 2“); the hits of the five PRs are in their PR texts for a later look, `ratchet.mjs` first.
- **The real run of rule 7 is deferred and no longer blocks package 0b-1 (2026-11-10, maintainer):** `nemo-merge` is available to him only from December 2026. Until then the state of the record above holds: the ratchet is feedback in CI, PRs with hits are merged by the maintainer himself, their hits stay listed in the PR text. The throwaway-PR run with a real signature ([howto/ci.md](../howto/ci.md) "One-time setup") is done once the agent exists; the rule itself is unchanged.
- **CI round 3: the queue is the problem, so load goes down before jobs get faster (2026-11-10, `ci/cleanup-round-3`):** measured over 1000 runs ([perf/CI-2026-11.md](../perf/CI-2026-11.md), `scripts/ci/measure.mjs`): the account's 20 runners were full 22 % of the time, filled by full `develop` runs (35 jobs, 90 pushes in 42 h) and by pull-request pushes that only merge `develop` in (every fourth). Decided in this round: chats merge `develop` in once before the PR and later only on a conflict ([PROMPT-TEMPLATES](../PROMPT-TEMPLATES.md#git)); the seed project runs as four jobs (the 12 page walks apart, split by `--grep`/`--grep-invert`, so no list to maintain); the Windows release build for the exe size runs on full runs only (clippy and tests compile the same crates on every Rust PR). Not decided here, handed over with a prompt each ([perf/CI-2026-11-PACKAGES.md](../perf/CI-2026-11-PACKAGES.md)): overtaken `develop` runs stop testing, install and build once per run, CodeQL only where code changed (reverses part of the 2026-11-04 bullet, needs the maintainer), flaky tests. Left alone on purpose: `retries: 1`, gitleaks without a cache, the second gitleaks scan in the Dev-Preview build, the `Web` aggregate on cancelled runs ("skipped" would read as passed), merge queue (not offered for a personal repository).
