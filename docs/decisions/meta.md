# Decisions – chats and docs process

- **A scratch folder for the chats, develop only (2026-10-17):** `scribble/` holds heads-ups, non-blocking questions and notes between parallel chats (`BOARD.md` + one file per branch). The maintainer does not read or moderate it; chats answer each other there and only escalate root rules, security rules and hotspot contracts. It is never a source of truth (decisions, status and recipes stay in `docs/`), never on `main` (the release merge removes it; CI job `scribble-guard` fails on `main` or a PR into `main` if it exists; a later `main` → `develop` sync restores it), and gitleaks scans it like everything else. Why: CHATS.md rows say *that* someone works somewhere; the chats also need a cheap place for *what* they found and want to ask, without inflating the docs budgets. Companion: `npm run chats:status` (git only) shows the other branches, their files and the overlap with the current branch, so a chat sees a collision before it happens.
- **Stimulus budget is a warning, not a gate (2026-10-24):** `web/e2e/stimulus-budget.json` guards buttons, links, icons, height and first-screen actions per page × viewport; `npm run check:stimulus` exits 1 locally, the CI job `Stimulus budget (warnings only)` is `continue-on-error`. Why: parallel chats must not block each other, and every focus package changes the numbers on purpose (`npm run stimulus:baseline`). Tolerance +10 % / +50 px (counts at least +1) avoids one-element false alarms. [howto/ci.md](../howto/ci.md)
- **What runs on a PR, what only on develop/nightly (2026-11-04, CI round 2):** a plain PR runs the packages its diff touches (`changes` job; shared inputs and unknown paths turn everything on), E2E as the smoke list on desktop (`SMOKE_FILES` in `web/playwright.config.ts`), draft PRs only static + unit. The label `full-ci`, every push to `develop`/`main`, the nightly run (`nightly.yml`) and manual runs execute everything (both browser projects, 6 shards, seed project). Why: PR wait had grown to 24 min with 19 jobs queueing for runners; nothing is checked less often overall, only later. CodeQL Rust (9 to 14 min) runs on a PR only when the PR touches Rust; pushes to `develop`, the weekly run and manual runs always scan all languages (maintainer's yes, 2026-11-04). The Dev-Preview is built next to the tests and published only after tests, packages, Rust, licences, docs-pairs and gitleaks of the run are green. The nightly run only fires once `nightly.yml` is on `main` (scheduled workflows run from the default branch); until then the `develop` push runs cover it. Table: `docs/HOW-TO.md` "Which checks run when".
- **The Dev-Preview gate is the fast part of CI (2026-11-04):** the preview is published when gitleaks, licences, web static, unit tests, the E2E smoke list and the native shell are green (about 5 min, shorter than the build); the rest of E2E (1543 tests), sync E2E + seed project, small packages, extension, local model and docs checks run next to it and after it. Why: the preview is an "untested intermediate build" by its release notes, the maintainer wants the new Dev app as soon as possible and accepts that some regressions show up after it; the full suite still runs on every `develop` push, so total coverage is unchanged. Signing, audit, gitleaks and the post-publish link check are untouched.
