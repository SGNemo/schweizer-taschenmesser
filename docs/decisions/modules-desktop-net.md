# Decisions – modules and tools – browser, downloads, torrent

Part of [modules](modules.md). Index of areas: [DECISIONS](../DECISIONS.md).

- 2026-11-02 **Built-in browser (P1):** tabs are child webviews of the main window (Tauri `unstable` multiwebview), isolated three ways: capabilities match the `main` _webview_ (not the window), no capability has `remote` or names `browser-*` (guard test `tests/commands.rs`), every browser command checks its caller; no script is ever injected (back/forward = the tab's own address list, popups/downloads/non-HTTP(S) stopped in navigation handlers). Own profile `browser-profile` (private tabs: in-memory), deletable. Ad/tracker blocker: request-level on Windows (WebView2 `WebResourceRequested`, `src/browser_win.rs`), own hand-written domain list in `crates/browser-filter` because the usual lists are GPL/CC-BY-SA (licence policy); users add rules from the "Blocker" panel. Browser is in the "no aiSchema" allow-list (what you read stays private); data is device-local. Selection text for "Als Notiz" is not read (would need injection): title + URL only.
- 2026-11-02 **Download manager (P2):** jobs live in Rust (`crates/downloader`, `downloads.json`, atomic writes), not in Dexie: no collections, `dataApi: false`, no `aiSchema`. HTTP(S) only, `Range` resume (also after a restart; a job that was running comes back _paused_, nothing starts by itself), `.part` file next to the target, never overwrites (`name (1).ext`), file names sanitised (no folders, no Windows-reserved names), SHA-256 shown after the download and compared with a pasted SHA-256/SHA-512 (MD5/SHA-1 deliberately not offered). Files are never opened or run; "folder" only reveals them. A download offered by a web page arrives as `/downloads?add=<url>`: the add dialog opens prefilled and waits for a click (no event-bus coupling, no auto start). Speed limit = the job's own or an equal share of the global one; at most three run at once. Downloads from the browser do not carry its cookies.
- 2026-11-02 **BitTorrent (P3):** embedded `librqbit` 9.1 (Apache-2.0, pure Rust, rustls, no HTTP API/web UI; all 81 new crates pass the licence allow-list) in `crates/torrent`, instead of libtorrent bindings (C++ build, heavier). The part is off by default and on only behind the one-time notice `downloads-torrent`; the engine starts when the Downloads page opens with the part on. Only what the user hands over (pasted magnet link, opened `.torrent` ≤ 10 MB): no search, no site list, no scraping. **Nothing starts by itself:** before the engine reads its saved list every entry is marked paused in `session.json` (also after a crash; `librqbit` ignores a pause request when its file check succeeds). Multi-file torrents land in `<folder>/<name>/` (`librqbit` would otherwise spill into the folder; name sanitised), a previewed magnet link is added from the saved metadata. Seeding stops at a ratio / time the user sets (default ratio 1.0); a stopped torrent shows "done", the ratio uses our own max-seen upload counter because the engine's restarts at zero when paused. DHT on by default (magnet links need it), UPnP off, no listen-port setting. Known limit: `librqbit` binds its UDP tracker client to `[::]`, so the engine cannot start on a machine without any IPv6 stack (the tests skip there). Public IP only on a click via the existing `ip` flow.
- 2026-11-02 **Browser on Android + association (P4):** Android opens addresses in a Chrome Custom Tab (own Kotlin plugin `custom-tabs`, http(s) only); no embedded webview there, so tabs, find, zoom and blocking are the system browser's and Nemo keeps only address bar, bookmarks and history (history = what was opened from Nemo). The `magnet:`/`.torrent` association is opt-in and registers Nemo only as a _possible_ handler (HKCU `Classes\<id>.Magnet|.Torrent` + `RegisteredApplications`, never `UserChoice` or a bare `magnet` key); the user picks it in Windows' default apps, removing deletes exactly those keys. A launch argument only pre-fills the add dialog (magnet ≤ 8 KB, `.torrent` ≤ 10 MB, must exist), needs the downloads module and the torrent part (notice) on, and never starts anything.
