# Decisions in full – features – Google accounts and mail module

Part of [features](features.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Several Google accounts (2026-11-01):** needed for the mail module. First account keeps its keystore keys (no migration), extra accounts get `oauth:google#<id>:refresh` and a list in the connector status; the account address is read with already granted scopes instead of requesting `email`/`openid`. Calendar sync and the mail scan stay on the first account until a feature needs more.
- **Mail module, package 1 (2026-11-02):** read-only Gmail inside the existing Google connector (`gmail.readonly`, no new scope, no second login). The seam is `ConnectorDef.mailbox: MailProvider` in `core/mail`, so IMAP can follow as another connector. Mail content stays out of every model: no `aiSchema`, not searchable, `dataApi: false`, `core/ai` cannot import it (test). The cache holds headers and opened mails only, sealed with the device key, device-local and deletable (an unlocked-vault key was rejected: reading mail must not need the vault). HTML is untrusted: DOMPurify + sandboxed `srcdoc` iframe with its own CSP; remote images are fetched by the app on request and inlined (the app CSP stays strict). Opening a mail does not mark it read (writes come in a later package with their own scope).
- **Mail → Nemo entries (2026-11-02):** one menu, six destinations, reusing the capture sheet instead of a second form: it already shows a live preview and saves only on confirm (the "Vorschau-Pflicht"). The heuristics moved to `core/mail` so the module can use them without importing a connector. The link to the mail travels in the entry's own fields (no schema change in other modules); the back-reference is a device-local `mail_link` collection of ids only, titles are read from the entry. Mail text is never copied unless the user ticks "Anfang der Mail in die Notiz übernehmen".
- **Mail write actions (2026-11-02):** off until the user switches on `mail-modify` / `mail-send` in Verbindungen (two scopes, two explanations, a new login). Google lets `gmail.modify` send as well; Nemo still only sends with `mail-send` on, and the service layer enforces the per-feature gate, not just the UI. Anything that moves or deletes asks first (archive/label: setting, default on; the trash always), and every change has an undo. Sending is the only step that cannot be recalled, so it has three stops: a review screen, a confirmation, and a 10 s send window with "Zurückziehen"; the wait is in memory only, so a closed app sends nothing. No auto-reply, no scheduled send, no write from background code, widgets or the assistant. Plain-text compose only; original attachments are not forwarded.
- **New-mail notifications (2026-11-02):** opt-in and read-only, built on the existing calm pipeline instead of a second one: a poller keeps ids and times, a `soft` notification source says "N neue E-Mails". The text is a count by default (a lock screen is not private); names are a switch. `DueNotification.local` keeps such notifications off the Web Push upload (the sync server would see the text). Quiet hours, "Stumm", game mode and the per-hour limit apply unchanged, so there is no mail-specific quiet-hours setting. Only while the app runs: pushing "new mail" needs either the content on a server or a provider push channel (Gmail Pub/Sub), both rejected for a local-first app. Polling is at most every 5 minutes and slows down after failures.
- **Local model may read mail (2026-11-02):** opt-in, default off, and structurally local: the guard resolves only the built-in model or Ollama on loopback and routes its fetch through `loopbackOnly`, so a cloud or LAN endpoint cannot be reached even by a misconfigured entry; when no local model is ready the user gets a hint and a link to the AI settings, never a cloud fallback. Loopback instead of the existing `isLocalHost` because a LAN host is another machine. Results are plain text on screen only (not cached, not in `mail_link`); the model gets no tools or grammar, and the prompt says the mail is data, not instructions.
- **Mail actions in batches (2026-11-15, round "Tiefe"):** one table of steps (`modules/mail/mailActions.ts`) drives row, thread and batch actions, each step with its exact inverse, so an undo cannot drift from its action. Batches run thread by thread (four at a time, no Gmail batch endpoint for threads); each thread gets only the part of the change it lacks, and the undo sends exactly the inverse of that part, so a mixed selection or a mail outside the inbox is never changed back further than it was. Limits: actions work on the whole conversation (labels are the union of its messages), like Gmail's conversation view, so in the trash or spam folder a partly trashed conversation comes back whole and its undo trashes it whole; and the delta is computed from the labels last fetched, so a change made elsewhere since then can make an undo restore a label (still never deletes anything). A per-message model was rejected for this package (more calls, more state). Spam is a label change (`SPAM` in, `INBOX` out) and asks like the trash; star, important and removing a label move nothing and go straight through. Select mode is behind a "Auswählen" button instead of standing checkboxes (stimulus load). "Später erinnern" stays "In den Plan": Gmail's API has no snooze.
- **Finding mail (2026-11-15, round "Tiefe"):** filter chips write Gmail operators into the search text instead of a second filter model, so a chip and a typed `is:unread` are the same thing and a remembered search keeps them. Chips show only while a search is typed or running (the plain inbox stays calm). Remembered searches live in `localStorage` like the history (a search can name a person, so it never syncs), at most ten, in the folder column. Keyboard shortcuts follow Gmail, not the app's E = edit: an open mail carries `data-shortcut-scope="mail"`, so the app's E steps aside (like the vault entry's T) and E archives; J/K and ? stay the app's own; each key runs its button's code, so trash and spam still ask; a module setting turns them off.
- **Reply and newsletters (2026-11-15, round "Tiefe"):** forward now takes the original attachments (replaces "not forwarded" above): they are fetched into the compose window, listed and removable, and appear again on the review step, so nothing travels unseen; what would exceed one mail is left out and named. Text snippets stay in `localStorage` (the user's own words, device-local like remembered searches). „Newsletter abbestellen …“ offers only an https `List-Unsubscribe` page, names its host in a confirmation and opens it in the browser; Nemo never sends the `mailto:` variant or a one-click POST, because unsubscribing must stay the user's act. Attachment preview covers PNG, JPEG, GIF and WebP as data URLs; SVG (script) and PDF (the app CSP allows no frames) are saved instead.
- **Fields in „Aus dieser Mail anlegen“ (2026-11-16, fix/mail-create-fields):** the sheet never had fields of its own: it read one prefilled line, so a mail whose amount or due day the heuristics missed (letters: „Forderung“, „Kostennote“, „bis zum …“, „innerhalb von 14 Tagen“, amount after 1500 characters) left an invoice that could not be saved and showed nothing to fill in. Each capture target now declares its fields (`CaptureTarget.fields`, `required` pinned against `build` in `fields.targets.test.ts`); the mail dialog shows them under the line (`CaptureForm editFields`), edits win over the line and carry over on a chip switch, and a missing field is named at the field only after a save attempt. The quick-capture sheet stays line-only (stimulus load). Picking „Rechnung“ reads amount, due day and reference even when the mail does not look like a bill to the scan. An expense keeps no mail link (finance has no link field and `mail_link` has no `finance` type; no format change in a hotfix).
- **Mail links say where they go (2026-11-23, launch review M6):** a click on a link whose visible text names another domain than its target (the phishing shape; every domain in the text counts, file names like `Rechnung.pdf` do not) asks first, naming the real host; other http(s), `mailto:` and `tel:` links open as before, nothing else opens. No extra click for ordinary links. Source: `modules/mail/linkCheck.ts`.
- **Search on this device + in the mailbox (2026-11-23, round „Mail finden“, package 1):** the search runs twice: a local index over what the cache already holds (sealed headers, opened mails: sender, subject, preview, text, attachment names) answers first and offline, Gmail's answer follows below without the doubles, each part named („Auf diesem Gerät“ / „Im Postfach“). The index lives in memory only (`modules/mail/searchIndex.ts`), rebuilt from the sealed cache when it changes and dropped with it, so it can never reach sync, a backup, diagnostics or a model (`isolation.test.ts`, `core/ai/privacy.test.ts`); a persisted index (sealed Dexie table) was rejected: more to keep in step and to delete for ≈ 0,2 s saved per 5 000 mails. Typos are forgiven only in names (1 letter from 4, 2 from 8). Operators the cache cannot answer (`to:`, `size:` …) leave the local part silent instead of guessing. Hits are marked as React text, never HTML. Free words look at the sender's name and the address before the @ (a domain is no name; `from:` sees all of it); Gmail syntax without a colon (`-wort`, `OR`, groups) and user labels count as mailbox-only too. „Persönlich“ does not narrow a search. The device part shows 50 hits at a time. The cache keeps 1 000 headers per account (was 200) so the local part reaches back months; the list, head, widget and notifications still read the newest 200; Gmail's `hasAttachment` is read from the message type (`multipart/mixed`) of the metadata call, no new scope. Measured: [design/mail-find/ANALYSIS.md](../design/mail-find/ANALYSIS.md).
- **„Wartet auf mich“ and kinds (2026-11-23, round „Mail finden“, package 2):** a queue of the mails that want something from the person, by a rule they pick (`waitingRule`: to me, newest message not mine, no invoice or newsletter, last 30 days – default; or starred; or off), read from the cached headers only. „Erledigt“ (until a newer message) and „Morgen wieder“ (until 06:00) are device-local marks in `localStorage` (thread ids and times, never synced), each with an undo; no Gmail write, so the queue works read-only too. The count stands like a folder's, muted, never red. A walk goes mail by mail (Erledigt · Morgen wieder · Nächste; „In den Plan“ stays the mail’s own button). Kinds come from one local rule table (`modules/mail/kinds.ts`, pinned as a table): bulk tabs → newsletter, invoice words → invoice, not a person → newsletter. „Rechnungen“ and „Newsletter“ are chips beside „Persönlich“ (one filter at a time); a fourth order system (tabs) and a „Rest“ chip were rejected. The planner reads only `mailQueueSummary()` → `{ count, target }` and the route `/mail?view=waiting` (read once, removed from the address, no write); agreed with `design/planner-hub-2`, which adds the pile contribution itself.
