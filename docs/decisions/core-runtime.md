# Decisions in full – Core – runtime and performance

Part of [core](core.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Precache without tool views, chat view and zxcvbn dictionaries (2026-10-31):** they load on first use; the SW runtime cache keeps them offline; never loaded + offline = calm note, no error. Details, rule, budget: `perf/COLD-START-2026-10.md`.
- **Command palette loads on first opening (2026-11-03):** `layout/AppShell.tsx` mounts `CommandPalette` as `lazy()` only after `paletteOpen` was true once (the shortcut and the voice key only set the store flag, so they work before the chunk is there). Measured with `check:bundle`: critical path 667.5 → 635.8 KB gzip, 86 → 82 requests. Tried and dropped: lazy `ask`/`searchEntries` inside `useAssistant` and lazy `OnboardingWizard` alone (−2.6 KB, more requests: the pieces just move into shared chunks). Settings sections stay eager until the settings chat splits the registry (`scribble/perf-bundle-findings.md`).
- **Contribution hooks share one live query per input (2026-11-04, `perf/live-queries`):** `core/modules/sharedQuery.ts` `useSharedLiveQuery(key, querier)`: instances with the same key run the module sources once and re-run once per write (the home page mounted `useCalendarItems` 5×, `useAttentionItems` 3×, each with its own full scans); the query stops 50 ms after the last subscriber left. Behaviour as `useLiveQuery` (`undefined` first, previous result kept while another key loads, errors thrown to the boundary). The key must contain every input of the query. The function given to Dexie's `liveQuery` has to be a native `async` function, otherwise Dexie loses read tracking across `await` and the query never re-runs (found by `e2e/now-strip.spec.ts`). The lazy sources are loaded first (`prepare`), because a first run that awaits a still-pending `import()` loses tracking too (`calendar/__tests__/nextWidget.test.tsx` showed it). Measured: `perf/DATA-BASELINE-2026-11-03.md`.
- **Full text search keeps an in-memory index (2026-11-04, `perf/search-index`):** `core/ai/search/index.ts`, one MiniSearch (already a dependency, no new package) per database and set of enabled `aiSchema` collections, built by the first search and kept current from Dexie's `storagemutated` (also other tabs and sync): a changed table is re-read and only changed documents are replaced. No `updatedAt` watermark: rows applied by sync can be older than the newest local one, so it would miss them. Not persisted (nothing to migrate, sync or back up), dropped after 5 idle minutes, only collections with `searchable` in `aiModules`, so `accounts` is never in it. A worker was left out (documents would be copied to it). Measured: `perf/DATA-BASELINE-2026-11-03.md`.
- **Data-layer reads use the index they declare (2026-11-04, `perf/finance-data`):** measured with 33k rows (`perf/DATA-BASELINE-2026-11-03.md`), a read of a whole table (`repo.active().toArray()`) is the dominant cost, not memory or size. Where a read only needs a range, it uses `repo.table.where('date').between(…)` + `notDeleted` (finance month sums, subscription price window). `balances()` is one pass (was quadratic). Shared-snapshot caches of bookings were rejected for now: sync writes bypass module repos, so a cache cannot be invalidated safely at module level; sharing happens at the live-query/contribution level (next package). No new index without a reader.
- **Awaited `module.disabling` before the state and the wipe (2026-11-05, planner package 1):** `disableModule` emits `module.disabling` and awaits it before writing `enabled: false` and before a delete-policy wipe, so a module can hand foreign records back (the planner restores the ToDos' own dates). `bus.emit` swallows handler errors: a throwing listener never keeps a module switched on. No existing listener changed; `module.disabled` keeps firing afterwards.
- **Undo entries can carry a scope (2026-11-05, planner package 1, council):** `undoable(label, fn, scope?)` tags an entry with a module id and `forgetUndo(scope)` drops those entries – a module that is switched off (and maybe wiped) must not be replayed into by Ctrl+Z or a toast's Rückgängig. Only the planner uses it so far.
