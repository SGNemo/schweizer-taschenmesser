# Decisions in full – Core – sync basics and server

Part of [core](core.md). Index of areas: [DECISIONS](../DECISIONS.md).

## Sync

- **Field-level last-write-wins by greatest HLC; rule implemented twice on purpose** (`core/sync/ops.ts`, `server/src/store.ts`), pinned by `contract/lww-cases.json`. The server never merges values, only assigns a monotonic `seq`. Change both or neither. Source: architecture.md "Sync & backup".
- **`SyncAdapter` abstraction** (`selfHosted` built; `googleDrive.stub.ts` documents the unbuilt second backend). Source: architecture.md "Layers".
- **Optional E2E encryption of each op value (Argon2id → AES-GCM, AAD = `collection/id/field`)**; old PBKDF2 vaults are recognised and refused, not joined (`core/sync/vaultKey.ts`); ids/fields/HLC stay readable because the server needs them. Source: architecture.md "Encryption".
- **Server is single-tenant, no tombstone GC** – accepted known limits. Source: architecture.md "Not built / known limits".
- **The sync server's failed-login limit only slows wrong tokens; a valid token always passes.** Authentication runs first, then the per-address failure counter and its `429`. Why: clients behind one reverse-proxy address or LAN must not lock each other out; guessing stays capped by the per-address request limit and the ≥ 16-character tokens. Source: QA P6 (Tom, F-05); `server/test/devices.test.ts`.
- **Sync storage adapter works in batches (2026-11-04, `perf/sync-backup-batch`):** `readOutbox` and `applyRemote` read a chunk with one `bulkGet` per collection and write merged records with one `bulkPut` per collection; `markAllDirty` writes the outbox in slices of 5,000. Same results and order as before (tests in `core/storage/dexie.test.ts`); the merge rule `mergeOps` stays the single LWW implementation (client and server change together or not at all). Restore keeps one transaction (atomic); parsers stay on the main thread (small inputs, a worker copy would cost what it saves). Measured: `perf/DATA-BASELINE-2026-11-03.md`.
- **`syncSettled()` and the pull-complete flag (2026-11-05, planner package 1):** `core/sync/service.ts` `syncSettled()` is true without a sync configuration, otherwise only when this tab's sync chain is idle (a running round is awaited first – bounded by the queued rounds) and the last pull ended complete – `pullAll` clears a device-local `_meta` flag (`sync.pullComplete`, `StorageAdapter.setPullComplete`, optional for test doubles) when a pull starts and sets it after the last page. A paged or failed pull can split one record's field ops, so a consumer that acts on another device's fields (the planner on a ToDo's `plannedFor` + `planMark`) waits for the flag; nothing else touches `navigator.locks`. `core/db/metaKv.ts` (`getMeta`/`setMeta`/`deleteMeta`, optional database) holds device-local state, so modules never import `db`.
- **"Server is encrypted, no key" is decided on the whole pulled page, before the drift filter (2026-11-10):** `core/sync/engine.ts` `pullAll` throws `no-key` when any op of the page is ciphertext, and only then drops stamps beyond `MAX_HLC_DRIFT_MS`. Before, a keyless device whose clock was more than an hour behind dropped every encrypted op as "too far ahead", saw nothing encrypted and uploaded its plain data; the encrypted devices then stopped with `decrypt` on a page of plain ops only. Found through `e2e/sync` (the fresh-install test left its fixed-clock context open; it is closed now). The server side of this is the next bullet.
- **A server with a vault holds ciphertext only (2026-11-10):** `POST /v1/push` refuses a batch with any non-`enc:v1:` value as a whole (400 `missing-enc`, the LAN hub's code), and `PUT /v1/vault` refuses when ops are stored (409 `not-empty`), so plain data and a vault cannot come to coexist; before, a keyless device whose round fell between the vault's creation and the first encrypted push (empty page), or an older client, uploaded everything in plain text. The client maps `missing-enc` to `no-key` (not retried); a device with the key skips plain ops (counted as rejected, cursor moves on) and raises `decrypt` only when ciphertext is there and none of it decrypts. Clients before this change see a retried "server error" and keep their data queued. LWW is unchanged: a server that took plain ops earlier keeps them (an encrypted re-upload has the same stamps) until "reset and rebuild encrypted". Pinned in `contract/sync-paging-cases.json` (level `server`).
- **Sync token in the OS keystore in the apps (S5, 2026-11-23):** with `getPlatform().secrets.protection === 'os-keystore'` the own-server token lives under `sync.token` (`core/sync/names.ts`); the `_secrets.syncConfig` record keeps URL, key and device id with `token: ''` (the service worker reads only the key). An old record moves on the first `loadSyncConfig`, serialised with save and clear (a token lock) and only while the record still holds that token; a refusing keystore keeps the token in the record. A selfHosted record with an empty token always asks the secret store (whatever the start's probe said); none there → sync error `token-missing` with the reconnect step, no empty token is sent. Existence and kind checks (`hasSyncConfig`, `syncConfigKind`: planner, trash, bookmarks preview, status restore, Wi-Fi watcher) read the record only. The PWA keeps the token in the record: its `device-key` store is the same origin's IndexedDB, so a second place would add no second barrier. Reset deletes `sync.token`.
- **Security package 10, web part (2026-11-23, `fix/security-web-lows`):** (1) backup and share import pull a field stamp beyond `MAX_HLC_DRIFT_MS` back to now and keep the row (a clock running ahead must not cost data), so a file cannot plant a field that wins forever and stalls sync; a share file writes only the pair's modules, on first contact the ones it names (`planShare`/`applyShare` take them). (2) The self-hosted server sends the served PWA the desktop shell's CSP (the inline theme script allowed by its SHA-256, computed from `index.html` at start), `frame-ancestors 'none'`, nosniff and no referrer; the API keeps its own headers. (3) Web Push connects through an agent whose DNS lookup refuses private answers, so a rebinding endpoint never reaches the home network; IP literals are checked when stored. (4) Docker publishes on `BIND_ADDRESS` (default `0.0.0.0` as before; the doc says 127.0.0.1 behind a tunnel). Source: `core/backup/backup.ts`, `core/share/share.ts`, `server/src/{app,push}.ts`, `server/docker-compose.yml`.
