# Decisions in full – Core – device exchange: files

Part of [core](core.md). Index of areas: [DECISIONS](../DECISIONS.md). Concept: `docs/design/device-exchange/CONCEPT.md` §4–6; earlier packages: [core-device-exchange-hub](core-device-exchange-hub.md).

- **Device exchange package 2a: file records (2026-11-16, `feat/exchange-files`):** package 2 is cut in four (2b in two, see 2b-1): **2a** (`crates/lan-sync` only: file records and received names), **2b** (transport loop with an input-latency test, session flow, receiver store with part/resume/hash/limits/daily counter/`Zone.Identifier`, phone client), **2c** (shell commands by token, dialogs, drag-drop/picker, thumbnails, cards). Records in `exchange/wire.rs`: `offer`/`accept`/`wait`/`refuse`/`chunk`/`end`/`result`/`cancel`; `Offer` only via `Offer::new` (size ≤ 4 GB, raw name 1–255 bytes UTF-8 without NUL, media type `type/subtype` of RFC 6838 token characters ≤ 64 or empty – a receiver that cannot read it takes it as unknown); a decoded offer over 4 GB is `TooLarge` (answered `refuse {too-large}`), an unreadable one `Unusable` (answered `refuse {rejected}`); a sender passes its local name through `name::clean` (always a valid offer name); `Debug` shows no name, type or size; `chunk_header` lets the sender read a file straight behind the header; `accept.from` and `chunk.offset` ≤ 4 GB (no overflow in 2b); a chunk fills exactly one 65 535-byte frame; `FEATURE_FILES` defined but not offered, so a session still closes on a file tag.
- **Device exchange package 2a: received names (2026-11-16, `feat/exchange-files`):** `exchange/name.rs`. `clean`: every prototype case plus Windows specials; NFC before and after filtering; tab, line breaks and line separators become one space; controls, format characters and every default-ignorable code point go (accepted: ZWJ/ZWNJ go too, so an emoji sequence or a Persian joiner in a name falls apart – the threat, bidi and zero-width, is in the same class); blank-looking letters and `<>:"/\|?*` become `_`; the stored name is cut **at the end** to ≤ 120 bytes with its extension kept (the card cuts in the middle, package 2c); a cut never creates an extension the name did not have (`a….exe.bbbb…` → `a….exe_`; the prototype gave `.sc` for its `.scf…` case); device names with `_`; shortcut and theme types (now with `pif`) and the whole name `desktop.ini` get `_` on the final name; fallback `Datei` (2b/2c: a localized fallback or an extension from the media type); a trailing `_` (defused or cut) is explained on the card in calm words (2c). Every Unicode space becomes one plain space. `risk`: allow-list. `candidates`: the name, then " (2)" … " (9999)" before the last extension within 120 bytes (`Backup.tar (2).gz`, accepted) – the store creates each create-new and takes the first that works; `unique` wraps it with an existence check. `part`: device key and id only. NFC and the categories come from `icu_normalizer`/`icu_properties` 2.3 (range, not pin) – the versions the shell already locks through `url`/`idna`, so the app gains two dependency edges and no library. The downloader's `name.rs` stays as it is.
- **Device exchange package 2b-1: file flow and transport loop (2026-11-16, `feat/exchange-transfer`):** `crates/lan-sync` only; the store on disk and the phone's use of the client are **2b-2**. Boundary `exchange::files::ExchangeFiles` (receive: `offered` → accept from an offset / wait / refuse, `decided` for the user's late answer, `write`, `finish`, `stopped(Lost | Cancelled | Withdrawn)`; send: `next_offer(skip)`, `queued`, `read`, `sent(Waiting | Refused | Done | Cancelled | Interrupted)`); its header states the timing (asked at most every 50 ms; `write`/`read` once per chunk on the connection's thread; hash incrementally; the one long call is `offered` re-hashing a part) and that a replaced session may still deliver a late call (the store serializes per device and id, newest wins). `Exchange::with_files`: `FEATURE_FILES` only when the shell wired files. `exchange/transfer.rs`, per direction: one active transfer (offered, streaming, ended) plus up to **3 offers waiting** for the receiver's user that do not hold the slot (a device accept for a waiting PC file starts it when the slot frees; the PC's late decisions are asked only while nothing comes in); the next offer only when nothing is active (else the session closes); chunks contiguous and within the size; frames that crossed an end are dropped, never a reason to close; `end` before the last byte answers `mismatch` without `finish`; a file the PC took out of its queue is cancelled at the device; at most 64 incoming offers and 64 outgoing failures per session; while a file streams, switch, grant, outbox and shell are asked at most every 50 ms. Transport loop: up to 64 incoming frames that are already there, then unasked frames for one tick or 256 frames (stopping at once on stop or a closed connection), then a 1 ms read while frames wait – 8 MB PC → phone 27.8 s with the old loop, under 5 s now; media key presses on the input session during the transfer reached the PC well under 250 ms **on loopback** (the test allows 15 s / 1 s for CI); over Wi-Fi a transfer shares the air: hand test AX-T1. Device client: `open_with(features)` (`open` stays text only), file events (`wire::ChunkBytes`, `Debug` shows the length), senders, and a guard on the PC's file frames (only for an accepted offer, contiguous, within its size, at most 3 standing offers; late frames dropped); `on_event` must not block. For 2c: a 300-an-hour limit counts delivered files like items (show „geht in N Minuten weiter“ calmly), and „Annehmen“ prompts go when an offer is withdrawn.
