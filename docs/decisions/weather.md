# Decisions – Weather

- **Weather line (2026-10-19, package 4a):** one muted line under "Jetzt wichtig" (`core/weather/*`, synced scope `weather` {enabled default on, place, lat, lon}); nothing is shown or requested until a place is chosen (Settings → Verbindungen → Wetter), no error text when unreachable. Open-Meteo (no key); only the typed name (search) and the position rounded to ~1 km go out, plain `fetch`. Registered as data flow `weather` (+ one-time notice, DATA-FLOWS, website, README, user docs). Rain hint: first of the next 12 h with ≥ 60 %. Not a module (no collection). Open for the maintainer: Open-Meteo's free tier is non-commercial with attribution (CC BY 4.0); check that it fits before release.
- **Weather follow-up (2026-10-19):** the line is a single link element (icon + text) to the settings; without a place one hint "Wetter: Stadt wählen" with "Später nicht mehr" (device-local `tm-weather-hint`, then only the settings). Cache in `core/weather/cache.ts`: no request while offline, old values stay with "Stand hh:mm" and without the rain hint, removing the place clears the cache; a failed request waits 5 min before the next try (no request storm while the service is down). The line's accessible name is its text (no `aria-label`). Parsers are Zod. Place and position are canaries in the diagnostics negative-list test. No setup-assistant step (calmer first run; the hint and the settings suffice). Details: [features/weather.md](../features/weather.md).
- **Attribution (2026-10-23):** the weather settings credit Open-Meteo.com (CC BY 4.0) with a link, in all five languages; independent of the open licence question.
- **Cache values are validated (2026-10-24):** `tm-weather` and `tm-weather-tried` are parsed with Zod in `core/weather/cache.ts` (group must be a known `CodeGroup`); an invalid or foreign value reads as absent and its entry is removed, so the line just asks again. No change to `api.ts`, `settings.ts` or the line.
- **Weather preview (2026-10-29):** a tap on the line opens a calm `Dialog` (12 h + 7 days, text rows, no colour or warning, rain only from 30 %) instead of the settings, which stay one link away. Chosen without asking: one request as before (`hourly`/`daily`, `forecast_days=7`), no new data flow, only the rounded position leaves; the cache schema is additive (an old value stays valid for the line, the open preview asks once); "now" is the place's clock, not the device's; icons only from the existing set (sun / thermometer), no new route, widget or notification.
- **Weather preview v2 (2026-10-29):** on the maintainer's wish the preview became a wide, graphic view: SVG chart (no chart dependency), 24 h list, felt temperature / wind / gusts / humidity / UV / sun times / rain amount, and a three-step rating (good / so-so / unpleasant) with "Beste Zeit". Still one request and only the rounded position leaves; the extra values are optional in the cache (old values stay valid). Colour only for the rating and always with word and icon, no red (warning amber for "unpleasant"), rain named from 30 %. Rating thresholds live in `rate()`; the weather icons are added to the shared icon set (`ui/icons.tsx`, lucide names already bundled).
- **Air quality and pollen (2026-10-30):** on the maintainer's wish (asthma, allergy) the preview gets an "Atemwege & Allergie" section from Open-Meteo's air-quality API: the same provider and the same rounded position, so no new data flow, only one more request (documented in DATA-FLOWS wording). Optional by design: failure or a place without data never touches the forecast. Pollen limits per type are approximate and the rating errs on the careful side; the section says it is orientation, not medical advice. No settings entry (nothing to configure, the weather switch covers it); the Dialog got an additive size `xl`.
- **Weather preview v3: colour with meaning, fewer things at once (2026-10-31):** on the maintainer's wish ("übersichtlicher, mehr Farben") the window got structure, not decoration. Colour only where it says something and always next to a word or number: rating as a soft chip + a quiet rail at the row's left (good = green, unpleasant = amber), rain in blue, strong UV / pollen in amber, temperature tone (cold blue, warm amber), the week's range bars as a cool→warm gradient, pollen steps graded (low green, moderate amber, high/very high accent), air quality value coloured by band. "Now" is a tinted card with the facts as small icon tiles instead of one dotted line. No red (overdue only, `ui/semantics.ts`), no new data.
