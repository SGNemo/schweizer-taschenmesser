# Decisions – Weather

- **Weather line (2026-10-19, package 4a):** one muted line under "Jetzt wichtig" (`core/weather/*`, synced scope `weather` {enabled default on, place, lat, lon}); nothing is shown or requested until a place is chosen (Settings → Verbindungen → Wetter), no error text when unreachable. Open-Meteo (no key); only the typed name (search) and the position rounded to ~1 km go out, plain `fetch`. Registered as data flow `weather` (+ one-time notice, DATA-FLOWS, website, README, user docs). Rain hint: first of the next 12 h with ≥ 60 %. Not a module (no collection). Open for the maintainer: Open-Meteo's free tier is non-commercial with attribution (CC BY 4.0); check that it fits before release.
- **Weather follow-up (2026-10-19):** the line is a single link element (icon + text) to the settings; without a place one hint "Wetter: Stadt wählen" with "Später nicht mehr" (device-local `tm-weather-hint`, then only the settings). Cache in `core/weather/cache.ts`: no request while offline, old values stay with "Stand hh:mm" and without the rain hint, removing the place clears the cache; a failed request waits 5 min before the next try (no request storm while the service is down). The line's accessible name is its text (no `aria-label`). Parsers are Zod. Place and position are canaries in the diagnostics negative-list test. No setup-assistant step (calmer first run; the hint and the settings suffice). Details: [features/weather.md](../features/weather.md).
- **Attribution (2026-10-23):** the weather settings credit Open-Meteo.com (CC BY 4.0) with a link, in every app language; independent of the open licence question.
- **Cache values are validated (2026-10-24):** `tm-weather` and `tm-weather-tried` are parsed with Zod in `core/weather/cache.ts` (group must be a known `CodeGroup`); an invalid or foreign value reads as absent and its entry is removed, so the line just asks again. No change to `api.ts`, `settings.ts` or the line.
- **Weather preview (2026-10-29):** a tap on the line opens a calm `Dialog` (12 h + 7 days, text rows, no colour or warning, rain only from 30 %) instead of the settings, which stay one link away. Chosen without asking: one request as before (`hourly`/`daily`, `forecast_days=7`), no new data flow, only the rounded position leaves; the cache schema is additive (an old value stays valid for the line, the open preview asks once); "now" is the place's clock, not the device's; icons only from the existing set (sun / thermometer), no new route, widget or notification.
- **Weather preview v2 (2026-10-29):** on the maintainer's wish the preview became a wide, graphic view: SVG chart (no chart dependency), 24 h list, felt temperature / wind / gusts / humidity / UV / sun times / rain amount, and a three-step rating (good / so-so / unpleasant) with "Beste Zeit". Still one request and only the rounded position leaves; the extra values are optional in the cache (old values stay valid). Colour only for the rating and always with word and icon, no red (warning amber for "unpleasant"), rain named from 30 %. Rating thresholds live in `rate()`; the weather icons are added to the shared icon set (`ui/icons.tsx`, lucide names already bundled).
- **Air quality and pollen (2026-10-30):** on the maintainer's wish (asthma, allergy) the preview gets an "Atemwege & Allergie" section from Open-Meteo's air-quality API: the same provider and the same rounded position, so no new data flow, only one more request (documented in DATA-FLOWS wording). Optional by design: failure or a place without data never touches the forecast. Pollen limits per type are approximate and the rating errs on the careful side; the section says it is orientation, not medical advice. No settings entry (nothing to configure, the weather switch covers it); the Dialog got an additive size `xl`.
- **Weather preview v3: colour with meaning, fewer things at once (2026-10-31):** on the maintainer's wish ("übersichtlicher, mehr Farben") the window got structure, not decoration. Colour only where it says something and always next to a word or number: rating as a soft chip + a quiet rail at the row's left (good = green, unpleasant = amber), rain in blue, strong UV / pollen in amber, temperature tone (cold blue, warm amber), the week's range bars as a cool→warm gradient, pollen steps graded (low green, moderate amber, high/very high accent), air quality value coloured by band. "Now" is a tinted card with the facts as small icon tiles instead of one dotted line. No red (overdue only, `ui/semantics.ts`), no new data.
- **Hourly list shows every third hour by default (2026-10-31):** the 24-row list was the part where people got lost; now 8 rows (every third hour, starting now) with a ghost switch "Alle Stunden zeigen" / "Nur alle 3 Stunden" next to the heading. The state lives only while the window is open (no setting, calmer by default every time); the chart above always shows all 24 hours.
- **Places and severe-weather hints (2026-11-03):** up to five places (main + four), rename, order, make main. Hints for today/tomorrow come only from the already cached forecast (never a request): always in "Jetzt wichtig" (`warning`, not red), a notification only when `warnNotify` is on (off by default, one for the morning, one for the evening before, `soft` + `local`). Still own hints, not official warnings. Radar not built (new third-party host).
- **Weather scenes, design round (2026-11-24):** the head's small sky becomes one illustrated scene (layers by weather, time of day, wind, frost, season; landscape "Mittelgebirge", no chooser), the hint of the day moves into the stage (still "berechnet, keine amtliche Warnung"), the word follows the WMO code. Moon and sky events are calculated on the device by an own small module (5.5 KB gzip, measured against astronomy-engine: light ≤ 0.01 pp, rise / set ≤ 0.2 min) – no dependency, no new network destination; lunar eclipses from a shipped table to 2050. Motion answers opening the page: 5 s, then still; on by default with "Standbild" and "Schlicht" one setting away (decided in the round, the maintainer may turn the default). No moon is drawn until it is calculated. Struck for lack of a source: aurora, official warnings, planets. `Sky` is not grown (the music head never used it) and goes with package 4. Why and how: [design/weather-scenes](../design/weather-scenes/README.md); built in five packages (1a, 1b, 2, 3, 4).
- **Weather scenes, the maintainer's answers (2026-11-24):** the overview widget gets the scene as its card background (the one named exception to "a widget is a tone step"; "Ruhig" keeps the plain card); motion stays on by default and "Standbild" switches it off; aurora and official warnings may use new sources – NOAA SWPC's Kp forecast (a global file, no position sent) and the DWD's warning service for places in Germany (position ~1 km), only for a main place inside Germany, from DWD level 2, replacing the computed hint of the same kind; the switch "Amtliche Warnungen" is on by default; built as package 3b with two new DATA-FLOWS rows ([CONCEPT-SOURCES](../design/weather-scenes/CONCEPT-SOURCES.md)).
- **Weather scenes 1a – word by code, data, ice hint (2026-11-24):** the word follows the WMO code (22 words, COPY §1) at every place a word stands; `CodeGroup` keeps nine members (cache validity, frozen languages), the raw `code`, `tz` and `now.snowDepth` sit beside it, all optional, so old caches stay valid and need no refetch. The one extra word in the head's detail line uses limits of the picture only (no rating or hint changes). UV is shown only while the sun is up at the place; at night the third chip is the next sunrise. New hint kind `ice` for freezing drizzle and rain (56, 57, 66, 67), ordered after wind and before rain; frost gets the thermometer. The bar above the head and its sentence stay until package 1b.
- **Weather scenes 1b – the scene in the head (2026-11-25):** the head's `Sky` gives way to one SVG scene (`ui/weather-scene`, a port of `mockups/scene.js` shape by shape; model `core/weather/scene.ts`). Colours are `--scene-*` tokens and `color-mix()` of them, declared once per scene as custom properties on the `<svg>`; "Ruhig" / "Modulfarben: Aus" draw the same shapes through a grey filter and a surface wash instead of a second palette. The ink of text on the stage follows the scene (`data-ink`), chips, pill, module row and gear keep the theme's ink on an opaque backing. The hint is a pill in the stage (no bar above the head); stage 280 / 272 px. Motion 5 s after opening, then rest; setting "Bild im Wetter-Kopf" (motion · still · plain) in the shared `weather` scope. No moon until package 2. One stop changed: dawn bottom `#7d6390` → `#7c628f` (4.48 → 4.55 : 1 with the light ink; the mockup's own measure missed the 4.5 line by rounding).
- **Weather scenes 2 – the moon (2026-11-25):** the moon is calculated on the device by `core/sky/` (a TypeScript port of `reference/astro`, Meeus with all 60 terms; no dependency, no network), checked against `vectors.json` (astronomy-engine 2.1.19) with the tolerances of CONCEPT-MOON §7. Names by rule (ii) on the place's local day (`Forecast.tz`, `Intl`), rise and set only when read. Moonrise / moonset search: the reference's 10-minute grid, but far from the horizon it jumps by |altitude| / 0.3° per minute (the altitude cannot change faster), which finds the same events (test against the plain grid, Tromsø included) and brings `moonOfDay` for seven days + now to 3.7 ms median at CPU ×4 (6.4 ms with the plain grid). The day moon stands at its own place in the sky, not at the mockup's fixed spot (which could sit on the sun), and is left out of the phone's crop. Switch "Mond und Himmelsereignisse" (on by default): off = no moon anywhere, the night chip falls back to the sunrise.
