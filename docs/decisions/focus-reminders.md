# Decisions in full – Focus and attention aids – notifications and reminders

Part of [focus](focus.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Notification policy in one place (2026-10-03):** all channels go through `collectDue` (quiet hours for automatic extras only, hourly limit folds the surplus into one summary). Rejected: dropping surplus notifications (information loss) and moving explicitly set reminders into the morning (an early flight reminder must stay early). The morning digest replaces per-task ToDo notifications; both stay opt-out.
- **Notification centre instead of an automatic banner (2026-10-03):** the bell (top bar, count + live region) opens a dialog with "Nächste Erinnerung" (earliest open), "Zufällige Erinnerung" (+ "Noch eine", never the same twice in a row), the open list, Erledigt / Später / Öffnen and "Alle gelesen"; the same two buttons are in the "Als Nächstes" widget and the command palette. "Open" = `collectDue` of the last 24 h (same sources and calm policy as the scheduler) minus answered base keys (`reminders.acked`, device-local); "Später" = snooze entry + answered. Rejected: a `done` field on events (schema change, reminders recur) and storing fired notifications (a second source of truth). "Öffnen" does not mark done (explicit, calm).
- **In-app card is opt-in (2026-10-03):** `focus.inAppPrompt` default `false` (was `true`), new `inAppPosition` (top|bottom) and `inAppSeconds` (0 = until answered). Values stored by users stay; only users who never touched it change. OS notifications (permission granted) are unchanged: with the card off the scheduler shows the OS popup as before.
- **"Stumm": a pause, not a switch-off (2026-10-12, `feat/comfort-mute`).** One hour or until tomorrow 08:00, ends by itself, device-local (`localStorage` `tm-mute`; `core/notifications/mute.ts`). Applied last in `applyPolicy`, so every channel (in-app card, Android schedule, Web Push upload) agrees: reminders the user set explicitly still arrive but **without sound** (`DueNotification.quiet` → `silent` in the browser/service worker, low-importance channel `nemo-quiet` on Android); automatic extras (`soft`) wait for the end. Nothing is lost and nothing important is held back. Not silenced: the OS toast sound of desktop notifications (the plugin has no switch). Started in Settings (quick bar) and the palette.
- **Reminders repeat until answered, calmly (2026-10-17, `feat/repeat-reminders`).** `focus.followUp` (default now **on**, only explicit calendar reminders) turns the single follow-up into `:r1…:r<max>` every 10/30/60 min (default 30), cap 3/6/10 (default 6) with a polite last text; "Noch offen: …", no blame. Repeats in quiet hours or "Stumm" are dropped, not moved (a pile at 07:00 would be a flood) and still count toward the cap; the hourly limit applies, repeats rank behind first-time reminders. Answers moved from device-local `_meta` to the synced `reminders` scope, one field `ack:<key>` per answer (fields merge independently, so two devices answering different reminders offline lose nothing; answers older than 3 days are dropped on write; older local answers still read). Limit: an answer reaches other devices with the next sync; until then their scheduled repeats can fire, at most once per gap. A repeat popup uses the reminder's key as OS tag and after a long pause only the latest repeat is shown. "Später" on a repeat stores the reminder's own title (`baseTitle`). Existing installations keep `followUp` off (`LEGACY_FOCUS_DEFAULTS`), fresh ones start with it on. "Später" entries and appointments do not repeat; the Android alarm budget favours first-time reminders.
- **Zock-Modus: leise Zustellung im Vollbild-Spiel (2026-10-17, `feat/gaming-quiet-reminders`).** Entschieden ohne Rückfrage: (1) Erkennung nur über Windows' `SHQueryUserNotificationState` (beschäftigt, D3D-Vollbild, Präsentation) als ein Ja/Nein, nie Prozessliste oder Fenstertitel; wird bei jeder Zustellung abgefragt, kein Dauer-Polling. (2) Schalter `off | auto | on`, geräte-lokal wie „Stumm“ (`tm-game-mode`); Standard `auto` auf dem Desktop (ändert nur, wie leise etwas ankommt, nichts geht verloren), sonst `off`. „Immer“ ist bewusst nicht befristet (ein Spiel dauert länger als eine Stunde); er wirkt nur auf die Zustellart, Erinnerungen kommen weiter an. (3) Ton: Web Audio bei sichtbarem Fenster, sonst Rust `PlaySound` (WebView2 drosselt/blockiert Audio bei verstecktem Fenster); die Noten kommen aus einer Quelle (`sound.ts`) und Rust rendert nur, was validiert ist (≤ 8 Noten, ≤ 2,5 s, 100–4000 Hz). (4) „Stumm“ gewinnt immer: eine stumme Erinnerung bekommt keinen Ton. (5) App-Ton < 1,2 s, sanft, Standard 40 %. (6) Android/PWA: kein Ton, „An“ sammelt Erinnerungen als `quiet` (`policy.ts` `quietAll`). (7) „OS-Ton nicht stumm schaltbar“ (Stumm-Eintrag) war zu vorsichtig: ohne `sound` ist der Toast `silent`; Handtest Z1.
- **User-set reminders may repeat until answered (2026-10-17, focus round 2):** the earlier "never a chain" rule now applies only to automatic extras. A reminder the user set explicitly repeats at a settable interval (default 30 min) until "Erledigt" or "Später", with a cap (default 6), quiet hours, Stumm and the per-hour limit unchanged. Why: a single missed reminder is the most common failure the app is meant to catch; the guardrails keep it from becoming pressure. Built in `feat/reminder-repeat`.
- **Calm Erinnerungen tab (2026-10-24):** row = "Erledigt" (= the existing pause, no new state) + "⋯"; a repeat only gets "Pausieren" (Erledigt would end the series).
- **P5 package A: reminders honest and calm (2026-10-29, `feat/qa-reminders-safety`):** (1) Settings text depends on the platform (`notifications.intro*`): Android hands reminders to the OS, desktop only while running, PWA needs push for a closed app; the push card is hidden on native. (2) Appointment with a time gets "Erinnern: Keine · 1 h · 1 Tag · Andere Zeit" (`LeadRow`); "Als Vorgabe merken" stores `focus.eventLead`, which only preselects the chip in the editor, never switches reminders on for other appointments. A missing-permission note appears only after a lead is chosen, one sentence, "Nicht mehr zeigen" / switch `focus.leadHint` (default on: it is part of the user's own action, not an automatic notification). (3) "Genommen": optional `taken` flag on a reminder renames the answer; same ack, nothing counted. (4) The hourly summary carries `members`; the centre lists them by title and folds what is from before today under "Früher"; automatic (`soft`) extras from before today clear themselves, explicit reminders never do. (5) "Ruhe" is the one name for the pause (`tm-mute`) and the gaming mode (`tm-game-mode`); storage unchanged, no migration; coupling to shifts/events deferred (no shifts model).
