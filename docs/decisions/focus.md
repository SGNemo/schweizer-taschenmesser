# Decisions in full – Focus and attention aids (2026-10-02)

One-line summary: [DECISIONS](../DECISIONS.md) → UI section.

- **Opt-out per aid, sensible defaults:** every aid (next-one-thing, day plan, calm attention strip, focus mode, time-to-next) is a setting in the core section "Fokus & Aufmerksamkeit", synced scope `focus`; device-local state (focus timer, skipped suggestions) lives in `_meta`. Alternative rejected: a single "focus mode" master switch (too coarse, hides what each aid does).
- **No pressure by design:** overdue ToDos read "Wartet noch" with no daily counter; red stays for money deadlines and exceeded budgets; "Neu planen" spreads ToDos over the next days with undo. Streaks (package 4) get rest days and never show a loss.
- **Order of work:** package 1 "Anfangen" (next-one-thing, day plan, calm strip, focus mode, estimates), 2 "Erinnerungen", 3 "Erfassen/Ruhe/Wiederfinden", 4 "Fortschritt"; one PR each. Details, mockups and scope: [../features/focus-aids.md](../features/focus-aids.md); rules: [../design/FOCUS-GUIDELINES.md](../design/FOCUS-GUIDELINES.md).
- **Doc budgets raised** (start context 2 600 instead of 2 000, STATUS 5 000, CHATS and PROMPT-TEMPLATES 2 000): small rule additions no longer force cuts elsewhere; the target stays ≈ 2 000 (`docs/meta/DOCS-GUIDE.md`).
- **Notification policy in one place (2026-10-03):** all channels go through `collectDue` (quiet hours for automatic extras only, hourly limit folds the surplus into one summary). Rejected: dropping surplus notifications (information loss) and moving explicitly set reminders into the morning (an early flight reminder must stay early). The morning digest replaces per-task ToDo notifications; both stay opt-out.
- **"Später" lives in the synced `reminders` scope (2026-10-03):** one small array, pruned on write, so "Wenn ich am PC bin" works across devices without a new collection (no schema change). The in-app card, not OS buttons, is where snooze happens (no native action buttons in the Android plugin).
- **Capture saves instead of asking (2026-10-03):** a doubtful quick-capture text goes to the ToDo inbox exactly as typed. Rejected: guessing the type from the parsed fields (the parser removes dates and amounts from the title, so a wrong guess loses information) and keeping the question as default (it is the decision moment that makes people not capture at all). Sorting later is one thing at a time.
- **Display aids stay device-local (2026-10-03):** text size, line spacing, in-app motion and the calm home view live in `localStorage` like the other display choices, so a phone and a desktop can differ; they are applied before first paint.
- **Notification centre instead of an automatic banner (2026-10-03):** the bell (top bar, count + live region) opens a dialog with "Nächste Erinnerung" (earliest open), "Zufällige Erinnerung" (+ "Noch eine", never the same twice in a row), the open list, Erledigt / Später / Öffnen and "Alle gelesen"; the same two buttons are in the "Als Nächstes" widget and the command palette. "Open" = `collectDue` of the last 24 h (same sources and calm policy as the scheduler) minus answered base keys (`reminders.acked`, device-local); "Später" = snooze entry + answered. Rejected: a `done` field on events (schema change, reminders recur) and storing fired notifications (a second source of truth). "Öffnen" does not mark done (explicit, calm).
- **In-app card is opt-in (2026-10-03):** `focus.inAppPrompt` default `false` (was `true`), new `inAppPosition` (top|bottom) and `inAppSeconds` (0 = until answered). Values stored by users stay; only users who never touched it change. OS notifications (permission granted) are unchanged: with the card off the scheduler shows the OS popup as before.
- **"Stumm": a pause, not a switch-off (2026-10-12, `feat/comfort-mute`).** One hour or until tomorrow 08:00, ends by itself, device-local (`localStorage` `tm-mute`; `core/notifications/mute.ts`). Applied last in `applyPolicy`, so every channel (in-app card, Android schedule, Web Push upload) agrees: reminders the user set explicitly still arrive but **without sound** (`DueNotification.quiet` → `silent` in the browser/service worker, low-importance channel `nemo-quiet` on Android); automatic extras (`soft`) wait for the end. Nothing is lost and nothing important is held back. Not silenced: the OS toast sound of desktop notifications (the plugin has no switch). Started in Settings (quick bar) and the palette.
- **Reminders repeat until answered, calmly (2026-10-17, `feat/repeat-reminders`).** `focus.followUp` (default now **on**, only explicit calendar reminders) turns the single follow-up into `:r1…:r<max>` every 10/30/60 min (default 30), cap 3/6/10 (default 6) with a polite last text; "Noch offen: …", no blame. Repeats in quiet hours or "Stumm" are dropped, not moved (a pile at 07:00 would be a flood) and still count toward the cap; the hourly limit applies, repeats rank behind first-time reminders. Answers moved from device-local `_meta` to the synced `reminders` scope, one field `ack:<key>` per answer (sync merges fields independently, so two devices answering different reminders in the same offline window lose nothing; answers older than 3 days are dropped on write; older local answers still read). Remaining limit: an answer reaches other devices only with the next sync, so until then their (already scheduled) repeats can still fire, at most once per gap. A repeat popup uses the reminder's key as OS tag and after a long pause only the latest repeat is shown. "Später" on a repeat stores the reminder's own title (`baseTitle`). Existing installations keep `followUp` off (`LEGACY_FOCUS_DEFAULTS`), fresh ones start with it on. Chosen without asking: default on for explicit reminders as requested; "Später" entries and appointments do not repeat; Android alarm budget favours first-time reminders over repeats.

- **Calm defaults for new installations (2026-10-14, focus audit 2, package 1):** the home view starts as "Nur das Wichtigste" (`HOME_VIEWS` order: calm first), `streaks`, `weekReview` and `moduleNow` are off by default. Why: the default home was ~20 widgets / 6598 px on the phone and every extra counter or repeated strip is stimulus without a diary-proven benefit. Nothing is removed; each is one switch away. An installation that already existed keeps its behaviour: at the first start of this version `core/focus/defaults.ts` writes the old values explicitly (only where nothing was stored) and sets the home view to "all" if none was chosen; a fresh app (no setup state, no data) is detected before `ensureSetupState` and gets the new defaults. Marker `_meta` `focus.defaultsEra`. Risk: a second device that syncs an account before the first one started the new version may briefly show the new defaults.
- **Focus settings: 14 visible rows → 6 + "Weitere Einstellungen" (2026-10-14):** the rarely changed ones (plan limit, timer length, sound, indicator, module strips, streaks, week review, search history) sit in a folded block; stored keys and search anchors are unchanged (a deep link opens the block first).
- **Zock-Modus: leise Zustellung im Vollbild-Spiel (2026-10-17, `feat/gaming-quiet-reminders`).** Entschieden ohne Rückfrage: (1) Erkennung nur über Windows' `SHQueryUserNotificationState` (beschäftigt, D3D-Vollbild, Präsentation) als ein Ja/Nein, nie Prozessliste oder Fenstertitel; wird bei jeder Zustellung abgefragt, kein Dauer-Polling. (2) Schalter `off | auto | on`, geräte-lokal wie „Stumm“ (`tm-game-mode`); Standard `auto` auf dem Desktop (ändert nur, wie leise etwas ankommt, nichts geht verloren), sonst `off`. „Immer“ ist bewusst nicht befristet (ein Spiel dauert länger als eine Stunde); er wirkt nur auf die Zustellart, Erinnerungen kommen weiter an. (3) Ton: Web Audio bei sichtbarem Fenster, sonst Rust `PlaySound` (WebView2 drosselt/blockiert Audio bei verstecktem Fenster); die Noten kommen aus einer Quelle (`sound.ts`) und Rust rendert nur, was validiert ist (≤ 8 Noten, ≤ 2,5 s, 100–4000 Hz). (4) „Stumm“ gewinnt immer: eine stumme Erinnerung bekommt keinen Ton. (5) Der App-Ton ist kurz (< 1,2 s), sanft, Lautstärke mit gemäßigter Kurve, Standard 40 %. (6) Android/PWA: kein Ton, „An“ sammelt die Erinnerungen als `quiet` (Kanal `nemo-quiet`/`silent`) über `policy.ts` `quietAll`. (7) Der Stumm-Eintrag oben („OS-Ton der Desktop-Toasts nicht stumm schaltbar“) war zu vorsichtig: ohne `sound` ist der Toast laut Quelltext `silent`; Handtest Z1 prüft das.
- **User-set reminders may repeat until answered (2026-10-17, focus round 2):** the earlier "never a chain" rule now applies only to automatic extras. A reminder the user set explicitly repeats at a settable interval (default 30 min) until "Erledigt" or "Später", with a cap (default 6), quiet hours, Stumm and the per-hour limit unchanged. Why: a single missed reminder is the most common failure the app is meant to catch; the guardrails keep it from becoming pressure. Built in `feat/reminder-repeat`.
- **Second round of improvements before the week of use (2026-10-17):** five parallel chats (voice key, AI reminders, quiet ping, reminder repeat, focus package 2) run before the diary week, prompts in `docs/product/focus/13-parallel-prompts.md`. Stimulus numbers are measured with `npm run measure:stimulus` before and after each package.
- **One "Heute" card instead of three lists (2026-10-17, audit 2, package 2a):** `todos:next` (key unchanged) is the card: time to next appointment, "Jetzt dran", plan, today's appointments (`todos/today.ts`); the suggested task is not repeated in the plan. `calendar:next`/`calendar:today` stay registered (they work without ToDos, stored choices untouched) and are only left out while the card exists (`withoutFolded`, `home/layout.ts`). Deliberately not in `LEGACY_WIDGET_KEYS` (renames only: mapping a hidden "Heute & Morgen" would hide the card). Tomorrow's appointments left the home. "Anfangen" is the one filled button, "Etwas anderes" is in the "⋯" menu.
- **Pinning = additive `pinned` list in the home layout (2026-10-17):** `_settings` scope `home` gets `pinned: string[]` (zod default `[]`, old records read as none, no migration write). Calm view = card + pins; "Mehr anzeigen · n" switches the device-local view to "all", "Anheften…" opens the edit mode (pin toggle; pinning un-hides). Rejected: a separate pin store, pinning the attention strip.
- **Calm ToDo page (2026-10-18, package 2b):** head = add field + one "⋯" menu (list filter as checked entries, named in words under the title; "Neue Liste", "Erweitert", "Mit KI eintragen"). Pages tell the shell their wishes via `core/shell/pageChrome.ts` (`hideFab`, `writeInMenu`; only ToDos so far). "Wartet noch" is one `GroupedList` group with "Neu planen" as `action`, each waiting row has a visible "Auf heute". Rejected: folding it by default (needs a second state), a button on every row.
- **"Später" is one rule (2026-10-19, package 3):** `todos/postpone.ts`: plan for tomorrow, a date due today/past moves too, a later plan is never pulled forward; also skipped for today's suggestion (a date within 3 days would bring it back). Used by the card, the first entry of every open row's menu and the swipe-left. No new row button (stimulus). Touch targets: real gaps (logo, skip link, short tabs, calendar day numbers) fixed in shared CSS; controls with a deliberate 44 px hit area (icon/small buttons, switch tracks, chips, segments) are accepted and excluded in `e2e/targets.spec.ts`.
