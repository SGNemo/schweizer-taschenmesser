# Decisions – Tools

- **Screenshot tool (2026-10-19, focus audit 2, package 4b):** `tools/screenshot`, group extra, **off by default** (a daily function for one person, one more entry for everyone else), the toolbar/library like any tool. Browser/desktop app: `getDisplayMedia` → one frame → PNG on the page; Save (`getPlatform().saveFile`) or Copy (clipboard image); nothing is stored or sent, the picture is gone on discard. A dismissed picker is "Nichts aufgenommen.", not an error; phones and webviews without capture get a plain explanation and no button. No new dependency, no new data flow (the picture never leaves the page). Rejected: a home widget (a button that needs a picker prompt is not a glance), "into a note" (tools never write to modules). A shortcut for it comes with the shortcut map (4c).
- **Screenshot tool follow-up (2026-10-19):** optional 3 s pause that starts *after* the source is picked (so the user can switch windows; `getDisplayMedia` needs the click's user activation, which a pause before the picker could lose); plain-text counter with a Cancel button, no animation. Copy stays on the Web `ClipboardItem` API on every platform (`getPlatform().clipboard` is text-only; an image method would touch the platform seam hotspot). Share only where `navigator.canShare` accepts a file. Closing the sheet during the pause or the picker ends the capture (stream stopped, no object URL kept). `NotSupportedError` (a webview that refuses capture) shows the same "not available here" text as a missing API. A Rust capture would be a new dependency: left to the maintainer.
- **Text compare and regex tester (2026-10-24, `feat/tools-diff-regex`):** `tools/diff` and `tools/regex`, group dev, **off by default** (few people need them; one more toolbar entry for everyone else), chords `T F` / `T E`. Decided without asking: (1) Diff is our own LCS on lines, then on words of paired changed lines, no dependency; "n lines changed" counts per block the larger of removed/added (a rewritten line once). Input is limited to 20 000 characters per side with a notice; above 4 M table cells the changed middle is shown as removed + added with a "rough" note instead of a slow exact result. Added/removed are marked by sign, screen-reader text and underline/strike-through on words, on a neutral background: no new colour meaning. (2) Regex runs only in a Web Worker (one per run, `terminate()` after 1 s → "Muster zu aufwendig"); the page never executes a pattern, no `eval`/`new Function`; test text limited to 50 000 characters, at most 1 000 matches shown. Typing is debounced (250 ms) and an older run is cancelled. Matches are marked by background, underline and their number, not by colour alone. Rejected: a synchronous fallback where no Worker exists (shows a plain "not safe here" note), saving patterns/texts (tools keep no data; nothing is stored), a regex-flavour switch (JavaScript only).
