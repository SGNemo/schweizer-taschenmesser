# Decisions – modules and tools – household, knowledge, media, plan modules

Part of [modules](modules.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Knowledge/media pass (2026-11-03):** Merkliste link preview is opt-in (off): title/description/site go on the item, the picture into `_blobs` (`bookmarks:preview:<id>`, local, not pruned by the vault); `bookmark.requested` takes optional `kind`/`tags`; new kind `book`, status started (`manifest.version` 2, no data change). Mail: three columns from 1200 px (`layout: 'full'`), list quick actions with undo, recent searches device-local. Browser: reader mode and tab pictures fetch the address again without cookies (private tabs never); a test pins that the module never injects into or reads from a tab. Downloads: history = filter on the existing list. News stays retired ([features/news-proposal.md](../features/news-proposal.md)).
- 2026-11-03 **Household and vault depth (`feat/household-vault-identity`):** signatures (shelf, receipt + suitcase, avatar ring, folder tabs, vault door) are built **inside** the module and put into the head with `HeroSlot`; `ui/identity`, tokens and `SIGNATURES` stay untouched (`receipt` is also planned for Rechnungen: lift it together later). Shopping and packing stay one module (`lists`, `list.kind`), birthdays and gifts one module (`people`): no split, so no new collections, only optional fields with a no-op migration step.
- 2026-11-03 **Pantry and gifts talk through events:** `pantry.restock` (bought goods → pantry, adds to the item of that name) and `gift.requested` (bookmarks → people inbox, kept in module settings until a person is picked; only http(s) links). Added next to `shopping.requested`; no module imports another.
- 2026-11-03 **Barcode scan without a platform seam:** like the QR tool, the browser's `BarcodeDetector` + camera; no `getPlatform()` addition, no native plugin yet. Where the detector is missing (e.g. desktop Chromium on Windows/Linux, perhaps Android WebView) the number is typed. The barcode is stored only on the pantry item; no online product database. A native or WASM decoder is a follow-up.
- 2026-11-03 **Weather hint for trips is a click, not a feed:** `TripWeather` calls `searchPlaces`/`fetchForecast` from `core/weather` after the `weather` notice, for a trip within the 7-day forecast; nothing is stored, nothing is asked on page load.
- 2026-11-03 **Passwörter additions stay outside the crypto:** the door head reads the idle deadline through a read-only accessor; the age hint uses an optional `changedAt` inside the encrypted entry (set in the form when the password changes); strength/reuse/age run in memory over open entries and show titles only; the emergency sheet holds no secret. No change to `vault.ts`, `bridge/`, `backup.ts`, the exclusion rules or the widget (status only).
- 2026-11-03 **Contacts import = files:** `.vcf` and `.ics`, parsed locally. The browser Contact Picker has no birthdays and a native contacts plugin is not built; `.ics` year is ignored (often a placeholder).
- **Habits return as a new module (2026-11-03, `feat/plan-habits`):** the 2026-10-01 retirement (unused, streak pressure) is reversed on purpose, with the focus rules built in: rest days never count against any number, streaks only behind the existing `streaks` setting (off by default), reminders stop by themselves once the day's goal is met and have an off switch. It uses **new collections** (`habits_goal`, `habits_entry`); the old `habits_habit` / `habits_check` tables stay on the `REMOVED_ON_PURPOSE` list and are never reused, so no old device op or backup can collide. The legacy redirect `/habits` → `/` is removed.
- **Time tracking returns as a new module (2026-11-03, `feat/plan-timetrack`):** the 2026-10-01 retirement is reversed on purpose. **New collections** (`timetrack_client`, `timetrack_job`, `timetrack_session`); the old `timetrack_project` / `timetrack_entry` tables stay on `REMOVED_ON_PURPOSE` and are never reused. Money is integer cents, rounded **per session**. The idle question never changes the time by itself, and PDF export, a tray display and AI-side time entries stay out. The legacy redirect `/timetrack` → `/` is removed.
- 2026-11-04 **Feeds module = a subscription list, not a reader (`feat/feeds-module`):** it stores only the address, name and group of a feed and opens the site on tap; fetching feeds needs a proxy on the web build (CORS) and reading is a larger design, so it is a separate decision. No `aiSchema` (the list of what someone reads is personal). Same feed written with/without `www.`/trailing slash counts as a duplicate (`feedKey`). OPML in/out arrives as an importer on top (package 2c).
- 2026-11-04 **OPML for feeds (`feat/feeds-opml`):** import is an ordinary importer of the feeds module (preview, duplicates by `feedKey`, undo, report), the export is a plain OPML 2.0 file through `saveFile`; only http(s) feed addresses are accepted so a hostile file cannot plant `javascript:` links. Spotify is not a source: it has no feed export.
- 2026-11-08 **Fitness = one module in Haushalt (`feat/fitness-1`, Sven):** training sessions and meals in one module with one widget (week + today), `dataApi: false`, nothing `searchable` for the assistant, no streaks, no red for eating; a kcal goal is typed or estimated (Mifflin-St Jeor × activity) and only the result is stored, never weight/height/age; quick capture uses word prefixes `training`/`kcal` (one letters are taken) and a `training` line makes its own session (no append). Concept: [features/fitness.md](../features/fitness.md).
- 2026-11-08 **Fitness package 2 (`feat/fitness-2`):** a planned session is a session with `planned: true`, not a ToDo; the planner gets it pinned to its day (no `onAssign`, the user's day stays), done in the plan = logged; „Jetzt wichtig“ only for a plan with a user-set time today; templates are their own collection (no date, no note).
- 2026-11-08 **Fitness package 3 (`feat/fitness-3`):** imports from Strong, Hevy and Cronometer are ordinary `importers/<source>` units recognised by the CSV header (no app picker buttons, the shared list stays untouched); sets of one exercise collapse into one exercise (sets, heaviest weight with its reps) because the module stores one line per exercise; meals keep an occurrence number in their dedupe key so equal entries on one day are not lost.
- 2026-11-08 **Fitness package 4 „Eigenart“ (`feat/fitness-4`, Sven: all recommendations):** pictograms by movement pattern (13 + dumbbell), not one drawing per exercise and no photos (offline, calm, both themes, no licences); the head's signature is a plate week (trained / planned ahead / nothing), never a body figure (focus rules: no body image); catalogue of 40 exercises in 8 groups with a picker, own names stay free text.
- 2026-11-08 **Fitness package 5 (`feat/fitness-5`):** MyFitnessPal is read from its Premium export ZIP; exercise rows of one day become one session (MFP has no workouts), meals stay MFP's per-meal sums (it exports no single foods); `Measurement-Summary` is never read, because Fitness keeps no body data. Yazio waits for a real export file, since its format is not documented.
