# Decisions in full – features – disk module and platform-only modules

Part of [features](features.md). Index of areas: [DECISIONS](../DECISIONS.md).

## Disk module & platform-only modules

- **Modules can declare `platforms`; the filter is `availableManifests()`, resolved lazily.** Module states are synced, so a desktop-only module must vanish from router, nav, dashboard and services on the other platforms, not only from the library. The platform is known only after `initPlatform()`; importing it in the registry would create a cycle through the DB, hence `core/modules/available.ts`. Source: PR #8 (2026-09-30).
- **Own recursive scan with `read_dir` + `rayon`, not `jwalk`/`walkdir`.** Folder sums come straight from the recursion (jwalk yields flat entries and would need a rebuild), cancel is per folder, errors are collected per folder, no hidden-file skipping by default. `walkdir` is single-threaded. Source: PR #8 (2026-09-30).
- **Size = space on the volume (rounded to clusters), file size shown next to it; cloud-only files count 0.** The tool answers "what eats my space". `GetCompressedFileSizeW` per file would be too slow. Source: PR #8 (2026-09-30).
- **Scan tree stays in Rust; the webview gets views by node id.** Keeps IPC small for millions of files and means a compromised webview cannot name arbitrary paths to delete. Source: PR #8 (2026-09-30).
- **Recycle bin through `IFileOperation` with an abort sink instead of the `trash` crate.** `trash` runs with `FOF_NO_UI` (includes no-confirmation) so an item the bin cannot take is deleted silently. Here `PreDeleteItem` without `TSF_DELETE_RECYCLE_IF_POSSIBLE` returns `E_ABORT`; the report offers a separate, deliberate "permanent" step. Source: `trash` 5.2.9 source; PR #8 (2026-09-30).
- **Block list checked in Rust on resolved paths, twice (plan and run), text-based rules.** Deleting takes node ids, never paths; the resolved path must equal the planned one (link swap after the scan is refused). Source: PR #8 (2026-09-30).
- **A second confirmation is enforced in Rust** for permanent or large (> 10 GiB / > 10 000 files) deletions: the dialog asks "Wirklich löschen?" once more and `disk_delete` refuses without `confirmedTwice` (`confirmation-missing`). The second "yes" only works 0.6 s after the question appears, so a double click is not two confirmations. Replaces typing the name / `LÖSCHEN` (PR #8), which the maintainer found tiring; block list, plan and recycle-bin default are unchanged. Source: maintainer request 2026-10-11.
- **Commands that create or close webviews run off the main thread (`#[tauri::command(async)]`, 2026-11-09, `fix/browser-webview-breaks-app`).** A synchronous command runs on the main thread; building a webview there deadlocks WebView2 on Windows (Tauri `WebviewBuilder` docs, wry#583), and the hung main thread stopped every IPC call and app asset, so other module pages stayed at "…". Pinned by `tests/commands.rs`; the browser page also times out after 15 s and shows the reason instead of an empty frame.
- **Per-command Tauri permissions (`AppManifest::commands`) granted on desktop only.** Before, every app command was open to the webview. Source: PR #8 (2026-09-30).
- **Scan results are never persisted, synced, backed up or given to the assistant/local API** (no collections, no `aiSchema`, `dataApi: false` + id block). Optional scan cache and MFT quick scan (admin) are ideas only. Source: PR #8 (2026-09-30).
- **`pdf-lib` 1.17.1 pinned, loaded only when the PDF tool opens.** Last release (unmaintained, MIT); the alternative is a WASM PDF engine (much bigger). Source: PR #8 (2026-09-30).
- **Pantry → shopping list through the event `shopping.requested`**; the shopping module subscribes while enabled (no module import). Source: PR #8 (2026-09-30).
- **PC care, package 1 – clean-up suggestions are ordinary scans; one journal for the way back (2026-11-15, `feat/disk-optimize-p1`):** the tab "Aufräumen" reads the well-known places (the user's temp folder at its fixed place below LocalAppData, never what `TEMP` says; browser caches per profile; crash reports; old downloads) as normal scan trees with every file as its own entry and returns node ids; deleting stays `disk_delete_plan` → block list → `disk_delete`, so there is no second way to delete. A place that is a link or junction is left out. The clean-up scans live in their own map (they neither evict a drive scan nor get evicted). Rules: temp keeps the last 7 days (as Windows' Disk Cleanup does), downloads only ≥ 90 days and never preselected (the user's own data), a cache whose browser runs is not preselected. Not built on purpose: emptying the recycle bin and removing update leftovers (`C:\Windows\SoftwareDistribution` is block-listed, both are permanent) – the page opens Windows' own tools from a fixed list by full path (`pc_tune::Tool`, no argument from the webview). New crate `pc-tune`: `Registry` trait whose only write functions target `HKCU\Software` (never a `Policies` or `Classes` key; no machine-hive write exists, so nothing built on it can need admin rights; a value that exists but cannot be read exactly is an error, never "missing"), and a journal: a change is made only after its undo values are saved, "Rückgängig" replays the newest change of a subject, the values before the **first** change are kept apart so "Alle zurücksetzen" survives the capped history. **In this package nothing is persisted:** clean-ups are noted in session memory only (category and size, never a name or path), so the rule "the disk module never holds data" stands as written. The device-local journal file (`<app local data>/pc-care/journal.json`) is first written by the packages that store undo values (autostart, settings), which needs the maintainer's word on that rule. The list of places on the drives tab gave way to a pointer. Plan: [design/disk-deep/PLAN.md](../design/disk-deep/PLAN.md).
- **Autostart is switched through Windows' own `StartupApproved` value, never by removing the Run value or the shortcut**; only the user's entries (HKCU Run, startup folder), machine-wide Run keys are read-only with a link to Windows' settings; no start-time figure (Windows has no public API for its "startup impact"); scheduled logon tasks are left out until they can be read through the Task Scheduler API and verified on Windows (`schtasks` output is not reliable enough). Source: `feat/disk-optimize-p2` (2026-11-15).
- **"Einstellungen" (Windows tweaks) is a closed catalogue with an admission rule**: per-user setting Windows offers itself, Microsoft-documented mechanism with URL, no admin, restored from the journal; where a documented API exists (`SystemParametersInfo`, `SHGetSetSettings`, power-scheme API) it is used instead of the registry value behind it; no policy keys; an undocumented default shows as "Standard von Windows" instead of a guessed switch. Catalogue and rejected candidates: `docs/design/disk-deep/TWEAKS.md`. Source: `feat/disk-optimize-p3` (2026-11-15).
