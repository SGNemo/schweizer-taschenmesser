# Decisions – shell – Klar 2 areas, cockpit, Planen group

Part of [ui-shell](ui-shell.md). Index of areas: [DECISIONS](../DECISIONS.md).

## Design "Klar 2" – shell and areas (2026-10-02, PR `feat/design-shell`)

- **Areas are navigation only.** `ModuleManifest.area` (required, validated) groups modules for sidebar, rail, bottom nav and the tab row above module pages; modules stay separate in code and data, paths stay (`/finance`, `/todos`, …) so deep links, notifications, PWA shortcuts and E2E keep working. Area pages (`/planen`, `/geld`, `/haushalt`, `/wissen`, `/tresor`, `/geraet`) have no content: they redirect to the module last used in the area (`tm-area-last`, device-local), else the first by `order`. The System area is `/geraet`, so it does not collide with the former `/system` path (now a redirect to `/disk?tab=system`).
- **Assignment** (since 0.4.0): plan = calendar, todos, people · money = finance, invoices, subscriptions, budgets, contracts · household = shopping, pantry, packing, gifts · knowledge = notes, bookmarks, launcher · vault = accounts, vault · system = disk ("Dieser PC"). Retired modules (habits, news, timetrack) have no area. An area without an enabled module is hidden; later packages move modules (e.g. Erinnerungen into Kalender) by editing `area` only.
- **Favourites:** max 5, synced (`_settings` scope `nav`, `favourites: string[]`, unset = Kalender, ToDos, Finanzen), toggled by the star on sidebar items (hover/focus) or the switch list in Einstellungen; disabled modules are filtered at read time. Sixth favourite is refused with a toast.
- **Shell:** sidebar 248 px (Heute, Favoriten, collapsible Bereiche, Bibliothek, Einstellungen) or a 64 px rail (see "Collapsed sidebar", 2026-11-10); the rail is automatic below 1200 px and a user choice above (`tm-sidebar`, Einstellungen → Darstellung). Top bar: search, one filled "+ Neu" (desktop; the FAB exists only below 900 px), Werkzeuge with label. Bottom nav: Heute + the first three areas + Mehr (rest of the areas, Werkzeuge, Bibliothek, Einstellungen).
- **Master–detail** from a 1200 px viewport (was 1500); panel `clamp(22rem, 30%, 30rem)`, 32 rem from 2200 px. Modules adopt `SplitView` per module in the design-5 PRs.
- **Page switches** crossfade for 120 ms (no slide); the full motion pass stays Phase 6.

## Cockpit mode (2026-11-01, PR `feat/cockpit-mode`)

- **A shell flag, not a route.** `cockpit` lives in the UI store (device-local, remembered; "Mit Cockpit starten" optional). The shell drops its chrome and renders the overview as the background; every other path shows in a panel on top with the router as the single source of truth (`navigate('/')` closes it), so deep links, quick capture targets and `?new=1` keep working and no module is rendered twice.
- **Own layout scope** `cockpit` in `_settings` (same schema as `home` plus `dense`, `stats`); the overview's arrangement is never touched from the cockpit.
- **Keys:** F10 is the rebindable `cockpit` F-key action; the settings page gave up its default F10 (all seven assignable keys were taken; Ctrl+K "Einstellungen" stays one keystroke away). Esc closes the panel first, then the cockpit, never while a dialog is open. F11 asks the platform for real full screen only inside the cockpit.
- **Big figures from core only** (clock, next appointment, "Jetzt wichtig" count); module figures such as the balance wait for a `contributions.headline` in the identity package, so the manifest contract changes once.
- **Platform:** a separate `DisplayService` (full screen, Android immersive, keep-awake) instead of widening `ScreenService` (screenshot protection stays untouched); Android gets its own tiny `screen-mode` plugin.

- **Planen group, package 1 (2026-11-03, `feat/plan-calendar`):** holidays are computed (`calendar/holidays.ts`, Easter algorithm + rule table), never fetched, and off by default (`holidayRegion`); regional community holidays are left out rather than guessed. A removed single occurrence of a recurring event is `exdates` on the event (`manifest.version 3`, no data rewrite; `expandEvent` and the notification source honour it). Overlaps are marked by a dashed edge plus text, not by colour. Habits and Zeiterfassung return as new modules in later packages (reversal of the 2026-10-01 retirement, new collection names).
- **Calendar depth (2026-11-03, same package):** named calendars are a collection of their own (`calendar_calendar`, db v27) with a palette index, never a free hex colour; hidden = filtered in the item source, not deleted. Drag editing is pointer + `Alt+arrow` with 15-minute snap, own single-day events only; series stay in the editor so "only this one / all" remains a deliberate choice. The reminder time ring reuses `Ring` and never animates.
- **ToDos depth (2026-11-03, `feat/plan-todos`):** the four views are computed from the dates, not stored (only `someday` is a flag); an undated open task counts as "Irgendwann", a future `startDate` puts a task under "Demnächst". Board moves write dates through `movePatch` and tick through `setDone`. Projects are lists with `kind: 'project'` (no new collection); links store only id + title and are filled through the event bus (`todo.requested.link`). The view bar uses touch-size chips instead of the shared `Segmented` (32 px on desktop would break the 44 px target test).
- **Maps depth (2026-11-03, `feat/plan-maps`):** an appointment's location reaches Karten & Orte as a URL (`/maps?q=`) that only prefills the search; geocoding stays a user click (no `place.requested` event, no consumer that would geocode on its own). The pin head draws no map, so opening the module still fetches nothing. No AI actions for places: they need coordinates, which the assistant never sees or dictates.
