# Decisions in full – Core – device exchange (phone ↔ PC)

Part of [core](core.md). Index of areas: [DECISIONS](../DECISIONS.md).

- **Own module „Austausch“ (`exchange`), area System, desktop + Android – not part of the AI chat or remote control (2026-11-16, `design/device-exchange`):** the AI chat would put device messages one slip away from the provider and need permanent exceptions to the AI privacy rule; remote control's rule forbids clipboard and files in either direction and is a grant to steer, not to receive. No `aiSchema`, not `searchable`, `dataApi: false`, in `BLOCKED_MODULES`. Source: [design/device-exchange/CONCEPT.md](../design/device-exchange/CONCEPT.md) §3.
- **Transport: handshake mode 4 on the LAN hub's listener (2026-11-16):** same keys, trust list, limits and home-network gate as modes 2/3, own tags `0x30–0x3f`, never mixed with sync or input; the phone always dials (Android never listens), the PC keeps a per-device outbox and hands it over on the next session the phone opens; the phone keeps the session open while the page is visible. Mode 4 has its own `home && exchange` admission check and closes on home-network loss. Delivery state is Rust's (inbox/outbox files; `ack` only after the inbox write; Dexie is the history). Files in frames ≤ 65 494 B, one transfer per session, SHA-256 while writing, resume from `<peer>-<hex id>.part` for 24 h, never overwrite. Prototype: ≈ 300 MB/s for the layer on one host, 0.2 ms per message; PC → phone is capped at ≈ 0.3 MB/s by today's transport loop (one unasked frame per 200 ms pass) until package 2 changes it. Source: CONCEPT §4, §10.
- **Storage (2026-11-16):** messages in `exchange_items` with `local: true` on each device (not synced, never in a backup, fixed 30-day retention); files only on disk (PC `Downloads/Nemo` chosen by a Rust folder dialog; phone app storage with Teilen/Speichern unter), never in IndexedDB or sync; paths only in Rust, no command takes a path; PC → phone files by reference with a change check; thumbnails made in Rust with decoder limits, kept as small files in the app cache (never IndexedDB, never SVG/HEIC); saving and sharing by token in Rust (`platform.saveFile` takes bytes from JS and is not used). Source: CONCEPT §5.
- **Security (2026-11-16):** own per-device grant at the PC, off by default, stored device-local in `trust.json`, never set over the network; every widening (device on, un-pause, module on with a stored grant) in remote control's native Rust dialog, refused during a mouse/keyboard session – the web view renders peer-sent content and must not widen alone; first run preselects only when exactly one device is paired; up to 100 MB per file and 1 GB per device per day without asking (fixed); shortcut-like types (`url`, `lnk`, `searchconnector-ms` …) saved with `_` appended so Explorer never resolves them (NTLM leak); names cleaned (last segment, NFC, no control/format/bidi characters, reserved Windows names, ≤ 120 bytes, unique); _Öffnen_ only for an allow-list of types (a deny-list misses handlers), everything else only „Im Ordner zeigen“ with a warning; Windows `Zone.Identifier` ZoneId 3 (failed write → treated as „other“); never from `accounts`; clipboard read only on a tap, never written automatically; nothing of it in logs or diagnostics. Hard-rule line proposed (package R, Sven merges). Source: CONCEPT §6.
- **Notifications and settings (2026-11-16):** a system notification on receipt only on the PC, `soft`, off by default (FOCUS-GUIDELINES), switch in the module and „Ruhige Erinnerungen“; widget and tray line carry the news. v1 settings: receive folder and that switch only (100 MB and 30 days fixed). English name „Device drop“ („Exchange“ reads as the mail server). Source: CONCEPT §3, §7.
