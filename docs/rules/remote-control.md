# Hard rule – remote control (phone → PC input)

Unabridged text of the rule; short line in root [CLAUDE.md](../../CLAUDE.md), index in [RULES.md](../RULES.md). Desktop is the target, Android the controller. Rationale and threat model: [design/remote-control/CONCEPT.md](../design/remote-control/CONCEPT.md); decision: [decisions/core.md](../decisions/core.md).

- A paired device controls nothing by pairing alone.
- Input travels only in the LAN hub's input session (handshake mode 3 on the hub's listener: same keys, trust list, bind rules and limits as LAN sync; never a listener, port or bind address of its own, never the Local API; accepted only on the stored home network, never on a network that is listened on only for an open pairing window; frames ≤ 512 bytes; home binds are flagged from the stored network id, fail-closed); a sync session never carries input and an input session never carries sync data or touches the store.
- The hub accepts it only while the PC's master switch is on and only from a device whose grant is set – both off by default, stored device-local on the PC, never synced, never changeable by a network message; every widening (raising a level, un-pausing, master switch on with a stored grant, loosening an option) is confirmed in a native dialog shown by Rust and refused while a mouse/keyboard session is open, checked again when the dialog returns.
- Two levels: media/volume/lock/monitor off (API calls only, no simulated input, no media keys) and mouse/keyboard; a session's level is fixed when it opens (the smaller of request and grant) and checked per event on the PC, as are the lock state (locked: at most the media level – media, volume, lock, monitor off; a session may always let go of a mouse button it pressed itself, also on a locked PC and when it ends), the rate limits and the fixed lists (keys and media commands are enum ids, never raw key codes; text has no control characters).
- Power (shut down, restart, sleep, hibernate, sign out) is a separate permission per device (`remotePower`, stored and widened like the level, cleared when the level goes to off, counts only with at least the media level and no pause; off by default): API calls only, never forced, one countdown at a time for the whole hub, at most 2 starts per 60 s per device (memory only, kept across reconnects), never on a locked PC. Each one is unlocked on the phone natively (or confirmed there when the phone has no screen lock) and runs only after a 10-second countdown in a window the PC shows from Rust state; _Abbrechen_ there, in the tray or from the phone (always allowed), ending remote control at the PC, the master switch off, the permission taken away or paused, locking the PC or closing that window stops it; no window, no action; a dropped phone connection does not stop it. When Nemo on the PC is still working (another device's sync, a download, a backup), the phone is told before a countdown starts. No Tauri command starts a power action or a program; the calls live in `crates/remote-input`.
- Programs (mouse/keyboard level only) start only from a list kept on the PC (device-local, at most 8 entries, added only with the PC's own file dialog, names at most 40 characters of plain text, never synced, never set over the network); the phone sends a slot number, never a path or argument, and learns only the names the PC's owner gave the entries.
- While a device controls, the PC shows which one (tray, from Rust-held state the web view cannot remove) and one click ends it and pauses that grant.
- Never screen content, clipboard, files, window or track titles in either direction (the program names of the PC's own list are the one exception, PC → phone).
- Never log, store or put into diagnostics any input (no key, text, coordinate, click or time of use – an input session does not update `lastSeen`); the only remote-control state stored on the PC is the master switch, the program list and per device the level, the power grant, the pause flag and the unlock option; throttles live in memory only.
- The phone's commands are granted to the phone only (`capabilities/mobile.json`).
- Input simulation lives only in `crates/remote-input` (Windows only; other systems answer `unsupported`; never on Android), is reached only from the hub's input session, and no Tauri command simulates input.
- `crates/lan-sync` stays free of `unsafe`, logging and OS input APIs.
