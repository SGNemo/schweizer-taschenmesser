How to read it:
- Also in the E2E part: the jobs `Stimulus budget` (blocking, strict on both sides) and `e2e-seed` run whenever E2E runs and count for the check `Web`. On a PR the ratchet step compares merge base and head: a raised budget or baseline, fewer seed rows, a changed signature-block list, a `web/package.json` change beyond `version` and plain-range dependencies or **any change to a protected file – every workflow under `.github/workflows/**` included, repo-wide** – is a hit and red until Sven approves it (signed comment for the merge, label `stimulus-raise` for CI; [howto/ci.md](howto/ci.md)). Dependabot PRs for actions and release-workflow changes go that way too; npm bumps (plain version ranges) and version bumps are free. `scribble-guard` runs only for `main` (push or PR into `main`; fails while a `scribble/` folder exists).
- **Skipped means "not needed for this diff"** and counts as passed. The check **Web (lint, types, unit, E2E)** fails if a part that was needed did not run or one that was not needed did.
- **Need everything on your PR now** (UI-wide change, accessibility, layout, Pixel 7)? Add the label `full-ci` (the immediate full run starts only for branches of this repository; later pushes follow the label). It starts one separate full run now and makes every later push run the full set; a red smoke run from before stays visible next to it until the next push. Removing the label applies from the next push.
- **A draft PR** runs the web static checks and unit tests only (if `web/` changed); marking it ready starts the plain PR set.
- **Docs-only changes** (see [howto/ci.md](howto/ci.md)) start none of the heavy jobs; `README*.md` and other root files are not docs for the pre-check and run every package; `docs/AI-IMPORT*` and `docs/user/installation*` run static + unit.
- **What leaves the plain PR runs later, not never:** Pixel 7 and the specs outside the smoke list first run after the merge (push `develop`) or overnight; accessibility, layout, touch, calm mode, hide-values, identity and the seed specs run on every web PR (desktop project; the phone ones set their own viewport). A red `develop` run blocks the Dev-Preview; the chat whose merge broke it fixes it (check Actions → CI on `develop` after merging).
- **Nightly** (`nightly.yml`) is a scheduled workflow and GitHub fires those only from the default branch: it is active once `nightly.yml` is on `main` (next release merge). Until then the push runs on `develop` cover the same set.
- **CI feels slow?** `node scripts/ci/measure.mjs` (repo root; needs `gh`, read-only) prints wait and run time per job, push → green, runner load per hour, overtaken runs and, with `--tests 150`, failed and retried tests by file:line. Last report and levers: [perf/CI-2026-11.md](perf/CI-2026-11.md). Each push to a PR costs about 35 runner minutes: merge `develop` in once ([PROMPT-TEMPLATES](PROMPT-TEMPLATES.md#git)).
- Add a spec to the PR smoke set only if it guards start-up, data safety, navigation or a module's create/edit path: `SMOKE_FILES` in `web/playwright.config.ts` (a protected file: that PR is a ratchet hit and needs Sven's approval).

## Set up & run locally

- `cd web && npm ci`, `cd ../server && npm ci` (and `cd ../mcp && npm ci` if you touch `mcp/`, `cd ../packages/vault-core && npm ci` for the shared package, `cd ../extension && npm ci` for the extension).
- Everyday start: `npm run dev:all` (app in the Dev-Preview flavour with invented test data + local sync server with a random token printed on start; without `server/node_modules` only the app). Plain dev server: `npm run dev`. Production build: `npm run build`; serve: `npm run preview` (:4173).
- Native shell: `npm run tauri -- dev` (needs Rust; Linux: `libwebkit2gtk-4.1-dev libgtk-3-dev …`). Compile with embedded frontend: `npm run tauri -- build --debug --no-bundle`.
- Sync server: `cd server && cp .env.example .env` (set `SYNC_TOKEN`, ≥ 16 chars), `npm run dev`. Docker: `server/docker-compose.yml` (serves PWA + API).

Windows-only code compiles without a Windows box: `rustup target add x86_64-pc-windows-msvc`, then `cargo check -p taschenmesser-disk-scan --target x86_64-pc-windows-msvc` (the main crate needs the Windows toolchain). |
| Version consistency                                                   | `npm run version:check`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

- Definition of done: `lint`, `typecheck`, `test`, `e2e` green; for a UI-wide, layout or phone change also the specs you touched on `pixel-7` (or `e2e:full`, or the label `full-ci`); CLAUDE.md/docs updated.
- **Unit-test environment:** test files run in `node` by default; a file that needs a DOM (React components, `document`, `localStorage`, `window`, `DOMParser`, code such as `stores/ui.ts` that reads them) starts with `// @vitest-environment jsdom`. A forgotten marker fails with "document is not defined" (or, where app code guards the access with try/catch, silently takes the fallback path – add the marker to any test whose subject touches a DOM global). Building a jsdom per file used to cost more than all test bodies together.
- Sandbox: run e2e/vitest in the foreground (`timeout 115 …`, or `--shard`); background jobs only make progress while a foreground command runs. Never `pkill -f` a pattern that appears in your own command line.
- Before `npm run e2e` stop any own `vite preview` on :4173 (`pkill -f "[v]ite preview"`). Chromium is at `/opt/pw-browsers/chromium`; never `playwright install`.

## Git workflow

- Work on a feature branch, PRs into `develop`; `main` only receives release merges. Conventional Commits (`feat(scope):`, `fix:`, `feat!:`). Merge `develop` into your branch (no rebase of shared history).

- Bundle and cold start (`web/`): `npm run check:bundle` (critical path per entry, lazy chunks, precache, budget `scripts/bundle-budget.json`; warning in `npm run check` and CI E2E shard 1; `-- --baseline` for intended changes, `-- --modules` for the largest modules) · `npm run measure:coldstart` (pixel-7, CPU 4×, Fast 3G, median of 5): [perf/COLD-START-2026-10.md](perf/COLD-START-2026-10.md).

The README pictures are `docs/assets/screenshots/*.webp`, shot from the seeded build with `npm run app:screenshots -- --readme` (in `site/`); the social preview comes from `npm run gen:social`.
- Use the local AI import API / MCP: `docs/AI-IMPORT.md`.
