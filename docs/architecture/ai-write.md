# AI writes and local model (PR A/B)

See also [ai.md](ai.md) (router, query layer).

**AI writes (rules → local model → cloud)** – `web/src/core/ai/write/`, UI `layout/assistant/WritePreview.tsx`, tests `core/ai/write/*.test.ts`, eval set `web/tests/ai/eval-set.json`.

- **Write contract:** `aiSchema.actions` in a module's `ai.ts` (`AiActionDef`: `kind` `create|update|delete|transition`, `collection`, `fields`, `required`, `set`, `examples`, `parse` hints for the rule parser). Optional; a module without actions stays read-only for the assistant, `accounts`/`disk` have no `aiSchema` at all. `validateAiActions` (`core/modules/aiActions.ts`) runs in `validateManifest` and `npm run check:modules`; transitions with side effects go through `contributions.aiActionHandlers` (invoices: `markPaid` → `invoice.paid`, undo → `invoice.unpaid`).
- **Stages (`assistant.ts`, `ask` with `deps.write`):** after the free query parser: **0** `write/rules/parse.ts` (verbs, module words from the manifests' `parse.keywords`, `quickCapture/parser/extract.ts` for amount/date/time/recurrence/URL, typo-tolerant, fallbacks by signal; multi-entry on newline/`;`) → **1** `LocalStage` slot (`write/stages.ts`, built-in model, not shipped yet) → **2** cloud: one `propose_actions` tool plus a compact action list (`prompt.ts` `buildActionText`), only when `write.cloud` is on; the cache keeps the validated intent. Every answer carries its stage; `_aiUsage.stage` (`rule|local|cloud|cache`, 0 tokens for rules/local) feeds Settings → KI → Statistik (`totalsByStage`, `dailyByStage`).
- **Privacy:** the cloud sees the sentence, the date, the field schemas and the action list – never entries. Targets of update/delete/mark are the user's own words, resolved on the device (`write/targets.ts`, fuzzy); ambiguity is a choice in the preview, so no candidate list leaves the device.
- **Preview and commit:** `prepareOp` (`write/prepare.ts`) whitelists fields, coerces values, validates with the collection's Zod schema and returns lines (before → after for changes, stored values for deletes), missing fields and target candidates; `commitOps`/`undoGroup` (`write/commit.ts`) write one importer batch per module (origin `assistant`, shared `groupId`) through `core/importer` (which gained deletes and handlers). An entry edited after the preview is skipped, never overwritten. Nothing writes without the user's confirmation; there is no auto-confirm setting.
- **Settings:** scope `ai.write` (`write/settings.ts`: global switch, per-module switch, cloud fallback, asking for missing fields); the bar promotes an "Eintragen" option for sentences that look like entries (`rules/intent.ts`), modules with actions show "Mit KI eintragen" in `AreaFrame`.

**Local model (stage 1)** – Rust crate `web/src-tauri/crates/local-llm` (llama.cpp via `llama-cpp-2`, grammar-constrained JSON, KV-cache prefix reuse, one worker thread), behind Cargo feature `local-llm` (off by default; `local-llm-vulkan` adds Vulkan). Commands `llm_*` in `src/local_llm.rs` (stub without the feature). TS: `core/platform/localModel.ts` (seam, `fakeLocalModel.ts` for tests), `core/ai/local/` (`catalogue.json` = data-driven model list, `prompts/v1.ts`, `grammar.ts`, `stage.ts`, `state.ts`, device-local `prefs.ts`).
- **Downloads:** only after consent (size, source, SHA-256 shown); https to huggingface.co/hf.co only; size + SHA-256 verified, mismatch deleted; stored in `<data folder>/models`. A catalogue entry with `sha256: null` cannot be downloaded (not pinned yet).
- **Privacy:** the prompt holds instructions, compact action schemas, date and the sentence; entries and `accounts` never. The cloud fallback defaults to off while a local model is active (`cloudAllowed`).
- **Measure:** `npm run ai:eval -- --bin <llm-batch> --models <id>=<file.gguf>` (see `howto/ai-actions.md`). CI job `local-llm` builds/tests the crate with a random smoke model.
- **Size:** Linux release exe 10.7 MB without, 15.6 MB with the feature (CPU build, +4.9 MB).
