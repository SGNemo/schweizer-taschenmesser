# Native distribution: shell, platform layer, Android, portable exe (Phases 7–8, 13)

Part of the architecture notes ([index](../architecture.md)); map of paths: [ARCHITECTURE-MAP](../ARCHITECTURE-MAP.md); decisions: [DECISIONS](../DECISIONS.md).

**Native distribution (Phases 7–10).**

- **Shell:** `web/src-tauri` (identifier `io.github.sgnemo.taschenmesser` – never change it, Android updates depend on it; product name "Nemo" (window title, app label; the identifier and update endpoints keep the old name); **Windows ships as one portable executable, no NSIS/MSI** (`tauri build --no-bundle`); plugins notification, http, dialog, fs, clipboard-manager, opener; capabilities in `capabilities/default.json` are the minimum `core/platform/tauri` uses). The frontend is the unchanged web app (`frontendDist: ../dist`). Native builds are recognised by the Tauri CLI env `TAURI_ENV_PLATFORM`: `vite.config.ts` then drops the PWA plugin (no service worker, no manifest) and aliases `virtual:pwa-register/react` to `pwa/register-stub.ts`. The PWA build is unaffected and remains the fallback.
- **Data:** the native app has its own WebView origin → its own IndexedDB. Moving data from the PWA = JSON backup (Settings → Backup) or sync. `use_https_scheme` stays default (http scheme) so plain-http LAN sync servers work.
- **`PlatformService` (`core/platform/`)** is the only place that differs between browser and native shell: `fetch` (native = `plugin-http`, no CORS), `notifications` (`NotificationService`; native permission state is cached because the plugin check is async), `saveFile` (browser download / save-as dialog + `plugin-fs`; needed on Android where blob downloads do not work), `clipboard.writeSensitive` (clears after N ms unless the user copied something else), `app.version/openUrl`, `lifecycle.onBackground`. `initPlatform()` (called first in `main.tsx`) picks the implementation – the only place that looks for `__TAURI_INTERNALS__`; the Tauri adapter is a lazy chunk. Everything else calls `getPlatform()`. **ESLint enforces it:** `@tauri-apps/*` imports only in `core/platform/tauri/**`, `__TAURI*` only in `core/platform/**`. Tests swap it with `setPlatform()`; the Tauri adapter is unit-tested with `vi.mock` of the plugin modules.
- **Versioning:** `web/package.json` is the single source. `tauri.conf.json` has `"version": "../package.json"`; `Cargo.toml`/`Cargo.lock` mirror it (`version:sync`, checked by `version:check` in CI). `core/update/semver.ts` (parse/compare/`androidVersionCode`, erasable TS so Node scripts import it directly) derives the Android `versionCode = ((major*1000+minor)*1000+patch)*100 + rank` (release 99, `alpha.N` 0–29, `beta.N` 30–59, `rc.N` 60–89) – monotonic in SemVer order, unlike Tauri's default derivation which ignores pre-releases. Only `alpha|beta|rc` pre-release labels are accepted. Release bump: `npm run version:set -- 0.2.0` (updates package.json, lock file, Cargo files).
- **Conventional Commits from now on** (`feat(scope): …`, `fix: …`, `feat!:` / `BREAKING CHANGE:`). `scripts/changelog.mjs` (+ tested `scripts/lib/changelog.ts`) renders release notes: breaking changes, features, fixes, performance, refactoring, docs, build/CI; chore/test/style and merges are hidden; older non-conventional commits appear under "Other changes". Range = previous release tag (for a stable release) or previous tag of any kind (pre-release) up to HEAD.
- **Android (Phase 8).** Tauri Mobile: the Android Gradle project is generated in CI (`npx tauri android init --ci`, `src-tauri/gen/` is git-ignored); build `npx tauri android build --apk --target aarch64 --target armv7 --config "$(node scripts/version.mjs android-config)"` (the config override sets the derived `versionCode`). The unsigned APK is signed by `scripts/android-sign.mjs` (zipalign `-p`, apksigner, verify; passwords via env, never argv; `scripts/lib/android.ts` finds the newest build-tools and validates the env) – not by Gradle, so nothing depends on patches to the generated project. Local plugin **`src-tauri/plugins/apk-installer`** (Rust + Kotlin, id `io.github.sgnemo.taschenmesser.apkinstaller`): commands `can_install`, `download(url, sha256)` (https only, ≤ 300 MB, SHA-256 checked, one file kept in `cacheDir/updates`), `download_progress` (polled – no event channel), `install(path)` (only files inside `updates/`; opens the "install unknown apps" switch when not allowed, otherwise the installer via FileProvider). Its manifest adds `REQUEST_INSTALL_PACKAGES` and a `FileProvider` **subclass** (`ApkFileProvider` – the app template already declares the base class and manifest merging keys on the class name). Desktop builds compile a stub whose commands return `unsupported`. Android verifies the APK signature against the installed app, so only builds signed with our keystore can update it.
- **Closed-app reminders on Android:** the Tauri WebView has no Web Push, so `NotificationService.scheduleUpcoming` (Android only) hands the next 14 days (≤ 100, earliest first) to the OS via `plugin-notification` (`Schedule.at`, `allowWhileIdle`); the whole set is replaced on every change (`core/notifications/nativeSchedule.ts`, triggers shared with Web Push in `triggers.ts`: start, 10 min, visible, after outbox changes). When `scheduleUpcoming` exists the in-app scheduler stays quiet (`checkDue`) to avoid duplicates. Desktop keeps the in-app scheduler (works while the app runs). Not verified on a device (no Android SDK in the sandbox): first proof is the CI dry-run plus a manual check.

- **Portable Windows build (Phase 13).** **Data location:** unchanged default = Tauri's `app_local_data_dir` (`%LOCALAPPDATA%\io.github.sgnemo.taschenmesser`, WebView2 profile inside) – the same folder the formerly installed version used, so existing data is found without migration (the exe can be replaced or moved freely). **Portable mode:** a folder `data/` next to the exe makes `create_main_window` (Windows only; `tauri.windows.conf.json` sets `create: false` for the main window and repeats its size settings – keep both in sync) pass `data_directory(<exe>/data)`; Tauri forces a data directory on Windows itself, so an env var would be ignored. Pre-update backups stay in `%APPDATA%` (limit). **WebView2:** `webview2.rs` checks the EdgeUpdate registry keys (WOW6432Node, HKLM, HKCU) before Tauri starts and shows a German message box with the download link instead of failing silently. **Build:** `tauri build --no-bundle`, signed with `tauri signer sign` (updater key); a non-blocking smoke-test step starts the exe on the runner. **Migration from the old installer:** the steps are in the README (export backup, start portable, uninstall the old app _without_ ticking "delete application data"); the old installed `0.2.0-beta.1` cannot self-update onto the portable file.
