# Start data, importers, HelpHint (Phase 13 step 2)

Part of the architecture notes ([index](../architecture.md)); map of paths: [ARCHITECTURE-MAP](../ARCHITECTURE-MAP.md); decisions: [DECISIONS](../DECISIONS.md).

**Start data & importers (Phase 13, step 2)** – `web/src/core/importer/`, `web/src/core/io/`, `ui/HelpHint.tsx`.

- **Manifest contract:** `contributions.onboarding` is **required** (`validateManifest`; use `noOnboarding` when a module has nothing to import). It is plain data (`ImporterMeta[]`: `id`, `kind` `text|file|template|form|connector`, label, description, options/fields/templates) plus a lazy `load()` returning the `ImporterRuntime` (parse/`optionChoices`/dedupe key), so manifests stay free of parser code. Every module declares at least one importer except `accounts` (the vault has its own CSV import, and nothing there may be handled generically).
- **Flow (`OnboardingWizard`, native `<dialog>`):** choose source → input (text box, file, template ticks or a small form) → **preview** with per-row checkboxes, duplicates pre-deselected and marked, invalid rows shown → confirm → result. Nothing is written before the confirmation. The dialog lives in one global `OnboardingHost` (`core/importer/host.tsx`, mounted in `AppShell`; `StartDataButton` only opens it via a zustand store) – the buttons sit in empty states that vanish with the first imported entry, which would otherwise tear the dialog down before the result step.
- **Entry points:** `StartDataButton` in the empty state of each module page, in Settings ("Startdaten einrichten", one row per module, incl. the list of earlier imports), and an offer after enabling a module in the library ("Überspringen" is remembered in local `_meta` `onboarding.<id>`).
- **Batches & undo:** every confirmed import is one batch in the local table `_imports` (`synced: false`; batch id, module, importer, collection → record ids, source, time). Records are written through `repo.createMany` (`core/db/repo.ts`) with deterministic ids `imp-<batch>-<n>`. **Undo** soft-deletes only records that are still unedited (`updatedAt === createdAt`) and reports how many were kept; deletions sync as tombstones. The "recently imported" list keeps batches undoable after the dialog was closed.
- **Parsers (`core/io`, pure, unit-tested with invented fixtures):** `csv.ts` (delimiter detection `;`/`,`/tab, BOM, quotes; `accounts/csv.ts` builds on it), `ics.ts` (VEVENT: dates, date-times, UTC/TZID, LOCATION, RRULE subset → `recurrenceSchema`; EXDATE, unknown RRULEs, overrides and cancelled events produce warnings, never silent loss), `bookmarksHtml.ts` (Netscape bookmark export), `textLines.ts`, `dates.ts`, `pickFile.ts` (≤ 10 MB).

- **HelpHint:** `?` button (44 px target) that toggles a popover on tap/click, opens on hover/keyboard focus, closes on Esc (the handler also calls `preventDefault`, otherwise a surrounding native dialog would close too) or an outside tap; text in `t.help`. The bubble has `transition: none` on purpose: the global reduced-motion rule sets every transition duration to 0.01 ms, which turns the default `transition: all 0s` into a real transition, and the viewport check then kept measuring the old position (infinite update loop). E2E: `e2e/onboarding.spec.ts`, wizard + hint in `e2e/a11y.spec.ts`.
