# Connectors, calendar sync, bank import (Phase 13 step 3)

Part of the architecture notes ([index](../architecture.md)); map of paths: [ARCHITECTURE-MAP](../ARCHITECTURE-MAP.md); decisions: [DECISIONS](../DECISIONS.md).

**Connectors, calendar sync, bank import (Phase 13, step 3)** – `web/src/core/connectors/` (framework), `web/src/connectors/<id>/` (one folder per service), `server/src/proxy.ts`.

- **Isolation (lint + `connectors/isolation.test.ts`):** a connector talks to one outside service and returns plain data. Code in `src/connectors/**` must not import modules, `@/core/db/*`, `@/core/sync|backup/*` or **`@/core/ai/*`** (what was read from a mailbox can never reach a model); modules must not import connectors; `core/ai` must not import `core/connectors`. Modules receive data through manifest contributions – the calendar module's `contributions.externalCalendar` is an `ExternalCalendarSink` (`apply / clear / count / knownKeys`), and the importers of invoices, subscriptions, contracts and calendar accept `ImportInput` kind `connector` (`MailFinding[]`).
- **`ConnectorDef`** (`core/connectors/types.ts`): `id, name, authType (oauth-pkce|none|…), platforms, oauth endpoints, features[] (each with its own OAuth scopes), calendar? {listCalendars, sync}, mail? {scan}, nowPlaying? {read, control}` ([spotify](../features/spotify.md)), `oauth.preferredPort?` (fixed redirect port), `client?` (own client-id form wording), `isConfigured?, settings?` (lazy extra UI). `ConnectorContext` hands the connector `fetch` (platform), `accessToken()` (refreshes on demand, in-memory cache), `fetchPublic(url)` (native: direct; browser: through the sync server proxy, else `no-proxy`), scoped `secrets` and `redact()`.
- **State & secrets:** status per connector in local `_meta` `connector.<id>` (`disconnected|connected|expired|rate-limited|error`, features, `lastSyncAt`, `retryAt`, redacted German message); sync tokens/selected calendars in `_meta` `connector.<id>.*`. Secrets only in `PlatformService.secrets` (OS keystore): `oauth:<id>:refresh|client-id|client-secret`, `connector:<id>:*`. `core/connectors/redact.ts` strips tokens, client secrets, JWTs and secret iCal addresses from every error text; tests assert no token appears in stored status or messages. `scripts/lib/audit.ts` additionally fails a release build containing a `GOCSPX-…` client secret.
- **Several accounts (`ConnectorDef.multiAccount`, Google):** the first account keeps the plain keystore keys (`oauth:<id>:refresh`), further ones use `oauth:<id>#<accountId>:refresh` (`accountKey()` in `context.ts`); client id/secret stay per connector. Extra accounts live in `_meta` `connector.<id>` as `accounts: [{id, email?, features}]` (old statuses load unchanged). `addAccount / removeAccount` in `service.ts`; `createContext(def, now, accountId)`. `disconnect` and the device reset (`deviceSecretNames`) cover all accounts. The address comes from `ConnectorDef.identify` using the scopes already granted (Gmail profile, else the primary calendar id) – no extra scope. Calendar sync and the Gmail scan still use the first account.
- **OAuth (`oauth.ts`, `service.ts`):** PKCE S256 + `state`; the desktop shell binds a one-shot **loopback listener** (`src-tauri/src/oauth.rs`: `oauth_listen_start` returns the port, `oauth_listen_wait` waits ≤ 5 min for `/callback`, ignores foreign `state`, German result page; commands are app commands, no capability entry needed), the system browser does the login (`app.openUrl`), the token exchange goes through `PlatformService.fetch`. `PlatformService.oauth` is `supported: false` in the browser and on Android (later step). `invalid_grant` ⇒ status `expired` + "Neu anmelden"; 429/quota ⇒ `rate-limited` with `retryAt` (backoff 1–60 min); the copied events stay untouched. The user brings their **own Google OAuth client** (type "Desktop app"): client id/secret are typed into Settings → Verbindungen and go straight into the keystore – nothing is shipped in the repo or binary.
- **Calendar sync (`service.syncCalendars`):** background loop (`startConnectorSync`: start, every 5 min while visible; a connector syncs when ≥ 30 min old), manual "Jetzt abgleichen". Google: `calendarList`, then per selected calendar `events.list` with `singleEvents=true`; first sync = window today −60 d … +400 d, later `syncToken` (cancelled events arrive as removals, **410** ⇒ full window again), etag unchanged ⇒ no write; all-day end is exclusive → inclusive; timed events converted to the device's local wall clock; HTML notes stripped. ICS subscriptions (`ics` connector, `authType: none`, address = secret): full sync of the feed each time (RRULE subset via `core/io/ics`). Events land in the **synced** collection `calendar_external` (ids `ext-<source>-<sha256(calendar,extId)>`, so all devices converge; read-only in the UI with an "extern" badge and detail dialog "Im Kalender-Dienst öffnen"); a calendar switched off or removed at the source takes its events with it; disconnect asks "keep or delete copied events". They appear in `useCalendarItems`, the dashboard widget and the assistant's agenda without further code; `aiSchema` lists the collection (field names only).
- **Gmail scan (`gmail.readonly`, separate feature switch):** `messages.list` with a keyword query + `after:` date (1/3/6/12 months, ≤ 300 messages), then `messages.get?format=metadata` for `From/Subject/Date/List-Unsubscribe` + the preview snippet – the body is never requested (test asserts the `format` and header list). `connectors/google/heuristics.ts` (pure, invented fixtures) recognises invoice (amount, due date), subscription (amount, rhythm, next charge), appointment/ticket (date, time, place) and contract (end, notice period); newsletters (`List-Unsubscribe`) only count as invoices with amount **and** due date; repeated monthly mails are de-duplicated. The wizard shows what was read ("N Mails … Absender, Betreff, Datum, Vorschauzeile"), the user confirms each suggestion; only extracted fields + a link to the mail are stored, calendar suggestions are de-duplicated against own and synced events.
- **Proxy `GET /v1/proxy?url=`** (`server/src/proxy.ts`, injectable `ProxyDeps` like push): needed by the PWA for ICS (and later RSS). Deliberately narrow because it is an SSRF hazard: http(s) only, no URL credentials, ports 80/443/8080/8443, every hop resolves the host and refuses loopback/private/link-local (metadata)/CGNAT/ULA/multicast/reserved addresses also in IPv4-mapped, NAT64 and 6to4 form (if any answer is blocked, all are), the socket is **pinned** to the checked address (custom `lookup`, no second DNS query), manual redirects ≤ 3 re-checked per hop, 2 MB / 10 s, feed-like content types only (never HTML/JSON/script), `content-security-policy: sandbox`, route rate limit 60/min, `If-None-Match`/`If-Modified-Since` forwarded (304), CORS exposes `etag`/`last-modified`. Errors: 400 `invalid-url`, 403 `blocked`, 413, 415, 502, 504.
- **Bank statements (`core/io/bank.ts`, `subscriptionDetect.ts`):** CSV of the savings banks' "CSV-CAMT" export (semicolon, `dd.MM.yy`, German amounts; header names are matched tolerantly) and CAMT.052/.053 XML (namespace-agnostic `Ntry` parsing). Finance importer `bank` (option: target account) books expenses/income; duplicates are detected by date+amount+payee+purpose (the n-th identical booking of a file gets its own key, so two coffees on a day are not "duplicates" but a second import of the file is); subscriptions importer `bank` finds recurring debits (≥ 3, same normalised payee, median gap ≈ weekly/monthly/quarterly/yearly, ≥ 75 % regular gaps, amount ±10 %). **The column names were written from the documented export layout, not from a real file** – check with a real export (see "Manuelle Tests offen").
- **Mail module (read-only, `core/mail` + `modules/mail`):** the connector's `mailbox: MailProvider` (`labels / threads / thread / attachment / unread`, Gmail search text passed through untouched) is what an IMAP connector would implement later. `core/mail/service.ts` resolves an account (`listMailAccounts`: first account + extra accounts with feature `mail`) to provider + `createContext(def, undefined, accountId)`; `expired`/`rate-limited` of the first account update the connector status like everywhere else. Gmail: `threads.list` + `threads.get?format=metadata` for rows (4 calls in parallel), `format=full` for a thread (MIME tree → text/html/attachments/`cid:` parts), one token refresh after a 401, 403 ⇒ `denied` (scope missing, UI says so). **Cache** (`modules/mail/cache.ts`): collections `mail_thread` / `mail_body`, `local: true` (no outbox, no backup), `dataApi: false`; only sorting fields in the clear, sender/subject/preview/body sealed with the device key (AES-GCM, `sealJson`, aad = row id); newest 200 headers per account and 60 opened mails; "Zwischenspeicher leeren" in the mail settings; seed rows (`demo`) hold plain invented text. **HTML** (`core/mail/sanitize.ts`): DOMPurify with no `<style>`/forms/frames/SVG/`srcset`/ids, CSS declarations with `url()`/`@import`/`expression` dropped, tracking pixels (≤ 2 px, hidden) always removed, remote images withheld until "Bilder laden" (or setting `always`): the **app** downloads them (platform `fetch`, ≤ 20 × 1.5 MB, no referrer/credentials) and inlines them as `data:` URLs, so the frame never needs network and the app CSP (`img-src 'self' data: blob:`, `frame-src 'none'`) stays untouched – a `srcdoc` iframe renders under it (checked in Chromium). Shown in `<iframe sandbox="allow-same-origin" srcdoc>` (no `allow-scripts`; the same-origin flag only lets the app size the frame and open clicked links in the system browser) with its own CSP `default-src 'none'; img-src data:; style-src 'unsafe-inline'`.
- **Not built / limits:** Google login on Android (needs its own authorization plugin), two-way calendar sync, Sparkasse FinTS/PSD2, mail write actions (archive, reply, send), notifications, IMAP.
