## System info data sources (`crates/system-info`, Dieser PC → System; all read-only, no admin rights, nothing stored)
| Fact | Source | Notes |
|---|---|---|
| CPU load, clock, memory, uptime, boot time, processes (memory + CPU %), disk read/write rate, network counters | `sysinfo` 0.38 (`system`, `network`, `disk`) | rates are differences between two readings (3 s refresh); CPU % of a process is 0 until the second reading |
| Graphics adapters | DXGI (`EnumAdapters1`: name, vendor id, dedicated/shared memory, LUID, "has a screen") **merged** with the display-class registry key (`DriverDesc`, `DriverVersion`, `ProviderName`, `HardwareInformation.qwMemorySize`) in `gpu.rs::merge_gpus` | the "Microsoft Basic Render Driver" (software flag **or** vendor `0x1414` **or** name) is never listed; a card DXGI misses comes from the registry; 0 B dedicated memory falls back to the registry value or is shown as shared memory; the adapter with a screen is "aktiv". GPU load/temperature are not read (no reliable no-admin source). |
| Network adapters | `GetAdaptersAddresses` (name, description, `IfType`, state, IPv4, IPv6 with privacy/deprecated flags) → `net.rs::classify` (ethernet/Wi-Fi/virtual by `IfType`, name and description) | link-local and loopback hidden; one main IPv6, the rest behind "alle anzeigen"; no MAC addresses |
| Wi-Fi name and signal | WLAN API (`WlanQueryInterface` current connection) | can be empty on Windows 11 24H2 without the location permission → "nicht gefunden" |
| Board, BIOS, RAM modules | SMBIOS table via `GetSystemFirmwareTable('RSMB')` → `smbios.rs::parse` (types 0, 2, 17) | no serial numbers or asset tags are ever read |
| Windows build | registry `CurrentVersion` (`DisplayVersion`, `CurrentBuild`, `UBR`) | |
| Monitors | `EnumDisplayMonitors` + `EnumDisplaySettingsW` | resolution, refresh rate |
| Default audio devices | `IMMDeviceEnumerator` (friendly names only), COM initialised per reading | |
| Drives: model, bus, health, temperature | `IOCTL_STORAGE_QUERY_PROPERTY` (`StorageDeviceProperty`, `StorageDeviceTemperatureProperty`) and `IOCTL_STORAGE_PREDICT_FAILURE` on `\\.\X:` opened with access 0 → `drives.rs` parsers | what Windows refuses without admin is shown as "nicht verfügbar – …" with the reason (`needsAdmin` / `unsupported`); never a serial number |
| Quick sizes, recycle bin | bounded walk (`sizes.rs`, ≤ 300 000 entries / 3 s per place, links never followed) and `SHQueryRecycleBinW` | "mindestens X" when the walk stopped early; emptying the bin stays in Explorer |
Not available without admin or extra drivers (and therefore not shown): CPU temperature, GPU temperature/load, battery wear and cycles. The browser/Android builds have none of this (`platforms: ['desktop']`).
Commands (all in `build.rs` + `capabilities/desktop.json`): `system_info`, `system_processes`, `system_disk_io`, `system_open_task_manager` (opens `taskmgr.exe`; Nemo never ends a program), `disk_list_drives`, `disk_place_sizes`, `disk_recycle_size`.
History for sparklines and "belegt seit letztem Scan" lives only in the memory of the running session (`modules/disk/history.ts`, `live.ts`); nothing is persisted.

## Disk module: scan and delete flow
1. **Scan:** `disk_scan_start(root)` → thread → rayon walk (`scan.rs`): one task per folder returns a `DirTemp`; arena `Tree` built at the end. Symlinks/junctions/mount points never entered; cloud placeholders never opened; unreadable folders listed; files under 1 MiB folded into one entry per folder (type totals stay exact); size = space on volume (cluster rounded). Progress/`done` via Tauri `Channel`; `disk_scan_cancel/pause`. Tree stays in Rust behind `RwLock`; the webview gets views (`disk_children`, `disk_query`) by node id.
2. **Delete:** UI sends node ids only → `disk_delete_plan` (block list, sizes, flags) → confirmation (typed phrase checked in Rust) → `disk_delete(plan, mode)`: block list again + resolved path must equal the planned one; trash via `IFileOperation` sink that aborts a would-be permanent delete (`trash_win.rs`), permanent via bottom-up walker (links removed, never followed); report per entry; tree corrected in place (`apply_to_tree`).
3. **Block list** (`guard.rs`): text-segment rules on canonicalised paths: drive roots, `Windows`, `Program Files (x86)`, `ProgramData`, `System Volume Information`, `$Recycle.Bin`, `Users` + every profile root, `AppData` + `Local|Roaming|LocalLow`, pagefile/hiberfil/swapfile/DumpStack, own exe dir + app data dirs + everything above them, running programs' folders. Known-folder API adds the real locations.
